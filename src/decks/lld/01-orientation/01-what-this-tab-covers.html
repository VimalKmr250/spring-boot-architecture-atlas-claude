Low-level design: from a one-line prompt to classes that run

This tab prepares you for the low-level design round, sometimes called object-oriented design or machine coding. You get a prompt such as "design a parking lot" and turn it into requirements, a class diagram and working Java in under an hour. It starts with the principles and the 23 patterns, works seven classic problems end to end, and ends with concurrency, scale and the interview itself.

7

problems solved in full: parking lot, library, ATM, chess, elevator, movie booking and Splitwise. Each has its requirements, a class diagram, runnable code and the follow-up questions interviewers ask.

23

Gang of Four patterns. The common ones get a slide each with running code; the rest share slides. One slide shows which patterns are easy to confuse and how to tell them apart.

21

JDK 21 is the baseline. Features added after Java 17 carry a since 21 tag, so you know which to avoid if your interview runs on an older JDK.

How to use it

  • Arrow keys move through slides; C opens contents, where each problem is its own section.
  • New to LLD? Read Foundations and SOLID first. The problem sections assume you know the vocabulary.
  • Short on time? Read the 45-minute plan, then do two problems with the code covered: write your own version, then compare.
  • Class diagrams are drawn as text, in the notation on Reading the class diagrams, because that is what you can draw in a shared editor.
How the code is writtenA code label that starts with a file name, such as ParkingLot.java · 1 of 3, is a complete Java file, or one numbered part of one. The parts join in slide order into a file that compiles with javac --release 21 -Xlint:all without warnings. The block labelled Output on JDK 21 is what that file actually printed. Demos use a fixed clock and ordered maps, so they print the same thing on every run.
