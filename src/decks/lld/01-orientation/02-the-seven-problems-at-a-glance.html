Seven problems, chosen for the ideas each one forces

These seven cover most LLD prompts. A new prompt is usually one of them in disguise: a hotel booking is the movie-booking problem, a vending machine is the ATM, a snake-and-ladder game is a smaller chess. Learn what each one teaches, not just its code.

The same five steps each time

Each problem runs through the same slides: requirements, class diagram and responsibilities, the domain model in code, the services with a demo and its output, then the decisions and follow-ups. That is the order to use in the interview, too.

Scoped to fit the hour

Each solution is the size you can write in a 45 to 90 minute round: about 150 to 250 lines. The last slide of each problem lists what was left out and how you would add it, which is usually the interviewer's next question.

How to practise

Read only the requirements slide. Spend 40 minutes on your own diagram and code. Then compare, looking first at the responsibilities (which class owns which decision), not the syntax.
