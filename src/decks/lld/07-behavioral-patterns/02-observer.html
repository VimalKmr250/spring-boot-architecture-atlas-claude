Observer: tell the interested parties, without knowing who they are

A subject keeps a list of listeners and calls them when something happens. The subject depends only on the listener interface, so adding a new reaction (an email, a metric, a display update) is a new subscriber, not an edit to the subject. The real design work is in the details: ordering, a listener that throws, and unsubscribing.

ObserverDemo.java · a small typed event bus
import java.util.*;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.function.Consumer;

record BookReturned(String isbn, String title) {}

final class EventBus<E> {
    private final List<Consumer<? super E>> listeners = new CopyOnWriteArrayList<>();

    AutoCloseable subscribe(Consumer<? super E> listener) {
        listeners.add(listener);
        return () -> listeners.remove(listener);  // handle to unsubscribe
    }

    void publish(E event) {
        for (var l : listeners) {                 // snapshot: safe even if a
            try {                                 // listener unsubscribes
                l.accept(event);
            } catch (RuntimeException ex) {       // one bad listener must not
                System.out.println("  listener failed: " + ex.getMessage());
            }                                     // starve the others
        }
    }
}

final class Catalogue {                           // the subject
    private final EventBus<BookReturned> returned;
    Catalogue(EventBus<BookReturned> returned) { this.returned = returned; }
    void giveBack(String isbn, String title) {
        System.out.println("returned " + title);
        returned.publish(new BookReturned(isbn, title));
    }
}

public class ObserverDemo {
    public static void main(String[] args) throws Exception {
        var bus = new EventBus<BookReturned>();
        var waiting = new ArrayDeque<>(List.of("ana", "bo"));
        int[] returns = {0};

        bus.subscribe(e -> System.out.println("  notify " + waiting.poll()
                + ": '" + e.title() + "' is ready"));
        bus.subscribe(e -> returns[0]++);
        AutoCloseable flaky = bus.subscribe(e -> {
            throw new IllegalStateException("SMS gateway down");
        });

        var catalogue = new Catalogue(bus);
        catalogue.giveBack("978-0134685991", "Effective Java");
        flaky.close();                            // unsubscribe
        catalogue.giveBack("978-0201633610", "Design Patterns");
        System.out.println("returns counted: " + returns[0]);
    }
}

DecisionChoices to state
Push or pullSend the event data (push, as here), or just "changed" and let listeners query (pull).
Sync or asyncSynchronous is simple and ordered, but a slow listener slows the subject. Async needs an executor and loses ordering.
FailureIsolate each listener, as here. Never let one exception stop the loop.
LifetimeListeners that are never removed leak memory. Return an unsubscribe handle.
Thread safetyCopyOnWriteArrayList suits lists that are read often and changed rarely.
Across servicesBetween processes the same idea becomes a message broker, with delivery guarantees to think about. See the Event-driven tab. In Spring, ApplicationEventPublisher and @EventListener are an in-process observer.
