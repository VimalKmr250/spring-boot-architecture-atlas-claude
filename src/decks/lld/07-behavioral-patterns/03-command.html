Command: turn a request into an object you can store, undo and replay

A command object holds everything needed to perform an action later: the receiver, the arguments, and enough state to reverse it. Once requests are objects you can keep a history (undo and redo), queue them (a job scheduler), log them (an audit trail) or send them elsewhere. Chess moves, editor edits and ATM transactions are all commands.

CommandDemo.java · an editor with undo and redo
import java.util.*;

interface Command {
    void execute();
    void undo();
}

final class Document {                          // the receiver
    final StringBuilder text = new StringBuilder();
    @Override public String toString() { return "\"" + text + "\""; }
}

record Insert(Document doc, int at, String s) implements Command {
    public void execute() { doc.text.insert(at, s); }
    public void undo()    { doc.text.delete(at, at + s.length()); }
}

final class Delete implements Command {
    private final Document doc;
    private final int from, to;
    private String removed = "";                // captured for undo
    Delete(Document doc, int from, int to) { this.doc = doc; this.from = from; this.to = to; }
    public void execute() {
        removed = doc.text.substring(from, to);
        doc.text.delete(from, to);
    }
    public void undo() { doc.text.insert(from, removed); }
}

final class Editor {                            // the invoker
    private final Deque<Command> undo = new ArrayDeque<>();
    private final Deque<Command> redo = new ArrayDeque<>();
    void run(Command c) { c.execute(); undo.push(c); redo.clear(); }
    boolean undo() {
        if (undo.isEmpty()) return false;
        Command c = undo.pop(); c.undo(); redo.push(c);
        return true;
    }
    boolean redo() {
        if (redo.isEmpty()) return false;
        Command c = redo.pop(); c.execute(); undo.push(c);
        return true;
    }
}

public class CommandDemo {
    public static void main(String[] args) {
        var doc = new Document();
        var ed = new Editor();
        ed.run(new Insert(doc, 0, "hello world"));   System.out.println("insert  " + doc);
        ed.run(new Delete(doc, 5, 11));             System.out.println("delete  " + doc);
        ed.run(new Insert(doc, 5, ", LLD"));        System.out.println("insert  " + doc);
        ed.undo();                                  System.out.println("undo    " + doc);
        ed.undo();                                  System.out.println("undo    " + doc);
        ed.redo();                                  System.out.println("redo    " + doc);
        ed.run(new Insert(doc, 0, ">> "));           System.out.println("insert  " + doc);
        System.out.println("redo after a new edit: " + ed.redo());
    }
}

Two ways to undoEach command stores what it needs to reverse itself, as Delete stores the removed text. Or the invoker stores a snapshot of the whole state before each command (memento). Reverse operations are cheap; snapshots are simpler and always correct. Chess uses the first: a Move remembers the captured piece.
The redo ruleA new command after an undo must clear the redo stack. Otherwise redo replays an edit on top of text it was never meant for. Interviewers test this exact case.
Command or strategy?Both are objects holding behaviour. A strategy answers how to do something the context always does. A command is a request: it knows its receiver and arguments, and can be stored and undone.
