Chain of responsibility: pass the request along until a handler takes it

Each handler either deals with the request or hands it to the next one. The sender knows only the first handler, and the chain can be reordered or extended without touching it. Approval limits, request validation, servlet filters and the ATM's note dispenser (50s, then 20s, then 10s) are all chains.

ChainDemo.java · expense approval, then the same chain as functions
import java.util.*;
import java.util.function.Function;

record Expense(String who, long amount, String category) {}

abstract class Approver {
    private Approver next;
    Approver then(Approver next) { this.next = next; return next; }   // fluent

    final String handle(Expense e) {
        String verdict = decide(e);
        if (verdict != null) return verdict;                  // handled
        return next != null ? next.handle(e)                  // pass it on
                            : "rejected: nobody can approve " + e.amount();
    }
    protected abstract String decide(Expense e);              // null = pass
}

final class PolicyCheck extends Approver {
    protected String decide(Expense e) {
        return e.category().equals("gift") ? "rejected by policy" : null;
    }
}

final class Limit extends Approver {
    private final String role;
    private final long max;
    Limit(String role, long max) { this.role = role; this.max = max; }
    protected String decide(Expense e) {
        return e.amount() <= max ? "approved by " + role : null;
    }
}

public class ChainDemo {
    public static void main(String[] args) {
        Approver chain = new PolicyCheck();
        chain.then(new Limit("team lead", 1_000))
             .then(new Limit("manager", 10_000))
             .then(new Limit("director", 100_000));

        var expenses = List.of(new Expense("ana", 400, "travel"),
                new Expense("bo", 7_500, "hardware"), new Expense("cy", 250, "gift"),
                new Expense("di", 60_000, "training"), new Expense("ed", 250_000, "travel"));
        expenses.forEach(e -> System.out.printf(Locale.ROOT, "%-3s %,8d  %s%n",
                e.who(), e.amount(), chain.handle(e)));

        List<Function<Expense, Optional<String>>> handlers = List.of(   // the
            e -> e.category().equals("gift") ? Optional.of("policy") : Optional.empty(),
            e -> e.amount() <= 1_000 ? Optional.of("team lead") : Optional.empty(),
            e -> Optional.of("finance review"));                   // lambda form
        System.out.println("functional: " + handlers.stream()
                .map(h -> h.apply(expenses.get(1)))
                .flatMap(Optional::stream).findFirst().orElseThrow());
    }
}

Pure chain

Exactly one handler deals with the request and the rest never see it, as with approval limits above.

Pipeline

Every handler does its part and passes it on: servlet filters, Spring Security's filter chain, middleware. Each can still stop the request.

Say what happens at the endA request that falls off the end of the chain must produce a defined result, like the "nobody can approve" line above. Silent drops are the classic bug. Build the chain in one place so its order is visible.
In the ATMDispensing from ₹500, ₹200 and ₹100 slots is a chain: each slot takes as many notes as it can and passes the remainder on. With limited notes, "as many as it can" is not always right, so the ATM's chain backs off and retries. See ATM · the model.
