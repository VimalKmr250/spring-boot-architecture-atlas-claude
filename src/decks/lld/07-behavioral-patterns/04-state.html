State: when every method starts with a check on the status field, make the status an object

A vending machine answers "select item" differently when it has no money, has money, or is sold out. Written with an enum and ifs, every method re-checks the status and the rules for one state are spread across all of them. With the State pattern each state is a class that handles every event, and returns the next state. Each state's rules live in one class.

StateDemo.java · a vending machine
import java.util.*;

interface State {                                   // each event, with a
    default State insert(Machine m, int coin) {     // safe default
        m.say("coin returned: " + coin); return this;
    }
    default State select(Machine m, String item) {
        m.say("insert money first"); return this;
    }
    default State cancel(Machine m) { return this; }
}

final class Idle implements State {
    public State insert(Machine m, int coin) { m.credit += coin; return new HasCredit(); }
}

final class HasCredit implements State {
    public State insert(Machine m, int coin) { m.credit += coin; return this; }
    public State select(Machine m, String item) {
        int price = m.price(item);
        if (m.stock(item) == 0) { m.say(item + " sold out"); return this; }
        if (m.credit < price) { m.say("need " + (price - m.credit) + " more"); return this; }
        m.vend(item, price);
        return m.empty() ? new SoldOut() : m.credit > 0 ? this : new Idle();
    }
    public State cancel(Machine m) { m.refund(); return new Idle(); }
}

final class SoldOut implements State {
    public State insert(Machine m, int coin) { m.say("sold out, coin returned"); return this; }
    public State cancel(Machine m) { m.refund(); return this; }
}

final class Machine {                                 // the context
    private final Map<String, int[]> items = new TreeMap<>();   // price, stock
    private State state = new Idle();
    int credit;

    Machine add(String item, int price, int stock) { items.put(item, new int[] { price, stock }); return this; }
    void insert(int coin)      { state = state.insert(this, coin); show(); }
    void select(String item)   { state = state.select(this, item); show(); }
    void cancel()              { state = state.cancel(this); show(); }

    int price(String item) { return items.get(item)[0]; }
    int stock(String item) { return items.get(item)[1]; }
    boolean empty() { return items.values().stream().allMatch(v -> v[1] == 0); }
    void vend(String item, int price) { items.get(item)[1]--; credit -= price; say("vend " + item); }
    void refund() { if (credit > 0) say("refund " + credit); credit = 0; }
    void say(String s) { System.out.print(s + "; "); }
    private void show() {
        System.out.println("[" + state.getClass().getSimpleName() + ", credit " + credit + "]");
    }
}

public class StateDemo {
    public static void main(String[] args) {
        var m = new Machine().add("chips", 20, 1).add("cola", 30, 1);
        m.select("cola");
        m.insert(20);
        m.select("cola");
        m.insert(20);
        m.select("cola");
        m.select("chips");
        m.select("cola");
        m.cancel();
        m.insert(10);
        m.select("chips");
        m.insert(10);
        m.select("chips");
        m.insert(5);
    }
}

State or strategy?The classes look the same. The difference is who changes them. A strategy is chosen from outside and stays until someone swaps it. A state changes itself: each handler returns the next state, so the transitions are part of the design.
Enum with a switch is fine for small machinesWith three states and two events, an enum plus a switch is shorter and easy to read. Move to state classes when states have their own data, or the switch appears in more than one method. The ATM uses state classes.
