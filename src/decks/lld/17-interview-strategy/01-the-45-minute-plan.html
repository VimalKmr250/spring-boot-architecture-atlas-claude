The 45-minute plan: requirements, model, code, then change

Most failed LLD rounds fail on time, not on knowledge: twenty minutes on a perfect class diagram and no code, or code from minute two with the wrong model. Fix the time box before the round and say it at the start: "I'll spend five minutes on requirements, ten on the design, and most of the rest on code." Interviewers like a candidate who manages the clock.

MinutesPhaseWhat you produceWhat the interviewer is checking
0–5ClarifyA short list of in-scope use cases, out-of-scope items and assumptions, written where both can see itDo you ask before you build? Do you scope, or try to build everything?
5–10EntitiesNouns to classes, enums and value objects; the one or two points of variationIs the model right? Title versus copy, spot versus vehicle
10–15Class diagramClasses, key fields and methods, relationships, interfaces. Text is fine.Responsibilities: who owns each decision
15–35CodeModel first, then the service, then a demo or test for the main flowClean, working code; naming; validation; no god class
35–40Run itThe happy path and two edge cases, run or walked throughDo you test your own code, unprompted?
40–45ExtendTheir change request, done or described class by class; concurrency if askedDoes the design bend, or break?

Machine-coding rounds (90–120 min)

Same phases, longer code phase. The output must run. Budget 15 minutes at the end for the demo, the input parser they specified, and reading your own code for bugs.

If you are behind at minute 25

Say so, and cut: "I'll finish the main use case and describe the reservation flow rather than code it." A working core beats three half-built features.

If you are ahead

Offer the follow-up before they ask: thread safety, a second strategy, or a test for the edge case you noticed. Raising your own design's weak spot is the strongest senior signal.
