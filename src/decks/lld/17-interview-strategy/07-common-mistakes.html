Common mistakes, and the fix for each that you can apply mid-interview

Most of these are recoverable if you notice them yourself. Saying "this manager class is getting too big; let me move the fee rule out" costs thirty seconds and turns a mistake into a demonstration of judgement.

Modelling mistakesFix
A …Manager or …System class with every methodMove each rule to the object that owns its data
Classes with only getters and settersReplace setters with intent-named methods that enforce rules
Inheritance for code reuse (Car extends Vehicle extends ParkingThing)Enum or composition; inheritance only for real "is-a"
A subclass per value (RedCar, SmallSpot)A field or an enum
One class where two lifecycles exist (book and copy)Split by identity: what gets borrowed versus what gets searched
Bidirectional references everywhereKeep the direction the use cases need; look the other way up by id
Process and code mistakesFix
Patterns announced before requirementsIntroduce each pattern when a requirement needs it
Twenty minutes on the diagramTime-box it; the diagram is a sketch, the code is the answer
double for moneylong minor units or BigDecimal
LocalDateTime.now() inside the logicInject a Clock
Check-then-act on shared mapsputIfAbsent, compute, or one lock around both
Singletons for the main serviceCreate it in main and pass it in
Never running the codeA main with the happy path and two edge cases
Arguing when challenged"Good point. The trade-off is… Here is what I'd change."
