S · A class should have one reason to change

"One reason to change" means one group of people who would ask for the change. It does not mean one method. An invoice class that calculates tax, saves to a database and emails a PDF changes when finance changes a rule, when the DBA changes the schema, and when marketing changes the email. Three groups, so three classes.

Before · one class, three reasons to change
class InvoiceService {
    Invoice create(Order order) {
        BigDecimal tax = order.subtotal()
                .multiply(new BigDecimal("0.18"));        // finance rule
        Invoice inv = new Invoice(order.id(), order.subtotal(), tax);
        jdbc.update("INSERT INTO invoice VALUES (?,?,?)", // storage
                inv.id(), inv.net(), inv.tax());
        mail.send(order.email(), "Your invoice",          // delivery
                pdf.render(inv));
        return inv;
    }
}
After · each rule has one home
final class TaxPolicy {                     // changes with finance
    BigDecimal taxOn(BigDecimal net) { return net.multiply(RATE); }
}
interface InvoiceRepository { void save(Invoice inv); }   // with storage
interface InvoiceNotifier { void issued(Invoice inv); }   // with delivery

final class InvoiceService {                // only coordinates
    private final TaxPolicy tax;
    private final InvoiceRepository repo;
    private final InvoiceNotifier notifier;
    // constructor omitted

    Invoice create(Order order) {
        var inv = new Invoice(order.id(), order.subtotal(),
                              tax.taxOn(order.subtotal()));
        repo.save(inv);
        notifier.issued(inv);
        return inv;
    }
}

How to spot a violation

The class name ends in Manager, Helper or Util. It imports from three unrelated packages. Describing it needs the word "and". Its tests need a database and a mail server.

How far to split

Split by who asks for changes, not until every class has one method. Invoice can still compute its own total, because that is invoice logic. Ten classes of three lines each is its own smell.

In the LLD round

The usual violation is one ParkingLotManager that finds spots, prices tickets and prints receipts. Put the fit rule on ParkingSpot, the price in a PricingStrategy, and keep the service thin.
