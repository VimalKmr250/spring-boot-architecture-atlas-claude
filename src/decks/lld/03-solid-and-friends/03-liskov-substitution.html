L · A subtype must keep every promise its supertype makes

Code written against a type must still work when handed any subtype. The test is behaviour, not whether the types compile. A square is a rectangle in geometry, but a mutable Square breaks a promise a mutable Rectangle makes: that setting the width leaves the height alone.

LiskovDemo.java · the broken subtype, then the fix
import java.util.*;

class Rectangle {
    protected int w, h;
    void setWidth(int w)  { this.w = w; }     // promise: height unchanged
    void setHeight(int h) { this.h = h; }     // promise: width unchanged
    int area() { return w * h; }
}

class Square extends Rectangle {              // compiles, and is wrong
    @Override void setWidth(int s)  { w = s; h = s; }
    @Override void setHeight(int s) { w = s; h = s; }
}

sealed interface Shape permits Rect, Sq { int area(); }
record Rect(int w, int h) implements Shape {  // immutable: no setter
    public int area() { return w * h; }       // promise to break
}
record Sq(int side) implements Shape {
    public int area() { return side * side; }
}

public class LiskovDemo {
    static void resize(Rectangle r) {         // written for Rectangle
        r.setWidth(5);
        r.setHeight(4);
        System.out.println(r.getClass().getSimpleName()
                + ": expected 20, got " + r.area());
    }

    public static void main(String[] args) {
        resize(new Rectangle());
        resize(new Square());

        List<Shape> shapes = List.of(new Rect(5, 4), new Sq(4));
        shapes.forEach(s -> System.out.println(s + " area " + s.area()));

        List<Integer> fixed = List.of(1, 2);  // the JDK's own compromise
        try { fixed.add(3); }
        catch (UnsupportedOperationException e) {
            System.out.println("List.of(..).add -> " + e.getClass().getSimpleName());
        }
    }
}

A subtype may notExample
Demand more of its inputsAn override that rejects a null the parent accepted
Promise less about its resultA sort override that sometimes leaves the list unsorted
Break an invariantA Square whose sides can no longer be set separately
Throw what the parent does notA ReadOnlyAccount.withdraw that throws UnsupportedOperationException
The fix is usually in the hierarchyIf a subtype has to refuse a method, it is not really that type. Make the shapes immutable, or give them a common interface with only the operations every one supports. Java's List.of breaks LSP on purpose, and documents the "optional operation"; your design should not need to.
