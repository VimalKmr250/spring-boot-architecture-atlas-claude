Low coupling, high cohesion, and knowing which class should own a job

Coupling is how much one class knows about others; keep it low. Cohesion is how closely the parts of one class belong together; keep it high. The Law of Demeter and the GRASP patterns are practical rules for getting both, and GRASP's information expert is the most useful single rule in an LLD round.

Law of Demeter · talk to your friends, not their friends
// Before: the caller walks the object graph, and
// breaks when any link in the chain changes
long rate = ticket.getSpot().getFloor().getLot()
                  .getPricing().getHourlyRate();

// After: tell, don't ask. The ticket knows its lot
// and asks it; the caller knows only the ticket.
long fee = ticket.feeAt(exitTime);
Demeter, preciselyA method may call methods on this, its parameters, objects it creates, and its own fields. Chains on value objects and fluent builders (stream().map().toList()) are fine, because they return the same kind of thing rather than reaching into another object's parts.
GRASP patternThe question it answers
Information expertWho should do this? The class that has the data. ParkingSpot.canFit(vehicle), not Manager.fits(spot, vehicle).
CreatorWho creates B? The class that contains, aggregates or closely uses B. A ParkingFloor creates its spots.
ControllerWho first receives a use case from the UI? A thin service per use case, such as BookingService.
Low coupling · high cohesionThe two tests every choice is scored against.
PolymorphismHow to handle behaviour that varies by type? Subtypes, not conditionals.
Pure fabricationNo domain class fits? Invent one: a repository, a DebtSimplifier.
IndirectionHow to decouple two classes? Put an intermediary between them, such as an interface or an event.
Protected variationsHow to protect code from change? Wrap the unstable part behind a stable interface. This is OCP by another name.
