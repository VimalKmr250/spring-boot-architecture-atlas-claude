I · No client should depend on methods it does not use

A fat interface forces every implementer to provide methods it cannot support, and every caller to depend on methods it never calls. Split interfaces by client, the way each caller uses them. It is LSP's partner: most UnsupportedOperationExceptions mean an interface is too wide.

Before · one interface for every machine
interface OfficeMachine {
    void print(Document d);
    void scan(Document d);
    void fax(Document d, String number);
}

final class BasicPrinter implements OfficeMachine {
    public void print(Document d) { /* works */ }
    public void scan(Document d) {
        throw new UnsupportedOperationException();   // LSP broken too
    }
    public void fax(Document d, String n) {
        throw new UnsupportedOperationException();
    }
}
After · one role per interface
interface Printer { void print(Document d); }
interface Scanner { void scan(Document d); }
interface Fax     { void fax(Document d, String number); }

final class BasicPrinter implements Printer {
    public void print(Document d) { /* works */ }
}
final class MultiFunctionDevice implements Printer, Scanner, Fax {
    public void print(Document d) { }
    public void scan(Document d) { }
    public void fax(Document d, String number) { }
}

final class PayslipJob {             // needs printing and nothing else
    private final Printer printer;
    PayslipJob(Printer printer) { this.printer = printer; }
}

In the library problem

A reference book can be read but not borrowed. Give the catalogue item a Borrowable role instead of a borrow() that throws for reference books.

In the ATM problem

The customer screen and the maintenance panel use the same machine through different interfaces: CustomerSession and MaintenanceOps. A customer can never reach refillCash.

How narrow is too narrow

One interface per method is rarely right. Group methods that the same client always uses together. Comparable has one method and is perfect; Collection has fifteen and is fine because its callers use them together.
