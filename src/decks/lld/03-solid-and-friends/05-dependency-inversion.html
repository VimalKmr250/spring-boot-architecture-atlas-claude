D · Business rules depend on interfaces they own, and never on the details

The high-level class (OrderService) declares the interface it needs (PaymentGateway), and the low-level class (the vendor adapter) implements it. The source-code arrow now points from detail to policy, the reverse of the call direction. That is what lets you swap the vendor, or test with a fake, without editing the business rule.

DipDemo.java · the policy owns the interface
import java.util.*;

record Order(String id, long amountCents) {}
record Charge(String orderId, long amountCents, String reference) {}

interface PaymentGateway {                  // declared by the order module
    Charge charge(String orderId, long amountCents);
}

final class OrderService {                  // high-level policy
    private final PaymentGateway gateway;   // injected, never created here
    OrderService(PaymentGateway gateway) {
        this.gateway = Objects.requireNonNull(gateway);
    }
    String checkout(Order o) {
        if (o.amountCents() <= 0) throw new IllegalArgumentException("amount");
        Charge c = gateway.charge(o.id(), o.amountCents());
        return "order " + o.id() + " paid, ref " + c.reference();
    }
}

final class FakeGateway implements PaymentGateway {        // tests, demos
    final List<Charge> charges = new ArrayList<>();
    public Charge charge(String id, long cents) {
        var c = new Charge(id, cents, "FAKE-" + (charges.size() + 1));
        charges.add(c);
        return c;
    }
}

final class CardNetworkGateway implements PaymentGateway { // the detail
    public Charge charge(String id, long cents) {          // would wrap the
        return new Charge(id, cents, "ch_" + id.toLowerCase()); // vendor SDK
    }
}

public class DipDemo {
    public static void main(String[] args) {               // composition root
        var fake = new FakeGateway();
        var underTest = new OrderService(fake);
        System.out.println(underTest.checkout(new Order("A-1", 2500)));
        System.out.println(underTest.checkout(new Order("A-2", 990)));
        System.out.println("recorded: " + fake.charges.stream()
                .map(Charge::reference).toList());

        var live = new OrderService(new CardNetworkGateway());
        System.out.println(live.checkout(new Order("B-7", 4200)));
    }
}
Output on JDK 21 · DipDemo.java

order A-2 paid, ref FAKE-2
recorded: [FAKE-1, FAKE-2]
order B-7 paid, ref ch_b-7
Call direction OrderService ──calls──> CardNetworkGateway Source dependency, inverted OrderService ──> «interface» PaymentGateway ▲ ┆ implements CardNetworkGateway
Inversion is not injectionDependency injection is how the object arrives: through the constructor, from main or from Spring. Dependency inversion is who owns the interface. Injecting a concrete CardNetworkGateway is injection without inversion, and still couples the policy to the vendor.
