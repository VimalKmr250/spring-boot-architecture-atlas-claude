O · Open for extension, closed for modification, at the points you expect to change

When a requirement you expected arrives, such as a new pricing rule, you should be able to add a class rather than edit a working one. That needs a seam: an interface at the point of variation. You cannot be closed against every change, so choose the seams from the requirements, and say which ones you chose.

Before · every new rule edits this method
long fee(Ticket t, Instant exit) {
    long hours = t.hoursUntil(exit);
    switch (t.lot().pricingMode()) {
        case "HOURLY":  return hours * 40;
        case "WEEKEND": return isWeekend(exit) ? 100 : hours * 40;
        case "EVENT":   return 300;
        // next month: "EV_DISCOUNT" goes here, and the tests
        // for the other three rules must run again
        default: throw new IllegalStateException();
    }
}
After · a new rule is a new class
interface PricingStrategy {
    long fee(Ticket t, Instant exit);
}
final class HourlyPricing implements PricingStrategy {
    public long fee(Ticket t, Instant exit) { return t.hoursUntil(exit) * 40; }
}
final class FlatEventPricing implements PricingStrategy {
    public long fee(Ticket t, Instant exit) { return 300; }
}
// EV discount: a decorator that wraps any strategy, no edits
final class EvDiscount implements PricingStrategy {
    private final PricingStrategy inner;
    EvDiscount(PricingStrategy inner) { this.inner = inner; }
    public long fee(Ticket t, Instant exit) {
        long base = inner.fee(t, exit);
        return t.vehicle().electric() ? base * 80 / 100 : base;
    }
}
The honest versionSomething still has to choose which strategy to use: a factory, a configuration map, or the composition root in main. That one place is allowed to change. OCP moves the change to where it is cheap and safe; it does not remove it.
When a switch is the better answerIf the types are fixed (a sealed Vehicle) and operations keep being added, a switch over the sealed type is closed in a different way: the compiler finds every switch that needs a new case. Say which axis you expect to change. See the Java 21 toolkit.
