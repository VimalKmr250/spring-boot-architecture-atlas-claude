Value objects are equal by value; entities are equal by identity

A value object such as Money, Seat or Position has no identity: two with the same fields are the same value. Make it immutable, and a record gives you equals and hashCode for free. An entity such as Member or Booking keeps its identity while its fields change, so it is equal by its id alone.

ValueObjects.java · money, an entity, and the mutable-key trap
import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.*;

record Money(BigDecimal amount, Currency currency) {     // value object
    Money {                                              // compact constructor:
        Objects.requireNonNull(amount, "amount");        // validate, then
        Objects.requireNonNull(currency, "currency");    // normalise the scale
        amount = amount.setScale(currency.getDefaultFractionDigits(),
                                 RoundingMode.HALF_EVEN);
    }
    static Money of(String amount, String code) {
        return new Money(new BigDecimal(amount), Currency.getInstance(code));
    }
    Money plus(Money o) {
        if (!currency.equals(o.currency))
            throw new IllegalArgumentException("currency mismatch");
        return new Money(amount.add(o.amount), currency);
    }
}

final class Member {                                     // entity
    private final String id;
    private String email;                                // may change
    Member(String id, String email) { this.id = id; this.email = email; }
    void changeEmail(String email) { this.email = email; }
    @Override public boolean equals(Object o) {
        return o instanceof Member m && id.equals(m.id);
    }
    @Override public int hashCode() { return id.hashCode(); }
    @Override public String toString() { return id + "<" + email + ">"; }
}

final class MutablePoint {                               // the trap
    int x, y;
    MutablePoint(int x, int y) { this.x = x; this.y = y; }
    @Override public boolean equals(Object o) {
        return o instanceof MutablePoint p && x == p.x && y == p.y;
    }
    @Override public int hashCode() { return Objects.hash(x, y); }
}

public class ValueObjects {
    public static void main(String[] args) {
        System.out.println("double 0.1 + 0.2       = " + (0.1 + 0.2));
        System.out.println("Money  0.10 + 0.20     = "
                + Money.of("0.10", "USD").plus(Money.of("0.20", "USD")));
        System.out.println("BigDecimal 10.5 vs 10.50: "
                + new BigDecimal("10.5").equals(new BigDecimal("10.50")));
        System.out.println("Money      10.5 vs 10.50: "
                + Money.of("10.5", "USD").equals(Money.of("10.50", "USD")));

        Set<Member> members = new HashSet<>();
        Member ana = new Member("M-1", "ana@old.example");
        members.add(ana);
        ana.changeEmail("ana@new.example");
        System.out.println("entity found after edit: " + members.contains(ana));

        Set<MutablePoint> points = new HashSet<>();
        MutablePoint p = new MutablePoint(1, 2);
        points.add(p);
        p.x = 5;                                          // hash changes
        System.out.println("mutable key found:       " + points.contains(p)
                + " (size " + points.size() + ")");
    }
}

Money  0.10 + 0.20     = Money[amount=0.30, currency=USD]
BigDecimal 10.5 vs 10.50: false
Money      10.5 vs 10.50: true
entity found after edit: true
mutable key found:       false (size 1)

The rules the demo shows

  • Never use double for money. Use BigDecimal with a fixed scale, or a long of minor units (cents).
  • BigDecimal.equals compares scale too, so 10.5 and 10.50 differ. Normalise the scale in the constructor, or compare with compareTo.
  • Validate in the compact constructor. Then no invalid Money can exist anywhere in the program.
  • Base an entity's equals on its id only, and make the id final. Editing an email must not change which member it is.
  • Never put a mutable object in a hash set or use it as a map key if the fields in its hashCode can change. The object is still in the set, but contains looks in the wrong bucket and cannot find it.
