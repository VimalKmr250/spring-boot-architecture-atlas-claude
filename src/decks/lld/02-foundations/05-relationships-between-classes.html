Six relationships, and the one question that separates them: who owns the lifetime?

Each relationship is a different amount of coupling. Pick the weakest one that works. In Java, several of them look identical in code (a field), so the difference is in who creates the object, who else can hold it, and whether it outlives its holder.

RelationshipMeansJava shapeLifetimeExample
Dependency ┄┄>Uses it brieflyA parameter or a local variableOnly for the callFeeCalculator uses a Ticket passed to fee(ticket)

The same field, three relationships
final class ParkingFloor {                 // composition: creates its spots,
    private final List<ParkingSpot> spots; // never exposes the list
    ParkingFloor(int n) {
        spots = IntStream.range(0, n).mapToObj(ParkingSpot::new).toList();
    }
}

final class Group {                        // aggregation: users come from
    private final Set<User> members = new LinkedHashSet<>();
    void add(User u) { members.add(u); }   // outside and outlive the group
}

final class Loan {                         // association: one reference
    private final Member member;           // to an independent object
    Loan(Member member) { this.member = member; }
}
Why interviewers ask"Is that composition or aggregation?" is really "who deletes it, and can anyone else change it?" Answer with the lifecycle: "The floor creates its spots and never hands the list out, so it is composition. When a floor is closed, its spots go with it." Nobody will mark you down for the diamond's colour; they will for a spot that two floors can both mutate.
