Records, sealed types and pattern matching make models shorter and safer

Modern Java changes what an LLD answer looks like. A value object is one line. A closed family of types is a sealed interface, and a switch over it must handle every case or it does not compile. Say what you are using and why: "sealed, so adding a vehicle type breaks the build instead of silently falling through".

Toolkit.java · sealed types, record patterns, sequenced collections
import java.util.*;

sealed interface Vehicle permits Car, Motorbike, Truck {
    String plate();                        // records implement it for free
}
record Car(String plate, boolean electric) implements Vehicle {}
record Motorbike(String plate) implements Vehicle {}
record Truck(String plate, int axles) implements Vehicle {}

enum SpotSize { SMALL, MEDIUM, LARGE }

public class Toolkit {
    static SpotSize sizeFor(Vehicle v) {
        return switch (v) {                // exhaustive: no default, and a
            case Motorbike m -> SpotSize.SMALL;  // new Vehicle will not compile
            case Car c       -> SpotSize.MEDIUM;
            case Truck t     -> SpotSize.LARGE;
        };
    }

    static int hourlyRate(Vehicle v) {
        return switch (v) {
            case Car(String p, boolean e) when e -> 3;   // record pattern + guard
            case Car c                           -> 4;
            case Motorbike m                     -> 2;
            case Truck(String p, int axles)      -> 5 + 2 * axles;
        };
    }

    public static void main(String[] args) {
        List<Vehicle> queue = List.of(new Car("KA-01", false),
                new Car("KA-02", true), new Motorbike("KA-03"),
                new Truck("KA-04", 3));
        Map<SpotSize, List<String>> bySize = new EnumMap<>(SpotSize.class);
        for (Vehicle v : queue) {
            bySize.computeIfAbsent(sizeFor(v), k -> new ArrayList<>())
                  .add(v.plate());
            System.out.println(v + " -> " + hourlyRate(v) + "/h");
        }
        System.out.println(bySize);
        System.out.println("first " + queue.getFirst().plate()
                + ", last " + queue.getLast().plate()
                + ", reversed " + queue.reversed().stream()
                        .map(Vehicle::plate).toList());
    }
}

Sealed type or interface with a method?Both are right for different problems. Use a sealed type and switch when the set of types is fixed but operations keep being added (pricing, sizing, reporting). Use an ordinary interface and polymorphic methods when new types keep arriving and the operations are fixed. Say which axis you expect to change; that is the design decision.
