Virtual threads: a thread per task is cheap again, but the downstream is not

Java 21 made virtual threads final since 21. A virtual thread that blocks on I/O or sleep unmounts from its carrier thread, so a program can hold millions of them. In an LLD answer this means "one virtual thread per request" is a reasonable design, and a fixed thread pool is no longer the default. The limit moves to the service you call, so bound that explicitly.

VirtualThreads.java · one thread per task, a semaphore for the slow dependency
import java.time.Duration;
import java.util.List;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.stream.IntStream;

public class VirtualThreads {
    static final Semaphore priceApi = new Semaphore(3);    // it allows 3 at once
    static final AtomicInteger inFlight = new AtomicInteger();
    static final AtomicInteger peak = new AtomicInteger();

    static int quote(String showId) throws InterruptedException {
        priceApi.acquire();
        try {
            peak.accumulateAndGet(inFlight.incrementAndGet(), Math::max);
            Thread.sleep(Duration.ofMillis(20));           // blocking: unmounts
            return showId.length() * 100;
        } finally {
            inFlight.decrementAndGet();
            priceApi.release();
        }
    }

    public static void main(String[] args) throws Exception {
        List<String> shows = IntStream.range(0, 50).mapToObj(i -> "SHOW-" + i).toList();
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            List<Future<Integer>> quotes = shows.stream()
                    .map(s -> executor.submit(() -> quote(s))).toList();
            int total = 0;
            for (Future<Integer> f : quotes) total += f.get();
            System.out.println("quoted " + quotes.size() + " shows, total " + total);
        }
        System.out.println("peak concurrent calls to the price API: " + peak.get());

        var slept = new AtomicInteger();
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 10_000; i++)
                executor.submit(() -> {
                    Thread.sleep(Duration.ofMillis(100));
                    return slept.incrementAndGet();
                });
        }                                                   // waits for all
        System.out.println(slept.get() + " virtual threads each slept 100 ms");

        Thread t = Thread.ofVirtual().name("booking-", 1).unstarted(() -> { });
        System.out.println(t.getName() + " is virtual: " + t.isVirtual());
    }
}

RuleWhy
Never pool virtual threadsThey are cheap to create; a pool only adds a queue. Create one per task.
Limit the resource, not the threadsA Semaphore or a connection pool protects the database or API. Ten thousand threads will otherwise open ten thousand connections.
Avoid blocking inside synchronized on 21On JDK 21 to 23 it pins the carrier thread. Use ReentrantLock around blocking calls. JDK 24 removed most pinning (JEP 491).
Use ThreadLocal sparinglyA million threads mean a million copies. Scoped values are the replacement, and are final from JDK 25.
CPU-bound work gains nothingVirtual threads help waiting, not computing. Use a pool sized to the cores, or parallel streams.
Structured concurrency, on its wayStructuredTaskScope runs subtasks as a unit: if one fails, the others are cancelled, and none outlive the block. It is a preview API on JDK 21 through 25, so it needs --enable-preview and is not used in this tab's code. Mention it for "fetch price and seat map in parallel, fail fast".
