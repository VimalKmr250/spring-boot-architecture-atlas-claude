Producer-consumer with a bounded queue, and the lock ordering that prevents deadlock

Many LLD systems hand work between threads: orders to a fulfilment worker, notifications to a sender. A bounded BlockingQueue makes producers wait when consumers fall behind (back-pressure), and a poison pill per consumer shuts them down cleanly. The other classic is deadlock. Two transfers lock the same two accounts in opposite orders, and each waits for the other forever.

ProducerConsumer.java · three producers, two consumers, clean shutdown
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.*;

public class ProducerConsumer {
    record Order(int id, long amount) {}
    static final Order POISON = new Order(-1, 0);       // a sentinel, compared by ==

    public static void main(String[] args) throws Exception {
        BlockingQueue<Order> queue = new ArrayBlockingQueue<>(10);   // bounded
        int producers = 3, consumers = 2, perProducer = 1_000;
        var processed = new AtomicInteger();
        var total = new LongAdder();

        try (var pool = Executors.newVirtualThreadPerTaskExecutor()) {
            List<Future<?>> made = new ArrayList<>();
            for (int p = 0; p < producers; p++) {
                int base = p * perProducer;
                made.add(pool.submit(() -> {
                    for (int i = 1; i <= perProducer; i++)
                        queue.put(new Order(base + i, i));   // blocks when full
                    return null;
                }));
            }
            for (int c = 0; c < consumers; c++) {
                pool.submit(() -> {
                    while (true) {
                        Order o = queue.take();              // blocks when empty
                        if (o == POISON) return null;
                        processed.incrementAndGet();
                        total.add(o.amount());
                    }
                });
            }
            for (Future<?> f : made) f.get();                // all produced
            for (int c = 0; c < consumers; c++) queue.put(POISON);
        }                                                    // all consumed
        System.out.println("processed " + processed.get() + " orders, total " + total.sum());
        System.out.println("queue empty: " + queue.isEmpty());
    }
}

Deadlock, and the fix: always lock in a global order
// Thread 1: transfer(a, b)  locks a, then waits for b
// Thread 2: transfer(b, a)  locks b, then waits for a   → both wait forever
void transfer(Account from, Account to, long amount) {
    Account first  = from.id() < to.id() ? from : to;   // same order for
    Account second = from.id() < to.id() ? to : from;   // every caller
    synchronized (first) {
        synchronized (second) {
            from.debit(amount);
            to.credit(amount);
        }
    }
}
Deadlock needs all fourBreak it by
Mutual exclusionLock-free structures, or immutable data
Hold and waitTake every lock at once, or tryLock and back off
No preemptiontryLock(timeout): give up and retry
Circular waitA global lock order, as above. The usual answer.
