From one JVM to many: every in-memory guarantee needs a new owner

An LLD answer lives in one process: a synchronized method, a ConcurrentHashMap, an AtomicInteger for ids. Run three copies behind a load balancer and each of those guarantees silently covers only a third of the traffic. The scale follow-up is asking one thing: for each guarantee, what now enforces it?

Keep the model

The classes do not change. ParkingSpot.occupy still validates; the repository behind it now saves with a condition. The domain model survives; only its guardians move.

Push the invariant down

The database is the one thing all servers share. An invariant it enforces (a unique key, a check constraint, a conditional update) cannot be bypassed by a server with stale memory.

Say what becomes eventual

Seat maps, free-spot displays and balances shown to other users can lag by a second. Claims, debits and bookings cannot. Name which is which.
