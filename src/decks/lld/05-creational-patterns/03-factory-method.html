Factory method: one place decides which class to create

Callers ask for "a notifier for this channel" and never name the concrete class. There are two forms. A static factory is a method that picks the class from its input, and it is what LLD answers use most. The GoF factory method is an abstract method that a subclass overrides to choose the class used inside a fixed algorithm.

FactoryDemo.java · a static factory, and the GoF factory method
import java.util.List;

enum Channel { EMAIL, SMS, PUSH }

interface Notifier { String send(String to, String message); }

record EmailNotifier() implements Notifier {
    public String send(String to, String m) { return "email " + to + ": " + m; }
}
record SmsNotifier(int maxLength) implements Notifier {
    public String send(String to, String m) {
        String body = m.length() <= maxLength ? m : m.substring(0, maxLength - 3) + "...";
        return "sms   " + to + ": " + body;
    }
}
record PushNotifier() implements Notifier {
    public String send(String to, String m) { return "push  " + to + ": " + m; }
}

final class Notifiers {                    // static factory: the only code
    private Notifiers() {}                 // that names concrete classes
    static Notifier forChannel(Channel c) {
        return switch (c) {                // exhaustive over the enum
            case EMAIL -> new EmailNotifier();
            case SMS   -> new SmsNotifier(20);
            case PUSH  -> new PushNotifier();
        };
    }
}

interface RowFormat { String header(); String join(List<String> cells); }

abstract class ReportExporter {            // GoF factory method
    final String export(List<List<String>> rows) {  // the fixed algorithm
        RowFormat f = createFormat();      // the subclass picks the class
        StringBuilder out = new StringBuilder(f.header());
        rows.forEach(r -> out.append(f.join(r)).append('\n'));
        return out.toString();
    }
    protected abstract RowFormat createFormat();   // the factory method
}

final class CsvExporter extends ReportExporter {
    protected RowFormat createFormat() {
        return new RowFormat() {
            public String header() { return ""; }
            public String join(List<String> c) { return String.join(",", c); }
        };
    }
}

final class MarkdownExporter extends ReportExporter {
    protected RowFormat createFormat() {
        return new RowFormat() {
            public String header() { return "| plate | fee |\n|---|---|\n"; }
            public String join(List<String> c) { return "| " + String.join(" | ", c) + " |"; }
        };
    }
}

public class FactoryDemo {
    public static void main(String[] args) {
        for (Channel c : Channel.values())
            System.out.println(Notifiers.forChannel(c)
                    .send("ana", "Your car is ready at gate B"));

        var rows = List.of(List.of("KA-01", "120"), List.of("KA-02", "80"));
        System.out.print(new CsvExporter().export(rows));
        System.out.print(new MarkdownExporter().export(rows));
    }
}

What it buys youOnly Notifiers names the concrete classes. Adding WHATSAPP touches the enum and the factory, and the exhaustive switch will not compile until you add the case. No caller changes.
Where people overdo itA factory that wraps a single new with no choice in it is noise. So is a VehicleFactory interface with one implementation. Add the factory when there is a real decision to make, or when construction needs rules the caller should not know.
