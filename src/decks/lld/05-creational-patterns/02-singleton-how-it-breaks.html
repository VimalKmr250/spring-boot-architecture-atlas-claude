How a singleton breaks, and why dependency injection replaced it

A private constructor does not guarantee one instance. Reflection can call it, and deserialization creates a new object without calling it at all. Only the enum form survives both. The bigger problem is not a second instance, though. A singleton is hidden global state, and it makes the classes that use it hard to test.

SingletonBreak.java · reflection and serialization against three singletons
import java.io.*;
import java.lang.reflect.Constructor;
import java.lang.reflect.InvocationTargetException;

final class Naive implements Serializable {
    private static final long serialVersionUID = 1L;
    static final Naive INSTANCE = new Naive();
    private Naive() {}
}

final class Guarded implements Serializable {
    private static final long serialVersionUID = 1L;
    static final Guarded INSTANCE = new Guarded();
    private Guarded() {
        if (INSTANCE != null) throw new IllegalStateException("already created");
    }
    private Object readResolve() { return INSTANCE; }   // replace the copy
}

enum EnumSingleton { INSTANCE }

public class SingletonBreak {
    static String reflect(Class<?> type, Object one) {
        try {
            Constructor<?> c = type.isEnum()
                    ? type.getDeclaredConstructor(String.class, int.class)
                    : type.getDeclaredConstructor();
            c.setAccessible(true);
            Object copy = type.isEnum() ? c.newInstance("COPY", 1) : c.newInstance();
            return copy == one ? "same instance" : "SECOND INSTANCE";
        } catch (InvocationTargetException e) {
            return "blocked: " + e.getCause().getMessage();
        } catch (ReflectiveOperationException | IllegalArgumentException e) {
            return "blocked: " + e.getMessage();
        }
    }

    static String serialize(Object one) throws IOException, ClassNotFoundException {
        var bytes = new ByteArrayOutputStream();
        try (var out = new ObjectOutputStream(bytes)) { out.writeObject(one); }
        try (var in = new ObjectInputStream(
                new ByteArrayInputStream(bytes.toByteArray()))) {
            return in.readObject() == one ? "same instance" : "SECOND INSTANCE";
        }
    }

    public static void main(String[] args) throws Exception {
        Object[][] cases = { { Naive.class, Naive.INSTANCE },
                { Guarded.class, Guarded.INSTANCE },
                { EnumSingleton.class, EnumSingleton.INSTANCE } };
        for (Object[] c : cases) {
            Class<?> type = (Class<?>) c[0];
            System.out.printf("%-13s reflection: %s%n", type.getSimpleName(),
                    reflect(type, c[1]));
            System.out.printf("%-13s serialize:  %s%n", "", serialize(c[1]));
        }
    }
}

Cost of a singletonWhy
Hard to testA class that calls PaymentGateway.getInstance() cannot be given a fake.
Hidden dependencyThe constructor does not show that the class needs the gateway.
State leaks between testsOne test's data is still there in the next.
One per class loaderTwo web apps in one server each get their own "single" instance.
What to say about the parking lot"There is one ParkingLot in this program, but I'll create it in main and pass it in, not make it a singleton. Then a test can build a small lot with two spots." In Spring, a bean is a singleton by default (one per container), which gives you the single instance without the global access.
