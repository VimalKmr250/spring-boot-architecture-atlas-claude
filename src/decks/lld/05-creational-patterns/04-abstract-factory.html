Abstract factory: create a family of objects that must match

Use it when several objects vary together and mixing them would be a bug. A checkout in India needs a UPI authoriser, 18% GST and rupees. A checkout in Germany needs SEPA, 19% VAT and euros. One factory per region makes each checkout internally consistent, and the checkout code never names a region.

AbstractFactoryDemo.java · one kit per region
interface Authorizer { String authorize(long minor); }
interface TaxRule { long taxOn(long minor); }

interface RegionKit {                       // the abstract factory
    Authorizer authorizer();
    TaxRule taxRule();
    String currency();
}

final class IndiaKit implements RegionKit {
    public Authorizer authorizer() { return m -> "UPI mandate for " + m; }
    public TaxRule taxRule() { return m -> m * 18 / 100; }      // GST
    public String currency() { return "INR"; }
}

final class GermanyKit implements RegionKit {
    public Authorizer authorizer() { return m -> "SEPA debit for " + m; }
    public TaxRule taxRule() { return m -> m * 19 / 100; }      // VAT
    public String currency() { return "EUR"; }
}

final class Checkout {                      // knows only the interfaces
    private final RegionKit kit;
    Checkout(RegionKit kit) { this.kit = kit; }
    String pay(long netMinor) {
        long gross = netMinor + kit.taxRule().taxOn(netMinor);
        return kit.authorizer().authorize(gross) + " " + kit.currency();
    }
}

public class AbstractFactoryDemo {
    public static void main(String[] args) {
        for (RegionKit kit : new RegionKit[] { new IndiaKit(), new GermanyKit() })
            System.out.println(new Checkout(kit).pay(10_000));
    }
}

When it earns its placeRarely in a one-hour LLD round. It shows up in "support multiple regions", "support light and dark themes" and "support two database vendors". If there is only one product, you want a factory method; if nothing has to match, you want separate strategies.
