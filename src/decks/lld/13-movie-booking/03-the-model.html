Movie booking: atomic seat claims on the show, one-way transitions on the booking

The show exposes exactly three ways to change a seat's owner, and each is a single atomic call on ConcurrentHashMap. The booking's transitions are synchronized and each checks the clock. So "confirm" and "expire" can never both succeed on the same booking, whichever thread gets there first.

import java.time.*;
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

enum SeatCategory {
    REGULAR(200), PREMIUM(350), RECLINER(600);
    final long basePrice;
    SeatCategory(long basePrice) { this.basePrice = basePrice; }
}

record Seat(char row, int number, SeatCategory category) implements Comparable<Seat> {
    private static final Comparator<Seat> ORDER =
            Comparator.comparing(Seat::row).thenComparingInt(Seat::number);
    public int compareTo(Seat other) { return ORDER.compare(this, other); }
    @Override public String toString() { return "" + row + number; }
}

record Movie(String title, int minutes) {}

final class Show {
    private final String id;
    private final Movie movie;
    private final LocalDateTime start;
    private final SortedMap<String, Seat> seats = new TreeMap<>();
    private final ConcurrentMap<Seat, String> claims = new ConcurrentHashMap<>();

    Show(String id, Movie movie, LocalDateTime start, Map<Character, SeatCategory> rows, int perRow) {
        this.id = id; this.movie = movie; this.start = start;
        rows.forEach((row, cat) -> {
            for (int n = 1; n <= perRow; n++) seats.put("" + row + n, new Seat(row, n, cat));
        });
    }
    String id() { return id; }
    Movie movie() { return movie; }
    LocalDateTime start() { return start; }
    Collection<Seat> seats() { return seats.values(); }
    Seat seat(String label) {
        Seat s = seats.get(label);
        if (s == null) throw new IllegalArgumentException("no seat " + label);
        return s;
    }

    String claimant(Seat s) { return claims.get(s); }
    boolean claim(Seat s, String bookingId) { return claims.putIfAbsent(s, bookingId) == null; }
    boolean reclaim(Seat s, String fromId, String toId) { return claims.replace(s, fromId, toId); }
    void release(Seat s, String bookingId) { claims.remove(s, bookingId); }  // only if still ours
}

enum BookingStatus { HELD, CONFIRMED, EXPIRED, CANCELLED }

final class Booking {
    private final String id, user;
    private final Show show;
    private final List<Seat> seats;
    private final long amount;
    private final Instant heldUntil;
    private BookingStatus status = BookingStatus.HELD;
    private String paymentRef;

    Booking(String id, String user, Show show, List<Seat> seats, long amount, Instant heldUntil) {
        this.id = id; this.user = user; this.show = show;
        this.seats = List.copyOf(seats); this.amount = amount; this.heldUntil = heldUntil;
    }
    String id() { return id; }
    String user() { return user; }
    Show show() { return show; }
    List<Seat> seats() { return seats; }
    long amount() { return amount; }
    synchronized BookingStatus status() { return status; }

    synchronized boolean tryConfirm(Instant now, String ref) {
        if (status == BookingStatus.HELD && !now.isBefore(heldUntil)) status = BookingStatus.EXPIRED;
        if (status != BookingStatus.HELD) return false;
        status = BookingStatus.CONFIRMED;
        paymentRef = ref;
        return true;
    }

    synchronized boolean tryExpire(Instant now) {      // may its seats be taken?
        if (status == BookingStatus.HELD && !now.isBefore(heldUntil)) status = BookingStatus.EXPIRED;
        return status == BookingStatus.EXPIRED || status == BookingStatus.CANCELLED;
    }

    synchronized boolean isLive(Instant now) {         // for display only
        return status == BookingStatus.HELD && now.isBefore(heldUntil);
    }

    synchronized boolean cancel() {
        if (status != BookingStatus.HELD) return false;
        status = BookingStatus.CANCELLED;
        return true;
    }

    @Override public synchronized String toString() {
        return id + " " + user + " " + seats + " " + amount + " " + status
                + (paymentRef == null ? "" : " " + paymentRef);
    }
}
Three atomic operations, nothing elseputIfAbsent claims a free seat. replace(seat, old, new) takes a seat from a dead booking only if it still belongs to that booking. remove(seat, id) releases a seat only if it is still ours, so a late cancel cannot free a seat someone else has since claimed. There is no check-then-act anywhere, so there is no race window.
Why expiry is lazyA hold is dead the moment its time passes, whether or not anything noticed. tryExpire records that when a competing user asks for the seat. A cleanup job can still sweep old holds to tidy the map, but correctness never depends on it running on time.
Why Seat is ComparableA multi-seat hold claims seats in sorted order. If two users hold {A1, A2} and {A2, A1} and each claimed in the order given, each could get one seat and fail on the other. Both would then roll back, and could keep doing so under load. A fixed order, the same idea that prevents deadlocks, makes one of them win outright.
