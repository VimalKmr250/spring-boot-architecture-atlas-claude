Library: the model, with the copy guarding its status and the member guarding its limits

Copy.lendTo is the only way a copy goes out, and it enforces every status rule in one switch, including "on hold for someone else". Member.checkCanBorrow enforces the tier limit and the fines rule. The library service calls both before it changes anything.

record Book(String isbn, String title, List<String> authors) {
    Book { authors = List.copyOf(authors); }
    boolean matches(String text) {
        String q = text.toLowerCase(Locale.ROOT);
        return title.toLowerCase(Locale.ROOT).contains(q)
            || authors.stream().anyMatch(a -> a.toLowerCase(Locale.ROOT).contains(q));
    }
}

enum CopyStatus { AVAILABLE, ON_LOAN, ON_HOLD, REFERENCE_ONLY }

final class Copy {
    private final String barcode;
    private final Book book;
    private CopyStatus status;
    private String heldFor;                        // member id, while ON_HOLD
    private LocalDate holdUntil;

    Copy(String barcode, Book book, boolean referenceOnly) {
        this.barcode = barcode;
        this.book = book;
        this.status = referenceOnly ? CopyStatus.REFERENCE_ONLY : CopyStatus.AVAILABLE;
    }
    String barcode() { return barcode; }
    Book book() { return book; }
    CopyStatus status() { return status; }

    void lendTo(String memberId) {                 // every status rule, once
        switch (status) {
            case AVAILABLE -> { }
            case ON_HOLD -> {
                if (!memberId.equals(heldFor))
                    throw new IllegalStateException(barcode + " is on hold for " + heldFor);
            }
            case ON_LOAN -> throw new IllegalStateException(barcode + " is on loan");
            case REFERENCE_ONLY -> throw new IllegalStateException(barcode + " is reference only");
        }
        status = CopyStatus.ON_LOAN;
        heldFor = null;
        holdUntil = null;
    }

    void returned() {
        if (status != CopyStatus.ON_LOAN) throw new IllegalStateException(barcode + " is not on loan");
        status = CopyStatus.AVAILABLE;
    }

    void holdFor(String memberId, LocalDate until) {
        if (status != CopyStatus.AVAILABLE) throw new IllegalStateException(barcode + " is not free");
        status = CopyStatus.ON_HOLD;
        heldFor = memberId;
        holdUntil = until;                         // read by the expiry job
    }
}

enum Tier {
    STANDARD(3, 14), PREMIUM(5, 28);
    final int maxLoans, loanDays;
    Tier(int maxLoans, int loanDays) { this.maxLoans = maxLoans; this.loanDays = loanDays; }
}

final class Member {
    private final String id;
    private final Tier tier;
    private int onLoan;
    private long finesDue;

    Member(String id, Tier tier) { this.id = id; this.tier = tier; }
    String id() { return id; }
    Tier tier() { return tier; }

    void checkCanBorrow() {
        if (finesDue > 0) throw new IllegalStateException(id + " owes " + finesDue);
        if (onLoan >= tier.maxLoans)
            throw new IllegalStateException(id + " is at the " + tier + " limit of " + tier.maxLoans);
    }
    void loanStarted() { onLoan++; }
    void loanEnded(long fine) { onLoan--; finesDue += fine; }
    void payFines() { finesDue = 0; }
}

Status as an enum, not state classesThe copy has four statuses and two events, and only lendTo branches on status. That is small enough for an exhaustive switch. If each status grew its own data and several methods started switching, State classes would pay off, as they do in the ATM.
Tier as an enum with dataStandard and premium differ in two numbers, so each constant carries them. If tiers became configurable at runtime (a "student" tier added by staff), they would move to a table and Tier would become a record loaded at start-up.
Why Member is not a recordA member is an entity: its loan count and fines change while its identity does not. Records suit values such as Book and Loan. Equality for Member would be by id, as on Value objects, equals and hashCode; the demo never compares members, so it is left out here.
Validate before you mutateIf checkCanBorrow ran after lendTo, a member over the limit would leave a copy marked on loan with no loan behind it. The service calls every check that can throw first, then makes the changes.
