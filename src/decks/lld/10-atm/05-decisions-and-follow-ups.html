ATM: the choices to defend, and the follow-ups to expect

ATM follow-ups split into two kinds. New features (deposits, transfers, PIN change) test whether the state machine absorbs them. Failures (a timeout from the bank, power loss mid-dispense) test whether you think about money in two places. Have one answer ready for each kind.

DecisionWhy, and the alternative
State classesEach state handles every event in one place, and illegal actions fall to a safe default. An enum with a switch in five methods is the alternative, and it grows badly.
States return the next stateTransitions are visible where they happen. The alternative, atm.setState(...) from inside a state, hides them in side effects.
Plan, debit, dispense, or reverseCheap checks first; the debit before the cash; a compensating reversal if the cash fails. Never dispense before a successful debit.
Backing-off note chainCorrect with limited notes where greedy is not. The chain is still extensible: a ₹2,000 slot is one more link.
Bank interfaceTests use an in-memory bank; production uses a network client. The ATM code is identical.
Reversal is idempotentA retried reversal cannot refund twice, because the bank forgets a debit once it is reversed.
"The cash came out but the bank never heard back"The debit request timed out, so the ATM does not know whether it succeeded. Retrying could charge twice; not retrying could give free cash. The real answer: every debit carries a request id the ATM generates, and the bank treats a repeat of the same id as the same debit. The ATM retries until it gets an answer, and a nightly reconciliation compares the ATM's journal (what it dispensed) with the bank's ledger. See idempotency.
Follow-upWhat changes
DepositsA deposit event on AtmState (default: refuse), handled in Authenticated. Cash is counted before crediting; the credit is pending until the notes are verified.
Transfers, PIN change, mini-statementOne event each on Authenticated, each a call to a new Bank method. No other state changes, because the defaults already refuse.
Session timeoutA timer calls atm.timeout(); CardInserted and Authenticated return the card and go to Idle. Some banks keep the card instead.
Maintenance: refill cashA separate MaintenanceOps interface on the ATM, used only by the operator's panel, allowed only in Idle or OutOfService. See ISP.
Audit trailEvery event becomes a command object appended to a journal before it runs, so the machine's history can be replayed after a crash. See Command.
Many banksA BankRouter implements Bank and picks the issuing bank from the card number. The ATM still sees one Bank.
