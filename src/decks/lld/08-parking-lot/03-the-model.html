Parking lot: the model, where each object guards its own state

The spot refuses to be double-booked and refuses a vehicle that does not fit, so no caller can break those rules. The floor is the only class that touches its free lists, and both of its public methods are synchronized, so two entry gates cannot claim the same spot.

import java.time.*;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;

enum SpotSize { SMALL, MEDIUM, LARGE }          // declared smallest first

enum VehicleType {
    MOTORBIKE(SpotSize.SMALL), CAR(SpotSize.MEDIUM), TRUCK(SpotSize.LARGE);
    final SpotSize needs;
    VehicleType(SpotSize needs) { this.needs = needs; }
}

record Vehicle(String plate, VehicleType type) {
    Vehicle {
        Objects.requireNonNull(type, "type");
        if (plate == null || plate.isBlank()) throw new IllegalArgumentException("plate");
    }
}

final class ParkingSpot {
    private final String id;
    private final SpotSize size;
    private Vehicle vehicle;                    // null while free

    ParkingSpot(String id, SpotSize size) { this.id = id; this.size = size; }
    String id() { return id; }
    SpotSize size() { return size; }

    void occupy(Vehicle v) {
        if (vehicle != null) throw new IllegalStateException(id + " is taken");
        if (size.compareTo(v.type().needs) < 0)
            throw new IllegalArgumentException(v.type() + " does not fit " + id);
        vehicle = v;
    }
    void vacate() {
        if (vehicle == null) throw new IllegalStateException(id + " is already free");
        vehicle = null;
    }
}

final class ParkingFloor {
    private final int number;
    private final Map<String, ParkingSpot> spots = new HashMap<>();
    private final Map<SpotSize, Deque<ParkingSpot>> free = new EnumMap<>(SpotSize.class);

    ParkingFloor(int number, Map<SpotSize, Integer> layout) {
        this.number = number;
        for (SpotSize size : SpotSize.values()) {
            Deque<ParkingSpot> queue = new ArrayDeque<>();
            for (int i = 1; i <= layout.getOrDefault(size, 0); i++) {
                var spot = new ParkingSpot("F" + number + "-" + size.name().charAt(0) + i, size);
                spots.put(spot.id(), spot);
                queue.addLast(spot);
            }
            free.put(size, queue);
        }
    }

    int number() { return number; }

    synchronized Optional<ParkingSpot> claim(Vehicle v) {
        for (SpotSize size : SpotSize.values()) {          // smallest that fits
            if (size.compareTo(v.type().needs) < 0) continue;
            ParkingSpot spot = free.get(size).pollFirst();
            if (spot != null) {
                spot.occupy(v);
                return Optional.of(spot);
            }
        }
        return Optional.empty();
    }

    synchronized void release(String spotId) {
        ParkingSpot spot = spots.get(spotId);
        spot.vacate();
        free.get(spot.size()).addFirst(spot);              // reuse near spots first
    }

    synchronized String freeSummary() {
        StringBuilder s = new StringBuilder("F" + number + " free");
        free.forEach((size, q) -> s.append(' ').append(size).append('=').append(q.size()));
        return s.toString();
    }
}

record Ticket(String id, Vehicle vehicle, int floor, String spotId,
              Instant entry, PricingStrategy pricing) {}

record Receipt(String ticketId, String plate, String spotId, Duration stayed, long fee) {
    @Override public String toString() {
        return ticketId + " " + plate + " from " + spotId + ", "
                + stayed.toMinutes() + " min, pays " + fee;
    }
}
Why the size check lives in the spotInformation expert: the spot has the size, so it answers "does this fit?". The floor uses the same ordering to pick which queue to poll, and the spot's check is the last line of defence if the floor ever gets it wrong.
Why SpotSize relies on declaration ordercompareTo on an enum compares declaration order, so "fits" is one comparison and the claim loop tries sizes from smallest up. Put a comment on the enum, because reordering the constants would change behaviour silently. A rank field is the more defensive choice; say which you picked.
Why the ticket is a recordA ticket never changes after it is issued. It stores the floor and spot id, not the spot object, so it can be printed, stored or sent to a gate device without dragging the model along. It does store the PricingStrategy, because the rate in force at entry is part of the deal with the customer.
One lock per floorTwo gates claiming on different floors never wait for each other. A single lock for the whole lot would also be correct, and simpler; name the trade-off rather than picking silently. The decisions slide covers the race on the last spot.
