Splitwise: four split rules, one rounding rule, and a factory that parses them

Equal, share and percent splits are all "divide by weight": give each person the floor of their share, then hand the leftover paise out one at a time in the order listed. Writing that once, in byWeight, means every split type rounds the same way and every result adds up exactly. Each record checks its own input in its compact constructor, so an invalid split cannot be created.

import java.math.BigDecimal;
import java.util.*;

sealed interface SplitRule permits EqualSplit, ShareSplit, PercentSplit, ExactSplit {
    Map<String, Long> shares(long total);           // person -> paise, sums to total
}

record EqualSplit(List<String> people) implements SplitRule {
    EqualSplit {
        if (people.isEmpty()) throw new IllegalArgumentException("nobody to split with");
        people = List.copyOf(people);
    }
    public Map<String, Long> shares(long total) {
        Map<String, Long> ones = new LinkedHashMap<>();
        people.forEach(p -> ones.put(p, 1L));
        return SplitRules.byWeight(total, ones);
    }
}

record ShareSplit(Map<String, Long> weights) implements SplitRule {
    ShareSplit { weights = SplitRules.positive(weights); }
    public Map<String, Long> shares(long total) { return SplitRules.byWeight(total, weights); }
}

record PercentSplit(Map<String, Long> percents) implements SplitRule {
    PercentSplit {
        percents = SplitRules.positive(percents);
        long sum = percents.values().stream().mapToLong(Long::longValue).sum();
        if (sum != 100) throw new IllegalArgumentException("percents add up to " + sum);
    }
    public Map<String, Long> shares(long total) { return SplitRules.byWeight(total, percents); }
}

record ExactSplit(Map<String, Long> amounts) implements SplitRule {
    ExactSplit { amounts = SplitRules.positive(amounts); }
    public Map<String, Long> shares(long total) {
        long sum = amounts.values().stream().mapToLong(Long::longValue).sum();
        if (sum != total)                           // needs the total, so checked here
            throw new IllegalArgumentException("exact amounts add up to "
                    + Money.format(sum) + ", not " + Money.format(total));
        return amounts;
    }
}

final class SplitRules {                            // factory + shared rounding
    private SplitRules() {}

    static SplitRule of(String type, List<String> people, List<Long> values) {
        return switch (type) {
            case "EQUAL"   -> new EqualSplit(people);
            case "SHARES"  -> new ShareSplit(zip(people, values));
            case "PERCENT" -> new PercentSplit(zip(people, values));
            case "EXACT"   -> new ExactSplit(zip(people, values));
            default -> throw new IllegalArgumentException("unknown split " + type);
        };
    }

    static Map<String, Long> byWeight(long total, Map<String, Long> weights) {
        long sum = weights.values().stream().mapToLong(Long::longValue).sum();
        Map<String, Long> out = new LinkedHashMap<>();
        long given = 0;
        for (var e : weights.entrySet()) {
            long share = Math.multiplyExact(total, e.getValue()) / sum;   // floor
            out.put(e.getKey(), share);
            given += share;
        }
        for (var e : out.entrySet()) {              // leftover paise, in order
            if (given == total) break;
            e.setValue(e.getValue() + 1);
            given++;
        }
        return Collections.unmodifiableMap(out);
    }

    static Map<String, Long> positive(Map<String, Long> m) {
        if (m.isEmpty() || m.values().stream().anyMatch(v -> v <= 0))
            throw new IllegalArgumentException("values must be positive");
        return Collections.unmodifiableMap(new LinkedHashMap<>(m));
    }

    private static Map<String, Long> zip(List<String> people, List<Long> values) {
        if (values.size() != people.size())
            throw new IllegalArgumentException("every person needs a value");
        Map<String, Long> m = new LinkedHashMap<>();
        for (int i = 0; i < people.size(); i++)
            if (m.put(people.get(i), values.get(i)) != null)
                throw new IllegalArgumentException(people.get(i) + " listed twice");
        return m;
    }
}

final class Money {
    private Money() {}
    static long parse(String rupees) {              // "999.99" -> 99999
        return new BigDecimal(rupees).movePointRight(2).longValueExact();
    }
    static String format(long paise) { return BigDecimal.valueOf(paise, 2).toPlainString(); }
}

record Transfer(String from, String to, long amount) {
    @Override public String toString() { return from + " pays " + to + " " + Money.format(amount); }
}

Why the leftover goes in listed orderAny fixed rule is fine, as long as the result adds up and the same input always gives the same output. "Leftover paise to the first people listed" is easy to explain and to test. The largest-remainder method is fairer for percentages; say so if asked, and note that it is a change to one method.
Where validation livesPercent totals are checked in the constructor, because the percentages alone decide validity. Exact amounts can only be checked against the expense total, so ExactSplit.shares checks it. Both reject input before the ledger changes.
The factory is the parser's only linkSplitRules.of maps the command word to a record. A new split type is a record plus one line here, and the exhaustive switch in any reporting code tells you what else to update.
