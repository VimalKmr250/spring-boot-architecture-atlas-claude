Proxy: a stand-in with the same interface that controls access to the real object

A proxy looks exactly like the real object to its callers but decides when, whether and how the real one is reached. The common kinds are caching (skip a slow call), virtual (create the real object lazily), protection (check permissions first) and remote (hide the network). Java can generate a proxy for any interface at runtime, which is how Spring adds @Transactional.

ProxyDemo.java · a caching proxy, wrapped in a dynamic logging proxy
import java.lang.reflect.Proxy;
import java.util.*;

interface SeatMapService { List<String> freeSeats(String showId); }

final class RemoteSeatMapService implements SeatMapService {
    int calls;                                   // stands in for a slow call
    public List<String> freeSeats(String showId) {
        calls++;
        return showId.equals("S1") ? List.of("A1", "A2", "B7") : List.of("C3");
    }
}

final class CachingSeatMap implements SeatMapService {    // caching proxy
    private final SeatMapService target;
    private final Map<String, List<String>> cache = new HashMap<>();
    CachingSeatMap(SeatMapService target) { this.target = target; }
    public List<String> freeSeats(String showId) {
        return cache.computeIfAbsent(showId, target::freeSeats);
    }
    void invalidate(String showId) { cache.remove(showId); }  // on booking
}

public class ProxyDemo {
    static <T> T logging(T target, Class<T> type, List<String> log) {
        Object proxy = Proxy.newProxyInstance(type.getClassLoader(),
                new Class<?>[] { type },
                (p, method, args) -> {           // runs for every call
                    log.add("-> " + method.getName() + Arrays.toString(args));
                    Object result = method.invoke(target, args);
                    log.add("<- " + result);
                    return result;
                });
        return type.cast(proxy);
    }

    public static void main(String[] args) {
        var remote = new RemoteSeatMapService();
        var cached = new CachingSeatMap(remote);
        List<String> log = new ArrayList<>();
        SeatMapService seats = logging(cached, SeatMapService.class, log);

        seats.freeSeats("S1");
        seats.freeSeats("S1");
        seats.freeSeats("S2");
        cached.invalidate("S1");
        seats.freeSeats("S1");

        log.forEach(System.out::println);
        System.out.println("calls that reached the remote service: " + remote.calls);
        System.out.println("proxy class is generated: "
                + Proxy.isProxyClass(seats.getClass()));
    }
}

Proxy, decorator or adapter?All three wrap an object. An adapter changes the interface. A decorator keeps it and adds behaviour the caller asked for, stacked by the client. A proxy keeps it and controls access, usually without the caller knowing, and usually creates or owns the real object itself.
The Spring self-invocation trapSpring's @Transactional and @Cacheable are proxies like the one above. A call from one method of a bean to another method on this never goes through the proxy, so the annotation on the second method is silently ignored. The Spring Boot tab covers it on AOP limits.
