Bridge splits two dimensions of variation; flyweight shares what never changes

Bridge: when a type varies in two independent ways, such as kind of alert and delivery channel, a subclass per pair means m × n classes. Hold the second dimension as a field instead, and you need m + n. Flyweight: when a program has thousands of small objects with the same intrinsic state, share one immutable instance and pass the rest (the position, the owner) in from outside.

BridgeFlyweight.java · alerts × channels, and shared chess glyphs
import java.util.*;

interface Channel { String deliver(String to, String text); }  // implementor
record Email() implements Channel {
    public String deliver(String to, String t) { return "[email " + to + "] " + t; }
}
record Sms() implements Channel {
    public String deliver(String to, String t) { return "[sms " + to + "] " + t; }
}

abstract class Alert {                          // abstraction: holds the bridge
    protected final Channel channel;
    Alert(Channel channel) { this.channel = channel; }
    abstract String send(String to);
}
final class OutageAlert extends Alert {
    OutageAlert(Channel c) { super(c); }
    String send(String to) { return channel.deliver(to, "OUTAGE: lift 2 down"); }
}
final class ReminderAlert extends Alert {
    private final String what;
    ReminderAlert(Channel c, String what) { super(c); this.what = what; }
    String send(String to) { return channel.deliver(to, "Reminder: " + what); }
}

record Glyph(char symbol, String name) {}       // flyweight: intrinsic state

final class Glyphs {                            // the flyweight factory
    private static final Map<Character, Glyph> CACHE = new HashMap<>();
    private static final Map<Character, String> NAMES = Map.of('K', "king",
            'Q', "queen", 'R', "rook", 'B', "bishop", 'N', "knight", 'P', "pawn");
    static Glyph of(char c) {
        return CACHE.computeIfAbsent(c, k ->
                new Glyph(k, NAMES.get(Character.toUpperCase(k))));
    }
}

record PlacedPiece(Glyph glyph, int square) {}  // extrinsic state

public class BridgeFlyweight {
    public static void main(String[] args) {
        List<Alert> alerts = List.of(new OutageAlert(new Email()),
                new OutageAlert(new Sms()), new ReminderAlert(new Sms(), "book return"));
        alerts.forEach(a -> System.out.println(a.send("ana")));

        String setup = "RNBQKBNRPPPPPPPPpppppppprnbqkbnr";
        List<PlacedPiece> pieces = new ArrayList<>();
        for (int i = 0; i < setup.length(); i++)
            pieces.add(new PlacedPiece(Glyphs.of(setup.charAt(i)), i < 16 ? i : i + 32));
        Set<Glyph> distinct = Collections.newSetFromMap(new IdentityHashMap<>());
        pieces.forEach(p -> distinct.add(p.glyph()));
        System.out.println(pieces.size() + " pieces share " + distinct.size() + " glyph objects");
        System.out.println("Integer.valueOf(127) shared: " + (Integer.valueOf(127) == Integer.valueOf(127)));
        System.out.println("Integer.valueOf(128) shared: " + (Integer.valueOf(128) == Integer.valueOf(128)));
    }
}

Bridge in one sentence"Alert type and channel vary independently, so the alert holds a channel instead of extending one." Adding WhatsApp is one class, not one per alert type. It is composition over inheritance applied to two axes.
Flyweight rulesThe shared object must be immutable, since everyone holds the same instance. The extrinsic state (here, the square) lives outside it. The JDK's Integer.valueOf caches -128 to 127, which is why == on boxed integers works in tests and fails in production.
Only when there are manyFlyweight is a memory optimisation. Mention it for 10⁶ map tiles or characters in an editor; for 32 chess pieces it is a talking point, not a need.
