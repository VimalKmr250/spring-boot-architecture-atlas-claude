Web MVC: mapping, binding, responding

The full set you use on a real controller, plus the two response-shaping annotations that most teams only discover after their error format has already gone inconsistent.

OrderController.java — every common annotation in one place
@RestController
@RequestMapping("/api/orders")                    // class-level prefix
@Validated                                        // enables @Min/@NotBlank on params
class OrderController {

    @GetMapping("/{id}")
    OrderView get(@PathVariable UUID id) { ... }

    @GetMapping
    Page<OrderSummary> list(
            @RequestParam(defaultValue = "PLACED") OrderStatus status,
            @RequestParam(required = false) @Size(max = 64) String customerRef,
            @RequestHeader(value = "X-Channel", defaultValue = "web") String channel,
            @CookieValue(required = false) String sessionHint,
            @PageableDefault(size = 20, sort = "placedAt", direction = DESC) Pageable page) { ... }

    @PostMapping(consumes = APPLICATION_JSON_VALUE, produces = APPLICATION_JSON_VALUE)
    @ResponseStatus(CREATED)                      // 201 instead of the default 200
    OrderView place(@Valid @RequestBody PlaceOrderRequest body,
                    @RequestHeader("Idempotency-Key") @NotBlank String key,
                    @AuthenticationPrincipal Jwt jwt) { ... }

    @PatchMapping("/{id}/address")
    ResponseEntity<Void> reroute(@PathVariable UUID id, @RequestBody AddressPatch patch) {
        orders.reroute(OrderId.of(id), patch);
        return ResponseEntity.noContent().build();   // full control when you need it
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(NO_CONTENT)
    void cancel(@PathVariable UUID id) { ... }
}

@RestControllerAdvice

Class-level @ExceptionHandler methods shared across controllers. Scope it with @RestControllerAdvice(basePackages = "...") when different modules need different error shapes — otherwise one advice quietly owns the whole application.

@ResponseStatus two ways

On a handler method it sets the success status. On an exception class it maps that exception to a status without any advice — convenient for simple cases, but it produces Boot's default error body, not your ProblemDetail.

@CrossOrigin

Works, but scattering it across controllers means CORS rules live in fifteen files. Configure it once in WebMvcConfigurer.addCorsMappings — or at the gateway, which is where it belongs in an enterprise topology.

Return type: DTO or ResponseEntity?Return the DTO directly when the status is always the same — it is cleaner and reads better. Reach for ResponseEntity only when the status, headers or presence of a body genuinely vary at runtime (Location on create, ETag, conditional 304). Mixing both in one controller is fine and normal.
