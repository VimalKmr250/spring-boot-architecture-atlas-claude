The proxy-driven annotations, and the test set

@Async, the cache annotations and @Retryable work through the proxy from the bean-lifecycle slide — so each silently does nothing on a self-invocation or a private method, and a final class cannot be given a class-based proxy at all, which fails at startup. @Scheduled and the event listeners are registered by post-processors instead, so self-invocation does not affect them.

Async, scheduling, caching, events, retry
@EnableAsync @EnableScheduling @EnableCaching     // on a @Configuration

@Async("notificationExecutor")                    // ALWAYS name an executor
CompletableFuture<Void> sendConfirmation(OrderId id) { ... }

@Scheduled(cron = "0 0 2 * * *", zone = "Europe/London")
void nightlyReconcile() { ... }
@Scheduled(fixedDelayString = "PT30S")            // delay AFTER completion
@Scheduled(fixedRateString = "PT30S")             // every 30s regardless — can overlap

@Cacheable(cacheNames = "product", key = "#sku", sync = true)  // sync = stampede guard
ProductView byKey(String sku) { ... }
@CacheEvict(cacheNames = "product", key = "#p.sku")
@CachePut(cacheNames = "product", key = "#p.sku")              // always executes + caches
@Caching(evict = { @CacheEvict("product"), @CacheEvict("catalog") })

@EventListener                                    // fires immediately, same thread
@TransactionalEventListener(phase = AFTER_COMMIT) // fires only if the tx committed —
void on(OrderPlaced event) { ... }                // and is DROPPED if no tx was active
                                                  // (fallbackExecution = true runs it anyway)

// Spring Retry (3.x). @EnableRetry on a @Configuration.
@Retryable(retryFor = TransientException.class, maxAttempts = 3,
           backoff = @Backoff(delay = 100, multiplier = 2, random = true))
@Recover Tax fallback(TransientException e, Basket b) { ... }
Testing — pick the narrowest slice that proves the thing
@SpringBootTest                 // whole context. Slowest; use for real integration tests
@WebMvcTest(OrderController.class)      // MVC layer only: JSON, validation, security rules
@DataJpaTest                    // JPA + a real DB via Testcontainers; rolls back per test
@JsonTest @RestClientTest @DataRedisTest        // other slices

@MockitoBean  OrderService orders;      // Boot 3.4+ — replaces the deprecated @MockBean
@MockitoSpyBean PricingService pricing;

@TestConfiguration              // extra beans for tests, NOT picked up by component scan
@ServiceConnection              // Boot 3.1+: a container @Bean wires its own connection
@DynamicPropertySource          // anything @ServiceConnection does not cover
@ActiveProfiles("test")
@Sql("/seed-orders.sql")
@Transactional                  // on a test = rollback after each method
Three traps in one slide@Async without a named executor runs on Boot's applicationTaskExecutor: 8 core threads and an unbounded queue, so a slow downstream builds a silent backlog rather than more threads (with spring.threads.virtual.enabled it is a virtual-thread executor instead). Name a bounded ThreadPoolTaskExecutor with a rejection policy — and know that declaring any Executor bean makes Boot's own back off, unless you register yours with @Bean(defaultCandidate = false). fixedRate can overlap runs if one takes longer than the interval; fixedDelay cannot. @Transactional on a test rolls back — which means it also hides the constraint violations that only fire at commit.
Boot 4 the retry annotation you know is not the one you getFramework 7 ships its own @Retryable in org.springframework.resilience.annotation (the programmatic RetryTemplate lives in org.springframework.core.retry), and it is not a drop-in rename. retryFor/noRetryFor become includes/excludes; the nested @Backoff flattens into delay/multiplier/jitter/maxDelay; maxAttempts = 3 becomes maxRetries = 2 — it counts retries, not attempts, so a straight copy silently gives you one extra call; there is no @Recover, so recovery moves to a catch in the caller; and nothing is advised at all without @EnableResilientMethods. @ConcurrencyLimit arrives alongside it for bulkheads. Keep Spring Retry on the classpath if you rely on @Recover.
