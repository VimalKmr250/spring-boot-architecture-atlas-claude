Choosing and reading a garbage collector

Modern collectors are good enough that tuning flags is rarely the answer — choosing the right one and then fixing allocation almost always is.

CollectorPause timesThroughputUse when
G1 defaultTens of ms, target-drivenVery goodAlmost every enterprise service. Start here and stay unless you measure a reason
ZGC (generational, JDK 21+)Sub-millisecond, independent of heap sizeSlightly lowerLarge heaps (> 16 GB) or a hard p99 latency requirement
ParallelLong, stop-the-worldHighestBatch jobs where total throughput matters and pauses do not
SerialLongLow, tiny footprintSmall containers, one core — often chosen automatically, usually wrong for a web service
Flags worth setting, and the logging that makes tuning possible
JAVA_TOOL_OPTIONS: >-
  -XX:MaxRAMPercentage=75
  -XX:+UseG1GC
  -XX:MaxGCPauseMillis=200            # a TARGET, not a guarantee
  -XX:+HeapDumpOnOutOfMemoryError
  -XX:HeapDumpPath=/dumps
  -Xlog:gc*:file=/logs/gc.log:time,uptime:filecount=5,filesize=20M
  -XX:+ExitOnOutOfMemoryError         # die fast, let the orchestrator replace you
  -Duser.timezone=UTC
The container CPU trapThe JVM picks its collector and thread-pool sizes from available processors. A limit of 500m CPU makes availableProcessors() report 1, which selects SerialGC and sizes the common ForkJoinPool to one thread. Give the container at least 2 full cores, or set -XX:ActiveProcessorCount explicitly.

Read the symptom before touching a flag

Frequent young GCs
Normal and cheap. High allocation rate — look only if pauses hurt.
Old gen grows after full GC
A leak. Heap dump, not a flag.
Long full GCs
Heap too small for the live set, or a leak. Raising -Xmx buys time, not a fix.
Humongous allocations (G1)
Objects > half a region — usually a huge list or byte array. Page the query instead.
GC fine, latency bad
Not a GC problem. Go to the profiling slide.
The fix is usually allocation, not the collectorAn endpoint loading 50,000 entities to return 20 rows is a GC problem caused by a query problem. Paginate, project, stream — and the GC graph flattens without a single flag. Change collectors only once the allocation rate is defensible.
