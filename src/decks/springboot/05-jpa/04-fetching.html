Fetching: where the performance actually is

Fetch type is a default, not a plan. The plan is set per query — which is the distinction that separates people who have tuned Hibernate from people who have configured it.

Four ways to control what gets loaded
// 1. @EntityGraph — declarative, composes with Spring Data method names
interface OrderJpaRepository extends JpaRepository<OrderJpaEntity, UUID> {

    @EntityGraph(attributePaths = { "lines", "customer" })
    Optional<OrderJpaEntity> findWithLinesById(UUID id);

    @EntityGraph(attributePaths = "lines")
    Page<OrderJpaEntity> findByCustomerId(UUID customerId, Pageable page);
}

// 2. JOIN FETCH — explicit, one collection at a time
@Query("select o from OrderJpaEntity o join fetch o.lines where o.id = :id")
Optional<OrderJpaEntity> loadWithLines(@Param("id") UUID id);

// 3. @BatchSize — turns N+1 into N/size+1 when you cannot restructure
@OneToMany(mappedBy = "order")
@BatchSize(size = 50)
private List<OrderLineEntity> lines;

// 4. Don't load entities at all — project
@Query("select new com.retailco.OrderSummary(o.id, o.placedAt, o.totalMinor) " +
       "from OrderJpaEntity o where o.customerId = :c")
List<OrderSummary> summariesFor(@Param("c") UUID customerId);
Two join fetch on collections = cartesian productAn order with 10 lines and 10 promotions returns 100 rows, and Hibernate 6 will refuse with MultipleBagFetchException if both are List. Fetch one collection per query and let @BatchSize handle the second, or run two queries.
Pagination + join fetchLogs "firstResult/maxResults specified with collection fetch; applying in memory" — Hibernate loads every matching row then pages in the JVM. On 40,000 orders that is an OOM. Fix: page over ids first, then fetch the entities for that page. Set hibernate.query.fail_on_pagination_over_collection_fetch: true so it throws instead of quietly working until it doesn't.
Make it a testCount queries on your three hottest endpoints with datasource-proxy and assert an upper bound. An N+1 introduced six months later then fails the build rather than the Black Friday dashboard.
