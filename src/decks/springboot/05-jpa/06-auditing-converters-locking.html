Auditing, converters, soft delete, locking

The four cross-cutting concerns every enterprise entity eventually grows, each with a proper JPA mechanism and a common hand-rolled version that is worse.

Auditing — four annotations and one bean
@Configuration
@EnableJpaAuditing(auditorAwareRef = "auditorAware")
class AuditConfig {
    @Bean AuditorAware<String> auditorAware() {
        return () -> Optional.ofNullable(SecurityContextHolder.getContext())
                .map(SecurityContext::getAuthentication)
                .filter(Authentication::isAuthenticated)
                .map(Authentication::getName);
    }
}

@Entity
@EntityListeners(AuditingEntityListener.class)     // ← easy to forget; nothing happens without it
class OrderJpaEntity extends Auditable { ... }
Converters — for types JPA does not know
@Converter(autoApply = true)                       // applies to every Money field
class MoneyConverter implements AttributeConverter<Money, Long> {
    public Long convertToDatabaseColumn(Money m) { return m == null ? null : m.minorUnits(); }
    public Money convertToEntityAttribute(Long v)  { return v == null ? null : Money.ofMinor(v); }
}

@Convert(converter = EncryptedStringConverter.class)   // per-field, e.g. PII at rest
private String taxIdentifier;
Soft delete and locking
@Entity
@SoftDelete(columnName = "deleted")        // Hibernate 6.4+: adds the predicate everywhere
class PromotionEntity { ... }

// Optimistic (default choice): no locks held, retry on conflict
@Version private long version;

// Pessimistic: only for genuinely contended single rows
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("select i from InventoryItemEntity i where i.sku = :sku")
Optional<InventoryItemEntity> findForUpdate(@Param("sku") String sku);

@DynamicUpdate      // UPDATE only the changed columns, not all of them
@OptimisticLocking(type = OptimisticLockType.DIRTY)   // version-less, niche
Soft delete has a tailUnique constraints stop working the way you expect — a "deleted" row still occupies the unique value, so re-creating the same SKU fails. Use a partial index (CREATE UNIQUE INDEX ... WHERE deleted = false). And any native query or reporting join you write must repeat the predicate yourself; the Hibernate filter does not reach them.
Converter vs @EmbeddableUse AttributeConverter when the value type maps to one column (Money → bigint). Use @Embeddable when it maps to several (Address → four columns). Trying to force a multi-column type through a converter ends in a serialised blob nobody can query.
