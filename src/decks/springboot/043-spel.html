SpEL: where it appears, and where it should not

The same expression language powers cache keys, security rules, event conditions and property defaults. It is convenient, unit-testable nowhere, and fails at runtime — so keep expressions short.

The five places you will meet it
// 1. Cache keys — composite keys and conditions
@Cacheable(cacheNames = "orders", key = "#customerId + ':' + #status",
           condition = "#status != null", unless = "#result.isEmpty()")
List<OrderView> byCustomer(UUID customerId, OrderStatus status) { ... }

// 2. Security rules  (.value() — a value type never equals a String)
@PreAuthorize("hasRole('OPS') or #cmd.customerId.value() == authentication.name")
@PreAuthorize("@orderAccess.canView(#id, authentication)")   // call a bean — preferred

// 3. Event conditions
@EventListener(condition = "#event.total.amount > 1000")

// 4. Property values with defaults and SpEL
@Value("${shop.retries:3}")
@Value("#{systemProperties['user.timezone'] ?: 'UTC'}")
@Value("#{'${shop.regions}'.split(',')}")

// 5. Conditional bean registration
@ConditionalOnExpression("${shop.kafka.enabled:true} and !'${spring.profiles.active}'.contains('test')")

Syntax worth remembering

#name
a method argument (needs -parameters at compile time)
#result
the return value, in unless
#root.method
the method name, for generic keys
@beanName
reference a bean and call it
?.
safe navigation — returns null instead of throwing
?:
Elvis, for defaults
?[..] ![..]
collection filter and projection
${..} vs #{..}
property placeholder vs SpEL expression — different things
Never evaluate user input as SpELPassing a request parameter into parser.parseExpression(input) is remote code execution — SpEL can reach T(java.lang.Runtime). It appears in real CVEs. If you need user-supplied filtering, parse it yourself into a closed set of allowed operations.
The refactoring ruleOnce an expression contains both and and or, or exceeds about 60 characters, move it into a bean method and call that (@orderAccess.canView(...)). You get a compiler, a debugger and a unit test — none of which SpEL gives you.
