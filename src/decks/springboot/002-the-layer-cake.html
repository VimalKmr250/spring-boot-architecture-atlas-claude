What Spring Boot actually is

Boot is not a framework. It is three things layered on top of Spring Framework: an opinionated dependency set, a conditional configuration engine, and an embedded runtime. Knowing which layer a behaviour comes from is what makes problems diagnosable.

Boot adds no runtime model

There is no "Boot container". It is the same ApplicationContext Spring has always had — Boot just populates it for you and starts a server in main() instead of deploying a WAR.

Opinionated, not locked

Every auto-configured bean backs off the moment you declare your own. That is the single design rule the whole thing rests on — the next three slides are how it works.

Boot 4 finer modules

Boot 4 splits the framework and its own jars into smaller modules. Nothing changes conceptually, but it is the most common upgrade surprise — imports move.
