Inheritance: three strategies, three different tables

Payment types — card, bank transfer, store credit — are the canonical case. The choice is a schema decision you will not casually reverse, so make it on the query pattern.

StrategySchemaWinsCosts
SINGLE_TABLE defaultOne table, all columns, a discriminatorFastest — no joins, polymorphic queries are one scanSubclass columns must be nullable, so the database cannot enforce "card payments must have a last4"
JOINEDParent table + one table per subclass, sharing the PKProperly normalised; NOT NULL works per subclassA join per subclass on every read; polymorphic queries join everything
TABLE_PER_CLASSOne full table per concrete subclassNo joins for a known typePolymorphic queries become a UNION ALL; shared sequences get awkward. Rarely the right answer
@MappedSuperclassNot inheritance at all — column reuseShare createdAt/version across unrelated entitiesCannot query the superclass; it is not an entity
SINGLE_TABLE, the usual enterprise choice
@Entity
@Table(name = "payments", schema = "payment")
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "payment_type", length = 20)
abstract class PaymentEntity {
    @Id UUID id;
    long amountMinor;
    @Enumerated(STRING) PaymentStatus status;
}

@Entity @DiscriminatorValue("CARD")
class CardPaymentEntity extends PaymentEntity {
    String last4;                 // nullable in the DB — enforce in the domain instead
    String schemeToken;
}

@Entity @DiscriminatorValue("TRANSFER")
class BankTransferEntity extends PaymentEntity {
    String iban;
}
How to choose in one questionDo you query across all subtypes often ("show me every payment for this order")? → SINGLE_TABLE. Do subtypes have many distinct fields and integrity you need the database to enforce? → JOINED. Neither strongly? → SINGLE_TABLE, because it is the cheapest to live with.

The @MappedSuperclass you will actually write

@MappedSuperclass
public abstract class Auditable {
    @CreatedDate    Instant createdAt;
    @CreatedBy      String  createdBy;
    @LastModifiedDate Instant updatedAt;
    @LastModifiedBy   String  updatedBy;
    @Version        long version;
}
