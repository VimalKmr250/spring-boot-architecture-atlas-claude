What moved between Spring Boot 3 and 4

The changes worth being able to name — in an upgrade discussion or an interview. Everything in this tab is written against 3.x; this is the delta.

AreaSpring Boot 3.xSpring Boot 4.0 / Framework 7
BaselineJava 17, Jakarta EE 10Java 17 still (25 recommended), Jakarta EE 11, Servlet 6.1
Module layoutFew large jarsFiner-grained modules — the most common upgrade surprise; imports move
Auto-config registryAutoConfiguration.imports only — spring.factories registration was already removed in Boot 3.0Unchanged. Worth knowing the removal date: a starter that silently contributes nothing broke at 3.0, not at 4.0
HTTP clientsRestClient, HttpServiceProxyFactory by hand@ImportHttpServices — declarative groups with shared config
API versioningRoll your own, or a gatewayFirst class: @GetMapping(version = "2") + ApiVersionConfigurer
ResilienceSpring Retry: @EnableRetry, retryFor, maxAttempts, @Backoff, @RecoverCore @Retryable: @EnableResilientMethods, includes/excludes, maxRetries (retries, not attempts), flat delay/jitter/multiplier, no @Recover — plus @ConcurrencyLimit
Null safetySpring's own @Nullable (JSR-305 style)JSpecify — @NullMarked at package level, real tooling support
JSONJackson 2Jackson 3 — ISO-8601 dates by default, unchecked exceptions
DataRepositories built at runtimeSpring Data AOT — queries generated at build time, notably faster startup
Test mocks@MockBean (deprecated in 3.4)@MockitoBean / @MockitoSpyBean
Testing APIMockMvc, WebTestClient, TestRestTemplateUnified RestTestClient across all three
Removals—Spring JCL, javax.annotation, Undertow WebSocket, legacy path matching
4.1 additions—Spring gRPC, lazy JDBC connections, InetAddressFilter SSRF mitigation, @RedisListener
If you are asked "should we upgrade?"The honest answer names a driver: support window, a CVE in a pinned transitive, startup cost in a scale-to-zero environment, or a feature you would otherwise hand-build (API versioning, resilience). "It's the latest" is not a driver, and saying so is itself a good signal.
Upgrade order that worksGet onto the latest 3.x first and make the build green. Remove every deprecation warning. Then move to 4.x, where the remaining failures are almost all module-layout imports and Jackson defaults — both mechanical, both findable by the compiler.
