Identifiers: the choice that affects insert throughput

Four generation strategies with materially different behaviour under batch inserts, plus the two ways to model a composite key.

StrategyHow it worksBatch insertsUse when
IDENTITYDatabase auto-increment; id known only after the INSERT❌ disabledLegacy schemas you cannot change. Hibernate cannot batch, because it must round-trip per row
SEQUENCEDatabase sequence, pre-fetched in blocks✅ excellentThe default choice on PostgreSQL/Oracle. Set allocationSize to match the sequence's INCREMENT BY

Sequence with a matching allocation size
@Id
@GeneratedValue(strategy = SEQUENCE, generator = "order_seq")
@SequenceGenerator(name = "order_seq", sequenceName = "order_mgmt.order_id_seq",
                   allocationSize = 50)     // must equal the DB's INCREMENT BY
private Long id;

// DB: CREATE SEQUENCE order_mgmt.order_id_seq INCREMENT BY 50;
// Hibernate now fetches one value and hands out 50 ids without another round trip.
// Mismatch here = duplicate key errors that appear only under concurrency.
Composite keys — prefer @EmbeddedId
@Embeddable
record OrderLineId(UUID orderId, int lineNo) implements Serializable { }

@Entity
class OrderLineEntity {
    @EmbeddedId private OrderLineId id;        // one field, typed, reusable

    @MapsId("orderId")                         // the FK column IS part of the key
    @ManyToOne(fetch = LAZY)
    private OrderJpaEntity order;
}

UUID: the version matters

Random UUIDv4 primary keys fragment a B-tree index, because every insert lands in a random leaf page. On a large, insert-heavy table that costs real write throughput and index bloat.

Time-ordered UUIDs (v7) insert near-sequentially and largely remove the problem while keeping client-side generation.

// RFC 9562 version 7 — Hibernate ORM 7.0+ only
@Id @UuidGenerator(style = UuidGenerator.Style.VERSION_7)
private UUID id;

Do not reach for style = TIME expecting v7. Hibernate's TIME style is a custom version 1 layout — timestamp plus the host IP, not the Unix-epoch prefix v7 specifies. It is still index-friendly, but it is not the thing your DBA or your Postgres uuidv7() function means, and mixing the two in one column defeats the ordering you wanted. Style.VERSION_7 arrived in Hibernate ORM 7.0 — on 6.6 and earlier the enum has only AUTO, RANDOM and TIME, so generate v7 in the application and assign it yourself.

@IdClass vs @EmbeddedId@IdClass repeats every key field on the entity and in a separate class, so the two drift. @EmbeddedId keeps one definition and gives you a type you can pass around. Use @IdClass only when mapping a legacy schema whose queries you cannot change.
Natural vs surrogateUse a surrogate key even when a natural one exists. Order numbers get reformatted, customer references get reissued, and "this will never change" is a statement about the current business process, not about the data.
