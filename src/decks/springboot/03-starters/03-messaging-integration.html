The Kafka settings an enterprise service should not leave at default
spring.kafka:
  bootstrap-servers: ${KAFKA_BROKERS}
  producer:
    acks: all                       # client default since Kafka 3.0 — pin it anyway,
    properties.enable.idempotence: true   # so an inherited config cannot weaken it
  consumer:
    group-id: inventory
    auto-offset-reset: earliest     # default 'latest' SILENTLY skips a backlog
    enable-auto-commit: false       # the container already does this; be explicit
    isolation-level: read_committed
  listener:
    ack-mode: MANUAL_IMMEDIATE      # container default is BATCH (per poll)
    observation-enabled: true       # propagates the trace across the async hop
The default that still causes real incidentsauto-offset-reset: latest means a brand-new consumer group skips everything already on the topic, so a new service quietly starts from "now" and nobody notices until reconciliation. What is no longer true: acks defaulted to 1 only before Kafka 3.0 — since then the client defaults to acks=all with enable.idempotence=true. Set both explicitly regardless, because the failure mode is someone weakening them for throughput and nobody noticing until a leader election.
