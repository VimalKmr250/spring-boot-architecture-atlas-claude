Actuator: the endpoints worth having, and the ones to lock down

Actuator is the difference between a service you can operate and one you restart and hope. It is also the fastest way to leak your entire configuration if exposure is left open.

EndpointAnswersExposure
/healthShould traffic come here? Should I be restarted?Public path is fine; keep show-details authorised
/prometheusEvery metric, for scrapingInternal only — it reveals traffic shape and errors
/infoBuild version, git commit — invaluable in an incidentInternal
/conditionsWhy does this bean exist (or not)Internal
/configprops, /envEffective configurationNever public. Sanitised, but assume it leaks secrets
/loggersChange a log level at runtime, no restartInternal, write-protected — the best debugging tool Actuator has
/threaddump, /heapdumpWhat is every thread doing; full heapInternal. A heap dump contains customer data
/mappings, /beansRoutes and the bean graphInternal
The configuration to standardise across every service
management:
  server.port: 8081                      # separate port — no gateway rule can expose it
  endpoints.web.exposure.include: health,info,prometheus,loggers,conditions,metrics
  endpoint:
    health:
      probes.enabled: true               # /health/liveness and /health/readiness
      show-details: when_authorized
      group.readiness.include: db,redis,kafka
      group.liveness.include: livenessState     # deliberately NOT db — see the warning
  info.env.enabled: true
  metrics.tags.application: ${spring.application.name}

info.app:                                # surfaces at /info
  version: ${project.version}            # Gradle: processResources { expand(...) }
  # version: @project.version@           # Maven: resource filtering uses @...@
  commit: ${GIT_COMMIT:unknown}

# Simpler than either: let the build plugin write build-info.properties
# (Gradle springBoot { buildInfo() } / Maven build-info goal) and Boot
# exposes group, artifact, version and time at /info with no placeholders.
The outage pattern to avoidPutting the database in the liveness group means a brief database blip fails liveness on every pod at once, Kubernetes restarts the entire fleet, and the restart storm turns a 30-second blip into a 10-minute outage. Liveness answers "is this JVM wedged"; readiness answers "can it serve right now". Dependencies belong in readiness only.
