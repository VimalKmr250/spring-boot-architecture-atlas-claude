Spring Security is a filter chain, and order is everything

There is no magic here either: an ordered list of servlet filters, each with one job, running before your DispatcherServlet ever sees the request.

Spring Security 6 — lambda DSL, SecurityFilterChain bean, no WebSecurityConfigurerAdapter
@Bean
@Order(1)                                          // several chains: most specific first
SecurityFilterChain apiChain(HttpSecurity http) throws Exception {
    return http
        .securityMatcher("/api/**")                // this chain handles only these paths
        .authorizeHttpRequests(a -> a
            .requestMatchers(GET, "/api/products/**").permitAll()
            .requestMatchers("/api/admin/**").hasRole("OPS")      // ROLE_OPS
            .requestMatchers("/api/orders/**").hasAuthority("SCOPE_orders.write")
            .anyRequest().authenticated())
        .oauth2ResourceServer(o -> o.jwt(withDefaults()))
        .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
        .csrf(CsrfConfigurer::disable)             // safe ONLY because it is stateless + bearer
        .exceptionHandling(e -> e
            .authenticationEntryPoint(problemDetail401)          // your error shape
            .accessDeniedHandler(problemDetail403))
        .headers(h -> h.contentSecurityPolicy(c -> c.policyDirectives(
             "default-src 'self'; frame-ancestors 'none'")))
        .build();
}
