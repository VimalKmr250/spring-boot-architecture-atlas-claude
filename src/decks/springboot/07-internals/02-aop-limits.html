Why your aspect silently didn't run

Every one of these applies equally to Spring's own annotations. Learn them once here and you have debugged four different "annotation does nothing" bugs.

SituationWhat happensFix
Self-invocation — this.method()Advice never runs. No error, no warning, in every Spring version — the reference manual's own phrasing is that the annotation "may be silently ignored"Move the method to another bean, or inject self via @Lazy, or use the template API directly. AspectJ weaving is the only mode that advises it; an IDE inspection catches it in review
private or final methodCGLIB cannot override it — advice skippedMake it public (or at least non-final) on the proxied bean
final classCGLIB cannot subclass — bean creation fails, or proxying is skippedRemove final, or implement an interface so a JDK proxy can be used
Object created with newNot a bean, so no proxy exists at allLet Spring create it
Called from a different threadAdvice runs, but SecurityContext / transaction / MDC are thread-bound and emptyDelegatingSecurityContextExecutor, or pass context explicitly
Two aspects, wrong ordere.g. audit sees the pre-transaction state, or a retry re-runs inside a doomed transaction@Order on each aspect — and think about which must be outermost
The ordering bug worth internalisingRetry outside transaction: each attempt gets a fresh transaction — correct. Retry inside transaction: the first failure already marked it rollback-only, so every retry runs in a transaction that can never commit, and you get UnexpectedRollbackException after wasting three attempts.

Put @Retryable on the caller of the transactional method, not on the transactional method itself.

Proving a proxy exists, in two lines
System.out.println(AopUtils.isAopProxy(orderService));        // true?
System.out.println(AopUtils.isCglibProxy(orderService));      // which kind?
System.out.println(AopProxyUtils.ultimateTargetClass(orderService));
Kotlin and Lombok usersKotlin classes are final by default — the kotlin-spring compiler plugin opens the annotated ones for you. Lombok's @Value makes a class final, which quietly breaks proxying on any bean using it.
