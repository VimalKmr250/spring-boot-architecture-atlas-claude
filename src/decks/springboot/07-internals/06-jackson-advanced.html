Polymorphism, views, and the customisations that are safe

Two features worth knowing, one security warning, and the right way to change global behaviour without losing Boot's defaults.

Polymorphic payloads — events and payment types
@JsonTypeInfo(use = Id.NAME, include = As.PROPERTY, property = "type")
@JsonSubTypes({
    @Type(value = CardPayment.class,     name = "CARD"),
    @Type(value = BankTransfer.class,    name = "TRANSFER"),
    @Type(value = StoreCredit.class,     name = "CREDIT")
})
sealed interface PaymentMethod permits CardPayment, BankTransfer, StoreCredit { }

// {"type":"CARD","last4":"4242"} → CardPayment
// `sealed` + an explicit @JsonSubTypes list is the safe pattern:
// the set of permitted types is closed and visible.
Views — one model, two audiences
class Views { interface Public {} interface Internal extends Public {} }

record OrderView(@JsonView(Views.Public.class)   UUID id,
                 @JsonView(Views.Public.class)   OrderStatus status,
                 @JsonView(Views.Internal.class) String riskScore) { }

@GetMapping("/{id}") @JsonView(Views.Public.class)
OrderView get(@PathVariable UUID id) { ... }         // riskScore omitted
Never enable default typingactivateDefaultTyping() / @JsonTypeInfo(use = Id.CLASS) lets the payload name any class on your classpath, which is a well-known remote-code-execution path. Always use Id.NAME with an explicit @JsonSubTypes allowlist. This one shows up in security reviews.
Customise globally — without replacing the ObjectMapper
@Bean
Jackson2ObjectMapperBuilderCustomizer jackson() {
    return b -> b
        .serializationInclusion(NON_NULL)
        .featuresToDisable(WRITE_DATES_AS_TIMESTAMPS)
        .serializerByType(Money.class, new MoneySerializer());
}
// Declaring your own @Bean ObjectMapper instead means you silently lose
// every module Boot had registered — java.time support most painfully.
Views vs separate DTOsViews avoid duplicate classes but hide the contract inside annotations, and they do not compose well once you have three audiences. Past two views, separate records per audience are clearer and let each one evolve independently. Boot 4 Jackson 3 changes defaults — ISO-8601 dates out of the box and unchecked exceptions.
