Method security annotations, in full

The layer where authorisation becomes about data rather than paths. All of it runs on the same AOP proxy from the bean-lifecycle slide — with all the same limitations.

Enable it, then use it
@Configuration
@EnableMethodSecurity           // Security 6: prePostEnabled = true by default
                                //   securedEnabled = true  → @Secured
                                //   jsr250Enabled  = true  → @RolesAllowed
class MethodSecurityConfig { }

@Service
class OrderService {

    // Evaluated BEFORE the method runs — the one you want in almost every case.
    // .value() unwraps the CustomerId value type: comparing the record itself
    // to a String is always false, and SpEL reports no error for that.
    @PreAuthorize("hasRole('OPS') or #cmd.customerId.value() == authentication.name")
    void cancel(CancelOrderCommand cmd) { ... }

    // Evaluated AFTER — the method already ran, so only use it for reads
    @PostAuthorize("returnObject.customerId.value() == authentication.name")
    OrderView find(OrderId id) { ... }

    // Filters the INPUT collection before the call
    @PreFilter("filterObject.region == authentication.principal.region")
    void bulkApprove(List<OrderId> ids) { ... }

    // Filters the RETURNED collection after the call
    @PostFilter("hasRole('OPS') or filterObject.customerId == authentication.name")
    List<OrderView> search(OrderSearch f) { ... }

    @Secured("ROLE_OPS")            // older, no SpEL — string roles only
    @RolesAllowed("OPS")            // JSR-250 equivalent, portable
    void reindex() { ... }
}
Getting at the caller
void place(@AuthenticationPrincipal Jwt jwt) { jwt.getSubject(); }
void audit(@CurrentSecurityContext(expression = "authentication.name") String user) { }
// or anywhere: SecurityContextHolder.getContext().getAuthentication()
@PostFilter is a performance trapIt loads every row, then discards the ones the user may not see — so a query returning 50,000 orders filters in the JVM to show 12. Filter in the query (where customer_id = ?) and use @PostFilter only on small, already-bounded results.
Roles vs authoritieshasRole('OPS') checks for the authority ROLE_OPS — the prefix is added for you. hasAuthority('OPS') does not add it. Mixing the two forms across a codebase produces rules that look right and permit nothing; pick one convention and put it in the coding standard.

Useful SpEL

#param
a method argument by name (needs -parameters on the compiler)
returnObject
the return value, in @PostAuthorize
filterObject
the current element, in the filters
authentication
the full Authentication
principal
the principal — cast to your own type for richer rules
@beanName.method(..)
call a bean: @orderAccess.canView(#id, authentication)

Once an expression needs an and plus an or, move it into a bean method. SpEL is not unit-testable and fails at runtime, not compile time.
