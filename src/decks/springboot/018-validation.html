Validation: shape at the edge, rules in the domain

Bean Validation is excellent at "is this well-formed". It is a poor place for business rules, and the boundary between the two is worth being deliberate about.

The constraints you will actually use
record PlaceOrderRequest(
        @NotEmpty @Size(max = 100) List<@Valid LineRequest> lines,  // cascades into each
        @NotNull @Valid AddressRequest shipTo,
        @Pattern(regexp = "[A-Z]{3}") String currency,
        @NotBlank @Email String contactEmail,
        @Positive BigDecimal expectedTotal,
        @Future Instant deliverBy,
        @AssertTrue(message = "Terms must be accepted") boolean termsAccepted) { }

// @NotNull  — not null (but "" passes)
// @NotEmpty — not null and not empty (collection, string, map)
// @NotBlank — not null and contains non-whitespace. For strings, this is the one you want.
Two different annotations, two different jobs
@Valid      // Jakarta: cascade validation into this object
@Validated  // Spring: enables method-level validation on a bean,
            //         and is the only one that supports groups
A custom constraint — reusable and testable
@Target(FIELD) @Retention(RUNTIME)
@Constraint(validatedBy = SkuValidator.class)
public @interface ValidSku {
    String message() default "Not a known SKU format";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

class SkuValidator implements ConstraintValidator<ValidSku, String> {
    public boolean isValid(String value, ConstraintValidatorContext ctx) {
        return value == null || value.matches("SKU-\\d{4,8}");   // null = @NotNull's job
    }
}
Where the line isShape — "currency is three letters", "at most 100 lines" — belongs here. Rule — "this customer may not ship to that country", "discount cannot exceed the order value" — belongs on the aggregate, where it can be unit-tested without HTTP and cannot be bypassed by a second entry point such as a Kafka consumer or a batch job.
Turning violations into your error shapeHandle MethodArgumentNotValidException (body) and ConstraintViolationException (params) in your advice and emit a ProblemDetail with a errors property listing field and message. Without that, Boot's default body is a shape your frontend has to special-case.
