Resilience is four patterns, layered in order

Applied in the wrong order they amplify failures instead of containing them. Timeout first — without it, nothing else can work, because a call that never returns can never be retried, tripped or shed.

Spring Framework 7 core resilience — no extra dependency
@Configuration
@EnableResilientMethods          // ← without this, BOTH annotations do nothing
class ResilienceConfig { }

@Service
class TaxAdapter implements TaxCalculator {

    // maxRetries = 2 → 3 attempts total (1 initial + 2 retries)
    @Retryable(includes = TransientTaxException.class,
               maxRetries = 2, delay = 100, multiplier = 2.0,
               jitter = 50, maxDelay = 2000)
    @ConcurrencyLimit(20)              // bulkhead: at most 20 in flight
    public Tax calculate(Basket b) { return client.calc(b); }
}

// Core retry has NO @Recover. When every attempt fails, the last
// exception propagates — so the fallback lives in the caller:
class PricingService {
    Money quote(Basket b) {
        try {
            return tax.calculate(b).appliedTo(b);
        } catch (TransientTaxException e) {
            meters.counter("tax.fallback").increment();
            return Tax.estimatedFrom(b).appliedTo(b);  // degrade, don't fail checkout
        }
    }
}
Jitter is not optionalWithout it, every client that failed at T retries at exactly T+100ms, then T+300ms — a synchronised thundering herd that keeps the recovering dependency down. Randomising the delay spreads the load and is a one-word change.

Three things people get wrong on the 3.x→4.x move: the attribute is maxRetries, not maxAttempts, and it counts retries not attempts; there is no @Recover in core — that stays a Spring Retry feature; and nothing is advised until @EnableResilientMethods is present, which fails silently exactly like every other missing @Enable*.

Use Resilience4j when you need bulkheads with queueing, rate limiters, or a metrics-rich breaker with Actuator endpoints; keep Spring Retry if you depend on @Recover. The built-in annotations cover the common 80%.
