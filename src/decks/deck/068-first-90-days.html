If you are starting on Monday

Order of work for a greenfield enterprise service, or for bringing an existing one under control. Roughly a quarter, and each step makes the next one cheaper.

Weeks 1–2 Make the boundaries real

  • Name the bounded contexts with the business, not in a code review.
  • Create the module packages with api / spi / internal.
  • Add ArchUnit rules and modules.verify() to CI on day one — retrofitting them is what costs.
  • Schema per module, one database role per module, grants enforced.

Weeks 3–6 Make it observable and testable

  • Trace id end to end, including across Kafka; structured JSON logs.
  • Testcontainers from the first integration test; no H2.
  • One vertical slice fully built — controller to database to event — as the pattern everyone copies.
  • Error model (ProblemDetail) and the OpenAPI contract gate.

Weeks 7–10 Make it resilient

  • Timeouts on every outbound client; then retries, breakers, bulkheads in that order.
  • Outbox for every event that must not be lost; idempotent consumers with a DLT.
  • Idempotency keys on every mutating public endpoint.
  • SLOs defined for the top three journeys; burn-rate alerts wired.

Weeks 11–13 Make it operable

  • Expand/contract migration discipline and a rehearsed rollback.
  • Feature flags with expiry; deploy decoupled from release.
  • Four dashboards, not fourteen; a runbook per alert.
  • ADRs for every level 1–4 decision made so far, written while the context is fresh.
