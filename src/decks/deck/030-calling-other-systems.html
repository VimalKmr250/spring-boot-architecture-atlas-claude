Outbound HTTP, declared not hand-rolled

Spring Boot 4 made HTTP interface clients properly first-class with @ImportHttpServices. You declare the contract as an interface; Spring builds the proxy with your timeouts, observability and interceptors already attached.

payment/internal/gateway/ — the declared client
public interface PaymentGatewayClient {

    @PostExchange("/v1/authorizations")
    AuthorizationResponse authorize(@RequestBody AuthorizationRequest req,
                                    @RequestHeader("Idempotency-Key") String key);

    @PostExchange("/v1/authorizations/{id}/capture")
    CaptureResponse capture(@PathVariable String id, @RequestBody CaptureRequest req);
}

@Configuration
@ImportHttpServices(group = "payments", types = PaymentGatewayClient.class)
class PaymentClientConfig {

    @Bean RestClientHttpServiceGroupConfigurer paymentsConfigurer(
            ObservationRegistry observations) {
        // requestFactory() takes a ClientHttpRequestFactory — build one
        // from HttpClientSettings; it will NOT accept the settings object.
        var factory = ClientHttpRequestFactoryBuilder.detect()
                .build(HttpClientSettings.defaults()
                        .withConnectTimeout(Duration.ofMillis(500))
                        .withReadTimeout(Duration.ofSeconds(2)));   // never unbounded

        return groups -> groups.filterByName("payments").forEachClient((g, builder) ->
            builder.baseUrl("https://api.gateway.example")
                   .requestFactory(factory)
                   .observationRegistry(observations)               // traces + metrics, free
                   .defaultStatusHandler(new PaymentErrorHandler()));
    }
}

The anti-corruption layer

The gateway's JSON is their model, full of their vocabulary and their nulls. Translate it at this boundary into AuthorizationResult in your language. When they ship v4 with renamed fields, exactly one class changes.

HTTP interface
default — declarative, testable, observable
RestClient
imperative and fluent; what the interface runs on

when you genuinely need reactive streaming
RestTemplate
maintenance only; do not start new code on it
Non-negotiableA connect timeout and a read timeout on every outbound client. The single most common cause of a thread-pool-exhaustion outage is one dependency that stopped answering but never closed the socket.
Boot 4 set the floor globallyPer-client code is for the exceptions. Boot 4 gives every auto-configured client a default: spring.http.clients.connect-timeout: 2s and spring.http.clients.read-timeout: 5s. Put that in the service template so a client nobody configured is still bounded.
