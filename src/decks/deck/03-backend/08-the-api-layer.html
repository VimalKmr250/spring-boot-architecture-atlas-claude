The API layer is a translation layer, nothing else

Controllers parse, validate shape, delegate, and map the result. Any line in a controller that expresses a business rule is a line in the wrong file.

order/internal/web/OrderController.java
@RestController
@RequestMapping("/api/orders")
@Validated
class OrderController {

    private final OrderService orders;      // the module's own api interface

    @PostMapping
    @ResponseStatus(CREATED)
    OrderView place(@Valid @RequestBody PlaceOrderRequest body,
                    @RequestHeader("Idempotency-Key") @NotBlank String key,
                    @AuthenticationPrincipal Jwt jwt) {
        var cmd = body.toCommand(CustomerId.of(jwt.getSubject()));
        return orders.place(cmd);
    }

    @GetMapping("/{id}")
    OrderView get(@PathVariable UUID id) {
        return orders.find(OrderId.of(id)).orElseThrow(() -> new OrderNotFound(id));
    }

    @GetMapping
    Page<OrderSummary> list(@ParameterObject OrderSearch filter,
                            @PageableDefault(size = 20, sort = "placedAt", direction = DESC)
                            Pageable page) {
        return orders.search(filter, page);          // never returns entities
    }
}

// Request/response types are records with validation on them, in the web package:
record PlaceOrderRequest(
        @NotEmpty @Size(max = 100) List<@Valid LineRequest> lines,
        @NotNull @Valid AddressRequest shipTo,
        @Pattern(regexp = "[A-Z]{3}") String currency) { }

Three model families, on purpose

PlaceOrderRequest (wire, validated) → PlaceOrderCommand (application) → Order (domain). Collapsing them couples your public JSON to your database schema forever.

@Valid is shape, not rules

"Currency is 3 letters" is shape. "This customer may not order to that country" is a rule and lives in the domain, where it can be tested without HTTP.

Cursor over offset at scale

OFFSET 100000 makes Postgres walk 100k rows. Past a few thousand pages, switch to a keyset cursor: WHERE (placed_at, id) < (?, ?) ORDER BY placed_at DESC, id DESC LIMIT 20.
