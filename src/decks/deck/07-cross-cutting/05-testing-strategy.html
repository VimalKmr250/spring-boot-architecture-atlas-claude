A test pyramid shaped like your architecture

The mistake is uniform testing: everything through @SpringBootTest, or everything mocked. Match the test type to the layer, and the suite stays fast and meaningful.

Testcontainers 2, shared and fast — service connections (Boot 3.1+)
// Testcontainers 2 (Boot 4's version): testcontainers-* artifacts, and each
// module's classes in org.testcontainers.<module>, not ...containers.
import org.testcontainers.kafka.KafkaContainer;
import org.testcontainers.postgresql.PostgreSQLContainer;

@TestConfiguration(proxyBeanMethods = false)
class ContainersConfig {
    @Bean @ServiceConnection            // wires spring.datasource.* automatically
    PostgreSQLContainer postgres() {
        return new PostgreSQLContainer("postgres:17-alpine").withReuse(true);
    }
    @Bean @ServiceConnection
    KafkaContainer kafka() {
        return new KafkaContainer("apache/kafka:4.0.0").withReuse(true);
    }
}
// Two Kafka classes, two images:
//   org.testcontainers.kafka.KafkaContainer          → apache/kafka (KRaft)
//   org.testcontainers.kafka.ConfluentKafkaContainer → confluentinc/cp-kafka
// Pair the wrong one with your image and startup hangs until it times out.

// src/test: every test class with this same configuration shares ONE cached
// Spring context, and so one set of containers, for the whole build.
// withReuse(true) goes further — it keeps them alive across builds — but only
// with testcontainers.reuse.enable=true in ~/.testcontainers.properties.
@SpringBootTest
@Import(ContainersConfig.class)
class OrderFlowIT { ... }
H2 is not your databaseTesting against H2 while running PostgreSQL means your tests pass on SQL that production rejects — and silently skip the constraints, types and locking behaviour that matter. Testcontainers removed this excuse years ago.
Architecture tests are testsThe ArchUnit rules and modules.verify() run in the same suite. That is what makes the boundary real rather than aspirational.
Flaky E2E destroys trustThree reliable end-to-end journeys beat forty that fail randomly. A suite people re-run "because it's probably flaky" has already stopped being a gate.
