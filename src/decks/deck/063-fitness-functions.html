Evolutionary architecture: make the rules executable

A fitness function is any automated check that an architectural property still holds. It is the difference between architecture as a decision and architecture as a description of what the code happened to become.

Property you care aboutFitness functionRuns
Modules do not reach into each other's internalsArchUnit slice rules + ApplicationModules.verify()Every build
The domain stays framework-freeArchUnit: no Spring or JPA imports under ..domain..Every build
No module reads another's tablesA database role per module, granted only its own schemaEvery integration test
The API does not break consumersoasdiff against main; schema-registry BACKWARD compatibilityEvery PR
Hot endpoints stay free of N+1Query-count assertions on the top three endpointsEvery build
Checkout stays within its latency budgetA performance test with a p95 threshold that fails the pipelineNightly
No known-vulnerable dependencies shipCVE scan with a severity gateEvery build
Startup stays fast enough to roll back quicklyAssert boot time under a threshold in an integration testNightly
Nothing writes personal data to logsA test scanning log output for @Pii-annotated field valuesEvery build

How to introduce them into an existing codebase

  1. Baseline, do not block. Record today's violations in a file; fail the build only on new ones.
  2. Ratchet. Every sprint, remove a few from the baseline. The number only ever goes down.
  3. Add one per repeated review comment. If a reviewer catches the same mistake twice, that is a missing fitness function, not a missing reviewer.

A big-bang "turn on all the rules" attempt produces 400 failures on day one and gets disabled by day three.

The reframing worth carryingArchitecture is not the diagram — it is the set of properties you are defending. A property nobody measures is a preference. A property with a failing build behind it is a constraint, and constraints are what actually survive delivery pressure.
Good interview material"How do you stop a modular monolith degrading?" answered with three named, executable checks and a ratcheting strategy is a much stronger answer than "code reviews and discipline" — because the interviewer has watched discipline lose to a deadline before.
