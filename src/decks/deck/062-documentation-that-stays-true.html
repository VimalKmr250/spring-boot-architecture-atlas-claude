Documentation that is still true in a year

Every architecture document decays. The only ones that do not are the ones generated from the system, or the ones that record a decision rather than a state.

Why source beats a drawing toolIt lives beside the code, changes in the same pull request, diffs in review, and renders in CI. A diagram in a slide deck on a shared drive is accurate on the day it was exported and never again — and nobody can tell which day that was.
Write down what is deliberately absentThe most valuable and least written documentation is the list of things you chose not to do, and why: no service mesh yet, no multi-region, no event sourcing. Without it, every new joiner proposes all three in their first month, and the team re-litigates the same decisions annually.
One page per serviceName, owning team, what it does in a sentence, its SLO, its dependencies, its runbook links, how to run it locally. Generated where possible. This is the page people open at 2am, and it is worth more than any architecture deck.
