One error shape for the whole system

RFC 9457 ProblemDetail is built into Spring since 6. Adopting it means the frontend writes one error handler instead of five, and every 4xx carries something actionable.

shared/web/GlobalExceptionHandler.java
@RestControllerAdvice
class GlobalExceptionHandler {

    /** Every problem goes through here, so traceId is never forgotten. */
    private ProblemDetail problem(HttpStatus status, String detail, String slug) {
        var p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setType(URI.create("https://errors.retailco.com/" + slug));
        p.setProperty("traceId", currentTraceId());   // the one thing support needs
        return p;
    }

    @ExceptionHandler(OrderNotFound.class)
    ProblemDetail notFound(OrderNotFound ex) {
        var p = problem(NOT_FOUND, ex.getMessage(), "order-not-found");
        p.setTitle("Order not found");
        p.setProperty("orderId", ex.id());
        return p;
    }

    @ExceptionHandler(InsufficientStock.class)
    ProblemDetail stock(InsufficientStock ex) {
        var p = problem(CONFLICT,
                "Only %d left of %s".formatted(ex.available(), ex.sku()),
                "insufficient-stock");
        p.setProperty("sku", ex.sku());
        p.setProperty("available", ex.available());   // the UI can render a real message
        return p;
    }

    @ExceptionHandler(Exception.class)
    ProblemDetail unexpected(Exception ex) {
        log.error("unhandled", ex);                   // stack trace to logs, never to the client
        return problem(INTERNAL_SERVER_ERROR,
                "Something went wrong on our side.", "internal");
    }
}

Status codes that mean something400 malformed · 401 not authenticated · 403 authenticated, not allowed · 404 absent or invisible to you · 409 conflicts with current state · 422 well-formed but violates a rule · 429 slow down · 503 + Retry-After dependency down. Never a 200 with {"error": ...}.
LeakageStack traces, SQL fragments and internal hostnames in error bodies are a security finding, not a debugging aid. traceId is the bridge: the customer quotes it, you find the log.
