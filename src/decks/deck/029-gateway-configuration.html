What a gateway config actually contains

Spring Cloud Gateway, doing the five things a gateway should do and nothing else. Note that resilience settings live here and in the application — defence in depth, different budgets.

gateway/application.yaml
spring:
  cloud:
    gateway:
      default-filters:
        - RemoveRequestHeader=Cookie          # cookies terminate at the BFF, never reach services
        - AddRequestHeader=X-Request-Source, gateway
      routes:
        - id: orders
          uri: lb://order-platform
          predicates:
            - Path=/api/orders/**
          filters:
            - name: CircuitBreaker
              args: { name: ordersCb, fallbackUri: forward:/fallback/orders }
            - name: RequestRateLimiter
              args:
                redis-rate-limiter.replenishRate: 50      # per user, steady state
                redis-rate-limiter.burstCapacity: 100
                key-resolver: "#{@principalKeyResolver}"
            - name: Retry
              args:
                retries: 2
                methods: GET                              # NEVER retry POST here
                series: SERVER_ERROR
                backoff: { firstBackoff: 50ms, maxBackoff: 500ms, factor: 2 }

  security.oauth2.resourceserver.jwt.issuer-uri: https://id.retailco.com/realms/shop

management:
  endpoints.web.exposure.include: health,prometheus,gateway
  tracing.sampling.probability: 0.1           # 100% for errors via a custom sampler

Validate the token once

The gateway verifies signature, issuer, audience and expiry, then passes the JWT through. Services still verify — but they can trust the network less and cache JWKS longer.

Rate limit by identity

Limiting by IP punishes every user behind one corporate NAT. Key on the authenticated subject, fall back to IP only for anonymous traffic.

Timeout budget, top down

Client 10 s > gateway 8 s > service 5 s > downstream call 2 s. Each hop's timeout must be shorter than its caller's, or retries pile up behind a caller that already gave up.
