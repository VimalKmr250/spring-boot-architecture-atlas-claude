Where the boundary leaks, and how hard you enforce it

The convention does nothing on its own — it is a naming scheme until something fails the build. These are the four leaks that appear in every codebase, and the four levels of enforcement you can choose between.

The leakHow it arrivesWhat it costs
An entity in api"Just this once — the mapping is tedious"A column rename breaks another team's compile; lazy-loading fails inside their transaction scope
Optional<Order> instead of Optional<OrderView>The same leak, hidden in a generic parameterIdentical, and far harder to spot in review
Something in api that one caller usesA feature request routed the short wayNot a contract — a leak with good manners. Either everyone gets it, or that caller needs a different route
shared grows a business rule"Both modules need this, so it's common"Every module now depends on it: a distributed monolith at compile time
LevelMechanismFails as
0Package naming convention aloneNothing. Documentation
1Spring Modulith verify()Test failure — module to module
2ArchUnit slice + layer rulesTest failure — also inside a module
3Gradle subprojects (or JPMS)Compile error — cannot be suppressed
Where to startLevels 1 and 2 together, from week one — they are two test classes and about 90 lines, and the next two slides are exactly those. Escalate to level 3 only when you find suppressions appearing in the git history: a test failure can be @ArchIgnored under deadline pressure, a compile error cannot.
Cap shared deliberatelyValue types with no behaviour that changes — Money, Address, typed ids, base exception types. No repositories, no business rules, no services. When two modules need the same rule, one of them owns it and publishes it through api.
Why this pays backWhen payment becomes a service: api is already records and interfaces, so it becomes the REST contract unchanged; internal moves wholesale; spi implementations become HTTP clients. Callers change nothing at all. That property is the entire return on the convention — the tidy folders are incidental.
