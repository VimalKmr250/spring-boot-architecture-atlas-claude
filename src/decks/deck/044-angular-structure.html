An Angular structure that mirrors the backend modules

Same principle as the backend: group by feature, keep a thin shared layer, and make cross-feature imports a lint error rather than a habit.

features/orders/data/orders.store.ts — signals, no boilerplate
@Injectable({ providedIn: 'root' })
export class OrdersStore {
  private api = inject(OrdersService);          // generated client

  readonly filter  = signal<OrderSearch>({ status: null });
  readonly page    = signal(0);

  // declarative data fetching: refetches when filter or page changes
  private readonly resource = rxResource({
    request: () => ({ ...this.filter(), page: this.page() }),
    loader: ({ request }) => this.api.listOrders(request),
  });

  readonly orders  = computed(() => this.resource.value()?.content ?? []);
  readonly loading = this.resource.isLoading;
  readonly error   = this.resource.error;
}
State: pick the smallest tool that worksServer data is a cache, not state — let a resource/query layer own it. Keep a real store (NgRx, or signal stores) for genuine client state: multi-step checkout, a wizard, optimistic edits. Most teams reach for the store first and then maintain reducers that only mirror HTTP responses.
