A dummy, a tail, and three saved pointers

Reverse and merge are the two primitives; everything else composes them. Write the reverse from muscle memory — its four lines never change order, and half this family is built on it.

Primitive A · reverse (LC 25, 92)
// Four lines, always in this order. Step 1 must come first or
// step 2 severs your only route to the rest of the list.
ListNode reverse(ListNode head) {
    ListNode prev = null, cur = head;

    while (cur != null) {
        ListNode next = cur.next;   // 1 · save what is ahead
        cur.next = prev;            // 2 · flip this link
        prev = cur;                 // 3 · advance prev
        cur = next;                 // 4 · advance cur
    }
    return prev;                    // the new head
}

// Reversing a SEGMENT: seed prev with the node that should follow
// the segment, and the tail reconnection happens for free.
ListNode reverseSegment(ListNode start, ListNode stopAfter) {
    ListNode prev = stopAfter, cur = start;
    while (cur != stopAfter) {
        ListNode next = cur.next;
        cur.next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}
Primitive B · merge two sorted lists (LC 21, 23)
// Dummy + tail. The dummy removes "which list starts the result?"
// and the tail removes "where do I append?".
ListNode merge(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0);
    ListNode tail = dummy;

    while (a != null && b != null) {
        if (a.val <= b.val) { tail.next = a; a = a.next; }
        else                { tail.next = b; b = b.next; }
        tail = tail.next;
    }

    // At most one list remains; attach it whole rather than looping.
    tail.next = (a != null) ? a : b;

    return dummy.next;
}
The composition — reverse in k-groups (LC 25)
/**
 * Per group you need THREE references:
 *   groupPrev  the node before the group (starts as the dummy)
 *   kth        the group's last node, which becomes its first
 *   nextGroup  the node after the group, saved before rewiring
 */
ListNode reverseKGroup(ListNode head, int k) {
    ListNode dummy = new ListNode(0, head);
    ListNode groupPrev = dummy;

    while (true) {
        ListNode kth = walk(groupPrev, k);
        if (kth == null) break;              // fewer than k left — leave it

        ListNode nextGroup = kth.next;       // SAVE before rewiring
        ListNode oldHead = groupPrev.next;   // becomes the group's new TAIL

        // Seeding prev with nextGroup reconnects the tail for free.
        ListNode prev = nextGroup, cur = oldHead;
        while (cur != nextGroup) {
            ListNode next = cur.next;
            cur.next = prev;
            prev = cur;
            cur = next;
        }

        groupPrev.next = kth;                // front reconnection
        groupPrev = oldHead;                 // old head now precedes the next group
    }
    return dummy.next;
}

/** The k-th node after `from`, or null if the list runs out. */
private ListNode walk(ListNode from, int k) {
    while (from != null && k > 0) { from = from.next; k--; }
    return from;
}

The knobs

Dummy or not
Use one whenever the head can change. The only problems here that do not need one are those that never touch the first node.
What to save
Before any rewiring, name every pointer you will still need afterwards. Writing those declarations first prevents almost every bug in this pattern.
Seed of the reversal
null for a whole list; the following node for a segment, which performs one reconnection for free.
Iterative or recursive
Iterative. Lists here reach 5×10⁴ nodes and recursion risks a stack overflow — mention that trade-off rather than assuming.
Values or nodes
If the statement says the values may not be modified, you must move nodes. Read for that sentence before choosing the easy path.
The three bugs that actually happenRewiring before saving — cur.next = prev written first loses the remainder of the list, and the output is a truncated list rather than a crash. Returning head instead of dummy.next — after any head change, head points into the middle of the result. Leaving a cycle — forgetting to terminate the final node produces an infinite loop in the judge's traversal, not in yours, which makes it hard to spot locally.
