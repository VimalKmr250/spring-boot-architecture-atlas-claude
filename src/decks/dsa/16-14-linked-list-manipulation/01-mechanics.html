Rewire pointers without losing the rest of the list

Every one of these problems is the same physical act: change a next field. The difficulty is that overwriting cur.next destroys your only route to everything after it — so the discipline is save first, rewire second, and the tools are a dummy head and a fixed vocabulary of four moves.

The dummy head

Allocate one throwaway node that sits before the real head. Every "what if the head itself changes?" case vanishes, because the head is no longer special — it is just dummy.next.

Use it whenever the head might be removed, replaced, or reordered — which is most of this pattern. Return dummy.next, never the original head variable, since that node may no longer be first.

The cost is one node. The benefit is deleting an entire class of edge cases before they exist.

The four moves

Reverse
Three pointers, four lines, always in the same order: save next, flip the link, advance prev, advance cur.
Merge
A dummy plus a tail pointer. Repeatedly attach the smaller head and advance.
Split
Find a boundary node, then cut by setting its next to null — after saving what came after.
Interleave
Weave new nodes between existing ones so that position encodes a relationship, then unweave.

Everything in this family is a composition of those four. Naming which ones you need before writing anything is what keeps a Hard list problem tractable.

Applies when

You must restructure a list rather than just read it — reversing a section, merging, grouping, or deep-copying. Also when O(1) extra space is demanded, which rules out copying into an array.

Does not apply when

You only need to read values in order — copy them into a list and solve the array problem, unless the space constraint forbids it. Say that out loud before doing pointer surgery.

Complexity

O(n) for a single pass; merging k lists is O(n log k) with a heap. Space is O(1) for iterative solutions — prefer them, since recursion on a 10⁴-node list risks a stack overflow.

Recognition cues — the literal words in the statement"reverse the nodes in k-group" · "merge two sorted lists" · "swap every two adjacent nodes" · "reverse between positions left and right" · "a deep copy of the list" · "you may not modify the values in the list's nodes — only the nodes themselves may be changed". That last sentence is decisive: it forbids the value-swapping shortcut and forces genuine pointer work.
