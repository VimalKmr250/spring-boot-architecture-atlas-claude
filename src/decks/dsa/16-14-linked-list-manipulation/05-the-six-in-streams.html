A stream cannot rewire a list, but it can compute the new order

Pointer surgery changes the very structure being walked, and that is interference: a stream must not modify its own source. What a stream can do is walk the nodes and decide where each one goes, whether by an index map, a merge or a sort. It collects that order, and only then does a final pass rewire every node, once each. All six are clean and keep the loop's time bound, 23 aside. All six pay O(n) extra space for the list of nodes.

LC 21 · Merge Two Sorted Lists · clean
class Solution {
    // the two unmerged heads; each step takes the smaller
    record Heads(ListNode a, ListNode b) {
        boolean fromA() {
            return b == null || a != null && a.val <= b.val;
        }
        boolean more() { return a != null || b != null; }
        ListNode taken() { return fromA() ? a : b; }
        Heads next() {
            return fromA() ? new Heads(a.next, b)
                           : new Heads(a, b.next);
        }
    }

    public ListNode mergeTwoLists(ListNode list1,
                                  ListNode list2) {
        // Collect the merged order first; rewire only after.
        List<ListNode> order = Stream
                .iterate(new Heads(list1, list2), Heads::more,
                         Heads::next)
                .map(Heads::taken)
                .toList();
        return relink(order);
    }

    // ---- the same relink in 21, 24, 92, 23 and 25 ----
    // Each index writes one different node: parallel-safe.
    static ListNode relink(List<ListNode> order) {
        int n = order.size();
        IntStream.range(0, n).forEach(i -> order.get(i).next =
                i + 1 < n ? order.get(i + 1) : null);
        return n == 0 ? null : order.get(0);
    }
}
LC 24 · Swap Nodes in Pairs · clean
class Solution {
    public ListNode swapPairs(ListNode head) {
        List<ListNode> nodes = Stream.iterate(head,
                Objects::nonNull, x -> x.next).toList();
        int n = nodes.size();
        // Position i takes its pair partner i ^ 1 when there is
        // one: 0<->1, 2<->3, ... An odd last node stays put.
        return relink(IntStream.range(0, n)
                .map(i -> (i ^ 1) < n ? i ^ 1 : i)
                .mapToObj(nodes::get)
                .toList());
    }

    // ---- the same relink in 21, 24, 92, 23 and 25 ----
    // Each index writes one different node: parallel-safe.

}
LC 92 · Reverse Linked List II · clean
class Solution {
    public ListNode reverseBetween(ListNode head, int left,
                                   int right) {
        List<ListNode> nodes = Stream.iterate(head,
                Objects::nonNull, x -> x.next).toList();
        int lo = left - 1, hi = right - 1;   // 0-indexed
        // Inside [lo, hi], position i reads from its mirror.
        return relink(IntStream.range(0, nodes.size())
                .mapToObj(i -> nodes.get(
                        i >= lo && i <= hi ? lo + hi - i : i))
                .toList());
    }

    // ---- the same relink in 21, 24, 92, 23 and 25 ----
    // Each index writes one different node: parallel-safe.
    static ListNode relink(List<ListNode> order) {
        int n = order.size();
        IntStream.range(0, n).forEach(i -> order.get(i).next =
                i + 1 < n ? order.get(i + 1) : null);
        return n == 0 ? null : order.get(0);
    }
}
LC 23 · Merge k Sorted Lists · clean
class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        // Every node of every list, sorted by value. sorted()
        // is a barrier: the walk ends before relink rewires.
        return relink(Arrays.stream(lists)
                .flatMap(h -> Stream.iterate(h,
                        Objects::nonNull, x -> x.next))
                .sorted(Comparator.comparingInt(x -> x.val))
                .toList());
    }

    // ---- the same relink in 21, 24, 92, 23 and 25 ----
    // Each index writes one different node: parallel-safe.

LC 25 · Reverse Nodes in k-Group · clean
class Solution {
    public ListNode reverseKGroup(ListNode head, int k) {
        List<ListNode> nodes = Stream.iterate(head,
                Objects::nonNull, x -> x.next).toList();
        int n = nodes.size(), full = n / k * k;
        // Inside each complete group, position i reads from its
        // mirror in that group. The short tail stays put.
        return relink(IntStream.range(0, n)
                .mapToObj(i -> nodes.get(i < full
                        ? i / k * k + (k - 1 - i % k) : i))
                .toList());
    }

    // ---- the same relink in 21, 24, 92, 23 and 25 ----
    // Each index writes one different node: parallel-safe.
    static ListNode relink(List<ListNode> order) {
        int n = order.size();
        IntStream.range(0, n).forEach(i -> order.get(i).next =
                i + 1 < n ? order.get(i + 1) : null);
        return n == 0 ? null : order.get(0);
    }
}
LC 138 · Copy List with Random Pointer · clean
class Solution {
    public Node copyRandomList(Node head) {
        // old node -> a fresh copy. Node has no equals(), so
        // the map is keyed by identity, which is what we want.
        Map<Node, Node> copy = Stream.iterate(head,
                        Objects::nonNull, x -> x.next)
                .collect(Collectors.toMap(
                        x -> x, x -> new Node(x.val)));
        // Wire the copies through the map; get(null) is null.
        copy.forEach((old, c) -> {
            c.next = copy.get(old.next);
            c.random = copy.get(old.random);
        });
        return copy.get(head);
    }
}
Compute the order, then relink onceCollecting the nodes into a list before rewiring is what makes this safe: the walk is over before any next pointer changes. The relink itself is a forEach in which each index writes to a different node, so even that step would be correct in parallel. The tests also check that the nodes themselves move, since swapping values would break the rules of 24 and 25.
What it costsThe loop versions run in O(1) extra space, while every version here holds all n nodes in a list. When the follow-up says "constant extra space", the stream answer no longer qualifies. Reverse the pointers in place with a loop, and say that this is why.
