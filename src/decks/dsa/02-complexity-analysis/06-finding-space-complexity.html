Space is the peak, not the total

Time adds up everything that ever runs. Space asks a narrower question: at the worst single moment, how much extra memory is alive? Memory that is released and reused does not accumulate — which is why naive Fibonacci makes O(2ⁿ) calls but never needs more than O(n) of stack.

What goes in the count

Counts
Every structure you allocate that grows with the input: arrays, maps, sets, heaps, queues, DP tables.
Counts
The recursion stack — its maximum depth times a constant-size frame. It is the term most often forgotten.
Counts
Copies you make: substring, toCharArray, new ArrayList<>(path), a sorted copy of the input, an object sort's temporary buffer.
Excluded
The input, unless you copy it. Mutating it in place costs no space — but say that you are doing it.
Excluded
The output, by this deck's convention. Say "excluding the output" out loud, because some interviewers include it.
Constant
Anything whose size does not depend on the input — int[26], int[128], ten local variables — is O(1), however large it looks.

Java's stack is smaller than your Big-OA recursive solution can be O(n) in space and still crash. The default thread stack — typically 512 KB to 1 MB, set with -Xss — holds on the order of 10⁴ frames for a small method, so recursing down a 10⁵-node linked list or skewed tree throws StackOverflowError. When depth can reach n, rewrite with an explicit ArrayDeque: the same Big-O, but the stack now lives on the heap.
Space is usually spent to buy timeA HashSet turns an O(n²) pair scan into O(n) (06). A memo table turns O(2ⁿ) into a polynomial (27–30). When a problem demands O(1) extra space, it is refusing that trade — reach for Floyd's cycle detection (03), in-place marking, or a rolling array instead.
