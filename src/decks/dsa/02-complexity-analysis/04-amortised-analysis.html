When a loop inside a loop is still linear

Read per iteration, a while inside a for looks like n × n. That bound is true but loose. The aggregate question is sharper: across the entire run, how many times can the inner body execute in total? If every execution consumes something that can only be consumed once, the answer is n — and so is the complexity.

The aggregate method, in three moves

  1. Name what the inner loop consumes. An index passed over by l, an element popped from a stack, a node taken off a queue.
  2. Show it cannot be consumed twice. l never decreases. A popped index is never pushed again. A visited node is never queued again.
  3. Sum, then divide. Total inner work is at most the number of things there are to consume. Add the outer loop's own n and you have the total; divide by n and you have the amortised cost per step — O(1).

Amortised is not the same as average. An average is an expectation over inputs, and an unlucky input can beat it. An amortised bound holds for every input: individual steps may be expensive, but the total over any run is guaranteed.

The same argument, pattern by pattern

01 window
r admits each index once; l evicts each at most once. At most 2n moves.
02 two pointers
The gap r − l starts below n and every step shrinks it. At most n steps.
09 · 10 stack, deque
Each index is pushed once and removed at most once. At most 2n operations.
16 · 20 · 21 BFS
Each node is queued once — mark it when you enqueue it — and its adjacency list is scanned once, when it is dequeued. O(V + E).
22 union-find
Path compression flattens every path it walks. With union by size, O(α(n)) amortised — and α(n) ≤ 4 for any input that fits in memory.
ArrayList.add
A resize copies everything, but capacity grows geometrically, so all the copying over n adds sums to O(n). O(1) amortised.
When the argument breaksThe whole bound rests on "cannot be consumed twice". Reset l to 0, restart a scan from the beginning, or push a popped element back on, and the walk stops being monotone — the honest bound becomes O(n²). Before claiming O(n) for a nested loop, point at the variable that never moves backwards.
