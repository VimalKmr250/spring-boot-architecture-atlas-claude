Guess the answer, then check whether it works

The highest-yield pattern in this deck, and the one most people never recognise. Nothing here is sorted. What is monotone is feasibility: if a capacity of 5 is enough, so is 6. Binary search that, and an apparently intractable optimisation becomes an O(n log V) loop around a ten-line simulation.

The inversion

The question "what is the smallest capacity that works?" is hard. The question "does capacity 7 work?" is usually easy — a single greedy pass.

So stop optimising and start checking. Binary search over the range of possible answers, using the easy question as the predicate. You never derive the answer; you converge on it.

Cost: O(log V) checks, each O(n). With values up to 10⁹ that is 30 checks — the log factor is essentially free, which is why this beats almost any clever direct construction.

Three questions, in this order

  1. What exactly is the answer, and what range must it lie in? Pick lo as a value that obviously fails or is the smallest legal one, and hi as one that obviously works. Sloppy bounds are the main source of wrong answers here.
  2. Can I check one candidate in O(n)? Write feasible(x) as a literal simulation of the problem statement. Resist cleverness — it should read like the English.
  3. Is feasibility monotone? If x works, must x + 1 work? Say the argument out loud. If the answer is no, this pattern does not apply.

Answer those three and the code writes itself — it is an ordinary boundary search whose array comparison has been replaced by feasible(mid).

Applies when

The answer is a single number in a known range; you are asked to minimise a maximum or maximise a minimum; and checking one candidate is a straightforward greedy pass. The constraint shape "small n, huge values" is the giveaway.

Does not apply when

Feasibility is not monotone — for example "exactly k parts" where a larger cap can force fewer parts than required. Reformulate it as "at most k" first, or the search converges on a value that is not actually achievable.

Complexity

O(n log V) where V is the width of the answer range — typically 30 iterations for values to 10⁹, so about 30n. Space is O(1). For real-valued answers, use a fixed 100 iterations rather than an epsilon comparison.

Recognition cues — the literal words in the statement"minimise the maximum…" or "maximise the minimum…" (decisive on their own) · "the smallest X such that…" · "within D days" · "at most k operations" · "the minimum eating speed" · "split into k subarrays" · "the minimum capacity". Add the constraint tell: n ≤ 10⁵ next to value ≤ 10⁹ means the search is over the values, not the array.
