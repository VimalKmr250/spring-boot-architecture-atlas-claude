Anchor 1 · LC 743 — the path to the solution

The restatement
The signal reaches a node along its shortest path, so the time for all nodes is the maximum shortest-path distance from the source. Two standard pieces, composed.
Why not BFS
Edge weights differ, so a queue no longer produces nodes in distance order. BFS would report hop counts rather than travel times.
The substitution
Replace the queue with a priority queue ordered by distance. Everything else about BFS is unchanged, which is a useful way to remember Dijkstra.
Lazy deletion
Java cannot decrease a key, so push a new entry on improvement and skip stale ones with if (d > dist[node]) continue;.
The answer
The maximum over dist[1..n]. If any entry is still infinite, that node is unreachable and the answer is −1.
Edge cases
Nodes are 1-indexed, so size the arrays n + 1 and ignore index 0. Multiple edges between the same pair are fine — the relaxation keeps the best.
LC 743 · O(E log E) time, O(V + E) space
class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        // node -> list of (neighbour, weight). 1-indexed, so n + 1.
        List<int[]>[] adj = new List[n + 1];
        for (int i = 1; i <= n; i++) adj[i] = new ArrayList<>();
        for (int[] t : times) adj[t[0]].add(new int[]{t[1], t[2]});

        int[] dist = new int[n + 1];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[k] = 0;

        PriorityQueue<int[]> pq =
                new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
        pq.offer(new int[]{k, 0});

        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int node = cur[0], d = cur[1];

            // Stale entry: we already recorded a shorter route here.
            if (d > dist[node]) continue;

            for (int[] e : adj[node]) {
                int next = e[0], cand = d + e[1];
                if (cand < dist[next]) {
                    dist[next] = cand;
                    pq.offer(new int[]{next, cand});   // push, not update
                }
            }
        }

        int worst = 0;
        for (int i = 1; i <= n; i++) {
            if (dist[i] == Integer.MAX_VALUE) return -1;   // unreachable
            worst = Math.max(worst, dist[i]);
        }
        return worst;
    }
}

Anchor 2 · LC 787 — the path to the solution

Why Dijkstra fails
Its invariant is that a popped node is final. With a stop limit that breaks: reaching a node cheaply but using all your stops can be worse than reaching it expensively with stops to spare. A single distance per node no longer captures the state.
Fix one — add a dimension
Run Dijkstra over (node, stopsUsed) pairs. Correct, and worth mentioning, but the state space is larger and the bookkeeping is fiddlier.
Fix two — Bellman-Ford
Relax every edge, k + 1 times. After round r, dist[] holds the cheapest cost using at most r edges — so the hop limit is simply the number of rounds. Much simpler to get right.
Why k + 1
k stops means k + 1 flights. Off-by-one here is the most common wrong answer on this problem.
Why the snapshot
prev = dist.clone() before each round. Relaxing in place lets a route discovered earlier in the same round be extended again, chaining two edges in one round and exceeding the hop bound.
Edge case
Skip relaxation from unreachable nodes, or MAX_VALUE + price overflows into a negative and looks like a bargain.
LC 787 · O(k·E) time, O(V) space
class Solution {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        int[] dist = new int[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[src] = 0;

        // k STOPS means k + 1 FLIGHTS, hence k + 1 rounds.
        for (int round = 0; round <= k; round++) {

            // Snapshot: relaxing in place would let a route found
            // earlier in THIS round be extended again, using more
            // edges than the round count permits.
            int[] prev = dist.clone();

            for (int[] f : flights) {
                int from = f[0], to = f[1], price = f[2];

                // Unreachable so far — and MAX_VALUE + price overflows.
                if (prev[from] == Integer.MAX_VALUE) continue;

                dist[to] = Math.min(dist[to], prev[from] + price);
            }
        }
        return dist[dst] == Integer.MAX_VALUE ? -1 : dist[dst];
    }
}

1514 · Path with Maximum Probability Dijkstra, max

Path: maximise a product of probabilities rather than minimise a sum. Since every factor is in [0,1], extending a path can only shrink it — which is the same monotonicity Dijkstra relies on, just mirrored.

Delta: a max-heap on probability, double[] best initialised to 0, and prob * edgeProb in place of d + w. Return as soon as the destination is popped.

Watch for: the graph is undirected, so add both directions. Taking -log of each probability turns it back into a standard minimisation — a nice thing to mention, though the direct version is simpler.

1631 · Path With Minimum Effort minimax

Path: the cost of a path is its worst single step, not the total. That is still monotone — extending a path can only keep or raise the maximum — so Dijkstra applies unchanged.

Delta: cand = max(effortSoFar, |h[next] − h[cur]|) replaces the addition. The grid is the graph, with four-directional neighbours.

Watch for: binary search on the answer plus a connectivity check is an equally good alternative, as is union-find over edges sorted by weight. Naming all three shows you see the shape rather than one recipe.

1334 · City With Smallest Number of Neighbors Floyd–Warshall

Path: you need distances between all pairs. Running Dijkstra from every node is O(V·E log E) and works; with n ≤ 100 there is something much shorter.

Delta: Floyd–Warshall — three nested loops with k outermost, relaxing d[i][j] = min(d[i][j], d[i][k] + d[k][j]). Then count reachable cities per node and take the smallest count, breaking ties by the largest index.

Watch for: k must be the outer loop — it is the "intermediate vertex allowed" dimension, and reordering the loops silently produces wrong distances. Use a finite sentinel such as 10⁹ rather than MAX_VALUE to avoid overflow in the addition.

1976 · Number of Ways to Arrive at Destination Dijkstra + count

Path: ordinary Dijkstra finds the shortest time; the question additionally asks how many distinct routes achieve it.

Delta: carry long[] ways next to dist[]. On a strictly shorter route, replace the count with the predecessor's. On an equally short one, add it. Take everything modulo 10⁹+7.

Watch for: times sum to more than int range, so dist[] must be long. And the equal-distance branch must not push to the heap again — the node's distance has not changed, so re-expanding it would double-count.

If you only drill twoDo 743 and 787. 743 fixes the heap loop, the lazy-deletion skip, and the habit of reading Dijkstra as "BFS with a priority queue". 787 is the one that teaches the boundary of the pattern — recognising that an added constraint invalidates the finality invariant, and that the fix is either an extra state dimension or a different algorithm entirely.
