The same skeleton, with the guard moved to the top

Choose, explore, un-choose is unchanged. What is added is a guard clause before the choose, and incremental state that keeps that guard O(1).

Grid backtracking — the board as its own visited set (LC 79)
private static final int[][] DIRS = {{1,0},{-1,0},{0,1},{0,-1}};

boolean exist(char[][] board, String word) {
    for (int r = 0; r < board.length; r++)
        for (int c = 0; c < board[0].length; c++)
            if (dfs(board, word, r, c, 0)) return true;
    return false;
}

private boolean dfs(char[][] b, String w, int r, int c, int k) {
    if (k == w.length()) return true;                 // whole word matched

    // GUARD — bounds, then the letter test. Marked cells hold '#',
    // which never equals a real letter, so one check covers both
    // "already on the path" and "wrong letter".
    if (r < 0 || r >= b.length || c < 0 || c >= b[0].length) return false;
    if (b[r][c] != w.charAt(k)) return false;

    char saved = b[r][c];
    b[r][c] = '#';                                    // choose

    for (int[] d : DIRS) {
        if (dfs(b, w, r + d[0], c + d[1], k + 1)) {
            b[r][c] = saved;      // RESTORE even on success — the
            return true;          // caller's board must stay intact
        }
    }

    b[r][c] = saved;                                  // un-choose
    return false;
}
Placement with O(1) conflict tests (LC 51, 52)
// One queen per row, so only the COLUMN is chosen at each depth.
// Three boolean arrays make every conflict test a single read.
private boolean[] col, diag, anti;
private int n, count;

void solve(int row, List<String> board, List<List<String>> out) {
    if (row == n) { out.add(new ArrayList<>(board)); return; }

    for (int c = 0; c < n; c++) {
        int d = row + c;              // constant along one diagonal
        int a = row - c + n;          // + n shifts the range into [0, 2n)

        // GUARD before choosing — O(1), no board scan.
        if (col[c] || diag[d] || anti[a]) continue;

        col[c] = diag[d] = anti[a] = true;            // choose
        board.add(rowString(c));

        solve(row + 1, board, out);                   // explore

        board.remove(board.size() - 1);               // un-choose
        col[c] = diag[d] = anti[a] = false;           // ALL THREE
    }
}
Partitioning — the guard is a predicate on the piece (LC 131)
// Cut the string at every position; keep a cut only when the piece
// to the left satisfies the rule.
void partition(String s, int start, List<String> path,
               List<List<String>> out) {
    if (start == s.length()) { out.add(new ArrayList<>(path)); return; }

    for (int end = start; end < s.length(); end++) {

        // GUARD — this piece must be legal before we commit to it.
        if (!isPalindrome(s, start, end)) continue;

        path.add(s.substring(start, end + 1));        // choose
        partition(s, end + 1, path, out);             // explore
        path.remove(path.size() - 1);                 // un-choose
    }
}

// Two pointers, O(len). Precomputing an isPal[i][j] table in O(n^2)
// makes the guard O(1) and is the standard optimisation here.
private boolean isPalindrome(String s, int i, int j) {
    while (i < j) if (s.charAt(i++) != s.charAt(j--)) return false;
    return true;
}

The knobs

Guard position
Top of the loop body, before the choose. Pruning after recursing has already paid the cost.
Visited state
Mutate the input when it is allowed and restorable — a board cell, a used flag. Otherwise a separate structure, updated and undone in step.
Conflict encoding
Find an O(1) key. For diagonals, r + c and r − c + n. For sets, a bitmask. Scanning the partial solution is what turns a passing solution into a timeout.
Record point
At full depth for placements and partitions, or the moment the target is met for sum problems.
Precomputation
When the guard is expensive and called repeatedly on the same ranges, compute a table first. That is the standard LC 131 improvement.
The three bugs that actually happenRestoring only on failure — the board or flags stay dirty after a successful branch, which breaks any repeated call. Undoing some of the state — N-Queens has three arrays plus the path, and missing one produces too few solutions rather than a crash. A guard that scans — checking every placed queen is O(n) per test and turns a fast solution into a slow one; the array encoding is what makes it O(1).
