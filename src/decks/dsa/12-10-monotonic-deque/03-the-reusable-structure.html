Expire, evict, read — in that order, every time

The order is not stylistic. Expiring before evicting keeps the deque small; reading last guarantees the front is both in-window and maximal. Swap any two and the answer is wrong on some input.

The template — maximum of every window of width k
/**
 * Deque holds INDICES whose values DECREASE from front to back.
 * front = the maximum of the current window.
 *
 * Each index is added once and removed once (from one end or
 * the other), so the two inner loops still total O(n).
 */
int[] maxSlidingWindow(int[] a, int k) {
    int n = a.length;
    int[] out = new int[n - k + 1];

    Deque<Integer> dq = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {

        // 1 · EXPIRE — the front has slid out of the window.
        // Window covering i starts at i-k+1, so <= i-k is stale.
        while (!dq.isEmpty() && dq.peekFirst() <= i - k) {
            dq.pollFirst();
        }

        // 2 · EVICT — anything smaller than a[i] is dead forever:
        // a[i] is bigger AND outlives it.
        while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) {
            dq.pollLast();
        }
        dq.offerLast(i);

        // 3 · READ — only once the window is actually full.
        if (i >= k - 1) out[i - k + 1] = a[dq.peekFirst()];
    }
    return out;
}
Variant · two deques for max AND min (LC 1438)
// "Absolute difference at most limit" means max - min <= limit,
// so run one decreasing deque and one increasing deque side by
// side. The window is invalid while their fronts differ too much.
int longestSubarray(int[] a, int limit) {
    Deque<Integer> maxD = new ArrayDeque<>();   // decreasing
    Deque<Integer> minD = new ArrayDeque<>();   // increasing
    int l = 0, best = 0;

    for (int r = 0; r < a.length; r++) {
        while (!maxD.isEmpty() && maxD.peekLast() < a[r]) maxD.pollLast();
        maxD.offerLast(a[r]);
        while (!minD.isEmpty() && minD.peekLast() > a[r]) minD.pollLast();
        minD.offerLast(a[r]);

        // Here the left edge moves for VALIDITY, not for age.
        while (maxD.peekFirst() - minD.peekFirst() > limit) {
            if (maxD.peekFirst() == a[l]) maxD.pollFirst();
            if (minD.peekFirst() == a[l]) minD.pollFirst();
            l++;
        }
        best = Math.max(best, r - l + 1);
    }
    return best;
}
Variant · deque as a DP accelerator (LC 1696, 1425)
// dp[i] = a[i] + max(dp[i-k] .. dp[i-1])
// The inner max over a moving band is exactly what the deque gives
// in O(1), turning an O(n*k) DP into O(n).
int maxResult(int[] a, int k) {
    int n = a.length;
    int[] dp = new int[n];
    dp[0] = a[0];

    Deque<Integer> dq = new ArrayDeque<>();   // indices, dp decreasing
    dq.offerLast(0);

    for (int i = 1; i < n; i++) {
        // expire: only the last k positions may be jumped from
        while (!dq.isEmpty() && dq.peekFirst() < i - k) dq.pollFirst();

        dp[i] = a[i] + dp[dq.peekFirst()];    // best reachable predecessor

        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.offerLast(i);
    }
    return dp[n - 1];
}

The knobs

Direction
Decreasing for a maximum, increasing for a minimum. Both at once when the question is about a spread.
Expiry rule
By age for a fixed-width window (index <= i - k); by validity when the left edge is driven by a condition, as in the two-deque variant.
What you store
Indices when you need positions or an age test; raw values when the eviction is purely by comparison, as in LC 1438.
When to read
Guard with i >= k - 1 for fixed windows, or the first few outputs come from an incomplete window.
< or <= on eviction
<= keeps the deque shorter by discarding equal values. Both are correct for a maximum; prefer <=.
The three bugs that actually happenReading before the window is full — without the i >= k - 1 guard the first k−1 answers are maxima of partial windows. Expiring with < instead of <= — keeps one stale index, so the reported maximum can come from just outside the window. Using peek() on an ArrayDeque and expecting the back — peek() is peekFirst(); always write peekFirst and peekLast explicitly here, because both ends are in play.
