Draw the call tree, then count it

A recursive function's running time is the sum of the work done at every node of its call tree, each node charged only for what it does outside its recursive calls. Two questions settle the time: how many nodes does the tree have, and how much work does each do? Space asks a third question: how deep does the tree go?

The master theorem, for recursions that divide

For T(n) = a·T(n/b) + O(nd) — a calls on inputs of size n/b, plus nd work to split and combine — compare a with bd:

a < bd
The top call dominates: O(nd). Quickselect on average: a = 1, b = 2, d = 1 gives O(n).
a = bd
Every level costs the same: O(nd log n). Merge sort gives O(n log n); binary search, with d = 0, gives O(log n).
a > bd
The leaves dominate: O(nlogb a). Balanced-tree DFS: a = 2, b = 2, d = 0 gives O(n).
Memoisation changes what you countWith a memo, each distinct argument is computed once, so the tree collapses into a table: time = distinct states × work per state. Fibonacci drops from O(2ⁿ) to n states × O(1) = O(n). LC 322 is amount states × one try per coin = O(amount · coins). LC 1143 is m·n states × O(1).
