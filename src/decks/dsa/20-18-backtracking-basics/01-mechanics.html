Choose, explore, un-choose

Backtracking builds a candidate one element at a time and walks back the instant it cannot lead anywhere. The code is always the same three lines wrapped in a loop — and the entire difficulty is the start index, which decides whether you enumerate combinations or permutations.

The three lines

  1. Choose — add a candidate to the partial solution.
  2. Explore — recurse with the state updated.
  3. Un-choose — remove it, restoring the state exactly as it was.

Step 3 is what makes it backtracking rather than plain recursion. Every mutation on the way down must have a matching undo on the way up, so the state at any point describes only the current branch.

Write the undo immediately after the recursive call, before anything else — the same discipline as pairing admit with evict.

The start index decides everything

i + 1
Combinations. Each element may be used once, and order does not matter, because a fixed left-to-right sweep never revisits earlier positions.
i
Combinations with reuse. The same element may be chosen repeatedly, but still no reordering.
from 0, with a used[]
Permutations. Every position is reachable at every depth, so order matters and you need explicit tracking of what is already in the path.

Applies when

The problem asks you to enumerate — return all subsets, all permutations, all combinations summing to a target. The plural in "return all" is the signal.

Does not apply when

Only a count or the best one is wanted. Enumerating to count is exponential when a dynamic-programming recurrence would be polynomial — that distinction decides the whole approach.

Complexity

O(n·2ⁿ) for subsets, O(n·n!) for permutations — the output itself is that large, so it cannot be beaten. Space is O(n) for the path plus the recursion stack, excluding the output.

The constraint bound is confirmation: n ≤ 20 or smaller means an exponential answer is intended.
