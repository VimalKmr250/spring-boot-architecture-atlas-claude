The line that looks O(1) and is not

Step 2 of the method — price every line — is where most wrong answers come from. A single library call can hide a loop over the whole collection or the whole string. These are the Java calls that appear throughout this deck's solutions, with what each one really costs.

CallCostWhy it matters
ArrayList get(i) · set(i, x)O(1)Backed by an array. The same calls on a LinkedList walk the list from the nearer end: O(n).
list.add(x)O(1) amortisedA full list grows by half its size and copies across. Growth is geometric, so the copying over n adds totals O(n).
list.add(0, x) · list.remove(0)O(n)Shifts every later element. Using an ArrayList as a queue this way quietly makes a BFS quadratic.
list.contains(x) · indexOf · remove(Object)O(n)A linear scan. For membership tests, use a HashSet.
ArrayDeque push · pop · offer · poll · peekO(1) amortisedThe default stack and queue, at either end. Prefer it to java.util.Stack and LinkedList.
HashMap get · put · containsKey
HashSet add · contains		O(1) averagePlus the cost of hashing and comparing the key: O(L) for a String or List key of length L. That is why LC 49 is O(n·L), not O(n).
TreeMap · TreeSet get · put · floorKey · ceilingKey · firstO(log n)A red-black tree. The price of keeping keys in order.
PriorityQueue offer · pollO(log n)peek is O(1). remove(x) and contains(x) are O(n) scans — which is why Dijkstra in Java pushes duplicates and skips stale entries instead.
new PriorityQueue<>(collection)O(n)Heapifies in one pass — cheaper than n separate offers at O(n log n).
Arrays.sort(int[])O(n log n)Dual-pivot quicksort on primitives. Not stable, which cannot matter for primitives.
Arrays.sort(T[], cmp) · Collections.sort · list.sortO(n log n) time
O(n) space		Timsort: stable, and allocates up to n/2 temporary slots. That buffer is what "the sort's working memory" means when a space figure leaves it out.
new int[n] · Arrays.fill · clone() · Arrays.copyOfO(n)Allocation zeroes the memory. A new int[n] inside a loop of n is O(n²).
s.substring(i, j)O(j − i)A copy, not a view, since Java 7u6. charAt is O(1); slicing is not.
s.toCharArray() · new String(chars)O(L) time and spaceA full copy. Do it once, outside the loop.
s.equals(t) · compareTo · hashCode()O(L)Character by character. hashCode is cached on each String object after its first call, but a freshly built key pays it again.
s + t · s += cO(|s| + |t|)Builds a new String every time: n appends in a loop cost O(n²). Use a StringBuilder.
sb.append(c) · sb.setLength(len − 1)O(1) amortisedThe backtracking pair: append to choose, shorten to undo.
sb.insert(0, c) · sb.deleteCharAt(0) · sb.reverse()O(L)Shifts or touches every character. Prepending in a loop is O(n²) — append, then reverse once.
new ArrayList<>(path)O(size)The copy made at every backtracking leaf. It is the n in O(n·2ⁿ).
stream()… · Collections.max · String.joinO(n) per callEach one walks the whole collection. Inside a loop, it is a nested loop.
Boxed Integer in collectionsO(1), bigger constantSame Big-O as int[], but every element is a separate object: several times the memory, and slower. Prefer int[] when the key range is small.
The three that most often turn O(n) into O(n²)s += c in a loop — every append copies the whole string so far; use a StringBuilder. list.remove(0) as a queue — every poll shifts the rest of the list; use an ArrayDeque. list.contains(x) as a set — every lookup is a scan; use a HashSet. In each case the algorithm stays identical and only the container changes.
