Java 17 has no scan, so keep the state to one line

Every problem here starts from the running total, and a running total is a scan: each output depends on the one before it. Java 17 streams have no scan stage, so the prefix array comes from a map over a one-element array. That is the only lambda in these solutions that carries state, and everything after it reads the finished array and is clean. 930 avoids the scan altogether.

LC 303 · Range Sum Query — Immutable · stateful
class NumArray {
    private final int[] p;   // p[i] = sum of the first i values

    public NumArray(int[] nums) {
        // Java 17 streams have no scan, so the running total is
        // a stateful map, run once and in order.
        int[] run = {0};
        p = IntStream.concat(IntStream.of(0),
                Arrays.stream(nums).map(v -> run[0] += v))
                .toArray();
    }

    public int sumRange(int left, int right) {
        return p[right + 1] - p[left];
    }
}
LC 724 · Find Pivot Index · stateful
class Solution {
    public int pivotIndex(int[] nums) {
        int total = Arrays.stream(nums).sum();
        int[] run = {0};
        int[] p = IntStream.concat(IntStream.of(0),
                Arrays.stream(nums).map(v -> run[0] += v))
                .toArray();
        // left = p[i], right = total - p[i] - nums[i]; equal
        // exactly when 2·p[i] + nums[i] == total.
        return IntStream.range(0, nums.length)
                .filter(i -> 2 * p[i] + nums[i] == total)
                .findFirst().orElse(-1);
    }
}
LC 560 · Subarray Sum Equals K · stateful
class Solution {
    public int subarraySum(int[] nums, int k) {
        int n = nums.length;
        // 1 · the only stateful line: the running-total scan
        int[] run = {0};
        int[] p = IntStream.concat(IntStream.of(0),
                Arrays.stream(nums).map(v -> run[0] += v))
                .toArray();
        // 2 · clean from here on: prefix value -> its indices,
        //     ascending (groupingBy keeps encounter order)
        Map<Integer, List<Integer>> at = IntStream
                .rangeClosed(0, n).boxed()
                .collect(Collectors.groupingBy(i -> p[i]));
        // subarrays ending at j: earlier i, p[i] == p[j] - k
        return IntStream.rangeClosed(1, n)
                .map(j -> below(at.get(p[j] - k), j))
                .sum();
    }

    // how many indices in the ascending list are below j
    static int below(List<Integer> idx, int j) {
        if (idx == null) return 0;
        int pos = Collections.binarySearch(idx, j);
        return pos >= 0 ? pos : -pos - 1;
    }
}
LC 930 · Binary Subarrays With Sum · clean
class Solution {
    public int numSubarraysWithSum(int[] nums, int goal) {
        int n = nums.length;
        // No scan: the positions of the ones, fenced by -1, n
        int[] one = IntStream.concat(IntStream.of(-1),
                IntStream.concat(IntStream.range(0, n)
                                .filter(i -> nums[i] == 1),
                        IntStream.of(n)))
                .toArray();
        if (goal == 0)        // all-zero runs: z(z+1)/2 each
            return IntStream.range(1, one.length)
                    .map(j -> one[j] - one[j - 1] - 1)
                    .map(z -> z * (z + 1) / 2)
                    .sum();
        // Ones i .. i+goal-1: the left end sits in the gap
        // before them, the right end in the gap after them.
        return IntStream.rangeClosed(1, one.length - 1 - goal)
                .map(i -> (one[i] - one[i - 1])
                        * (one[i + goal] - one[i + goal - 1]))
                .sum();
    }
}
LC 974 · Subarray Sums Divisible by K · stateful
class Solution {
    public int subarraysDivByK(int[] nums, int k) {
        // Prefix remainders; floorMod keeps them in [0, k).
        int[] s = {0};
        IntStream rems = Arrays.stream(nums)
                .map(v -> s[0] = Math.floorMod(s[0] + v, k));
        Map<Integer, Long> byRem = IntStream
                .concat(IntStream.of(0), rems).boxed()
                .collect(Collectors.groupingBy(
                        x -> x, Collectors.counting()));
        // Equal remainders at both ends make a divisible sum,
        // and order stops mattering: c prefixes give c(c-1)/2.
        return (int) byRem.values().stream()
                .mapToLong(c -> c * (c - 1) / 2)
                .sum();
    }
}
LC 523 · Continuous Subarray Sum · stateful
class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {
        // Prefix remainders mod k (long: k can be 2^31 - 1)
        long[] run = {0};
        int[] rem = IntStream.concat(IntStream.of(0),
                Arrays.stream(nums).map(
                        v -> (int) (run[0] = (run[0] + v) % k)))
                .toArray();
        // The FIRST index each remainder appears at
        Map<Integer, Integer> first = IntStream
                .range(0, rem.length).boxed()
                .collect(Collectors.toMap(i -> rem[i], i -> i,
                                          (a, b) -> a));
        // A repeat two or more positions later is a subarray of
        // length >= 2 whose sum is a multiple of k.
        return IntStream.range(0, rem.length)
                .anyMatch(j -> first.get(rem[j]) < j - 1);
    }
}
Why the scan is statefulmap(v -> run[0] += v) gives the right answer only because a sequential stream calls it in encounter order. Add .parallel() and the totals are garbage. Keep that lambda to one line with one job, and the rest of the pipeline stays pure. The one-pass map version of 560 is shorter and O(n), but it puts the entire loop body inside a single lambda, and at that point it is the loop wearing a costume.
Counting pairs is a grouping974 counts pairs of equal remainders, and for pairs the order no longer matters. c prefixes that share a remainder give c·(c−1)/2 subarrays, so groupingBy(counting()) is the whole algorithm. 560 cannot do the same, because when k ≠ 0 the order i < j matters. That is why it pays for a binary search per end.
