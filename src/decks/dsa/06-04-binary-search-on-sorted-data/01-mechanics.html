Stop searching for a value; search for a boundary

Most people learn binary search as "find the target, return −1 if absent", then rewrite it badly for every variant. Learn it once as find the first index where a monotone predicate becomes true, and equality, insert position, first occurrence, last occurrence and rotated arrays all become the same eight lines.

The invariant — a half-open range

Maintain [l, r): left inclusive, right exclusive. Throughout the loop:

  • Every index below l is known false.
  • Every index at or above r is known true.
  • The boundary lies somewhere in [l, r).

When l == r the range is empty and the boundary is pinned: l is the answer. It needs no post-loop adjustment, which is where nearly all binary-search bugs live.

Start with r = n, not n − 1. That is deliberate: n is the legitimate answer meaning "no index satisfies the predicate", and it is exactly the insert position.

The one precondition — monotonicity

The predicate applied across the array must read F F F F T T T: once true, true forever. It flips exactly once.

A sorted array gives this for free with a[i] >= target. But the array is not what matters — the predicate is. That distinction is what lets the same eight lines work on input that is not sorted at all.

Before writing any binary search, state the predicate in words and check that it is monotone. If it is not, the loop will converge confidently on the wrong index.

Applies when

The array is sorted, or is locally reconstructible as sorted — a rotated sorted array still has one sorted half at every midpoint, and a mountain array is monotone on each side of the peak.

Does not apply when

The predicate is not monotone. Searching an unsorted array for a value is O(n) with a hash set, not O(log n). Duplicates in a rotated array break the sorted-half test — when both ends and the midpoint are equal you cannot tell which side is ordered, and the worst case degrades to O(n).

Complexity

O(log n) time — the range halves every iteration, so at most ⌈log₂ n⌉ ≈ 17 steps for n = 10⁵. O(1) space when written iteratively. Always write it iteratively; recursion adds an O(log n) stack for nothing.

Recognition cues — the literal words in the statement"sorted array" plus "O(log n) runtime" (the problem naming the pattern outright) · "first / last position of" · "insert position" · "rotated sorted array" · "find the minimum" on rotated input · "peak element" · "the array is guaranteed to have no duplicates" — that guarantee exists precisely so the sorted-half test stays decidable.
