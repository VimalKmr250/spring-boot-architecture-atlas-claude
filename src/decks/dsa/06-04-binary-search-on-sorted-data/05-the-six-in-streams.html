Binary search is the best fit for a stream in the whole deck

Binary search runs in log n steps over a two-field state. Its step is a pure function and its stop condition is a single test, which is exactly the shape Stream.iterate handles well. So all six solutions share one helper: firstTrue(lo, hi, ok) halves a [lo, hi) record until it is empty and returns the first index where ok holds. Each problem then comes down to choosing that predicate and the range.

LC 704 · Binary Search · clean
class Solution {
    public int search(int[] nums, int target) {
        int n = nums.length;
        // A (lo, hi) record, halved by Stream.iterate.
        int i = firstTrue(0, n, m -> nums[m] >= target);
        return i < n && nums[i] == target ? i : -1;
    }

    // ---- the same helper in all six ----
    // [lo, hi) halves towards the first index where ok holds
    record Range(int lo, int hi) {
        Range halve(IntPredicate ok) {
            int mid = (lo + hi) >>> 1;
            return ok.test(mid) ? new Range(lo, mid)
                                : new Range(mid + 1, hi);
        }
    }

    // First index in [lo, hi) where ok holds, else hi. The
    // step only ever sees non-empty ranges: filter stops first.
    static int firstTrue(int lo, int hi, IntPredicate ok) {
        return Stream.iterate(new Range(lo, hi),
                              r -> r.halve(ok))
                .filter(r -> r.lo() == r.hi())
                .findFirst().get().lo();
    }
}

LC 34 · Find First and Last Position of Element · clean
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int n = nums.length;
        // Two lower bounds: of target, and of anything greater.
        int first = firstTrue(0, n, m -> nums[m] >= target);
        if (first == n || nums[first] != target)
            return new int[]{ -1, -1 };
        int last = firstTrue(0, n, m -> nums[m] > target) - 1;
        return new int[]{ first, last };
    }

    // ---- the same helper in all six ----
    // [lo, hi) halves towards the first index where ok holds

        Range halve(IntPredicate ok) {

LC 153 · Find Minimum in Rotated Sorted Array · clean
class Solution {
    public int findMin(int[] nums) {
        int n = nums.length, last = nums[n - 1];
        // Left of the rotation point every value exceeds the
        // last one; from it onwards none does. The minimum is
        // at the first index with nums[m] <= last.
        return nums[firstTrue(0, n - 1, m -> nums[m] <= last)];
    }

LC 162 · Find Peak Element · clean
class Solution {
    public int findPeakElement(int[] nums) {
        // Not a monotone test, and it need not be: whichever
        // way the slope at mid points, a peak lies on that
        // side, so halving towards it keeps one in range.
        return firstTrue(0, nums.length - 1,
                         m -> nums[m] > nums[m + 1]);
    }

LC 33 · Search in Rotated Sorted Array · clean
class Solution {
    public int search(int[] nums, int target) {
        int n = nums.length, last = nums[n - 1];
        // 1 · the rotation point k, exactly as in 153
        int k = firstTrue(0, n - 1, m -> nums[m] <= last);
        // 2 · values <= last live in [k, n), the rest in [0, k)
        int lo = target <= last ? k : 0;
        int hi = target <= last ? n : k;
        int i = firstTrue(lo, hi, m -> nums[m] >= target);
        return i < hi && nums[i] == target ? i : -1;
    }

    // ---- the same helper in all six ----
    // [lo, hi) halves towards the first index where ok holds
    record Range(int lo, int hi) {
        Range halve(IntPredicate ok) {
            int mid = (lo + hi) >>> 1;
            return ok.test(mid) ? new Range(lo, mid)
                                : new Range(mid + 1, hi);
        }
    }

    // First index in [lo, hi) where ok holds, else hi. The
    // step only ever sees non-empty ranges: filter stops first.
    static int firstTrue(int lo, int hi, IntPredicate ok) {
        return Stream.iterate(new Range(lo, hi),
                              r -> r.halve(ok))
                .filter(r -> r.lo() == r.hi())
                .findFirst().get().lo();
    }
}
What the record buys youThe loop version makes three off-by-one decisions every time you write it: < or <=, mid or mid − 1, return lo or hi. The Range record answers all three once. The range is half-open, the step keeps ok(mid) inside it, and the answer is the point where it closes. Every problem above is only a predicate and a range, so there is nothing left to get wrong per problem.
Say this in the interview"I'll write the loop, but binary search is where a stream version genuinely reads better: the state is two ints, the step is pure, and it stops the moment the range is empty." Then write the loop. Naming the invariant is what scores. The helper is the invariant written down.
