Level order is what Stream.iterate was made for

Stream.iterate(firstLevel, l -> !l.isEmpty(), nextLevel) produces the levels one list at a time, with no queue and no size-snapshot loop. Every problem here is then a map over each level: its values, its average, its maximum, or its last node. After hashing, this is the cleanest pattern in the deck.

LC 102 · Binary Tree Level Order Traversal · clean
class Solution {
    public List<List<Integer>> levelOrder(TreeNode root) {
        // Each level, mapped to its values: no queue, and no
        // size snapshot to get wrong.
        return levels(root)
                .map(l -> l.stream().map(n -> n.val).toList())
                .toList();
    }

    // ---- the same level walk in all six ----
    static Stream<List<TreeNode>> levels(TreeNode root) {
        List<TreeNode> first = root == null ? List.of()
                                            : List.of(root);
        return Stream.iterate(first, l -> !l.isEmpty(),
                              Solution::below);
    }

    // the next level down: every child of this one, in order
    static List<TreeNode> below(List<TreeNode> level) {
        return level.stream()
                .flatMap(n -> Stream.of(n.left, n.right))
                .filter(Objects::nonNull)
                .toList();
    }
}

class Solution {
    public List<Double> averageOfLevels(TreeNode root) {
        // IntStream.average() sums in a long internally, so a
        // row of values near 2^31 cannot overflow.

class Solution {

LC 103 · Binary Tree Zigzag Level Order Traversal · clean
class Solution {
    public List<List<Integer>> zigzagLevelOrder(TreeNode root) {
        List<List<TreeNode>> lv = levels(root).toList();
        // Number the levels, and read every odd one backwards.
        return IntStream.range(0, lv.size())
                .mapToObj(d -> {
                    List<TreeNode> l = lv.get(d);
                    int w = l.size();
                    return IntStream.range(0, w)
                            .mapToObj(i -> l.get(d % 2 == 0
                                    ? i : w - 1 - i).val)
                            .toList();
                })
                .toList();
    }

    // ---- the same level walk in all six ----
    static Stream<List<TreeNode>> levels(TreeNode root) {
        List<TreeNode> first = root == null ? List.of()
                                            : List.of(root);
        return Stream.iterate(first, l -> !l.isEmpty(),
                              Solution::below);
    }

    // the next level down: every child of this one, in order
    static List<TreeNode> below(List<TreeNode> level) {
        return level.stream()
                .flatMap(n -> Stream.of(n.left, n.right))
                .filter(Objects::nonNull)
                .toList();
    }
}
LC 116 · Populating Next Right Pointers in Each Node · clean
class Solution {
    public Node connect(Node root) {
        // Within each level, node i points at node i + 1. The
        // walk reads left/right only, so setting next is safe.
        levels(root).forEach(l -> IntStream.range(1, l.size())
                .forEach(i -> l.get(i - 1).next = l.get(i)));
        return root;
    }

    // ---- the same level walk in all six, over Node here ----
    static Stream<List<Node>> levels(Node root) {
        List<Node> first = root == null ? List.of()
                                        : List.of(root);
        return Stream.iterate(first, l -> !l.isEmpty(),
                              Solution::below);
    }

    // the next level down: every child of this one, in order
    static List<Node> below(List<Node> level) {
        return level.stream()
                .flatMap(n -> Stream.of(n.left, n.right))
                .filter(Objects::nonNull)
                .toList();
    }
}
No queue, no size snapshotThe classic bug in the loop version is reading queue.size() inside the level loop instead of before it. Here, a level is an immutable List built from the previous one. There is no queue whose size can change underneath you, so there is nothing to snapshot.
What it costsEach level is held as a List, O(w) memory, the same as the queue. 116's follow-up asks for O(1) extra space, which you get by walking the next pointers already built on the level above. That is a loop over two pointers, and no pipeline expresses it.
