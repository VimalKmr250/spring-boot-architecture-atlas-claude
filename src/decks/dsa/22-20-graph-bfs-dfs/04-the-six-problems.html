Anchor 1 · LC 200 — the path to the solution

The reframing
An island is a connected component of land cells. Counting islands is counting components, which is the most standard graph question there is.
The algorithm
Scan every cell. On finding unvisited land, increment the counter and traverse its entire component, marking as you go. Every land cell is then visited exactly once across the whole run.
Why the count is right
The counter increments only at the first cell of each component, because every other cell of that component is marked before the scan reaches it.
The space saving
Overwrite '1' with '0' instead of keeping a boolean[][]. The existing land test then doubles as the visited test. State that you are mutating the input.
DFS or BFS
Either works — the question is about connectivity, not distance. DFS is shorter; BFS avoids deep recursion on a large grid.
Edge cases
An empty grid returns 0. The grid is character-based, so compare against '1', not 1.
LC 200 · O(mn) time, O(mn) space worst case
class Solution {
    private static final int[][] DIRS = {{1,0},{-1,0},{0,1},{0,-1}};

    public int numIslands(char[][] grid) {
        int count = 0;

        for (int r = 0; r < grid.length; r++) {
            for (int c = 0; c < grid[0].length; c++) {
                if (grid[r][c] == '1') {
                    // First cell of a new component — everything else
                    // in it gets marked before the scan reaches it.
                    count++;
                    sink(grid, r, c);
                }
            }
        }
        return count;
    }

    private void sink(char[][] g, int r, int c) {
        // One guard: out of bounds, water, or already visited.
        if (r < 0 || r >= g.length || c < 0 || c >= g[0].length) return;
        if (g[r][c] != '1') return;

        g[r][c] = '0';        // mark — never undone, unlike backtracking

        for (int[] d : DIRS) sink(g, r + d[0], c + d[1]);
    }
}

Anchor 2 · LC 994 — the path to the solution

Why not DFS
The question asks for elapsed time, which is a shortest distance. DFS may reach a cell by a long route and record that, so it is wrong rather than slow.
Why not one BFS per source
That is O(sources × cells) and needs a minimum across runs. Unnecessary work.
Multi-source BFS
Seed every rotten orange into the queue before the loop starts. A single pass then reaches each cell from its nearest source, because all sources expand in lockstep.
Time from levels
One BFS level is one minute. The size snapshot separates the levels, exactly as in a level-order tree traversal.
The two details
Count fresh oranges up front and decrement as they rot, so a leftover non-zero count means unreachable cells and the answer is −1. And guard the minute increment with fresh > 0, or the final drain level adds a phantom minute.
Edge case
Zero fresh oranges at the start returns 0 immediately, even if there are no rotten ones at all.
LC 994 · O(mn) time, O(mn) space
class Solution {
    private static final int[][] DIRS = {{1,0},{-1,0},{0,1},{0,-1}};

    public int orangesRotting(int[][] grid) {
        Queue<int[]> q = new ArrayDeque<>();
        int fresh = 0;

        // Seed EVERY source before the loop — that is what makes one
        // pass compute the distance to the nearest source.
        for (int r = 0; r < grid.length; r++)
            for (int c = 0; c < grid[0].length; c++) {
                if (grid[r][c] == 2)      q.offer(new int[]{r, c});
                else if (grid[r][c] == 1) fresh++;
            }

        int minutes = 0;

        // `fresh > 0` stops the loop before a level that rots nothing,
        // so the counter is never inflated by the final drain.
        while (!q.isEmpty() && fresh > 0) {
            int size = q.size();          // one level == one minute

            for (int i = 0; i < size; i++) {
                int[] cur = q.poll();

                for (int[] d : DIRS) {
                    int nr = cur[0] + d[0], nc = cur[1] + d[1];

                    if (nr < 0 || nr >= grid.length) continue;
                    if (nc < 0 || nc >= grid[0].length) continue;
                    if (grid[nr][nc] != 1) continue;

                    grid[nr][nc] = 2;     // mark on ENQUEUE
                    fresh--;
                    q.offer(new int[]{nr, nc});
                }
            }
            minutes++;
        }
        return fresh == 0 ? minutes : -1;   // leftovers were unreachable
    }
}

733 · Flood Fill DFS

Path: recolour the connected region sharing the starting colour. The bare traversal with a colour test as the guard.

Delta: almost none — but there is one real trap. If the new colour equals the starting colour, marking changes nothing and the recursion never terminates.

Watch for: guard with if (image[sr][sc] == color) return image; before starting. It is the single line that separates a passing solution from an infinite loop.

695 · Max Area of Island DFS

Path: identical to LC 200, except the traversal reports how many cells it visited.

Delta: make sink return 1 + the sum of its four recursive calls, and take the maximum across all starts.

Watch for: the base cases must return 0, not simply return. Writing 200 and 695 as one function that returns a size, and ignoring the result in 200, covers both problems with one piece of code.

1254 · Number of Closed Islands DFS + border

Path: a closed island touches no edge. Tracking that flag during each traversal works but is fiddly — a cleaner approach removes the disqualified components first.

Delta: flood every component reachable from a border cell, then count what remains. Any surviving component is closed by construction.

Watch for: the polarity is inverted here — 0 is land and 1 is water, the opposite of LC 200. Reading that from the statement is most of the difficulty.

1091 · Shortest Path in Binary Matrix BFS

Path: shortest path in an unweighted grid, so BFS from the top-left corner, counting levels until the bottom-right is reached.

Delta: the statement says 8-directionally connected, so DIRS has eight entries including the diagonals. Using four silently returns a longer path or −1.

Watch for: check that both the start and the end cells are 0 before beginning. A blocked start is a valid input and must return −1 rather than throwing. Path length counts cells, so the start counts as 1.

If you only drill twoDo 200 and 994. 200 fixes the component-counting shape that 695 and 1254 reuse almost verbatim. 994 teaches multi-source BFS and level-as-time, which is the idea that turns a whole class of "how long until everything is X" problems into a single pass — and the two off-by-ones it contains are the ones interviewers watch for.
