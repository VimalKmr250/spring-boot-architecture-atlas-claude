Anchor 1 · LC 64 — the path to the solution

Why greedy fails
Taking the cheaper neighbour at each step gives 9 on the traced grid instead of 7 — a cheap early cell leads into an expensive region. Say this first; it is the justification for the DP.
Brute force
Recurse over both moves. Exponential, and it recomputes the same cells repeatedly — which is the signal that memoisation applies.
The state
dp[r][c] = the cheapest cost to reach (r, c) from the start. Reach, not "from here onward" — either works, but mixing them mid-solution does not.
The transition
Only two cells reach (r, c), so the cost is grid[r][c] + min(above, left).
Base cases
The top row and left column have exactly one predecessor each, so they are running sums. Fill them before the main loops — padding with zeros would break a minimisation.
Space
Only the previous row is read, so one array of width cols suffices. Overwriting the input grid gives O(1) — a good option to mention, with the caveat that it mutates the caller's data.
LC 64 · O(mn) time, O(cols) space
class Solution {
    public int minPathSum(int[][] grid) {
        int rows = grid.length, cols = grid[0].length;

        // One rolling row: dp[c] holds the row above until it is
        // overwritten, and dp[c-1] already holds the current row.
        int[] dp = new int[cols];

        // Top row: only reachable from the left, so it accumulates.
        dp[0] = grid[0][0];
        for (int c = 1; c < cols; c++) dp[c] = dp[c - 1] + grid[0][c];

        for (int r = 1; r < rows; r++) {
            // Left column: only reachable from above.
            dp[0] += grid[r][0];

            for (int c = 1; c < cols; c++) {
                // dp[c]     is still the row ABOVE (not yet written)
                // dp[c - 1] is already the row LEFT (written this round)
                dp[c] = grid[r][c] + Math.min(dp[c], dp[c - 1]);
            }
        }
        return dp[cols - 1];
    }
}

Anchor 2 · LC 221 — the path to the solution

Brute force
For every cell, try every square size and verify it. O((mn)²) or worse.
The state that works
dp[r][c] = the side length of the largest square whose bottom-right corner is at (r, c)). Fixing the corner is what makes the recurrence expressible — a "largest square anywhere in the sub-grid" state has no usable transition.
The transition
A square of side k+1 ending here requires squares of side k ending at the cell above, the cell to the left, and the diagonal. So the minimum of those three limits it: dp = 1 + min(three).
Why the diagonal is needed
Up and left alone would allow an L-shape with a hole at the corner. The diagonal is what guarantees the interior is filled.
The answer
The maximum over every cell, not the bottom-right one — the largest square can end anywhere. And the question asks for the area, so square the side.
Edge cases
The matrix holds char values, so compare against '1'. The first row and column are 0 or 1 directly, since no larger square can end there.
LC 221 · O(mn) time, O(cols) space
class Solution {
    public int maximalSquare(char[][] matrix) {
        int rows = matrix.length, cols = matrix[0].length;

        // dp[c] = side length of the largest square ending at (r, c).
        int[] dp = new int[cols + 1];    // +1 so c-1 is always valid
        int best = 0;
        int diagonal = 0;                // dp[c-1] from the PREVIOUS row

        for (int r = 0; r < rows; r++) {
            diagonal = 0;                // reset at the start of each row

            for (int c = 1; c <= cols; c++) {
                int savedAbove = dp[c];  // dp[c] is still the row above

                if (matrix[r][c - 1] == '1') {
                    // A square of side k+1 needs three squares of side k
                    // meeting here. The DIAGONAL is what forbids an
                    // L-shape with a hollow corner.
                    dp[c] = 1 + Math.min(diagonal,
                                Math.min(savedAbove, dp[c - 1]));
                    best = Math.max(best, dp[c]);
                } else {
                    dp[c] = 0;           // a zero cell ends no square
                }
                diagonal = savedAbove;   // becomes the diagonal for c+1
            }
        }
        return best * best;              // the AREA, not the side
    }
}

62 · Unique Paths counting

Path: paths into a cell are paths from above plus paths from the left, since those are the only two ways in. Pure addition, no choice.

Delta: the transition is dp[c] += dp[c-1] on a rolling row initialised to all 1s — the top row has exactly one path to each cell.

Watch for: there is a closed form. Every path makes m−1 downs and n−1 rights in some order, so the answer is C(m+n−2, m−1) — O(min(m,n)) and worth naming even if you code the DP.

63 · Unique Paths II counting + obstacles

Path: identical to 62 with blocked cells. An obstacle is simply a cell no path can occupy.

Delta: set dp[c] = 0 at an obstacle. Every downstream cell then adjusts automatically — no special casing is needed beyond that one assignment.

Watch for: the first row and column must stop accumulating at the first obstacle, not skip past it. Everything beyond a blocked edge cell is unreachable, and handling that is where this problem actually differs from 62.

931 · Minimum Falling Path Sum three below

Path: a falling path starts anywhere in the top row and steps to one of three cells below each time.

Delta: the transition widens to grid[r][c] + min(dp[c−1], dp[c], dp[c+1]) on the row above, with the edge columns having only two options.

Watch for: guard the column bounds, or use sentinel padding on both sides. Any starting column is allowed, so the answer is the minimum of the final row — not a single cell.

120 · Triangle two below

Path: a triangle where row r has r+1 entries and you may step to index c or c+1 below.

Delta: work bottom-up. Start with the last row and fold upward: dp[c] = triangle[r][c] + min(dp[c], dp[c+1]). The answer ends up in dp[0].

Watch for: bottom-up is not just tidier — it makes c+1 always valid, removing every bounds check. Top-down needs them at both edges of every row, which is where the bugs live.

If you only drill twoDo 64 and 221. 64 fixes the two-predecessor transition and the rolling-row space collapse that 62, 63, 931 and 120 all reuse. 221 is the one that teaches state design in this family — realising that you must anchor the square at a corner to get a usable recurrence is the same move that makes several harder grid problems tractable.
