Anchor 1 · LC 45 — the path to the solution

Brute force
Try every jump length from every index. Exponential, then O(n²) with memoisation — a fine first answer.
The reframing
This is a shortest-path problem on an unweighted graph, so BFS gives the minimum. Each BFS layer is a contiguous band of indices, because reachability from a band is an interval.
What that buys
Contiguous layers need no queue. Scan left to right, track the furthest reach of the current band, and advance the band boundary when you hit its edge.
Why you never choose an index
The scan visits every index in the band before committing, so it already has the best reach available. There is no decision to make — which is why the code has no max over candidates beyond the running one.
The off-by-one
Loop to n − 2. Arriving at the last index ends the journey; counting a jump from it inflates the answer by one.
Edge cases
A single-element array needs 0 jumps, which the loop bound handles for free. The problem guarantees the end is reachable, so no failure path is needed.
LC 45 · O(n) time, O(1) space
class Solution {
    public int jump(int[] nums) {
        int jumps = 0;
        int bandEnd = 0;     // last index reachable with `jumps` jumps
        int farthest = 0;    // furthest anything in this band can reach

        // n - 1: arriving at the last index finishes the journey,
        // so we never jump FROM it.
        for (int i = 0; i < nums.length - 1; i++) {

            farthest = Math.max(farthest, i + nums[i]);

            // Reached the edge of the current band, so the next step
            // must cost one more jump. `farthest` is the true limit
            // of that next band, since we scanned the whole band.
            if (i == bandEnd) {
                jumps++;
                bandEnd = farthest;
            }
        }
        return jumps;
    }
}

Anchor 2 · LC 134 — the path to the solution

Brute force
Try every station as a start and simulate the full circuit. O(n²), and the natural first attempt.
Claim one — existence
If sum(gas) < sum(cost) no start can work, because the circuit is a closed loop and the total deficit is start-independent. If the total is non-negative, a valid start must exist.
Claim two — location
Suppose you start at s and run dry arriving at i. Then no station between s and i works either: each such start reaches i with less fuel than you had, since your running balance was non-negative throughout that stretch.
What that buys
On failure you skip the entire prefix in one move — restart at i + 1 rather than s + 1. So each station is examined once and the scan is O(n).
Why one pass proves it
The final candidate is the only one never invalidated, and claim one guarantees some start works. Therefore that candidate is the answer — no verification pass is needed.
Edge cases
Return −1 when the total is negative. The answer is unique, as the problem states, which is what makes the single candidate safe.
LC 134 · O(n) time, O(1) space
class Solution {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int total = 0;      // whole-loop surplus: decides EXISTENCE
        int tank = 0;       // running surplus since the candidate start
        int start = 0;

        for (int i = 0; i < gas.length; i++) {
            int diff = gas[i] - cost[i];
            total += diff;
            tank  += diff;

            if (tank < 0) {
                // Ran dry arriving at i. Every station from `start`
                // to i also fails — each would reach i with even less
                // fuel, because tank was non-negative all the way here.
                // So skip the whole prefix in one move.
                start = i + 1;
                tank = 0;
            }
        }
        // Non-negative total guarantees a solution exists, and `start`
        // is the only candidate never invalidated.
        return total >= 0 ? start : -1;
    }
}

55 · Jump Game skeleton A

Path: the DP marks each index reachable or not in O(n²). The greedy needs only the frontier.

Delta: track farthest; if i > farthest you have hit a gap you cannot cross, so return false. Otherwise extend and continue.

Watch for: "always take the biggest jump" is not correct here — a large jump can overshoot a launchpad. The frontier is what works, and knowing why the obvious greedy fails is the point of the problem.

763 · Partition Labels skeleton A

Path: a letter must live entirely inside one part, so a part cannot end before the last occurrence of any letter it contains.

Delta: record each letter's last index in one pass. Then sweep, extending end = max(end, last[c]); when i == end, cut. The frontier is over last-occurrences instead of jump reaches.

Watch for: the part length is i − start + 1, and start must be reset to i + 1 after each cut.

406 · Queue Reconstruction by Height skeleton B

Path: trying orderings is factorial. The insight is choosing a processing order in which each placement is forced.

Delta: sort tallest first, ties by ascending k. Insert each person at index k. Because everyone already placed is at least as tall, inserting at k puts exactly k taller-or-equal people in front — and later, shorter insertions are invisible to them, so no earlier placement is ever disturbed.

Watch for: List.add(index, element) is O(n) per insert, giving O(n²) overall. That is accepted; say so rather than reaching for something exotic.

621 · Task Scheduler skeleton C

Path: simulating with a max-heap and a cooldown queue works and is O(n log 26) — a correct answer worth stating. The closed form is better and much shorter.

Delta: the most frequent task forces (maxFreq − 1) blocks of width (n + 1), plus a tail of every task tied at maxFreq. Take max(bound, tasks.length).

Watch for: the max with tasks.length is essential — when there are many distinct tasks the gaps are already full and no idling occurs, so the bound underestimates.

If you only drill twoDo 45 and 134. 45 teaches the frontier and the layered-BFS view that also solves 55 and 763. 134 is the one where the code is eight lines and the argument is the whole problem — and being able to give both claims out loud is exactly what an interviewer is probing for when they ask why a greedy is safe.
