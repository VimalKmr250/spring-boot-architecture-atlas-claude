Six recurrences, three shapes

70, 198 and 213 have fixed lookback. 322 and 279 are unbounded choice over a target. 300 is the one that needs the "ending here" state — and it is the one people get wrong.

Anchor 1 · LC 198 — the path to the solution

Why greedy fails
"Take every other house" gives 2 + 9 + 1 = 12 here by luck, but on [2,1,1,2] it takes 2 + 1 = 3 while the optimum is 2 + 2 = 4. The choice at each house depends on the whole future, so it must be compared rather than guessed.
The state
dp[i] = the most you can rob considering the first i houses. Not "having robbed house i" — the prefix form is what makes the recurrence two-way.
The transition
Two options only. Skip house i, so the answer is dp[i−1]. Take it, which forbids house i−1, so the answer is dp[i−2] + nums[i]. Take the larger.
Base cases
dp[0] = nums[0], and dp[1] = max(nums[0], nums[1]). Handling those before the loop avoids negative indices.
The answer
dp[n−1], because the prefix state is non-decreasing — skipping is always available, so later cells can never be worse.
Space
Only two previous cells are read, so two variables suffice. Write the array version first, verify, then collapse it.
LC 198 · O(n) time, O(1) space
class Solution {
    public int rob(int[] nums) {
        // dp[i-2] and dp[i-1], rolled into two variables.
        // Starting both at 0 makes the first iteration correct:
        // cur = max(0, 0 + nums[0]) = nums[0].
        int prev2 = 0, prev1 = 0;

        for (int v : nums) {
            // SKIP house i: the answer is unchanged  -> prev1
            // TAKE house i: house i-1 is then forbidden, so build
            //               on the answer from two back -> prev2 + v
            int cur = Math.max(prev1, prev2 + v);

            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

Anchor 2 · LC 300 — the path to the solution

The state that does not work
"The longest increasing subsequence within the first i elements." You cannot extend it, because you do not know what it ends with — and without that, the transition is unwritable.
The state that does
dp[i] = the longest increasing subsequence ending exactly at index i. Now extension is decidable: any earlier j with a smaller value can be extended by i.
The transition
dp[i] = 1 + max(dp[j]) over all j < i with nums[j] < nums[i], defaulting to 1 when none qualifies. That inner scan is what makes it O(n²).
The answer
max(dp), not dp[n−1]. The "ending here" state is not monotone — the longest subsequence may end anywhere.
The O(n log n) version
Keep tails, where tails[k] is the smallest possible tail of a length-(k+1) subsequence. Binary search each value's position and overwrite. The list's length is the answer.
The caveat worth stating
tails is not itself a valid subsequence — only its length is meaningful. Claiming otherwise is a common mistake, and interviewers check for it.
LC 300 · O(n²) time, O(n) space — with the O(n log n) form below
class Solution {
    public int lengthOfLIS(int[] nums) {
        // dp[i] = longest increasing subsequence ENDING AT i.
        // The "ending at" part is essential: without it you cannot
        // decide whether a later element extends the sequence.
        int[] dp = new int[nums.length];
        Arrays.fill(dp, 1);              // every element alone has length 1

        int best = 1;

        for (int i = 1; i < nums.length; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            // "ending at i" is NOT monotone, so track the running max.
            best = Math.max(best, dp[i]);
        }
        return best;                     // NOT dp[n-1]
    }

    // O(n log n): tails[k] is the SMALLEST tail among increasing
    // subsequences of length k+1. Not a real subsequence — but its
    // length is exactly the answer.
    public int lengthOfLISFast(int[] nums) {
        int[] tails = new int[nums.length];
        int size = 0;

        for (int v : nums) {
            int lo = 0, hi = size;
            while (lo < hi) {                    // first index with tails[i] >= v
                int mid = lo + (hi - lo) / 2;
                if (tails[mid] < v) lo = mid + 1;
                else                hi = mid;
            }
            tails[lo] = v;
            if (lo == size) size++;              // v extended the longest run
        }
        return size;
    }
}

70 · Climbing Stairs shape A

Path: to reach step i you arrived from i−1 or i−2, so the ways add: dp[i] = dp[i−1] + dp[i−2]. It is Fibonacci with different base cases.

Delta: the simplest recurrence in the deck, and the right place to practise the four questions before anything harder.

Watch for: dp[0] = 1 — there is exactly one way to be at the bottom, namely doing nothing. Setting it to 0 makes every subsequent value wrong.

213 · House Robber II shape A ×2

Path: the circle means house 0 and house n−1 are adjacent, so they can never both be taken.

Delta: that single fact splits the problem cleanly. Run the linear solver on [0, n−2] and on [1, n−1], and take the larger. Every valid selection is covered by one of the two ranges.

Watch for: a single house must be special-cased — both ranges would be empty and return 0, losing the only available answer.

322 · Coin Change shape B

Path: greedy — take the largest coin that fits — is wrong. With coins [1,3,4] and amount 6, greedy gives 4+1+1 = 3 coins while the optimum is 3+3 = 2. Saying that out loud is what justifies the DP.

Delta: dp[t] = min over coins c of dp[t−c] + 1, with dp[0] = 0. Every coin is tried at every amount.

Watch for: use amount + 1 as the unreachable sentinel, not Integer.MAX_VALUE — adding 1 to MAX_VALUE wraps negative and wins the min.

279 · Perfect Squares shape B

Path: this is coin change where the coin denominations are 1, 4, 9, 16, …. Recognising that is the whole problem.

Delta: the same recurrence with the inner loop running j*j <= t. There are about √n squares below n, so the total is O(n√n).

Watch for: a BFS over amounts — each level being one more square — is an equally good solution and often finds the answer faster in practice, since the result is at most 4 by Lagrange's theorem.

If you only drill twoDo 198 and 300. 198 gives you the take-or-skip transition and the space collapse, which cover 70, 213 and much of what follows. 300 is the one that forces the state-definition discipline: the prefix form simply cannot express the recurrence, and discovering why is what teaches you to interrogate your state before writing any code.
