Drain the queue one level at a time

A plain queue traversal visits nodes in level order but loses the level boundaries. The entire pattern is one line that recovers them: capture the queue's size before the inner loop. That snapshot is exactly one level, because everything added during the loop belongs to the next.

The invariant

At the top of each outer iteration, the queue contains precisely one complete level and nothing else.

So int size = queue.size() is the width of that level. Dequeuing exactly size nodes processes it fully, and the children enqueued during those size steps form the next level — restoring the invariant automatically.

Reading queue.size() inside the loop instead destroys this: the size grows as children are added, and the levels smear into one another.

What the level gives you

Once you can process a level as a unit, a whole family of questions becomes trivial variations on where you put one line:

  • The level's list — collect every value as you dequeue.
  • The last node of each level — the right-side view.
  • The level's max or average — fold over the level.
  • Alternating direction — reverse every other level, or push to the front.
  • The first level satisfying a condition — BFS finds the shallowest, which DFS cannot promise.

Applies when

The answer is organised by level, or you need the shallowest node satisfying something. BFS reaches nodes in non-decreasing depth order, which is a guarantee a depth-first traversal cannot make.

Does not apply when

The answer depends on subtree structure — depths, path sums, shapes. Those compose naturally bottom-up, which is a depth-first job; forcing them into BFS means rebuilding the tree in the queue.

Complexity

O(n) time — every node is enqueued and dequeued once. Space is O(w) where w is the widest level, which for a complete tree is about n/2. That is worse than DFS's O(h) and worth stating.
