One loop, and a single line that changes per problem

The skeleton is identical across all six problems. What differs is which node of the drained level you keep, and whether the collected list gets reversed.

The template — level order
/**
 * INVARIANT: at the top of each outer iteration the queue holds
 * exactly one complete level.
 *
 * The size SNAPSHOT is the whole pattern — capture it before the
 * inner loop, because the queue grows as children are enqueued.
 */
List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> out = new ArrayList<>();
    if (root == null) return out;                 // empty tree, empty answer

    Queue<TreeNode> q = new ArrayDeque<>();       // ArrayDeque, not LinkedList
    q.offer(root);

    while (!q.isEmpty()) {
        int size = q.size();                      // SNAPSHOT — never read live
        List<Integer> level = new ArrayList<>(size);

        for (int i = 0; i < size; i++) {
            TreeNode node = q.poll();
            level.add(node.val);

            // Filter nulls HERE, so the snapshot stays meaningful.
            if (node.left  != null) q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
        out.add(level);
    }
    return out;
}

Variant · O(1) space using the links you just built (LC 116)
// The queue costs O(w) space. But once a level's `next` pointers
// exist, that level is ITSELF a linked list — so you can walk it
// without a queue and wire up the level below.
Node connect(Node root) {
    Node leftmost = root;

    while (leftmost != null && leftmost.left != null) {
        // Walk the current level using the next pointers already set.
        for (Node head = leftmost; head != null; head = head.next) {

            head.left.next = head.right;              // within this node

            // Across the gap to the neighbour's subtree — this is
            // the step that needs the level's own next pointer.
            if (head.next != null) {
                head.right.next = head.next.left;
            }
        }
        leftmost = leftmost.left;                     // drop one level
    }
    return root;
}

The knobs

What you keep
All values, the last one, a running max, or a running sum. That single line is usually the entire difference between two problems in this family.
Direction
For zigzag, either reverse alternate levels afterwards or use addFirst on a LinkedList. The second is O(1) per insert and avoids a second pass.
Queue type
ArrayDeque, not LinkedList — faster and it rejects null elements, which surfaces a null-enqueue bug immediately instead of silently.
Null root
Return the empty answer before touching the queue. Enqueuing a null root throws on ArrayDeque.
Accumulator width
long or double for level sums. LC 637 has a test case that overflows int precisely here.
The three bugs that actually happenReading q.size() inside the inner loop — the levels merge, because the size grows as children are added. This breaks every problem in the pattern in the same way. Enqueuing nulls — the snapshot then counts phantom nodes, so level widths are wrong, and ArrayDeque throws outright. Summing level values in an int — LC 637's test set includes values near Integer.MAX_VALUE, and the average comes back negative.
