One heap loop, and three ways to change what "shorter" means

The skeleton is fixed. What varies is the comparator, how costs combine, and whether the state needs an extra dimension for a constraint.

Dijkstra — the template
/**
 * Shortest distances from `src`. Requires NON-NEGATIVE weights:
 * the correctness argument is that a popped node can never be
 * improved by anything still in the queue.
 *
 * Lazy deletion: Java's PriorityQueue cannot decrease a key, so we
 * push a new entry and skip the stale one when it surfaces.
 */
int[] dijkstra(int n, List<int[]>[] adj, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;

    // (node, distance), ordered by distance
    PriorityQueue<int[]> pq =
            new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
    pq.offer(new int[]{src, 0});

    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int node = cur[0], d = cur[1];

        // STALE: a better route to this node was already recorded.
        if (d > dist[node]) continue;

        for (int[] e : adj[node]) {
            int next = e[0], w = e[1];
            int cand = d + w;

            if (cand < dist[next]) {
                dist[next] = cand;
                pq.offer(new int[]{next, cand});   // push, never update
            }
        }
    }
    return dist;
}

Bellman-Ford — when a constraint bounds the hops (LC 787)
/**
 * "At most k stops" breaks Dijkstra's invariant: a MORE expensive
 * route that uses fewer stops may still win later, so a single
 * distance per node is not enough information.
 *
 * Bellman-Ford relaxes every edge k+1 times. After round r, dist[]
 * holds the cheapest cost reachable using AT MOST r edges — so the
 * hop limit falls out of the round count for free.
 */
int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;

    for (int round = 0; round <= k; round++) {
        // Relax from a SNAPSHOT: without it, a route found earlier in
        // this same round could be extended again, using more than
        // `round + 1` edges and breaking the hop bound.
        int[] prev = dist.clone();

        for (int[] f : flights) {
            int from = f[0], to = f[1], price = f[2];
            if (prev[from] == Integer.MAX_VALUE) continue;

            dist[to] = Math.min(dist[to], prev[from] + price);
        }
    }
    return dist[dst] == Integer.MAX_VALUE ? -1 : dist[dst];
}

Choosing the algorithm

Unweighted
Plain BFS. A priority queue is wasted effort when every edge costs 1.
Non-negative weights
Dijkstra. O(E log E), and the default choice.
A hop or step limit
Bellman-Ford with the round count as the limit, or Dijkstra over (node, stepsUsed) states.
All pairs, small V
Floyd–Warshall. Three nested loops, O(V³), and trivial to write correctly when V ≤ 100.
Minimax rather than sum
Dijkstra with max in place of +. Union-find with sorted edges also solves these, and is worth naming.
The three bugs that actually happenOverflow when relaxing — dist[u] + w overflows when dist[u] is Integer.MAX_VALUE; skip unreachable nodes first, or use a large finite sentinel. Omitting the stale skip — still correct, but finalised nodes are re-expanded and the solution times out on dense graphs. Relaxing in place in Bellman-Ford — without the clone(), one round can chain several edges and the hop limit is silently violated, which is the classic LC 787 wrong answer.
