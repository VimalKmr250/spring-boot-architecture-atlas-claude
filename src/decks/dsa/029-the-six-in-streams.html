A list is already a stream; two pointers are one record

Stream.iterate(head, Objects::nonNull, x -> x.next) turns any list into a stream of its nodes. Two pointers moving at different speeds become a record whose step method moves both, and filter(…).findFirst() stops on the state you are after: the meeting point, the middle, or the node before the one to delete. Five of the six keep the loop's O(1) space. Only the palindrome check copies the values out.

LC 876 · Middle of the Linked List · clean
class Solution {
    record Ptrs(ListNode slow, ListNode fast) {
        boolean canStep() {
            return fast != null && fast.next != null;
        }
        Ptrs step() {
            return new Ptrs(slow.next, fast.next.next);
        }
    }

    public ListNode middleNode(ListNode head) {
        // Slow moves one node, fast two. The first state where
        // fast cannot move again has slow on the middle. step()
        // only ever runs on states that failed the filter.
        return Stream.iterate(new Ptrs(head, head), Ptrs::step)
                .filter(p -> !p.canStep())
                .findFirst().get().slow();
    }
}
LC 141 · Linked List Cycle · clean
class Solution {
    record Ptrs(ListNode slow, ListNode fast) {
        boolean canStep() {
            return fast != null && fast.next != null;
        }
        Ptrs step() {
            return new Ptrs(slow.next, fast.next.next);
        }
    }

    public boolean hasCycle(ListNode head) {
        // Floyd: in a cycle, fast gains a node per step, so it
        // must land on slow. With no cycle, fast hits the end,
        // canStep() fails, and the stream simply stops.
        return Stream.iterate(new Ptrs(head, head),
                              Ptrs::canStep, Ptrs::step)
                .skip(1)
                .anyMatch(p -> p.slow() == p.fast());
    }
}
LC 142 · Linked List Cycle II · clean
class Solution {
    // a always moves 1 node; b moves 2 in phase 1, 1 in phase 2
    record P(ListNode a, ListNode b) {
        boolean met() { return a == b; }
        boolean canRun() { return b != null && b.next != null; }
        P run() { return new P(a.next, b.next.next); }
        P walk() { return new P(a.next, b.next); }
    }

    public ListNode detectCycle(ListNode head) {
        // Phase 1: Floyd finds a meeting point in the cycle.
        ListNode meet = Stream.iterate(new P(head, head),
                                       P::canRun, P::run)
                .skip(1)
                .filter(P::met)
                .findFirst().map(P::a).orElse(null);
        if (meet == null) return null;
        // Phase 2: from head and from the meeting point, at
        // equal speed, the pointers meet exactly at the entry.
        return Stream.iterate(new P(head, meet), P::walk)
                .filter(P::met)
                .findFirst().get().a();
    }
}
LC 19 · Remove Nth Node From End of List · clean
class Solution {
    // fast first opens a lead of n + 1, then both walk together
    record Gap(ListNode slow, ListNode fast, int lead) {
        Gap step(int n) {
            return lead <= n
                    ? new Gap(slow, fast.next, lead + 1)
                    : new Gap(slow.next, fast.next, lead);
        }
    }

    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        // When fast falls off the end, slow is n + 1 behind it:
        // on the node just before the one to remove.
        Gap end = Stream.iterate(new Gap(dummy, dummy, 0),
                                 g -> g.step(n))
                .filter(g -> g.fast() == null)
                .findFirst().get();
        end.slow().next = end.slow().next.next;
        return dummy.next;
    }
}
LC 160 · Intersection of Two Linked Lists · clean
class Solution {
    record P(ListNode a, ListNode b) {
        // at its list's end, each pointer jumps to the other
        P next(ListNode headA, ListNode headB) {
            return new P(a == null ? headB : a.next,
                         b == null ? headA : b.next);
        }
    }

    public ListNode getIntersectionNode(ListNode headA,
                                        ListNode headB) {
        // Both pointers walk m + n nodes, so they line up on
        // the shared tail, or on null together if there's none.
        return Stream.iterate(new P(headA, headB),
                              p -> p.next(headA, headB))
                .filter(p -> p.a() == p.b())
                .findFirst().get().a();
    }
}
LC 234 · Palindrome Linked List · clean
class Solution {
    public boolean isPalindrome(ListNode head) {
        // Copy the values out, then compare mirrored pairs.
        // int[], not List<Integer>: == on boxed values past 127
        // compares references.
        int[] v = Stream.iterate(head, Objects::nonNull,
                                 x -> x.next)
                .mapToInt(x -> x.val)
                .toArray();
        return IntStream.range(0, v.length / 2)
                .allMatch(i -> v[i] == v[v.length - 1 - i]);
    }
}
Why fast.next.next never throws hereOn an infinite Stream.iterate(seed, f), filter(test).findFirst() applies f only to states that failed the test. So a step that would throw on the last state is safe, because the last state is the one the filter returns. The three-argument form applies its step once more on the last state it emits, so there (141, 142) the step must be safe on every state that passes hasNext, and canStep guarantees exactly that.
Where streams stop234's O(1)-space answer reverses the second half in place, and every problem in the linked-list pattern later in this deck is that kind of pointer surgery. A stream can walk the nodes and work out where each should go, but it must not rewire them while it walks: that is interference with its own source. It computes an order, and the rewiring happens once, afterwards.
