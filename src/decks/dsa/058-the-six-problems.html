Anchor 1 · LC 739 — the path to the solution

Brute force
For each day, scan forward for the first warmer one. O(n²), which at n = 10⁵ is 10¹⁰ and hopeless.
What the brute force wastes
On a long cold spell, every day rescans the same run of cold days. The scan is repeatedly re-deriving something already known.
The observation
If day j is warmer than day i and comes after it, then day i can never be the answer for anything to the right of j — j is closer and warmer. So i can be discarded permanently the moment j appears.
What "discard" means
A stack of days still waiting, kept decreasing in temperature. Each arriving day pops everything it beats, settling those answers.
Why indices
The answer is how many days, so you need i − poppedIndex. Storing temperatures alone makes that impossible.
Edge case
Days never warmed stay on the stack and keep the 0 default — which is exactly what the problem asks for.
LC 739 · O(n) time, O(n) space
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] ans = new int[n];                    // zeros are the correct default

        // Indices of days still waiting; their temperatures
        // decrease from the bottom of the stack to the top.
        Deque<Integer> stack = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {

            // Today is warmer than the day on top, so that day's
            // wait ends here. Settle it and keep going — today may
            // settle several days at once.
            while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
                int day = stack.pop();
                ans[day] = i - day;                // the distance, hence indices
            }

            stack.push(i);
        }
        // Days left on the stack never warmed: ans stays 0.
        return ans;
    }
}

Anchor 2 · LC 84 — the path to the solution

Brute force
Every pair (l, r), taking the minimum height between them. O(n³), or O(n²) carrying a running minimum.
The reframing
Stop enumerating rectangles. Instead ask, for each bar, what is the widest rectangle whose height is exactly that bar? Every maximal rectangle is limited by its shortest bar, so this enumeration is complete.
What that needs
For each bar, the first shorter bar to its left and the first shorter bar to its right. Those two indices give the width directly.
The insight
Both boundaries fall out of a single pass. When a bar is popped, the arriving element is its right boundary, and the item now exposed on the stack is its left boundary. No second pass is needed.
The sentinel
Iterate to n inclusive with a virtual bar of height 0. It forces every remaining bar to pop with the correct right boundary, removing the drain loop and the bugs that live in it.
Width, carefully
i − left − 1, where left is −1 when the stack empties. Deriving that from the trace once is worth more than memorising it.
LC 84 · O(n) time, O(n) space
class Solution {
    public int largestRectangleArea(int[] heights) {
        int n = heights.length, best = 0;
        Deque<Integer> stack = new ArrayDeque<>();

        // i == n is a VIRTUAL bar of height 0 that drains the stack.
        for (int i = 0; i <= n; i++) {
            int cur = (i == n) ? 0 : heights[i];

            while (!stack.isEmpty() && heights[stack.peek()] >= cur) {
                int height = heights[stack.pop()];

                // Right boundary is i. Left boundary is whatever the
                // pop exposed — or -1 if this bar reaches index 0.
                int left  = stack.isEmpty() ? -1 : stack.peek();
                int width = i - left - 1;

                best = Math.max(best, height * width);
            }
            stack.push(i);
        }
        return best;
    }
}

496 · Next Greater Element I next greater

Path: the nested-loop version is O(n·m) and passes at these limits, so say it first. The point of the problem is the decomposition, not the speed.

Delta: run the template over nums2 to get every element's next greater, storing results in a HashMap<value, answer> — the statement guarantees distinct values, which is what makes keying by value safe. Then map nums1 through it.

Watch for: elements left on the stack have no greater element, so their map entry must be −1. Easiest is to drain the stack after the loop.

503 · Next Greater Element II circular

Path: the naive fix duplicates the array and runs the template on 2n elements. That works and costs O(n) extra space — worth mentioning before the cleaner version.

Delta: loop i from 0 to 2n and index with i % n. Push only while i < n: the second pass exists solely to settle leftovers, and pushing again would let elements wait forever.

Watch for: the answer here is the value, not the distance, so record a[j] rather than j.

901 · Online Stock Span previous greater

Path: keeping every price and scanning back is O(n) per call, O(n²) overall. The span is really "distance to the previous greater price", which is this pattern in streaming form.

Delta: the stack is a field, surviving between calls. Push (price, span) pairs; when popping, absorb the popped span into your own — that merged count is what makes the amortised O(1) work without storing the whole history.

Watch for: pop while topPrice <= price, inclusive. The problem counts days with a price equal to today's as part of the span.

85 · Maximal Rectangle rectangle × rows

Path: enumerating all sub-rectangles is O((rows·cols)²). The reduction is the whole problem: treat each row as the base of a histogram whose bar heights are the counts of consecutive 1s above.

Delta: maintain one heights[] array across rows — heights[c] = matrix[r][c] == '1' ? heights[c] + 1 : 0 — and call the LC 84 routine on it after each row.

Watch for: the reset to 0 on a '0' cell is what makes the histogram correct; incrementing unconditionally silently merges rectangles across gaps. Solve 84 first — this problem is unreasonable without it.

If you only drill twoDo 739 and 84. 739 makes the push-once-pop-once argument concrete and forces you to store indices. 84 is where the pattern earns its reputation: the realisation that a single pop yields both boundaries is the idea that makes the Hard tag disappear, and 85 becomes a ten-line wrapper once you have it.
