Define the state, and the recurrence writes itself

Dynamic programming has a reputation for being hard. It is not — choosing the state is hard, and everything after that is mechanical. Get dp[i] to mean something precise and self-contained, and the transition, the base case and the answer all follow.

The four questions, in order

  1. What does dp[i] mean? Write it as a full English sentence. "The best answer considering the first i items" is usually right; "something about index i" is usually not.
  2. What is the transition? Given all smaller answers, how is dp[i] built? This is normally a choice: take this item, or skip it.
  3. What is the base case? The smallest input where the answer is obvious, not derived.
  4. Which cell is the answer? Often dp[n], but sometimes the maximum over the whole array — and confusing those is a real bug.

If you cannot answer question 1 in one sentence, the state is wrong. Do not proceed to the code.

Ending-here versus considering-first-i

Two state definitions dominate, and they are not interchangeable:

Prefix
"The best over the first i items." Monotone, so the answer is dp[n].
Ending here
"The best among subsequences that end at i." Not monotone, so the answer is max(dp) — this is the form a subsequence problem needs, because you must know what the sequence ends with to extend it.

Picking the prefix form for a subsequence problem is the most common way these go wrong, and the symptom is a recurrence you cannot write.

Applies when

The answer for n is built from answers for smaller inputs, subproblems overlap, and the question asks for a count or an optimum rather than the items themselves.

Does not apply when

You must list every solution — that is enumeration, and DP only carries aggregates. Also when a greedy choice is provably safe, which is simpler and faster.

Complexity

O(n) when each state looks back a constant number of cells, O(n²) when it scans all earlier states, and O(n·target) when the state includes a value. Space collapses to O(1) for fixed-lookback recurrences.

Recognition cues — the literal words in the statement"in how many distinct ways" · "the maximum amount you can rob" · "the fewest number of coins" · "the longest strictly increasing subsequence" · "you cannot take two adjacent" · "return −1 if it cannot be done". The combination of count or optimise with a sequence of decisions is the signature. If the answer is a list rather than a number, it is not this pattern.
