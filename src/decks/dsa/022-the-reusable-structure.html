Three skeletons that cover the whole family

Converging pointers for pairs, a nested wrapper for k-sums, and same-direction read/write pointers for in-place work. The third looks unrelated until you notice it is the same bookkeeping with both pointers moving the same way.

Skeleton A · converging, sum target (LC 167, 15, 16, 18)
// Requires a SORTED array. The comparison drives which side moves.
int[] twoSumSorted(int[] a, int target) {
    int l = 0, r = a.length - 1;

    while (l < r) {
        int sum = a[l] + a[r];

        if (sum == target) return new int[]{ l, r };
        else if (sum < target) l++;   // a[r] was a[l]'s best partner: a[l] is done
        else r--;                     // symmetric
    }
    return new int[]{ -1, -1 };
}
Skeleton B · converging, weaker end (LC 11, 42)
// No sort. The ordering that licenses the discard is the HEIGHT,
// and the value is capped by whichever side is smaller.
int maxArea(int[] h) {
    int l = 0, r = h.length - 1, best = 0;

    while (l < r) {
        best = Math.max(best, Math.min(h[l], h[r]) * (r - l));

        // Discard the shorter side — it cannot do better than
        // what we just measured, because width only shrinks.
        if (h[l] < h[r]) l++; else r--;
    }
    return best;
}
Skeleton C · the k-sum reduction — one core, wrapped k−2 times
/**
 * Every k-sum is the SAME two-pointer core with nested anchors around it.
 * Sort once; each extra nesting level costs one factor of n.
 *
 *   2Sum  O(n)     the core alone
 *   3Sum  O(n^2)   one anchor  + core
 *   4Sum  O(n^3)   two anchors + core
 *
 * The three lines that matter are identical at every level:
 *   skip duplicate anchors, skip duplicate hits, move BOTH pointers on a hit.
 */
List<List<Integer>> kSum(int[] a, long target, int k, int start) {
    List<List<Integer>> out = new ArrayList<>();
    if (start == a.length) return out;

    if (k == 2) {                                  // ---- the core ----
        int l = start, r = a.length - 1;
        while (l < r) {
            long sum = (long) a[l] + a[r];
            if (sum < target)      l++;
            else if (sum > target) r--;
            else {
                out.add(new ArrayList<>(List.of(a[l], a[r])));
                while (l < r && a[l] == a[l + 1]) l++;   // skip duplicate hits
                while (l < r && a[r] == a[r - 1]) r--;
                l++; r--;                                 // BOTH move — one alone re-finds the same pair
            }
        }
        return out;
    }

    for (int i = start; i + k - 1 < a.length; i++) {      // ---- one anchor level ----
        if (i > start && a[i] == a[i - 1]) continue;      // skip duplicate anchors
        for (List<Integer> sub : kSum(a, target - a[i], k - 1, i + 1)) {
            sub.add(0, a[i]);
            out.add(sub);
        }
    }
    return out;
}
Skeleton D · same direction, read and write
// Both pointers move right. `write` marks where the next kept
// element goes; `read` scans. No extra array is ever allocated.
int removeDuplicates(int[] a) {
    if (a.length == 0) return 0;
    int write = 1;

    for (int read = 1; read < a.length; read++) {
        if (a[read] != a[write - 1]) {   // the keep-condition: the only knob
            a[write++] = a[read];
        }
    }
    return write;                        // new logical length
}

Picking the skeleton

Sorted + target
Skeleton A. If the problem gives you the array already sorted, that is a deliberate signal.
Area, water, capacity
Skeleton B. Do not sort — sorting destroys the positions the width depends on.
Find k numbers
Skeleton C. Sort, then wrap. Use long for the running target: 4Sum with values near ±10⁹ overflows int, and that is the most common wrong answer on LC 18.
In place, O(1) space
Skeleton D. The phrase "modify the array in-place" is effectively naming this skeleton.
The three bugs that actually happenMoving only one pointer on an exact hit — the loop re-finds the same pair forever, or emits it twice. Skipping duplicates in the wrong place — the anchor skip uses i > start, not i > 0; getting that wrong drops valid triples that begin with a repeated value. Sorting when position matters — fatal in LC 11 and 42, and it silently returns a plausible wrong number rather than crashing.
