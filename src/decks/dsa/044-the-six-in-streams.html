Hashing is what collectors were built for

Every problem here is a membership test, a count or a grouping, and each of those is one collector: distinct, groupingBy with counting(), or toMap with a merge function. These are the six where a pipeline reads as well as the loop, often better, and none of them pays for it in time.

LC 217 · Contains Duplicate · clean
class Solution {
    public boolean containsDuplicate(int[] nums) {
        // distinct() keeps a hidden HashSet: the loop's O(n) /
        // O(n), minus the early exit on the first repeat.
        return Arrays.stream(nums).distinct().count()
                < nums.length;
    }
}
LC 242 · Valid Anagram · clean
class Solution {
    public boolean isAnagram(String s, String t) {
        // Equal letter counts. codePoints() also answers the
        // Unicode follow-up: a char is not a code point.
        return counts(s).equals(counts(t));
    }

    private static Map<Integer, Long> counts(String s) {
        return s.codePoints().boxed()
                .collect(Collectors.groupingBy(
                        c -> c, Collectors.counting()));
    }
}
LC 1 · Two Sum · clean
class Solution {
    public int[] twoSum(int[] nums, int target) {
        int n = nums.length;
        // value -> the LAST index holding it. Two passes, so
        // the probe-before-insert trap cannot happen: on [3,3]
        // the first 3 finds the second 3's index, not its own.
        Map<Integer, Integer> last = IntStream.range(0, n)
                .boxed()
                .collect(Collectors.toMap(i -> nums[i], i -> i,
                                          (a, b) -> b));
        // the partner's index, or i itself when there is none
        IntUnaryOperator mate =
                i -> last.getOrDefault(target - nums[i], i);
        int i = IntStream.range(0, n)
                .filter(k -> mate.applyAsInt(k) != k)
                .findFirst().getAsInt();
        return new int[]{ i, mate.applyAsInt(i) };
    }
}
LC 49 · Group Anagrams · clean
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        // All the work is the key; groupingBy does the rest.
        return new ArrayList<>(Arrays.stream(strs)
                .collect(Collectors.groupingBy(Solution::key))
                .values());
    }

    // A 26-slot count vector: O(L), where sorting is O(L log L)
    private static String key(String s) {
        int[] c = s.chars().collect(() -> new int[26],
                (a, ch) -> a[ch - 'a']++,
                (a, b) -> Arrays.setAll(a, i -> a[i] + b[i]));
        return Arrays.toString(c);  // "1,11" ≠ "11,1"
    }
}
LC 347 · Top K Frequent Elements · clean
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Long> freq = Arrays.stream(nums).boxed()
                .collect(Collectors.groupingBy(
                        v -> v, Collectors.counting()));
        // Invert: frequency -> the values that have it
        Map<Long, List<Integer>> byFreq = freq.keySet().stream()
                .collect(Collectors.groupingBy(freq::get));
        // Read the buckets from n down: no comparator, no sort.
        return LongStream.iterate(nums.length, f -> f > 0,
                                  f -> f - 1)
                .mapToObj(f -> byFreq.getOrDefault(f,
                                                   List.of()))
                .flatMap(List::stream)
                .limit(k)
                .mapToInt(Integer::intValue)
                .toArray();
    }
}
LC 128 · Longest Consecutive Sequence · clean
class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = Arrays.stream(nums).boxed()
                .collect(Collectors.toSet());
        // Walk only from run heads (v - 1 absent): every value
        // is then walked exactly once, so the total is O(n).
        return set.stream()
                .filter(v -> !set.contains(v - 1))
                .mapToInt(v -> (int) IntStream
                        .iterate(v, set::contains, x -> x + 1)
                        .count())
                .max().orElse(0);
    }
}
Why all six are cleanA collector is a mutable reduction whose container the stream owns. The HashMap inside groupingBy is created, filled and handed back by the pipeline, and nothing outside it ever sees it half-built. That is the whole difference from a lambda writing into an outer map. It is also why hashing is the pattern where streams are the idiomatic answer rather than a trick.
The one thing the loop does betterShort-circuiting. The loop for 217 returns at the first repeat, while distinct().count() reads everything. When that matters, !Arrays.stream(nums).allMatch(seen::add) stops early, but seen then lives outside the pipeline, which makes the solution stateful. The same trade-off, early exit against purity, comes back in almost every pattern after this one.
