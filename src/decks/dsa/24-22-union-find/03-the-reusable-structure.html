Twenty lines you should be able to type from memory

Write the class once, correctly, and every problem in this family becomes four or five lines of driver code. Both optimisations are one line each and neither is optional.

The class — path compression and union by size
class DSU {
    private final int[] parent;
    private final int[] size;
    private int components;      // live count, so no second pass is needed

    DSU(int n) {
        parent = new int[n];
        size   = new int[n];
        components = n;
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    /** Root of x's component, flattening the path on the way. */
    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];   // point at the grandparent
            x = parent[x];
        }
        return x;
    }

    /** true if two distinct components were merged; false if already joined. */
    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;          // this edge would close a cycle

        // Attach the SMALLER tree under the larger, keeping depth low.
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        size[ra] += size[rb];
        components--;
        return true;
    }

    boolean connected(int a, int b) { return find(a) == find(b); }
    int componentCount()            { return components; }
    int componentSize(int x)        { return size[find(x)]; }
}

Variant · grouping, then sorting within groups (LC 1202)
// Swappable index pairs form components. Within a component ANY
// permutation is reachable, so each component's characters can be
// sorted freely among its own positions.
String smallestStringWithSwaps(String s, List<List<Integer>> pairs) {
    DSU dsu = new DSU(s.length());
    for (List<Integer> p : pairs) dsu.union(p.get(0), p.get(1));

    // Bucket the indices by root.
    Map<Integer, List<Integer>> groups = new HashMap<>();
    for (int i = 0; i < s.length(); i++)
        groups.computeIfAbsent(dsu.find(i), k -> new ArrayList<>()).add(i);

    char[] out = s.toCharArray();

    for (List<Integer> idx : groups.values()) {
        // idx is ascending already, since i increased as we inserted.
        char[] chars = new char[idx.size()];
        for (int i = 0; i < idx.size(); i++) chars[i] = s.charAt(idx.get(i));
        Arrays.sort(chars);

        // Smallest characters into the smallest positions.
        for (int i = 0; i < idx.size(); i++) out[idx.get(i)] = chars[i];
    }
    return new String(out);
}

The knobs

Index mapping
Nodes must be 0..n−1. Subtract 1 for 1-indexed input, or map characters with c - 'a', or strings through a HashMap.
What to carry
A size array for balancing, a live component count, and sometimes a per-component aggregate such as a maximum. Update all of them inside union.
Edge order
Process in the given order when the problem asks for the last qualifying edge; sort by weight when building a minimum spanning tree.
Two DSUs
Some problems need separate connectivity views — LC 1579 runs one for each traveller and shares the type-3 edges between them.
Rank or size
Either balances correctly. Size is more useful, because it also answers "how big is this component?".
The three bugs that actually happenComparing the nodes instead of their roots — if (a == b) rather than if (find(a) == find(b)) misses every cycle that is not a self-loop. Forgetting to initialise parent[i] = i — Java zero-fills the array, so every node claims 0 as its root and the whole graph starts connected. Omitting both optimisations — the code is still correct, but a path-shaped union sequence makes each find O(n) and the solution times out on the large tests.
