Anchor 1 · LC 684 — the path to the solution

The setup
A tree on n nodes has exactly n − 1 edges. The input has n, so precisely one edge closes a cycle, and you must return the last such edge in the input order.
The DFS approach
After adding each edge, check whether the graph now has a cycle. Correct, but each check is O(V + E), so the whole thing is O(E²).
The observation
An edge closes a cycle exactly when its two endpoints are already in the same component. That is a connectivity query, and union-find answers it incrementally without re-examining anything.
Why the first false is the last edge
Edges are processed in input order and exactly one is redundant, so the first failure is that edge. Return immediately.
Indexing
Nodes are labelled 1 to n, so either size the arrays n + 1 and ignore index 0, or subtract 1 everywhere. Pick one and be consistent.
Edge case
The problem guarantees a solution exists, so no fallback return is needed — though returning an empty array keeps the compiler quiet.
LC 684 · O(n·α(n)) time, O(n) space
class Solution {
    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length;                 // n nodes, n edges
        int[] parent = new int[n + 1];        // nodes are 1-indexed
        for (int i = 1; i <= n; i++) parent[i] = i;   // MUST initialise

        for (int[] e : edges) {
            // Already connected means this edge closes a cycle.
            // Processing in input order makes the first such edge
            // the LAST one in the input that qualifies.
            if (!union(parent, e[0], e[1])) return e;
        }
        return new int[0];                    // guaranteed unreachable
    }

    private int find(int[] parent, int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];    // path compression
            x = parent[x];
        }
        return x;
    }

    private boolean union(int[] parent, int a, int b) {
        int ra = find(parent, a), rb = find(parent, b);
        if (ra == rb) return false;           // compare ROOTS, not a and b
        parent[rb] = ra;
        return true;
    }
}

Anchor 2 · LC 1579 — the path to the solution

The restatement
Keep the fewest edges such that Alice can reach everything and Bob can too. "Remove the maximum" is "keep the minimum", so the answer is total − kept.
The structure
Two separate connectivity views — one per traveller. Type 3 edges belong to both; type 1 to Alice only; type 2 to Bob only.
The ordering insight
Process type 3 first. A shared edge serves both travellers, so it is never worse than two single-type edges doing the same job. Taking them first is a greedy choice, and the exchange argument is that swapping a type-3 edge in can only reduce the count.
Counting kept edges
A type-3 edge counts once if it merged in either DSU. Type 1 and type 2 edges count when they merge in their own DSU.
The feasibility check
At the end both DSUs must have exactly one component. If either does not, some node is unreachable for that traveller and the answer is −1.
Edge case
Nodes are 1-indexed again, and duplicate edges appear in the test set — they union to false and are correctly discarded.
LC 1579 · O(E·α(n)) time, O(n) space
class Solution {
    public int maxNumEdgesToRemove(int n, int[][] edges) {
        DSU alice = new DSU(n + 1), bob = new DSU(n + 1);
        int kept = 0;

        // TYPE 3 FIRST: a shared edge does two jobs, so taking it can
        // never be worse than taking two single-type edges instead.
        for (int[] e : edges) {
            if (e[0] != 3) continue;
            boolean a = alice.union(e[1], e[2]);
            boolean b = bob.union(e[1], e[2]);
            if (a || b) kept++;          // useful to at least one traveller
        }

        // Then the private edges, each in its own structure.
        for (int[] e : edges) {
            if (e[0] == 1 && alice.union(e[1], e[2])) kept++;
            if (e[0] == 2 && bob.union(e[1], e[2]))   kept++;
        }

        // Component 0 is unused (1-indexed), so a fully connected graph
        // leaves 2 components: the real one plus the dummy node 0.
        if (alice.componentCount() != 2 || bob.componentCount() != 2) return -1;

        return edges.length - kept;
    }
}

547 · Number of Provinces count

Path: DFS over the adjacency matrix counting components is equally valid and equally fast — say so. Union-find is the natural choice if the edges were arriving over time.

Delta: iterate the upper triangle only (j > i); the matrix is symmetric, so the lower half is duplicated work.

Watch for: isConnected[i][i] is always 1 and must not be unioned — starting j at i + 1 handles that for free.

1319 · Operations to Make Network Connected count

Path: connecting k components needs k − 1 moves, and each move requires a spare cable — one that currently connects two already-connected computers.

Delta: check connections.length >= n - 1 first and return −1 otherwise; below that threshold there are not enough cables no matter how they are arranged. Then union everything and return componentCount() - 1.

Watch for: you never need to count the redundant cables explicitly. If there are at least n − 1 edges, there are always enough spares — proving that to yourself is the insight.

990 · Satisfiability of Equality Equations two-pass

Path: equality is an equivalence relation, which is exactly what union-find models. Inequality is a constraint checked afterwards.

Delta: two passes, and the order matters. Merge every == first, then verify that no != pair shares a root. Doing them in one pass fails when an equality appears after the inequality it contradicts.

Watch for: variables are single lowercase letters, so the universe is 26 elements — c - 'a' is the whole mapping, and "a!=a" must correctly return false.

1202 · Smallest String With Swaps group + sort

Path: the key realisation is that swaps are transitive. If you may swap (0,1) and (1,2), you can achieve any arrangement of positions 0, 1 and 2 — so a component's characters can be rearranged freely within its own positions.

Delta: union all pairs, bucket indices by root, then sort each bucket's characters and write the smallest into the smallest index.

Watch for: the indices in each bucket are already ascending if you collect them with an increasing loop, so only the characters need sorting — not both.

If you only drill twoDo 684 and 1202. 684 fixes the class itself and the boolean-returning union that most of this family depends on. 1202 is the one that teaches the modelling step — noticing that swap pairs are transitive, and therefore an equivalence relation — which is the move that makes a problem look like union-find when it did not at first.
