Anchor 1 · LC 1143 — the path to the solution

Brute force
Generate every subsequence of one string and test membership in the other. 2^m subsequences — impossible at m = 1000.
The recursive view
Compare the last characters. If they match, both are consumed and the problem shrinks by one on each side. If not, you must drop one of them — so try both and take the better.
Why memoisation applies
The recursion reaches the same (i, j) pair along many routes, which is exactly the overlapping-subproblem condition. A table of m × n entries solves each once.
Why a match needs no max
If the characters agree, pairing them is never worse than skipping either — any solution that skips a matched pair can be rewritten to include it without shortening. So take the diagonal outright.
The base row
Nothing is in common with an empty string, so row 0 and column 0 are 0 — which Java's array initialisation already gives you.
Space
Each cell reads only the previous row and the cell to its left, so two rows of length n + 1 suffice.
LC 1143 · O(mn) time, O(n) space
class Solution {
    public int longestCommonSubsequence(String text1, String text2) {
        int m = text1.length(), n = text2.length();

        // Two rolling rows. Base row is all zeros: nothing is in
        // common with an empty prefix.
        int[] prev = new int[n + 1];
        int[] cur  = new int[n + 1];

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {

                // NOTE the offset: dp index i maps to charAt(i - 1).
                if (text1.charAt(i - 1) == text2.charAt(j - 1)) {
                    // Pairing a match is never worse than skipping
                    // either side, so no comparison is needed.
                    cur[j] = prev[j - 1] + 1;
                } else {
                    // Drop one character from one of the strings.
                    cur[j] = Math.max(prev[j], cur[j - 1]);
                }
            }
            int[] swap = prev; prev = cur; cur = swap;   // roll the rows
        }
        return prev[n];      // after the final swap, prev holds row m
    }
}

Anchor 2 · LC 72 — the path to the solution

The state
dp[i][j] = the fewest operations to turn the first i characters of word1 into the first j of word2.
The base cases
dp[i][0] = i — deleting i characters reaches the empty string. dp[0][j] = j — inserting j characters builds it up. These are not zeros, and getting them wrong is the most common failure.
Match
The characters already agree, so no operation is needed: inherit the diagonal unchanged.
Mismatch — three options
Delete from word1 → dp[i−1][j]. Insert into word1 → dp[i][j−1]. Replace → dp[i−1][j−1]. Each costs one, so take 1 + min of the three.
Naming them matters
Attaching an operation to each source cell makes the recurrence derivable rather than memorised — and interviewers ask you to explain the three terms.
Space
Two rolling rows again, but the base column must be re-seeded at the start of every row: cur[0] = i.
LC 72 · O(mn) time, O(n) space
class Solution {
    public int minDistance(String word1, String word2) {
        int m = word1.length(), n = word2.length();

        int[] prev = new int[n + 1];
        int[] cur  = new int[n + 1];

        // Base ROW: turning an empty prefix into j chars costs
        // j insertions. NOT zero.
        for (int j = 0; j <= n; j++) prev[j] = j;

        for (int i = 1; i <= m; i++) {
            // Base COLUMN: turning i chars into nothing costs
            // i deletions. Re-seed it every row.
            cur[0] = i;

            for (int j = 1; j <= n; j++) {

                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    cur[j] = prev[j - 1];          // already equal — free
                } else {
                    cur[j] = 1 + Math.min(prev[j],            // delete
                                 Math.min(cur[j - 1],         // insert
                                          prev[j - 1]));      // replace
                }
            }
            int[] swap = prev; prev = cur; cur = swap;
        }
        return prev[n];
    }
}

583 · Delete Operation for Two Strings LCS reduction

Path: deriving a fresh recurrence works, but there is a shortcut worth seeing. The characters you keep must form a common subsequence, and keeping the longest one minimises the deletions.

Delta: answer = m + n − 2·lcs(a, b). Each string deletes everything outside the common subsequence, hence the factor of two.

Watch for: the direct DP is dp[i][j] = dp[i−1][j−1] on a match and 1 + min(dp[i−1][j], dp[i][j−1]) otherwise — it is edit distance without the replace option, which is a nice way to see the connection.

1312 · Minimum Insertion Steps for a Palindrome LCS reduction

Path: a Hard problem that collapses once you see the reduction. Characters that already form a palindromic subsequence need no partner; everything else needs one inserted.

Delta: the longest palindromic subsequence of s is the LCS of s with its reverse, so the answer is n − lcs(s, reverse(s)).

Watch for: the reduction is the entire difficulty. Once stated, the code is three lines on top of the LCS routine — so lead with the reasoning, not the code.

115 · Distinct Subsequences counting

Path: count how many distinct subsequences of s equal t. It is a counting problem, so the match branch adds rather than choosing.

Delta: on a match you may either use this character of s (dp[i−1][j−1]) or skip it (dp[i−1][j]), and both are valid — so sum them. On a mismatch only skipping is possible.

Watch for: the base cases are asymmetric. dp[i][0] = 1 — there is exactly one way to match the empty target, by deleting everything. dp[0][j] = 0 for j > 0. Counts overflow int, so use long or the problem's stated modulus.

97 · Interleaving String derived index

Path: the instinct is a 3D table over all three strings. That is unnecessary and is the main trap.

Delta: if you have consumed i characters of s1 and j of s2, you must be exactly at position i + j in s3. The third index is derived, so the table stays 2D and boolean.

Watch for: reject immediately when s1.length() + s2.length() != s3.length() — without it the index arithmetic runs off the end. The cell is true if either source could have supplied the next character.

If you only drill twoDo 1143 and 72. 1143 fixes the table shape, the index offset and the match-or-skip split that every problem here inherits. 72 adds the third option and the non-zero base cases — and being able to name each of its three source cells as delete, insert or replace is what turns this whole family from recalled formulas into a recurrence you can rebuild from scratch.
