One index per string, and a match-or-skip decision

Two strings, two indices, one table. dp[i][j] answers the question for the first i characters of one string and the first j of the other. Every problem in this family is that grid with a different rule at each cell — and the rule always splits on whether the two current characters match.

The two branches

Characters match
Consume both and inherit the diagonal: dp[i−1][j−1], usually plus 1 or unchanged. There is normally no choice to make.
Characters differ
You must drop one of them, so combine dp[i−1][j] and dp[i][j−1] — taking the maximum for a longest-subsequence question, the minimum for an edit distance.

Edit distance adds a third option, dp[i−1][j−1] for a substitution, giving a three-way minimum. Everything else here is the two-way form.

Why the table is (m+1) × (n+1)

Row 0 and column 0 represent the empty prefix of one string, and they are genuine base cases — the answer against nothing at all.

For a longest common subsequence that is 0. For an edit distance it is j or i, since turning a prefix into nothing takes that many deletions. For counting subsequences the empty pattern is matched exactly once, so it is 1.

Indices then shift by one: dp[i][j] compares s.charAt(i−1) with t.charAt(j−1). That offset is the most common source of bugs here — write it down before coding.

Applies when

Two sequences are compared and the answer is a length, a count or a distance. Also single-sequence problems that become two-sequence ones — a palindrome question is a string against its own reverse.

Does not apply when

You need the actual subsequence rather than its length — that needs a backtracking pass over the finished table. Also when the strings are very long, since the table is O(mn).

Complexity

O(m × n) time and space. Space collapses to O(min(m, n)) with two rolling rows, since each cell reads only the previous row and the cell to its left.
