Anchor 1 · LC 25 — the path to the solution

Brute force
Copy values into an array, reverse each block of k, write them back. O(n) time and O(n) space — but the statement forbids modifying values, so it is ruled out by the problem itself.
The decomposition
Two known procedures: find the k-th node ahead, and reverse a segment. Everything else is reconnecting the seam.
The three references
groupPrev (the node before the group), kth (its last node), and nextGroup (what follows). Naming these before writing any code is what makes the problem manageable.
The key fact
After reversing, the group's old head is its new tail. So it becomes groupPrev for the following iteration — no extra walk is needed.
The free reconnection
Seeding the reversal with prev = nextGroup leaves the old head already pointing at the next group, removing one of the two seam repairs.
Edge case
When fewer than k nodes remain, walk returns null and the loop exits, leaving the tail in its original order — exactly what the problem requires.
LC 25 · O(n) time, O(1) space
class Solution {
    public ListNode reverseKGroup(ListNode head, int k) {
        ListNode dummy = new ListNode(0, head);
        ListNode groupPrev = dummy;

        while (true) {
            // The group's last node, or null if fewer than k remain.
            ListNode kth = walk(groupPrev, k);
            if (kth == null) break;            // leave the short tail alone

            ListNode nextGroup = kth.next;     // SAVE before any rewiring
            ListNode oldHead = groupPrev.next; // becomes the group's new TAIL

            // Seeding prev with nextGroup means oldHead ends up
            // pointing at the next group automatically.
            ListNode prev = nextGroup, cur = oldHead;
            while (cur != nextGroup) {
                ListNode next = cur.next;
                cur.next = prev;
                prev = cur;
                cur = next;
            }

            groupPrev.next = kth;    // kth is now the group's first node
            groupPrev = oldHead;     // oldHead is now its last
        }
        return dummy.next;
    }

    private ListNode walk(ListNode from, int k) {
        while (from != null && k > 0) { from = from.next; k--; }
        return from;
    }
}

Anchor 2 · LC 138 — the path to the solution

Why it is hard
The random pointer may target a node you have not created yet, so a single naive pass cannot resolve it.
Solution one — a map
Pass 1 creates every copy and stores original → copy in a HashMap. Pass 2 sets copy.next and copy.random by looking up the originals. O(n) time, O(n) space, and completely correct. Give this first.
The follow-up
Do it in O(1) extra space. The map exists only to answer "which copy corresponds to this original?" — so encode that relationship in the list's own structure instead.
The interleave
Put each copy directly after its original: A → A' → B → B' → C → C'. Now the copy of any node x is simply x.next, which is O(1) with no storage at all.
Then three passes
Weave the copies in; set copy.random = original.random.next; unweave the two lists apart.
Edge cases
random may be null, so guard the second pass. The unweave must restore the original list exactly — leaving it damaged is a common and easily missed failure.
LC 138 · O(n) time, O(1) extra space
class Solution {
    public Node copyRandomList(Node head) {
        if (head == null) return null;

        // 1 · weave each copy in directly after its original,
        //     so copyOf(x) is always x.next — no map needed.
        for (Node cur = head; cur != null; cur = cur.next.next) {
            Node copy = new Node(cur.val);
            copy.next = cur.next;
            cur.next = copy;
        }

        // 2 · random pointers. The copy of cur.random is exactly
        //     cur.random.next, thanks to the interleaving.
        for (Node cur = head; cur != null; cur = cur.next.next) {
            cur.next.random = (cur.random != null) ? cur.random.next : null;
        }

        // 3 · unweave, restoring the original list intact.
        Node copyHead = head.next;
        for (Node cur = head; cur != null; cur = cur.next) {
            Node copy = cur.next;
            cur.next = copy.next;                       // restore original
            copy.next = (copy.next != null) ? copy.next.next : null;
        }
        return copyHead;
    }
}

21 · Merge Two Sorted Lists merge

Path: collecting all values, sorting and rebuilding is O(n log n) and wastes the fact that both inputs are already sorted.

Delta: the merge primitive verbatim. Dummy plus tail, attach the smaller head each step.

Watch for: when one list empties, attach the whole remainder with tail.next = a != null ? a : b. Looping the rest node by node works but is needless, and forgetting it entirely truncates the answer.

24 · Swap Nodes in Pairs reverse

Path: swapping the val fields is two lines and passes — but the follow-up forbids it, and the point is the pointer work.

Delta: this is LC 25 with k = 2. Writing the general version once covers both, and is barely longer than the special case.

Watch for: an odd-length list leaves a single trailing node untouched. The walk returning null handles that without a branch.

92 · Reverse Linked List II reverse

Path: one segment, given by 1-based positions left and right. Walk to the node before left, reverse right − left + 1 nodes, reconnect.

Delta: a dummy is what removes the left == 1 special case, where the head itself moves. With it, the code is uniform.

Watch for: positions are 1-based. Walking left steps instead of left − 1 reverses the wrong segment, and the off-by-one is invisible on symmetric test cases.

23 · Merge k Sorted Lists merge × k

Path: merging one at a time into an accumulator is O(n·k) — the accumulator is re-traversed each round. Say that, then improve it.

Delta: two ways to reach O(n log k). A min-heap of the k current heads, popping the smallest and pushing its successor; or pairwise merging in rounds, halving the list count each time. The heap is easier to explain; the pairwise version needs no extra structure.

Watch for: skip null lists when seeding the heap, or poll returns a null and throws on the first step.

If you only drill twoDo 25 and 138. 25 forces the full save-before-rewire discipline and the realisation that the old head becomes the new tail — after it, 24 and 92 are five-minute problems. 138 teaches the interleave trick, which is the one idea in this family that is not a reversal and the one most likely to appear as a follow-up you have not seen before.
