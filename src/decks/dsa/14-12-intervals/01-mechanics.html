Sort by one end, then a single pass decides everything

Interval problems are trivial once sorted and near-impossible before. The entire skill is choosing which end to sort by — start or end — because that one decision determines whether the following linear pass is correct.

The two sort keys, and when each is right

Sort by start
When you are building something: merging overlaps, inserting a new interval, counting simultaneous rooms. Processing in start order means each interval arrives exactly when it becomes relevant.
Sort by end
When you are keeping as many as possible: the classic activity-selection greedy. Finishing earliest leaves the most room for everything after it.

Get this backwards and the code still runs, still looks reasonable, and returns a wrong answer on the second test case. It is the only real decision in the pattern.

The overlap test

Two intervals a and b overlap when a.start <= b.end and b.start <= a.end. After sorting by start, the first condition is automatic, so the test collapses to b.start <= a.end.

Whether touching counts as overlapping is problem-specific. [1,2] and [2,3] merge in LC 56 but do not conflict in a meeting-room problem, where a room frees at the moment the meeting ends. That is <= versus <, and it decides correctness.

Read the statement for the word "touching", "adjacent", or an example with shared endpoints, and pick the operator deliberately.

Applies when

The input is a list of [start, end] pairs and the question is about overlap — merging, counting simultaneous, removing the fewest, or fitting the most.

Does not apply when

Intervals are inserted and queried dynamically — that wants a TreeMap or an interval tree. Also when you need per-point totals rather than interval structure, which is a range-update problem instead.

Complexity

O(n log n), dominated entirely by the sort; the pass itself is O(n). Space is O(n) for the output, or O(1) beyond it when you can sort in place.

Recognition cues — the literal words in the statement"merge all overlapping intervals" · "insert a new interval and merge" · "can a person attend all meetings" · "the minimum number of conference rooms" · "remove the minimum number of intervals to make the rest non-overlapping" · "the minimum number of arrows". The last two are the same greedy, and both are activity selection in disguise.
