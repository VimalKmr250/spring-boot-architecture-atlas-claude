Connect everything for the least total cost

A minimum spanning tree touches every node using exactly n − 1 edges at the lowest possible total weight. Two algorithms build it, both greedy, and both justified by the same fact: the cheapest edge crossing any split of the graph is always safe to take.

The cut property — why greedy is correct

Split the nodes into any two non-empty groups. The cheapest edge crossing that split belongs to some minimum spanning tree.

The proof is an exchange argument: take an MST without that edge, add it, and a cycle appears. That cycle must cross the split somewhere else, at an edge no cheaper. Remove it and the tree is still spanning, and no more expensive.

That one property licenses both algorithms — which is why they never need to reconsider a choice.

Kruskal and Prim

Kruskal
Sort all edges by weight, then take each one whose endpoints are not already connected. Union-find answers that test. O(E log E), best when the graph is sparse or you already have an edge list.
Prim
Grow one tree from an arbitrary start, repeatedly taking the cheapest edge leaving it. A priority queue supplies that edge. O(E log V), best when the graph is dense or implicit — as with points where every pair is connected.

Both give the same total weight. Choose by what the input looks like, and say why.

Applies when

Connect every node at minimum total cost — cables, roads, pipes. Also the minimax path family, where sorting edges and unioning until two nodes connect gives the smallest possible bottleneck.

Does not apply when

You want the shortest path between two nodes. An MST minimises the total edge weight, not any individual route — the MST path between two nodes is often longer than their shortest path.

Complexity

O(E log E) for Kruskal, dominated by the sort. O(E log V) for Prim with a heap. On a complete graph of n points, E is n², so both are about O(n² log n).

Two tells: "connect all", and an answer that is a total rather than a route.
