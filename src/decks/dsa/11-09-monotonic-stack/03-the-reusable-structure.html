One loop, four questions, two places to record

Flip the comparison to switch between greater and smaller. Record on pop for "next", record from peek() before pushing for "previous". That is the entire configuration space.

The template — next greater element, by index
/**
 * For each i, the index of the first j > i with a[j] > a[i].
 * Stack holds INDICES whose answer is still unknown, and their
 * values are strictly DECREASING from bottom to top.
 *
 * Each index is pushed once and popped at most once  ->  O(n).
 */
int[] nextGreater(int[] a) {
    int n = a.length;
    int[] ans = new int[n];
    Arrays.fill(ans, -1);                  // default when nothing is ever greater

    Deque<Integer> stack = new ArrayDeque<>();   // ArrayDeque, never java.util.Stack

    for (int i = 0; i < n; i++) {

        // a[i] dominates the top, so the top's wait is over.
        while (!stack.isEmpty() && a[stack.peek()] < a[i]) {
            ans[stack.pop()] = i;          // settle it ON THE WAY OUT
        }

        stack.push(i);                     // now i waits its turn
    }
    // Anything still on the stack never found a greater element,
    // and keeps the -1 default.
    return ans;
}
The four configurations
// NEXT greater  — settle on pop, decreasing stack
while (!st.isEmpty() && a[st.peek()] < a[i]) ans[st.pop()] = i;
st.push(i);

// NEXT smaller  — same shape, comparison flipped
while (!st.isEmpty() && a[st.peek()] > a[i]) ans[st.pop()] = i;
st.push(i);

// PREVIOUS greater — read peek() BEFORE pushing
while (!st.isEmpty() && a[st.peek()] <= a[i]) st.pop();
ans[i] = st.isEmpty() ? -1 : st.peek();
st.push(i);

// PREVIOUS smaller — same, comparison flipped
while (!st.isEmpty() && a[st.peek()] >= a[i]) st.pop();
ans[i] = st.isEmpty() ? -1 : st.peek();
st.push(i);

// CIRCULAR (the array wraps) — walk 2n and take i % n.
// Push only during the first pass, so nothing is settled twice.
for (int i = 0; i < 2 * n; i++) {
    int j = i % n;
    while (!st.isEmpty() && a[st.peek()] < a[j]) ans[st.pop()] = a[j];
    if (i < n) st.push(j);
}
The rectangle variant — both boundaries at once (LC 84)
// A bar of height h extends left until the first SHORTER bar and
// right until the next shorter bar. The pop moment gives you both:
// the new element is the right boundary, and the item beneath the
// popped one is the left boundary.
int largestRectangleArea(int[] h) {
    Deque<Integer> st = new ArrayDeque<>();
    int best = 0, n = h.length;

    for (int i = 0; i <= n; i++) {
        // A virtual bar of height 0 at index n forces the stack
        // to drain, so no case needs separate handling afterwards.
        int cur = (i == n) ? 0 : h[i];

        while (!st.isEmpty() && h[st.peek()] >= cur) {
            int height = h[st.pop()];

            // Left boundary is the item now on top; if the stack is
            // empty this bar reached all the way to index 0.
            int left  = st.isEmpty() ? -1 : st.peek();
            int width = i - left - 1;

            best = Math.max(best, height * width);
        }
        st.push(i);
    }
    return best;
}

The knobs

Direction of the stack
Decreasing for "greater" questions, increasing for "smaller". Get this backwards and the stack drains immediately, giving every element the same wrong answer.
Where you record
On pop for "next"; from peek() just before push for "previous".
Strict or not
< versus <= decides how equal values are treated. For rectangles it does not change the maximum — an equal-height bar is handled by its twin — but for "strictly greater" questions it does.
Sentinel
Iterating to n inclusive with a virtual 0 drains the stack automatically and removes the post-loop cleanup entirely.
Index or value
Push indices. You can always read the value, and only the index gives you the width.
The three bugs that actually happenUsing java.util.Stack — it is synchronised, slower, and iterates bottom-to-top which is the reverse of what you expect; use ArrayDeque. Pushing values instead of indices — then the width i − left − 1 is uncomputable and the rectangle problems become impossible. Forgetting the empty-stack case for the left boundary — when the stack empties, the bar reaches index 0, so the left boundary is −1 and the width is i, not i − 1.
