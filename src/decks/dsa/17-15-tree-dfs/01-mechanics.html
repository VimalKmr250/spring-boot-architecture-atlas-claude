Ask each node one question, and trust the recursion

Tree DFS is the shortest code in this deck and the hardest to reason about, because the recursive call does all the work. The discipline is to define exactly what the function returns for an arbitrary subtree, then write the body assuming the children already answered correctly.

The three-part contract

  1. Base case. What does a null node return? Almost always the identity for whatever you are combining — 0 for a depth, false for existence, MIN_VALUE for a maximum.
  2. Recurse. Call on both children. Do not think about what happens inside; assume the contract holds.
  3. Combine. Produce this node's answer from the two child answers and the node's own value.

Write the contract as a one-line comment before the body. Almost every wrong tree solution has a contract that changes meaning halfway through the function.

Return versus record — the distinction that matters

In the hardest problems here, what a node returns to its parent is not the same as the answer you are accumulating.

A path through a node — down one side, up through the node, down the other — cannot be extended by the parent, because the parent can only attach to one branch. So that value is recorded into a field, while the function returns the best single downward branch.

Conflating these two is the single biggest source of wrong answers in this pattern. When a problem mentions a path that "does not need to pass through the root", expect this split.

Applies when

The answer depends on subtree structure — depths, sums, paths, shapes. Any question phrased as "for every node…" or "the best path anywhere in the tree" is this pattern.

Does not apply when

You need level-by-level order, or the shallowest occurrence of something — DFS may find a deep answer first. Those want a breadth-first traversal instead.

Complexity

O(n) time, since each node is visited once. Space is O(h) for the call stack — O(log n) on a balanced tree but O(n) on a degenerate one, which is the case to mention.

Recognition cues — the literal words in the statement"the maximum depth" · "root-to-leaf path" · "the diameter" · "any path, not necessarily through the root" (the return/record split) · "invert the tree" · "return all paths that sum to" (backtracking on the path list) · "the number of nodes satisfying…". The phrase "not necessarily passing through the root" is the strongest signal that you need both a return value and a recorded one.
