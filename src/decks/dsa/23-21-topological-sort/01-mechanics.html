Repeatedly take whatever has nothing left blocking it

Given tasks with prerequisites, produce an order in which every task comes after everything it depends on. The algorithm is one sentence: keep a set of tasks with zero remaining prerequisites, take any of them, and decrement its dependents. If you run out before finishing, there is a cycle.

Kahn's algorithm — the invariant

indegree[v] counts how many prerequisites of v are still unprocessed. The queue holds exactly those nodes whose count has reached zero.

Processing a node decrements each of its dependents; any that hit zero join the queue. Each edge is examined once, so the whole thing is O(V + E).

Cycle detection is free: if fewer than V nodes were emitted, the remainder form a cycle — every one of them is still waiting on another, so none can ever reach zero.

Edge direction is the thing to get right

The input usually reads [a, b] meaning "to take a you must first take b". That is an edge from b to a — the prerequisite points at what it unlocks — and indegree[a] is what increments.

Building it backwards produces a perfectly plausible order that is exactly reversed. Write one concrete example on paper before coding: it takes ten seconds and prevents the most common failure in this pattern.

The DFS alternative uses three colours and produces the order reversed on the way out. Kahn's is easier to reason about and gives cycle detection without extra state.

Applies when

Directed dependencies and a question about ordering or feasibility — course schedules, build systems, recipe ingredients, task graphs. Also for detecting a cycle in a directed graph.

Does not apply when

The graph is undirected — "cycle" means something different there, and union-find is the tool. Also when edges have weights and you want a shortest path rather than an order.

Complexity

O(V + E) time: each node is enqueued once and each edge relaxed once. Space is O(V + E) for the adjacency list plus O(V) for the indegree array and queue.

Recognition cues — the literal words in the statement"prerequisites[i] = [a, b] means you must take b before a" · "can you finish all courses" (feasibility, so only the count matters) · "return the ordering of courses" · "eventual safe states" (reverse the edges) · "which recipes can you create" · "build order". The phrase "if it is impossible, return an empty array" is the cycle case being handed to you.
