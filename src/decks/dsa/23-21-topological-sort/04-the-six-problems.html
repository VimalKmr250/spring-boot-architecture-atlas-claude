Anchor 1 · LC 210 — the path to the solution

The restatement
Courses are nodes, prerequisites are directed edges, and a valid schedule is a topological order. Saying that out loud is most of the solution.
Reading the input
[a, b] means "take b before a", so the edge is b → a and indegree[a] increments. Getting this backwards is the failure mode for this whole family.
Why indegree and not removal
A course with three prerequisites must wait for all three. A counter that decrements handles that naturally; removing edges from a set would need extra bookkeeping.
Seeding
Every course with no prerequisites starts available. There may be several, and there may be disconnected groups — so seed them all before draining.
Cycle detection
Free. If fewer than n courses were emitted, the remainder are mutually blocking, and the problem asks for an empty array in that case.
Edge cases
No prerequisites at all means every course is immediately available and any order works. A self-loop [a, a] is a cycle of length one and is handled with no special case.
LC 210 · O(V + E) time, O(V + E) space
class Solution {
    public int[] findOrder(int numCourses, int[][] prerequisites) {
        // 1 · BUILD. [a, b] = "take b before a", so the edge is b -> a.
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());

        int[] indeg = new int[numCourses];
        for (int[] p : prerequisites) {
            int after = p[0], before = p[1];
            adj.get(before).add(after);     // finishing `before` unlocks `after`
            indeg[after]++;                 // `after` has one more blocker
        }

        // 2 · SEED every initially-unblocked course, not just one.
        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) if (indeg[i] == 0) q.offer(i);

        // 3 · DRAIN
        int[] order = new int[numCourses];
        int idx = 0;

        while (!q.isEmpty()) {
            int cur = q.poll();
            order[idx++] = cur;

            for (int next : adj.get(cur)) {
                // Freed exactly when its last prerequisite is done.
                if (--indeg[next] == 0) q.offer(next);
            }
        }

        // 4 · CHECK. Unemitted courses are mutually blocking: a cycle.
        return idx == numCourses ? order : new int[0];
    }
}

Anchor 2 · LC 2115 — the path to the solution

The restatement
A recipe is a node; each ingredient it needs is a prerequisite edge. Supplies are nodes that start satisfied. "Which recipes can I make?" is "which nodes does the topological sort reach?".
The naive approach
Loop repeatedly over all recipes, making any whose ingredients are all available, until a full pass changes nothing. Correct, but O(n²) in the number of recipes.
The change from LC 210
Nodes are strings, and not every ingredient is a recipe — some are raw supplies with no dependencies of their own.
Handling that
Give each recipe an indegree equal to its ingredient count, minus the ones already in supplies. Or more simply: seed the queue with every supply, and let an ingredient that is not a recipe simply never appear as a node.
The structure
Map<String, List<String>> from ingredient to the recipes it feeds, plus Map<String, Integer> for indegrees. Everything else is the template.
Why cycles matter
Two recipes can require each other. Neither ever reaches indegree zero, so neither is emitted — which is the correct answer with no extra code.
LC 2115 · O(V + E) time, O(V + E) space
class Solution {
    public List<String> findAllRecipes(String[] recipes, List<List<String>> ingredients,
                                       String[] supplies) {
        // ingredient -> recipes that need it
        Map<String, List<String>> adj = new HashMap<>();
        Map<String, Integer> indeg = new HashMap<>();

        for (int i = 0; i < recipes.length; i++) {
            String recipe = recipes[i];
            indeg.put(recipe, ingredients.get(i).size());

            for (String ing : ingredients.get(i)) {
                adj.computeIfAbsent(ing, k -> new ArrayList<>()).add(recipe);
            }
        }

        // SEED with the supplies — they are the zero-indegree nodes.
        Queue<String> q = new ArrayDeque<>(Arrays.asList(supplies));

        List<String> made = new ArrayList<>();

        while (!q.isEmpty()) {
            String have = q.poll();

            // An ingredient nobody needs simply has no entry here.
            for (String recipe : adj.getOrDefault(have, List.of())) {
                if (indeg.merge(recipe, -1, Integer::sum) == 0) {
                    made.add(recipe);      // every ingredient satisfied
                    q.offer(recipe);       // and it can feed other recipes
                }
            }
        }
        // Mutually-dependent recipes never reach zero and are excluded,
        // which is exactly the required behaviour.
        return made;
    }
}

207 · Course Schedule Kahn

Path: "can you finish all courses" is "is this graph acyclic". The order itself is never needed.

Delta: the template with return count == numCourses; and no output array. The DFS three-colour version is equally valid and slightly shorter if you prefer recursion.

Watch for: solve 210 instead and return order.length > 0 — one implementation covers both problems, and 210 is the one that exercises the edge direction.

802 · Find Eventual Safe States reversed

Path: a node is safe when every path from it ends at a terminal — equivalently, it can reach no cycle. Kahn's peels nodes with no outgoing edges rather than no incoming ones.

Delta: build the reversed graph and use outdegree where indegree normally goes. Seed with the terminals, and everything the peeling reaches is safe.

Watch for: the answer must be in ascending order. Collecting by scanning the safe[] array gives that for free; collecting in processing order does not.

1462 · Course Schedule IV closure

Path: answering each query with its own traversal is O(Q·(V+E)) and too slow. The queries need the transitive closure, not a single order.

Delta: run Kahn's while propagating a boolean[n] or BitSet of ancestors — when node u is processed, every dependent inherits u's ancestor set plus u itself. With n ≤ 100, Floyd–Warshall over a reachability matrix is also acceptable and easier to write.

Watch for: propagation must happen in topological order, or a node's ancestor set is incomplete when it is read.

1203 · Sort Items by Groups Kahn × 2

Path: two levels of ordering — groups must be ordered relative to each other, and items within a group must be ordered too.

Delta: assign every ungrouped item its own unique group first, so the group graph is well defined. Then topologically sort the groups, sort the items inside each group, and concatenate.

Watch for: that first step is what makes the problem tractable — without it, items with group == -1 are all lumped together and their mutual ordering is lost. A cycle in either sort means the answer is empty.

If you only drill twoDo 210 and 802. 210 fixes the edge direction and the count-based cycle check, which 207, 2115 and 1203 all reuse unchanged. 802 forces you to notice that reversing the graph turns "what depends on me" into "what do I depend on" — and that reversal is the move that makes several otherwise awkward graph problems fall out immediately.
