One derivation out loud, and six ways to get it wrong

LC 15, 3Sum, condensed from pattern 02. It has a sort, a loop, a while inside that, and two more whiles inside that. Counting keywords suggests O(n³). The five steps give O(n²), and every cost below sits on the line that incurs it.

LC 15 · each line priced
public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);                  // O(n log n), once
    List<List<Integer>> out = new ArrayList<>();  // output

    for (int i = 0; i + 2 < nums.length; i++) {   // n anchors
        if (i > 0 && nums[i] == nums[i - 1]) continue;

        // The gap r - l starts below n. Every path through
        // the body moves l right or r left, so the gap closes
        // by at least 1 per pass: at most n passes per anchor.
        int l = i + 1, r = nums.length - 1;
        while (l < r) {
            int sum = nums[i] + nums[l] + nums[r];
            if (sum < 0)      l++;
            else if (sum > 0) r--;
            else {
                // List.of on three items is O(1).
                out.add(List.of(nums[i], nums[l], nums[r]));

                // These move the SAME two pointers, so they
                // spend the same budget of n: nothing extra.
                while (l < r && nums[l] == nums[l + 1]) l++;
                while (l < r && nums[r] == nums[r - 1]) r--;
                l++; r--;
            }
        }
    }
    // n log n + n × n = O(n²) time.
    // O(1) extra space, beyond the output and the sort.
    return out;
}

The five steps, applied

1 · Variables
Just one: n, the length of nums. The triples are output, which is not counted.
2 · Unit of work
One pass of the while body: an addition, a comparison, a pointer move — O(1). List.of on three items is O(1). The sort is the only line that is not.
3 · Count
The sort runs once: n log n. The for loop runs n times. Within one anchor, every pass — including the duplicate-skipping whiles, which move the same two pointers — shrinks r − l, which starts below n. So at most n passes per anchor: n × n.
4 · Simplify
n log n + n² is O(n²). The sort is absorbed only because a larger term exists — in pattern 12 there is none, and the sort is the answer.
5 · Space
A handful of ints: O(1). Name the two exclusions — the output list and the sort's own working memory — rather than leaving them implied.
Say it in one breath"Sorting is n log n. Then, for each of n anchors, the two pointers close a gap of at most n, and the duplicate skips move those same pointers — so n² overall, which absorbs the sort. Space is O(1) beyond the output and the sort's own memory." Four claims, and every one of them can be checked against the code.

Counting loop keywords

Two nested loops can be O(n) — the window's inner loop is bounded over the whole run. One loop can be O(n²) — s += c or list.remove(0) in its body is a second loop in disguise.

Forgetting the sort

A solution that opens with Arrays.sort pays n log n before anything else runs, however linear the rest looks. Name it, then say whether a larger term absorbs it.

Collapsing variables

O(n·L) is not O(n): hashing n strings costs their length. O(R·C) is not O(n²) unless the grid is square. O(V + E) is not O(V): a dense graph has about V² edges.

Forgetting the stack

A recursive DFS that allocates nothing is still O(h) in space, and O(n) on a skewed tree. Only iterative code with a fixed set of variables earns O(1).

Counting calls for space

Space is measured at the deepest moment, not summed: naive Fibonacci makes O(2ⁿ) calls on an O(n) stack. Calls are time; depth is space.

Quoting average as worst

HashMap is O(1) on average; quickselect is O(n) on average and O(n²) at worst. Knapsack's O(n × capacity) looks polynomial but grows with the capacity's magnitude. Say which one you mean.
