Anchor 1 · LC 79 — the path to the solution

The shape
From every cell, try to walk the word. Each step moves to one of four neighbours, and the search is depth-first because a path must be followed to its end before an alternative is tried.
The constraint
A cell may not be reused within one path — but it is free again once that path is abandoned. So the visited set is per-branch, not global, which is exactly what backtracking provides.
The space trick
Instead of a separate boolean[][], overwrite the cell with a sentinel such as '#'. Since the sentinel never equals a real letter, the existing letter comparison also rejects visited cells — one check does two jobs.
Restoring
Put the character back before returning, on both the success and failure paths. The grid belongs to the caller.
Pruning that matters
The letter check at the top is the pruning — most starting cells fail at depth 0 or 1, which is why the exponential bound is rarely approached.
Worth mentioning
If the first letter is rarer than the last, searching the reversed word is faster. It is a small optimisation that signals you thought about the search shape.
LC 79 · O(m·n·4^L) worst case, O(L) space
class Solution {
    private static final int[][] DIRS = {{1,0},{-1,0},{0,1},{0,-1}};

    public boolean exist(char[][] board, String word) {
        for (int r = 0; r < board.length; r++)
            for (int c = 0; c < board[0].length; c++)
                if (dfs(board, word, r, c, 0)) return true;
        return false;
    }

    private boolean dfs(char[][] b, String w, int r, int c, int k) {
        if (k == w.length()) return true;          // matched everything

        // GUARD first: bounds, then the letter. A visited cell holds
        // '#', which matches no real letter, so this single test also
        // enforces "do not revisit".
        if (r < 0 || r >= b.length || c < 0 || c >= b[0].length) return false;
        if (b[r][c] != w.charAt(k)) return false;

        char saved = b[r][c];
        b[r][c] = '#';                             // choose

        for (int[] d : DIRS) {
            if (dfs(b, w, r + d[0], c + d[1], k + 1)) {
                b[r][c] = saved;                   // restore on SUCCESS too
                return true;
            }
        }

        b[r][c] = saved;                           // un-choose
        return false;
    }
}

Anchor 2 · LC 51 — the path to the solution

Brute force
Place queens on any of n² squares in all combinations. Astronomically large and entirely unnecessary.
Observation one
Exactly one queen per row, since two in a row always attack. So the search has depth n and each level chooses only a column — the problem collapses from C(n², n) to at most n!.
Observation two
Two queens share a ↘ diagonal exactly when r − c is equal, and a ↗ diagonal exactly when r + c is equal. Both are computable in O(1).
The encoding
Three boolean arrays: col[n], diag[2n] indexed by r + c, and anti[2n] indexed by r − c + n. The + n shifts a range that would otherwise be negative.
Why it is fast in practice
Conflicts appear early, so most branches die in the first few rows. The n! bound is never approached for the n ≤ 9 the problem allows.
LC 52
Identical search, incrementing a counter instead of building boards. Write 51 and you have both.
LC 51 · O(n!) worst case, O(n) space beyond the output
class Solution {
    private int n;
    private boolean[] col, diag, anti;
    private List<List<String>> out;

    public List<List<String>> solveNQueens(int n) {
        this.n = n;
        col  = new boolean[n];
        diag = new boolean[2 * n];      // indexed by r + c
        anti = new boolean[2 * n];      // indexed by r - c + n
        out  = new ArrayList<>();

        solve(0, new ArrayList<>());
        return out;
    }

    private void solve(int row, List<String> board) {
        if (row == n) { out.add(new ArrayList<>(board)); return; }

        for (int c = 0; c < n; c++) {
            int d = row + c;            // constant along a diagonal
            int a = row - c + n;        // + n keeps the index non-negative

            // O(1) guard — three reads, no board scan.
            if (col[c] || diag[d] || anti[a]) continue;

            col[c] = diag[d] = anti[a] = true;
            board.add(rowOf(c));

            solve(row + 1, board);

            board.remove(board.size() - 1);
            col[c] = diag[d] = anti[a] = false;    // undo ALL THREE
        }
    }

    private String rowOf(int queenCol) {
        char[] row = new char[n];
        Arrays.fill(row, '.');
        row[queenCol] = 'Q';
        return new String(row);
    }
}

17 · Letter Combinations no pruning

Path: a Cartesian product over the digit-to-letter mapping. Every branch is valid, so there is nothing to prune — which makes it the cleanest place to practise the skeleton.

Delta: depth equals the number of digits, and the branching factor is 3 or 4. Record at full depth.

Watch for: an empty input must return an empty list, not a list containing one empty string. Guard before recursing — it is the only edge case, and it is the one the tests check.

40 · Combination Sum II dedup + sum guard

Path: each candidate may be used at most once, and the input contains duplicates, so both the start index and the dedup rule matter.

Delta: sort, recurse with i + 1, and skip with if (i > start && nums[i] == nums[i-1]) continue;. Prune with if (nums[i] > remaining) break; — after sorting, every later candidate is larger too.

Watch for: break rather than continue on the sum prune. Using continue is correct but pointlessly scans the rest of the sorted range.

131 · Palindrome Partitioning predicate guard

Path: a cut position at every index, with each resulting piece required to be a palindrome. The guard is the palindrome test.

Delta: loop end from start, check the piece, and recurse from end + 1. Record when start reaches the end of the string.

Watch for: the same substring is tested many times. Precomputing isPal[i][j] with an O(n²) DP makes the guard O(1) and is the expected optimisation if asked to improve it.

52 · N-Queens II same search

Path: identical to 51. The only question is whether you notice that building the boards is wasted work when only a count is needed.

Delta: drop the board list and increment a counter at row == n. Everything else is unchanged.

Watch for: the bitmask version — three integers instead of three arrays, with Integer.lowestOneBit to iterate free columns — is meaningfully faster and a good thing to mention. Correctness first, then offer it.

If you only drill twoDo 79 and 51. 79 teaches per-branch state that lives in the input itself, and the restore-on-every-path discipline that goes with it. 51 teaches the move that defines this pattern: recognising that a constraint can be encoded so the feasibility test is O(1), which is what separates a search that finishes from one that does not.
