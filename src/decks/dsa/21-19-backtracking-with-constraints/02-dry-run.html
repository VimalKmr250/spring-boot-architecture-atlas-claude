The board's first row is A B C E, second S F C S, third A D E E. The word is found along a path that turns twice. The visited set is the board itself — each cell is temporarily overwritten and restored on the way out.

Why the cell must be restored even on successThe board is the interviewer's input, and leaving it full of '#' corrupts it for any later call — LC 212 calls this routine thousands of times on the same grid. Restore in a finally-like position: compute the result, put the character back, then return. Restoring only on failure is the subtle version of this bug, and it passes a single-call test.
