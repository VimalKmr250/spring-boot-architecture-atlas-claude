Anchor 1 · LC 124 — the path to the solution

Brute force
For every node, compute the best path through it by exploring its whole subtree. O(n²) on a balanced tree and worse on a chain.
The definition
A path is a sequence of connected nodes with no repeats. Crucially it may bend at one node — down the left branch, up through the node, down the right.
The observation
Every path bends at exactly one node: its highest point. So if each node computes the best path bending at itself, the maximum over all nodes is the answer, and each node's computation uses only its two child results.
The split
The bent value val + l + r cannot be passed up — a parent attaching to it would revisit this node. So record it in a field, and return val + max(l, r), which the parent can extend.
The clamp
Math.max(0, childGain). A branch with a negative total should be dropped rather than included, since the path may simply end at this node.
Edge cases
Initialise best to Integer.MIN_VALUE, not 0 — a tree of all-negative values has a negative answer, and 0 would wrongly win.
LC 124 · O(n) time, O(h) space
class Solution {
    private int best;

    public int maxPathSum(TreeNode root) {
        // Values can all be negative, so 0 is not a safe floor.
        best = Integer.MIN_VALUE;
        gain(root);
        return best;
    }

    /** CONTRACT: best sum of a path descending from node, or 0. */
    private int gain(TreeNode node) {
        if (node == null) return 0;

        // A negative branch is better left unused — the path can
        // simply stop here instead of descending into it.
        int l = Math.max(0, gain(node.left));
        int r = Math.max(0, gain(node.right));

        // RECORD: the path bending at this node uses BOTH branches,
        // so it is complete here and no parent can extend it.
        best = Math.max(best, node.val + l + r);

        // RETURN: one branch only, so the parent can build on it.
        return node.val + Math.max(l, r);
    }
}

Anchor 2 · LC 113 — the path to the solution

The difference from LC 112
112 asks whether a path exists, so it can short-circuit. 113 wants every path, so it must explore the whole tree and carry the route it took.
The naive approach
Build a fresh list at every node and pass copies down. Correct, but it allocates O(n) lists and is wasteful.
Backtracking
Carry one mutable list. Add the node on the way down, recurse, then remove it on the way out. At any moment the list holds exactly the route from the root to the current node.
Why the undo is unconditional
It runs whether or not the subtree produced a result. Placing it inside an if leaves stale entries behind and corrupts every subsequent path.
Why the copy is mandatory
out.add(path) stores a reference to a list that keeps mutating — by the end every entry is the same empty list. new ArrayList<>(path) snapshots it.
Edge cases
The leaf test must check both children. A null root returns an empty list, which falls out of the base case.
LC 113 · O(n·h) time, O(h) space
class Solution {
    public List<List<Integer>> pathSum(TreeNode root, int targetSum) {
        List<List<Integer>> out = new ArrayList<>();
        dfs(root, targetSum, new ArrayList<>(), out);
        return out;
    }

    private void dfs(TreeNode node, int remaining,
                     List<Integer> path, List<List<Integer>> out) {
        if (node == null) return;

        path.add(node.val);                    // CHOOSE

        if (node.left == null && node.right == null) {
            // A real leaf — both children absent.
            if (remaining == node.val) {
                // COPY: `path` keeps mutating after this returns.
                out.add(new ArrayList<>(path));
            }
        } else {
            dfs(node.left,  remaining - node.val, path, out);
            dfs(node.right, remaining - node.val, path, out);
        }

        // UNDO — unconditionally, on every exit from this node.
        path.remove(path.size() - 1);
    }
}

104 · Maximum Depth shape A

Path: there is nothing to derive — this is the contract in its purest form, and its value is as a template for everything else in the pattern.

Delta: base case 0, combine with 1 + max(left, right). Three lines.

Watch for: the iterative version is a level-order traversal counting levels. Worth knowing if the interviewer asks you to avoid recursion because of stack depth.

226 · Invert Binary Tree shape A

Path: swap the children at every node. The recursion handles the rest.

Delta: the only care needed is saving one child before overwriting it — node.left = invert(node.right) destroys node.left if you have not stored it. This is the same save-before-rewire discipline that list problems require.

Watch for: a null root must return null rather than throwing. It is the base case, and it is easy to omit on a problem this short.

112 · Path Sum shape A

Path: subtract as you descend, and test at the leaves. The subtlety is entirely in what counts as a leaf.

Delta: a leaf has both children null. Testing node == null instead treats a single-child node as a leaf, so a path that stops halfway down is wrongly accepted — and the bug only appears on unbalanced trees.

Watch for: negative values mean you cannot prune when the remainder goes below zero. That optimisation is only valid when all values are positive.

543 · Diameter of Binary Tree shape B

Path: the diameter is the longest path between any two nodes, measured in edges. It need not pass through the root, which is the signal for the split.

Delta: identical structure to LC 124 with sums replaced by counts — record l + r (the bent path's edge count), return 1 + max(l, r).

Watch for: the answer counts edges, not nodes, so a single-node tree has diameter 0. Returning the node count gives an answer one too large everywhere. Solve this before 124 — it is the same idea with easier arithmetic.

If you only drill twoDo 543 and 124. They are the same problem twice, and together they fix the return-versus-record distinction that governs every hard tree question. 543 is gentler because the arithmetic is just counting; 124 adds negative clamping and an initial value that cannot be zero. Once both are automatic, 104, 226, 112 and 113 are mechanical.
