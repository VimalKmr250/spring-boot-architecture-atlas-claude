Start at both ends and prove one side is useless

A sliding window walks two pointers in the same direction. Two pointers walks them towards each other, and the pattern lives or dies on one argument: at every step you must be able to prove that one of the two ends can never participate in a better answer, so discarding it is safe.

The invariant

The optimal answer always lies within [l, r]. Each step either records a candidate or strictly narrows the range — never both pointers at once, unless the step is provably neutral.

That invariant is only maintainable when the data is ordered — either literally sorted, or ordered by some property such as height or distance. Sorting first is not a preprocessing detail; it is what creates the ordering the discard argument depends on.

Total movement is bounded by n, so the scan is O(n) and the sort dominates at O(n log n).

The discard argument, in two shapes

Sum target
Array is sorted. If a[l] + a[r] < target, then a[l] paired with anything still in range is also too small — a[r] was its best remaining partner. So l can never be part of a solution: advance it. Symmetrically for too large.
Bounded by the weaker end
Container and rain-water problems. The value is capped by min(h[l], h[r]) and the width only shrinks, so keeping the shorter side can never beat what you already recorded. Discard the shorter.

If you cannot state one of these two arguments for your problem, two pointers is the wrong pattern and you will get a subtly wrong answer rather than a slow one.

Applies when

The data is sorted (or you may sort it), and you are looking for a pair, triple or k-tuple, or for a value bounded by the weaker of two ends. Also the in-place variant: a read pointer and a write pointer moving the same way.

Does not apply when

Order matters to the answer — sorting destroys the original indices, so a problem that asks you to return indices from unsorted input rules this out. Also when you need every subarray rather than every pair.

Complexity

O(n log n) dominated by the sort, or O(n) if the input arrives sorted. k-sum costs O(nk−1). Space is O(1) beyond the output and the sort's own working memory.

Recognition cues — the literal words in the statement"the array is sorted in non-decreasing order" (an explicit invitation) · "find two/three/four numbers such that…" · "return the indices of the two numbers" · "closest to target" · "container / area / trapped" · "remove duplicates in place" · "without using extra space". That last phrase is decisive: O(1) space on an array problem almost always means pointers, not a map.
