Count the work, then keep only what grows

Every pattern in this deck quotes a time / space figure. None of them needs memorising: each one is derived by counting, and the counting takes the same five steps every time. Learn the steps once and you can price code that is not on the list — including your own half-written solution, while there is still time to change it.

The five steps

  1. Name the size variables. n for the array, but also m for a second input, k for a window or heap, L for a string's length, V and E for a graph. Never fold two independent inputs into one n.
  2. Price one unit of work. Find the statement that runs most often, and cost every line that is not O(1): a sort, a substring, a heap push, a copy of a list.
  3. Count how often it runs. Sequential blocks add. Nested loops multiply. A range that halves contributes a log. Recursion is calls × work per call. A pointer that only moves forward is counted over the whole run, not per iteration.
  4. Simplify. Drop constant factors and lower-order terms: 3n² + 5n + 7 is O(n²). Independent variables stay side by side — O(n + m) does not become O(n).
  5. Repeat for space. The peak extra memory alive at any one moment: structures that grow with the input, plus the deepest recursion stack. The input and the output are excluded, and you say so.

Worst case, unless you say otherwiseA bare Big-O is read as the worst case. When a figure only holds on average — HashMap lookups, quickselect — say so, and expect the worst case as the follow-up question. When it only holds over the whole run, as with the sliding window's inner loop, say amortised. Interviewers listen for those two qualifiers.
