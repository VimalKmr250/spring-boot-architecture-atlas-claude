One skeleton, three parameters, one dedup rule

The body never changes. Where you record, what you pass as start, and whether you skip duplicates at the same depth — those three decisions cover all six problems.

The skeleton — choose, explore, un-choose
/**
 * KNOB 1 · where to record   — every node, leaves only, or depth == k
 * KNOB 2 · the start index   — i+1, i, or 0 with used[]
 * KNOB 3 · duplicate skip    — needed only when the input has repeats
 */
void backtrack(int[] nums, int start, List<Integer> path,
               List<List<Integer>> out) {

    // KNOB 1 · subsets record EVERY node, so there is no filter here.
    out.add(new ArrayList<>(path));      // COPY — path keeps mutating

    for (int i = start; i < nums.length; i++) {

        path.add(nums[i]);                          // 1 · choose
        backtrack(nums, i + 1, path, out);          // 2 · explore  (KNOB 2)
        path.remove(path.size() - 1);               // 3 · un-choose
    }
}
Knob 2 — the start index, and what it produces
// COMBINATIONS — each element once, order irrelevant (LC 78, 77, 90)
backtrack(nums, i + 1, ...);

// WITH REUSE — the same element may repeat (LC 39)
backtrack(nums, i, ...);          // note: i, not i + 1

// PERMUTATIONS — order matters, so every index is reachable
// at every depth and you must track what is already used.
for (int i = 0; i < nums.length; i++) {
    if (used[i]) continue;
    used[i] = true;
    path.add(nums[i]);

    backtrack(nums, 0, path, out);    // start is always 0

    path.remove(path.size() - 1);
    used[i] = false;                  // undo BOTH mutations
}

// FIXED SIZE k — record at the right depth instead of at every node
if (path.size() == k) { out.add(new ArrayList<>(path)); return; }
Knob 3 — the duplicate rule, and why it is written that way
// The input must be SORTED first, so equal values sit adjacent.
Arrays.sort(nums);

// COMBINATIONS with duplicates (LC 90, 40):
// skip a repeated value when it is not the FIRST choice at this depth.
for (int i = start; i < nums.length; i++) {
    if (i > start && nums[i] == nums[i - 1]) continue;
    ...
}
// `i > start`, NOT `i > 0`. Using i > 0 would also block the
// legitimate second copy at a DEEPER level, so [1,1] would vanish.

// PERMUTATIONS with duplicates (LC 47):
// only let the leftmost unused copy be chosen at each depth.
for (int i = 0; i < nums.length; i++) {
    if (used[i]) continue;
    if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue;
    ...
}
// !used[i-1] means the previous equal copy was already undone at
// THIS depth — so choosing this one would repeat the same branch.

The three bugs that actually happenAdding path instead of a copy — every entry in the output ends up being the same list, empty by the time you return. Always new ArrayList<>(path). Forgetting to undo — or undoing only one of two mutations in the permutation case, where both path and used[i] must be restored. i > 0 instead of i > start in the combination dedup — this drops legitimate results such as [1,1], and the failure appears only on inputs with repeats.
