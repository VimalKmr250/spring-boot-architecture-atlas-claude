Sort and union, or grow and pop

Kruskal is union-find with a sorted edge list. Prim is Dijkstra with the distance replaced by the single edge weight. Both are short; the choice between them is about the input shape.

Kruskal — sort, then take non-cycling edges (LC 1584, 1135)
/**
 * Sort every edge, take each one whose endpoints are not yet
 * connected. Union-find answers that test in near-constant time.
 * Stop at n-1 edges: the tree is then complete.
 */
int kruskal(int n, int[][] edges) {       // edges: {u, v, w}
    Arrays.sort(edges, (a, b) -> Integer.compare(a[2], b[2]));

    DSU dsu = new DSU(n);
    int total = 0, taken = 0;

    for (int[] e : edges) {
        // false means the endpoints already share a component,
        // so this edge would close a cycle.
        if (dsu.union(e[0], e[1])) {
            total += e[2];
            if (++taken == n - 1) break;     // spanning tree complete
        }
    }
    return taken == n - 1 ? total : -1;      // -1 if the graph is disconnected
}
Prim — grow one tree from any start (LC 1584 on points)
/**
 * Better when the graph is DENSE or IMPLICIT — with n points every
 * pair is an edge, so materialising all n^2/2 of them is wasteful.
 *
 * This is Dijkstra with one change: the key is the single edge
 * weight, not the accumulated distance.
 */
int primOnPoints(int[][] points) {
    int n = points.length;
    boolean[] inTree = new boolean[n];
    int[] best = new int[n];                 // cheapest edge into the tree
    Arrays.fill(best, Integer.MAX_VALUE);
    best[0] = 0;

    int total = 0;

    for (int iter = 0; iter < n; iter++) {
        // Pick the cheapest node not yet in the tree. With n <= 1000
        // a linear scan is O(n^2) overall and simpler than a heap.
        int u = -1;
        for (int v = 0; v < n; v++)
            if (!inTree[v] && (u == -1 || best[v] < best[u])) u = v;

        inTree[u] = true;
        total += best[u];

        // Relax: the key is the EDGE weight, not best[u] + weight.
        for (int v = 0; v < n; v++) {
            if (inTree[v]) continue;
            int d = Math.abs(points[u][0] - points[v][0])
                  + Math.abs(points[u][1] - points[v][1]);
            if (d < best[v]) best[v] = d;
        }
    }
    return total;
}
The virtual node — turning a per-node cost into an edge (LC 1168)
/**
 * Each house can either dig its OWN well at cost wells[i], or lay a
 * pipe to a neighbour. Two different kinds of cost, which is not an
 * MST — until you notice the trick.
 *
 * Invent node 0 as "the water source". A well at house i becomes an
 * EDGE from 0 to i with weight wells[i]. Now every cost is an edge,
 * and the answer is an ordinary MST over n+1 nodes.
 */
int minCostToSupplyWater(int n, int[] wells, int[][] pipes) {
    List<int[]> edges = new ArrayList<>();

    // Wells become edges from the virtual source.
    for (int i = 0; i < n; i++) edges.add(new int[]{0, i + 1, wells[i]});

    // Pipes are ordinary edges.
    for (int[] p : pipes) edges.add(new int[]{p[0], p[1], p[2]});

    edges.sort((a, b) -> Integer.compare(a[2], b[2]));

    DSU dsu = new DSU(n + 1);        // +1 for the virtual node
    int total = 0, taken = 0;

    for (int[] e : edges) {
        if (dsu.union(e[0], e[1])) {
            total += e[2];
            if (++taken == n) break;  // n+1 nodes, so n edges span them
        }
    }
    return total;
}

Choosing, and the variants

Edge list given
Kruskal. The sort is already the natural first move.
Points or a dense graph
Prim with a linear scan when n ≤ 1000, avoiding the n² edge list entirely.
Two kinds of cost
Look for a virtual node that converts the odd one into an edge. It is the single most reusable trick here.
Minimax path
Sort edges ascending and union until the two endpoints connect. The last edge added is the smallest possible bottleneck.
Critical edges
Compute the MST weight, then for each edge: force-exclude it and see whether the weight rises (critical), or force-include it and see whether the weight is unchanged (pseudo-critical).
The three bugs that actually happenForgetting the disconnected case — if fewer than n − 1 edges are accepted the graph cannot be spanned, and the answer is −1 rather than a partial total. Off-by-one with a virtual node — the DSU must be sized n + 1 and the stopping count becomes n, not n − 1. Treating Prim's key as a distance — relaxing with best[u] + weight makes it Dijkstra and produces a shortest-path tree, which is a different and more expensive tree.
