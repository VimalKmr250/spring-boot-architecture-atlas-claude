One skeleton, five knobs, six problems

Every variable-size window problem in this family is the same twelve lines. Memorise the skeleton, then learn which of the five marked knobs each problem turns — that is far less to carry than six separate solutions.

The canonical variable-size window · longest-valid form
/**
 * Longest window satisfying some monotone predicate.
 * Invariant: at the bottom of every iteration, [l, r] is a VALID window.
 * Each index is admitted once via r and evicted at most once via l  ->  O(n).
 */
int longestValidWindow(int[] a) {
    Map<Integer, Integer> win = new HashMap<>();   // KNOB 1 · the window state
    int l = 0, best = 0;

    for (int r = 0; r < a.length; r++) {

        win.merge(a[r], 1, Integer::sum);          // KNOB 2 · admit a[r]

        while (win.size() > 2) {                   // KNOB 3 · "the window is invalid"
            int out = a[l++];                      // KNOB 4 · evict a[l] — the exact mirror of KNOB 2
            if (win.merge(out, -1, Integer::sum) == 0) win.remove(out);
        }

        best = Math.max(best, r - l + 1);          // KNOB 5 · record, AFTER validity is restored
    }
    return best;
}
Variant B · shortest valid window (LC 209, 76)
// Two changes, and they always come together:
//   the while condition is inverted   (while VALID, not while invalid)
//   the record moves INSIDE the loop  (every shrink is a candidate)
int shortestValidWindow(int[] a, int target) {
    int l = 0, sum = 0, best = Integer.MAX_VALUE;

    for (int r = 0; r < a.length; r++) {
        sum += a[r];

        while (sum >= target) {                 // while VALID
            best = Math.min(best, r - l + 1);   // record here
            sum -= a[l++];
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}
Variant C · fixed size k (LC 567)
// The window grows by exactly one per step, so the shrink
// is an `if`, never a `while` — it can only ever be off by one.
int fixedWindow(int[] a, int k) {
    int l = 0, sum = 0, best = Integer.MIN_VALUE;

    for (int r = 0; r < a.length; r++) {
        sum += a[r];

        if (r - l + 1 > k) sum -= a[l++];       // `if`, not `while`

        if (r - l + 1 == k) best = Math.max(best, sum);
    }
    return best;
}
Variant D · counting with "exactly K"
// You cannot window "exactly K" directly — validity is not monotone.
// But "at most K" IS monotone, and:
//        exactly(K)  ==  atMost(K) - atMost(K - 1)
// Inside atMost, every window ending at r contributes (r - l + 1)
// subarrays, because every suffix of a valid window is valid too.
int exactlyK(int[] a, int k) {
    return atMost(a, k) - atMost(a, k - 1);
}

long atMost(int[] a, int k) {
    Map<Integer, Integer> win = new HashMap<>();
    long count = 0;
    for (int l = 0, r = 0; r < a.length; r++) {
        win.merge(a[r], 1, Integer::sum);
        while (win.size() > k) {
            int out = a[l++];
            if (win.merge(out, -1, Integer::sum) == 0) win.remove(out);
        }
        count += r - l + 1;                     // all windows ending at r
    }
    return count;
}

The five knobs, and nothing else

1 · state
int[128] for characters, HashMap for arbitrary ints, a plain sum or distinct counter when that is all you need. Prefer the array: it is faster and has no boxing.
2 · admit
One line. Whatever it does, knob 4 must undo precisely this.
3 · invalid
The only genuinely problem-specific line. Write it as a positive statement of what "broken" means, then negate nothing.
4 · evict
Write it immediately after knob 2, by copying that line and flipping the sign. Never write it later from memory.
5 · record
max after the loop for longest; min inside the loop for shortest; count += r - l + 1 for counting.
The three bugs that actually happenRecording before shrinking — you measure a window that was never valid, and the answer comes out too large. Forgetting win.remove at zero — a count of zero still occupies a key, so win.size() lies and the window never shrinks enough. if where while belongs — at r=6 in the trace, l had to move twice in one step; an if silently returns a wrong answer on exactly that input.
