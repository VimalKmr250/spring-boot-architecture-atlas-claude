Anchor 1 · LC 1109 — the path to the solution

Brute force
For each booking, loop the flights it covers and add the seats. O(q · n), which at 2×10⁴ bookings over 2×10⁴ flights is 4×10⁸ — too slow, and the natural first attempt.
The observation
Nothing is read until every booking has been applied. So the intermediate arrays are wasted work: only the net effect matters.
The reformulation
Record where each booking starts contributing and where it stops. That is two cells regardless of how many flights it spans.
The indexing detail
Flights are 1-indexed in the statement and the array is 0-indexed, so flight f sits at f − 1. The rise goes at first − 1 and the fall at last, which is already (last − 1) + 1.
Edge case
A booking ending at flight n writes to index n, which is why the array has n + 1 slots.
LC 1109 · O(q + n) time, O(n) space
class Solution {
    public int[] corpFlightBookings(int[][] bookings, int n) {
        // n + 1 so that a booking ending at flight n has somewhere
        // to put its cancellation.
        long[] D = new long[n + 1];

        for (int[] b : bookings) {
            int first = b[0], last = b[1], seats = b[2];

            // Flights are 1-indexed; the array is 0-indexed.
            D[first - 1] += seats;   // rise at the first flight
            D[last]      -= seats;   // (last - 1) + 1 — just past the last
        }

        int[] out = new int[n];
        long running = 0;

        for (int i = 0; i < n; i++) {
            running += D[i];         // the running total is the seat count
            out[i] = (int) running;
        }
        return out;
    }
}

Anchor 2 · LC 1094 — the path to the solution

Brute force
For each trip, add its passengers to every location it spans, then scan for a violation. O(q · M).
The alternative worth naming
Sort the pick-up and drop-off events and sweep them with a running count. That is the same algorithm; the difference array is simply the version that does not need a sort, because the statement bounds locations at 1000.
The detail that decides correctness
A passenger boards at from and leaves at to, so they are not in the car at to — the interval is half-open. The fall therefore goes at to, not to + 1.
Why that matters
Without it, two trips where one ends exactly where the next begins are counted as overlapping, and a car that is actually fine is reported as over capacity.
The early exit
You never need the finished array — only whether the running total ever breaks the limit. Return as soon as it does.
LC 1094 · O(q + M) time, O(M) space
class Solution {
    public boolean carPooling(int[][] trips, int capacity) {
        // The statement bounds locations at 1000.
        int[] D = new int[1001];

        for (int[] t : trips) {
            int num = t[0], from = t[1], to = t[2];

            D[from] += num;
            // The interval is HALF-OPEN: the passenger is gone by `to`,
            // so the fall lands on `to` itself, not to + 1. This is what
            // lets one trip end exactly where the next begins.
            D[to]   -= num;
        }

        int onboard = 0;
        for (int delta : D) {
            onboard += delta;
            if (onboard > capacity) return false;   // no need to finish
        }
        return true;
    }
}

370 · Range Addition template Premium

Path: the statement is the pattern with no story around it — apply k range additions to a zero array and return the result.

Delta: none. The template verbatim, with 0-indexed inclusive ranges, so the fall goes at r + 1.

Premium: locked behind LeetCode's paywall. 1109 above is the same problem and is free — solve that instead and you have covered this one entirely.

1893 · Check if All Integers in a Range Are Covered template

Path: checking each value against every interval is O(q · range), which is fine at these limits — but the difference array makes it one pass and generalises.

Delta: the array counts coverage rather than a value, so each interval contributes +1 and −1. After the sweep, the answer is "was the running total ever zero inside [left, right]?"

Watch for: values run 1 to 50, so size the array 52 and use inclusive ranges — the fall at end + 1.

1943 · Describe the Painting sparse events

Path: the coordinate range makes a dense array wasteful, and the output is a list of maximal stretches rather than per-index values.

Delta: a TreeMap keyed on endpoints replaces the array; iterating it in key order is the sweep. Between consecutive keys the running total is constant, and that stretch becomes one output segment.

Watch for: emit a segment only when the running total is non-zero — gaps between painted regions must not appear in the output. Sums reach 10⁹, so accumulate in long.

2381 · Shifting Letters II template

Path: applying each shift character by character is O(q · n). The accumulated shift per position is exactly what a difference array computes.

Delta: a shift is +1 or −1 depending on the direction flag, so the update value is direction == 1 ? 1 : -1. During the sweep, the running total is the net shift for that character.

Watch for: the net shift can be large and negative, so normalise with ((shift % 26) + 26) % 26 before adding it to the letter — the same signed-remainder trap that appears whenever Java's % meets a negative operand.

If you only drill twoDo 1109 and 1094. 1109 is the template in its cleanest form and forces you to get the 1-indexed-to-0-indexed shift right. 1094 is the one that teaches the half-open distinction — whether the fall belongs at r or r + 1 — which is the only genuinely subtle decision this pattern ever asks you to make.
