Record the edges of a range, not its contents

Adding v to every element of [l, r] costs O(r − l). Do that a hundred thousand times and you have an O(n·q) solution that times out. A difference array records each update as two numbers — a rise at l and a fall at r+1 — and reconstructs the whole array once at the end with a single prefix sum.

The invariant

D[i] holds the change between position i−1 and position i. Running a prefix sum over D therefore rebuilds the original array exactly.

So a range update becomes: D[l] += v and D[r+1] -= v. The first says "from here on, everything is v higher"; the second cancels it once the range ends.

Every update is O(1) regardless of range width. One O(n) sweep at the end turns all of them into the final array.

Why r + 1, and why size n + 1

The range is inclusive of r, so the cancellation must land on the first index after it. Writing D[r] -= v silently drops the last element of every range.

That means r + 1 can equal n, so D needs length n + 1. The extra slot is a deliberate overflow bin: it is written but never read, which removes the bounds check entirely.

This is the exact inverse of a prefix sum. One turns an array into its running totals; the other turns running totals back into an array.

Applies when

Many range updates land before any read. Also for interval occupancy — "is any point covered more than C times?" — where each interval contributes +1 at its start and −1 just past its end.

Does not apply when

Reads and writes interleave, since every read needs a fresh O(n) rebuild. That case wants a Fenwick or segment tree with lazy propagation. Also when the coordinate range is enormous and sparse — then sort the events instead of allocating an array.

Complexity

O(1) per update, O(n) for the single rebuild, so O(q + n) overall. Space is O(n). Use long when many updates can stack on one index.

The decisive shape is a list of intervals with a value, combined with the fact that nothing is read until every update has been applied.
