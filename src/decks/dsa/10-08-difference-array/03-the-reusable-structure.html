Two writes per update, one sweep at the end

The core is four lines. The variants differ only in what the array counts — seats, passengers, coverage, or a letter shift — and in whether you check a condition during the sweep or afterwards.

The template — apply many range updates, then rebuild once
/**
 * Apply q range updates in O(q), then rebuild in O(n).
 * D[i] holds the CHANGE between position i-1 and position i,
 * so a prefix sum over D reconstructs the array.
 */
int[] applyRangeUpdates(int n, int[][] updates) {
    // n + 1, not n: r + 1 can equal n, and that slot is a
    // deliberate overflow bin — written, never read.
    long[] D = new long[n + 1];

    for (int[] u : updates) {
        int l = u[0], r = u[1], v = u[2];

        D[l]     += v;      // from here on, everything is v higher
        D[r + 1] -= v;      // r + 1, NOT r — the range includes r
    }

    int[] out = new int[n];
    long running = 0;

    for (int i = 0; i < n; i++) {
        running += D[i];            // the running total IS the value
        out[i] = (int) running;
    }
    return out;
}
Variant · check a capacity during the sweep (LC 1094)
// When the question is "does it ever exceed C?", you do not need
// the finished array — bail out the moment the running total breaks.
boolean carPooling(int[][] trips, int capacity) {
    int[] D = new int[1001];        // the statement bounds locations at 1000

    for (int[] t : trips) {
        int num = t[0], from = t[1], to = t[2];

        D[from] += num;
        D[to]   -= num;             // NOT to + 1: the passenger leaves AT `to`,
                                    // so that stop is already free.
    }

    int onboard = 0;
    for (int v : D) {
        onboard += v;
        if (onboard > capacity) return false;
    }
    return true;
}
Variant · sparse coordinates, so sort events instead (LC 1943)
// When positions run to 1e9, you cannot allocate the array.
// Keep only the endpoints in a TreeMap and sweep the keys in order.
List<List<Long>> splitPainting(int[][] segments) {
    TreeMap<Integer, Long> d = new TreeMap<>();

    for (int[] s : segments) {
        d.merge(s[0],  (long) s[2], Long::sum);
        d.merge(s[1], -(long) s[2], Long::sum);
    }

    List<List<Long>> out = new ArrayList<>();
    long running = 0;
    Integer prev = null;

    for (Map.Entry<Integer, Long> e : d.entrySet()) {
        // The stretch from prev to this key carries the previous total.
        if (prev != null && running != 0) {
            out.add(List.of((long) prev, (long) e.getKey(), running));
        }
        running += e.getValue();
        prev = e.getKey();
    }
    return out;
}

The knobs

Array size
n + 1 whenever the range is inclusive of r. If the statement bounds coordinates directly, size to that bound plus one.
Where the fall goes
r + 1 for an inclusive range; r when the interval is half-open, as it is for a passenger who gets off at a stop. Read the statement carefully — this one line decides correctness.
Dense or sparse
An array when coordinates are bounded by roughly 10⁶; a TreeMap of events when they run to 10⁹.
When to read
After the sweep if you need the whole array; during it if you only need to test a threshold, which lets you exit early.
Element type
long when many updates can stack on one index. The trace above reached 55 from three bookings; 10⁵ bookings of 10⁴ seats overflows int.
The three bugs that actually happenD[r] -= v instead of D[r + 1] -= v — silently drops the last element of every range, so the answer is wrong only at the boundaries and passes small tests. Sizing D at n — throws the moment a range ends at the final index, which the example above does. Mixing 1-indexed input with a 0-indexed array — flight k lives at index k−1, and forgetting that shifts every answer by one position.
