A small vocabulary, used precisely

There is no single skeleton here — the pattern is a set of idioms. Knowing which operator matches which structure is the whole skill, and the list is short enough to memorise.

The idioms
// XOR FOLD — pairs cancel, the unpaired survivor remains
int unique = 0;
for (int v : nums) unique ^= v;          // O(n) time, O(1) space

// COUNT SET BITS — one iteration per SET bit, not 32
int count = 0;
while (n != 0) { n &= (n - 1); count++; }   // clears the lowest set bit

// READ and WRITE a single bit
boolean isSet = ((n >> i) & 1) == 1;
n |=  (1 << i);                          // set
n &= ~(1 << i);                          // clear
n ^=  (1 << i);                          // flip

// ISOLATE the lowest set bit — splits a set into two halves
int lowest = n & (-n);

// SAFE SHIFTING. Always >>> when looping over bits: >> copies the
// sign bit downward, so a negative number never reaches zero.
for (int i = 0; i < 32; i++) { int bit = (n >>> i) & 1; }

// ENUMERATE every subset of n elements
for (int mask = 0; mask < (1 << n); mask++)
    for (int i = 0; i < n; i++)
        if ((mask & (1 << i)) != 0) { /* element i is in this subset */ }
The three problem shapes
// 1 · PARITY PER LANE — appears twice except one (LC 136)
int singleNumber(int[] nums) {
    int x = 0;
    for (int v : nums) x ^= v;
    return x;
}

// 2 · COUNT PER LANE MOD k — appears three times except one (LC 137)
int singleNumberIII(int[] nums) {
    int result = 0;
    for (int bit = 0; bit < 32; bit++) {
        int count = 0;
        for (int v : nums) count += (v >>> bit) & 1;
        if (count % 3 != 0) result |= (1 << bit);
    }
    return result;
}

// 3 · BUILD FROM SMALLER ANSWERS — DP over bits (LC 338)
int[] countBits(int n) {
    int[] dp = new int[n + 1];
    for (int i = 1; i <= n; i++) {
        // i >> 1 is i with the last bit dropped — already solved.
        // Add back that last bit.
        dp[i] = dp[i >> 1] + (i & 1);
    }
    return dp;
}
Reversing bits, and why the mask matters (LC 190)
// Java has no unsigned int, so the result is returned as a signed
// int whose BIT PATTERN is correct — that is what the problem wants.
public int reverseBits(int n) {
    int result = 0;

    for (int i = 0; i < 32; i++) {
        result <<= 1;              // make room at the bottom
        result |= (n & 1);         // take n's lowest bit
        n >>>= 1;                  // UNSIGNED shift — >> would loop forever
    }
    return result;
}

Matching shape to operator

Pairs cancel
XOR fold. One line, O(1) space.
Groups of k cancel
Count each lane modulo k. The state-machine form is an optimisation of this, not a separate idea.
Two unique values
XOR everything, isolate any set bit of the result with x & (-x), and split the array by that bit — each half then has one unique value.
Counting bits for a range
DP on i >> 1, which is a strictly smaller index and therefore already computed.
Missing from a range
XOR all indices with all values; everything pairs off except the missing one. The arithmetic-sum version works too, but can overflow.
The three bugs that actually happenUsing >> instead of >>> — the arithmetic shift copies the sign bit, so a loop over the bits of a negative number never terminates. Operator precedence — & binds looser than == in Java, so if (n & 1 == 1) does not compile as intended; parenthesise every bitwise sub-expression. Overflow with 1 << 31 — that is Integer.MIN_VALUE; use 1L << i when you need bit 31 or above as a positive value.
