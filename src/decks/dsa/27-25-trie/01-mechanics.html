Share every prefix exactly once

A hash set answers "is this exact word present?" in O(1). It cannot answer "does any word start with this?" without scanning everything. A trie stores words as paths through a tree, so a shared prefix is stored once and every prefix question becomes a walk of length L — independent of how many words exist.

The structure

Each node holds up to 26 child links and a boolean isWord. The edges carry the letters; the nodes themselves store nothing but structure.

Walking from the root spells a prefix. Reaching a node with isWord set means a complete word ends there — which is why "car" and "card" coexist with the shorter one marked mid-path.

An int[26]-shaped array of children beats a HashMap for lowercase input: no hashing, no boxing, and the null check is the membership test.

What it buys over a hash set

Prefix queries
"Does anything start with app?" is a three-step walk, regardless of dictionary size.
Shared traversal
Searching a grid for 3000 words at once walks the board once, pruning the moment no word continues that way.
Ordered enumeration
Visiting children 'a' to 'z' emits words in lexicographic order for free — no sorting needed.
Wildcards
A . means "try every child", which is a branch in the recursion. A hash set cannot express that at all.

Applies when

Many strings share prefixes and the queries are about prefixes — autocomplete, dictionary lookup, word search over a grid, replacing words by their roots.

Does not apply when

Only exact membership is needed — a HashSet is simpler and uses less memory. Also when the alphabet is huge, since 26 links per node becomes wasteful and a map per node is better.

Complexity

O(L) per insert or query, where L is the word length. Space is O(total characters × 26) worst case — the constant is large, which is worth mentioning when memory is a stated constraint.

The tell is many words queried together, or a query about a prefix rather than a whole word.
