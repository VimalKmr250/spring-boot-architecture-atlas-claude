One path down is a Stream.iterate; in-order is a sort

A BST gives streams two shortcuts. When a problem follows a single path (700, 235), the ordering tells each step which child to take, so the walk is Stream.iterate(root, Objects::nonNull, step): O(h), with no recursion. When a problem needs the in-order, a BST's in-order is its sorted order, so sorting the values replaces the stack (230, 450). 98 carries its bounds down level by level, and 99 is the one problem that genuinely needs the in-order sequence of nodes.

LC 700 · Search in a Binary Search Tree · clean
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        // One path down: the BST order picks the side, and the
        // walk ends at the value or falls off the tree.
        return Stream.iterate(root, Objects::nonNull,
                        n -> val < n.val ? n.left : n.right)
                .filter(n -> n.val == val)
                .findFirst().orElse(null);
    }
}
LC 235 · Lowest Common Ancestor of a BST · clean
class Solution {
    public TreeNode lowestCommonAncestor(
            TreeNode root, TreeNode p, TreeNode q) {
        // -1: both below-left, +1: both below-right, 0: split.
        ToIntFunction<TreeNode> side = n ->
                p.val < n.val && q.val < n.val ? -1
                : p.val > n.val && q.val > n.val ? 1 : 0;
        // Walk down until p and q stop agreeing on a side.
        return Stream.iterate(root, n -> side.applyAsInt(n) < 0
                                         ? n.left : n.right)
                .filter(n -> side.applyAsInt(n) == 0)
                .findFirst().get();
    }
}
LC 98 · Validate Binary Search Tree · clean
class Solution {
    // a node, and the open interval its value must lie in
    record Box(TreeNode node, long lo, long hi) {
        boolean ok() { return lo < node.val && node.val < hi; }
        Stream<Box> children() {
            return Stream.of(new Box(node.left, lo, node.val),
                             new Box(node.right, node.val, hi))
                    .filter(b -> b.node() != null);
        }
    }

    public boolean isValidBST(TreeNode root) {
        // Carry each node's bounds down with it, level by
        // level; long bounds so Integer.MIN_VALUE is allowed.
        Box top = new Box(root, Long.MIN_VALUE, Long.MAX_VALUE);
        return Stream.iterate(List.of(top), l -> !l.isEmpty(),
                        l -> l.stream().flatMap(Box::children)
                                .toList())
                .flatMap(List::stream)
                .allMatch(Box::ok);
    }
}
LC 230 · Kth Smallest Element in a BST · clean
class Solution {
    public int kthSmallest(TreeNode root, int k) {
        // A BST's in-order IS its sorted order. Sorting every
        // value reaches it with no stack and no recursion.
        return levels(root)
                .flatMap(List::stream)
                .mapToInt(n -> n.val)
                .sorted()
                .skip(k - 1)
                .findFirst().getAsInt();
    }

    // ---- the level walk from the tree slides ----
    static Stream<List<TreeNode>> levels(TreeNode root) {
        List<TreeNode> first = root == null ? List.of()
                                            : List.of(root);
        return Stream.iterate(first, l -> !l.isEmpty(),
                              Solution::below);
    }

    static List<TreeNode> below(List<TreeNode> level) {
        return level.stream()
                .flatMap(n -> Stream.of(n.left, n.right))
                .filter(Objects::nonNull)
                .toList();
    }
}
LC 450 · Delete Node in a BST · clean
class Solution {
    public TreeNode deleteNode(TreeNode root, int key) {
        // Every value but the key, sorted, rebuilt as a
        // balanced BST. The shape changes; the judge accepts
        // any valid BST that holds the right values.
        int[] vals = levels(root)
                .flatMap(List::stream)
                .mapToInt(n -> n.val)
                .filter(v -> v != key)
                .sorted()
                .toArray();
        return build(vals, 0, vals.length);
    }

    // balanced BST over sorted a[lo, hi); depth is only log n
    static TreeNode build(int[] a, int lo, int hi) {
        if (lo >= hi) return null;
        int mid = (lo + hi) >>> 1;
        return new TreeNode(a[mid], build(a, lo, mid),
                            build(a, mid + 1, hi));
    }

    // ---- the level walk from the tree slides ----
    static Stream<List<TreeNode>> levels(TreeNode root) {
        List<TreeNode> first = root == null ? List.of()
                                            : List.of(root);
        return Stream.iterate(first, l -> !l.isEmpty(),
                              Solution::below);
    }

    static List<TreeNode> below(List<TreeNode> level) {
        return level.stream()
                .flatMap(n -> Stream.of(n.left, n.right))
                .filter(Objects::nonNull)
                .toList();
    }
}
LC 99 · Recover Binary Search Tree · clean
class Solution {
    public void recoverTree(TreeNode root) {
        List<TreeNode> in = inorder(root).toList();
        int[] sorted = in.stream().mapToInt(n -> n.val)
                .sorted().toArray();
        // The in-order differs from sorted order at exactly the
        // two swapped nodes. Swap their values back.
        int[] bad = IntStream.range(0, in.size())
                .filter(i -> in.get(i).val != sorted[i])
                .toArray();
        TreeNode a = in.get(bad[0]), b = in.get(bad[1]);
        int t = a.val;
        a.val = b.val;
        b.val = t;
    }

    // Recursion through Stream.concat: fine at n <= 1000, but
    // it costs far more stack per level than plain recursion.
    static Stream<TreeNode> inorder(TreeNode n) {
        return n == null ? Stream.empty()
                : Stream.concat(inorder(n.left), Stream.concat(
                        Stream.of(n), inorder(n.right)));
    }
}
The ordering does the work700 and 235 never branch. The BST order tells each step which child to take, so the whole search is a single Stream.iterate down one path: O(h) time, O(1) space, no recursion. Whenever a BST problem follows one path, this is its stream form, and it reads as well as the loop.
Sorting instead of walking230 and 450 sort all n values instead of walking in order, trading O(h + k) and O(h) for O(n log n). That is only honest because the constraints allow it. The in-order walk itself needs a stack. Recursing through Stream.concat to get it is safe only while the tree stays shallow: 99's 1,000-deep worst case passes on a 1 MB stack even in a cold JVM, but 230 and 450 allow ten times that depth.
