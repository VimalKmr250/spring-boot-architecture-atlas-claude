A fresh row per item makes 0/1 knapsack clean; reuse makes it state

The loop version walks capacity backwards because it overwrites one row in place, and walking forwards would count an item twice. Build a new row from the old one for each item and that hazard disappears: every entry reads only the previous row, so Stream.iterate(seed, step).skip(n) folds the items cleanly, at the price of one array per item. That covers 416, 494, 1049, 474 and 879. 518 is the opposite case: an unbounded item may be reused, which means reading the row being built, so it is stateful by design.

LC 416 · Partition Equal Subset Sum · clean
class Solution {
    public boolean canPartition(int[] nums) {
        int total = Arrays.stream(nums).sum();
        if (total % 2 == 1) return false;
        int half = total / 2;
        int[] start = new int[half + 1];
        start[0] = 1;                       // the empty subset reaches 0
        // can[s] is 1 if some subset of the items so far sums to s.
        // Each item maps the old row to a NEW row: nothing is overwritten.
        record Row(int i, int[] can) {}
        Row last = Stream.iterate(new Row(0, start), r -> new Row(r.i() + 1,
                        IntStream.rangeClosed(0, half)
                                .map(s -> r.can()[s] == 1
                                        || s >= nums[r.i()] && r.can()[s - nums[r.i()]] == 1 ? 1 : 0)
                                .toArray()))
                .skip(nums.length).findFirst().get();
        return last.can()[half] == 1;
    }
}
LC 494 · Target Sum · clean
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int total = Arrays.stream(nums).sum();
        // The plus signs pick a subset P with sum(P) = (total + target) / 2.
        if (Math.abs(target) > total || (total + target) % 2 != 0) return 0;
        int p = (total + target) / 2;
        int[] start = new int[p + 1];
        start[0] = 1;
        // ways[s]: subsets of the items so far that sum to s. A zero
        // doubles every count, which the formula handles on its own.
        record Row(int i, int[] ways) {}
        return Stream.iterate(new Row(0, start), r -> new Row(r.i() + 1,
                        IntStream.rangeClosed(0, p)
                                .map(s -> r.ways()[s]
                                        + (s >= nums[r.i()] ? r.ways()[s - nums[r.i()]] : 0))
                                .toArray()))
                .skip(nums.length).findFirst().get().ways()[p];
    }
}
LC 1049 · Last Stone Weight II · clean
class Solution {
    public int lastStoneWeightII(int[] stones) {
        // Smashing splits the stones into two piles; what is left is
        // |P - N|. Get one pile as close to total / 2 as possible.
        int total = Arrays.stream(stones).sum();
        int half = total / 2;
        int[] start = new int[half + 1];
        start[0] = 1;
        record Row(int i, int[] can) {}
        int[] can = Stream.iterate(new Row(0, start), r -> new Row(r.i() + 1,
                        IntStream.rangeClosed(0, half)
                                .map(s -> r.can()[s] == 1
                                        || s >= stones[r.i()] && r.can()[s - stones[r.i()]] == 1 ? 1 : 0)
                                .toArray()))
                .skip(stones.length).findFirst().get().can();
        int best = IntStream.rangeClosed(0, half).filter(s -> can[s] == 1).max().getAsInt();
        return total - 2 * best;
    }
}
LC 518 · Coin Change II · stateful
class Solution {
    public int change(int amount, int[] coins) {
        int[] ways = new int[amount + 1];
        ways[0] = 1;
        // Coins outer, so each combination is counted once, in coin
        // order. Ascending a reads ways[a - c] AFTER this coin's pass
        // updated it: that reuse is what "unbounded" means, and it is state.
        Arrays.stream(coins).forEach(c ->
                IntStream.rangeClosed(c, amount).forEach(a -> ways[a] += ways[a - c]));
        return ways[amount];
    }
}
LC 474 · Ones and Zeroes · clean
class Solution {
    public int findMaxForm(String[] strs, int m, int n) {
        // best[i][j]: the largest subset of the strings so far that fits
        // in i zeros and j ones. Each string builds a NEW table.
        record Table(int k, int[][] best) {}
        return Stream.iterate(new Table(0, new int[m + 1][n + 1]), t -> {
                    String s = strs[t.k()];
                    int zeros = (int) s.chars().filter(ch -> ch == '0').count();
                    int ones = s.length() - zeros;
                    int[][] b = t.best();
                    return new Table(t.k() + 1, IntStream.rangeClosed(0, m)
                            .mapToObj(i -> IntStream.rangeClosed(0, n)
                                    .map(j -> i >= zeros && j >= ones
                                            ? Math.max(b[i][j], b[i - zeros][j - ones] + 1)
                                            : b[i][j])
                                    .toArray())
                            .toArray(int[][]::new));
                })
                .skip(strs.length).findFirst().get().best()[m][n];
    }
}
LC 879 · Profitable Schemes · clean
class Solution {
    public int profitableSchemes(int n, int minProfit, int[] group, int[] profit) {
        int mod = 1_000_000_007;
        // f[g][p]: schemes among the crimes so far using AT MOST g members
        // with profit AT LEAST p. Taking crime k leaves p - profit[k] to
        // find elsewhere, and anything at or below 0 is already met.
        int[][] start = new int[n + 1][minProfit + 1];
        Arrays.stream(start).forEach(row -> row[0] = 1);   // the empty scheme
        record Table(int k, int[][] f) {}
        return Stream.iterate(new Table(0, start), t -> {
                    int g0 = group[t.k()], p0 = profit[t.k()];
                    int[][] f = t.f();
                    return new Table(t.k() + 1, IntStream.rangeClosed(0, n)
                            .mapToObj(g -> IntStream.rangeClosed(0, minProfit)
                                    .map(p -> (f[g][p]
                                            + (g >= g0 ? f[g - g0][Math.max(0, p - p0)] : 0)) % mod)
                                    .toArray())
                            .toArray(int[][]::new));
                })
                .skip(group.length).findFirst().get().f()[n][minProfit];
    }
}
A new row removes the backwards loopThe in-place loop walks s from the top down so that dp[s] reads dp[s - x] before this item overwrites it. Mapping the old row to a new one reads only old values, in any order, so the pipeline is clean and the direction no longer matters. The cost is an allocation per item: still O(sum) live memory, because each old row becomes garbage, but n arrays are created and dropped. 879's "at least p" definition is what lets each entry pull from exactly one old entry, f[g - g0][max(0, p - p0)], instead of summing over several.
518 cannot take a fresh rowAn unbounded coin may be used again, so the recurrence is new[a] = old[a] + new[a - c]: it reads the row being built. Any stream that writes that row is stateful, and the ascending order is load-bearing. Swap the loops, amounts outer and coins inner, and you count ordered sequences instead of combinations: that is 377, Combination Sum IV.
