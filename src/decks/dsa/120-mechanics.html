Answer "are these two connected?" in almost constant time

A traversal can tell you the components of a graph you already have. Union-find handles the harder case: edges arriving one at a time, with connectivity queries interleaved. Each element points at a parent; the root of that chain names the component.

Two operations, two optimisations

find(x)
Walk parent links to the root. Path compression re-points every node on the way directly at the root, so the next walk is one step.
union(a, b)
Find both roots; if they differ, attach one to the other. Union by size attaches the smaller tree under the larger, keeping the structure shallow.

Either optimisation alone is good; together they give O(α(n)) amortised — the inverse Ackermann function, which is below 5 for any input that fits in memory. Call it "effectively constant" rather than claiming O(1).

Without them, a chain of unions builds a linked list and every find is O(n).

The return value that does the work

Make union return a boolean: true if it merged two distinct components, false if they were already connected.

That single value answers most problems in this family directly. A false means the edge closed a cycle. Counting the true results tells you how many merges happened, so components = n − merges with no second pass.

Keeping a live component counter inside the structure is even simpler: start at n and decrement on every successful union.

Applies when

Edges arrive incrementally and you need connectivity as you go, or the question is about components, redundant edges, or merging equivalence classes. Also the core of Kruskal's spanning-tree algorithm.

Does not apply when

Edges are removed — union-find cannot split a set, and the standard workaround is to process the timeline backwards so deletions become insertions. Also when you need the path itself, not just whether one exists.

Complexity

O(α(n)) amortised per operation with both optimisations, so O(E·α(n)) overall — effectively linear. Space is O(n) for the parent and size arrays.

The tell is grouping by equivalence, or edges arriving as a list you process one by one.
