Every pattern's figure, and the sentence that derives it

The five steps, applied to each pattern's reusable structure. The two right-hand columns are the part to say out loud: if you can state where the time and the space go, the figure follows — and you can rebuild it for any variant. Variables: n input length, k window, heap or distinct-value count, L word length, h tree height, R × C a grid, V and E a graph's vertices and edges. In pattern 5 only, V is the width of the answer range.

1Sliding WindowO(n)O(k)r admits each index once and l evicts each at most once: at most 2n moves.Window state over k distinct values; a fixed int[128] makes it O(1).
2Two PointersO(n)
O(n log n) if sorted first
O(nk−1) for k-sum		O(1)Every step shrinks the gap r − l, so at most n steps. k-sum wraps k − 2 anchor loops around that pass.Two indices — the sort's working memory aside.
3Fast / Slow PointersO(n)O(1)Phase 1 ends within the tail plus one lap, L + C ≤ n steps; phase 2 walks the tail, L steps.Two references. A visited set also works, at O(n).
4Binary Search on Sorted DataO(log n)O(1)The range halves every iteration: after t steps n / 2t remain, which is 1 at t = log₂ n.Iterative. A recursive version adds an O(log n) stack for nothing.
5Binary Search on AnswerO(n log V)O(1)log₂ V halvings of the answer range, each paying for one O(n) feasibility pass.The check keeps a few counters.
6Hashing / Frequency MapsO(n) average
O(n·L) string keys		O(n)n inserts and lookups at O(1) average each, plus O(L) to hash a string key.One entry per distinct key.
7Prefix Sum / Running SumO(n) build
O(1) per query		O(n)One pass, pre[i + 1] = pre[i] + a[i]; a range query subtracts two entries.The prefix array, or a map of the prefix sums seen so far.
8Difference Array / Range UpdatesO(n + q)O(n)Each of q updates touches two cells; a single prefix pass rebuilds the array.The difference array itself.
9Monotonic StackO(n)O(n)Each index is pushed once and popped at most once: at most 2n operations.Sorted input never pops, so the stack can hold all n.
10Monotonic Queue / DequeO(n)O(k)Each index is added once and removed at most once, from either end.At most one window's k indices; over prefix sums, as in 862, up to n.
11Heap / Top KO(n log k)O(k)n offers into a heap capped at k, each costing O(log k).The heap never holds more than k + 1 entries.
12IntervalsO(n log n)O(1)
O(n) with a heap		The sort by start dominates; the sweep after it is O(n).Merging writes only the output; 253 keeps a heap of up to n end times.
13Greedy Scheduling / SortingO(n)
O(n log n) with a sort		O(1)One pass making the locally best choice, plus a sort when the choice needs an order. 406's list inserts are the exception, at O(n²).A few running values, or a 26-slot count.
14Linked List ManipulationO(n)
O(n log k) for k lists		O(1)
O(k) for k lists		Each node is relinked once. A k-way merge passes every node through a heap of size k.Pointer variables if iterative; the heap of k list heads for 23.
15Tree DFSO(n)O(h)Each node is visited once with O(1) work: T(n) = 2T(n/2) + O(1) when balanced.One stack frame per level of the current path — log n balanced, n skewed.
16Tree BFS / Level OrderO(n)O(w)Each node is enqueued and dequeued once.The queue holds about one level; the widest is about n/2.
17BST ProblemsO(h) per operation
O(n) in-order		O(1) iterative
O(h) recursive		One comparison per level discards an entire subtree.One pointer iteratively; one frame per level recursively.
18Backtracking BasicsO(n·2ⁿ)
O(n·n!)		O(n)2ⁿ subsets or n! permutations, each copied into the answer in O(n).The path plus a stack n deep; the answers are output.
19Backtracking with ConstraintsO(m·n·4L)
O(n!)		O(L)
O(n)		Branching factor to the power of the depth, from every start. Pruning cuts the practical cost, not the worst case.Stack depth, plus the constraint sets — N-Queens' column and diagonal flags.
20Graph BFS / DFSO(R·C)O(R·C)Each cell is queued once and checks four neighbours.The visited grid, and a frontier that can hold much of it.
21Topological Sort / DAGO(V + E)O(V + E)Each node is dequeued once; each edge decrements an indegree once.The adjacency list, plus the indegree array and the queue.
22Union Find / DSUO(E·α(n))O(n)E unions or finds at O(α(n)) amortised each, with path compression and union by size.The parent and size arrays.
23Shortest PathO(E log E)
O(k·E) Bellman-Ford		O(V + E)Each edge can push one heap entry, and each push or poll costs O(log E). Bellman-Ford relaxes all E edges once per round.The graph, the distances, and a heap that may hold stale entries under lazy deletion.
24MST / Graph GreedyO(E log E)O(V + E)Kruskal sorts the edges, then runs E finds at α(n) each. Prim with a heap is O(E log V).The edge list plus DSU arrays; array-based Prim on a complete graph needs only O(V).
25TrieO(L) per operationO(chars × 26)One node per character of the word, with an O(1) child lookup at each.One node per inserted character, each carrying a 26-slot child array.
26Bit ManipulationO(n)
O(1) per integer		O(1)The word size is fixed at 32 or 64 bits, so any loop over the bits is constant.A few integers.
271D DP BasicsO(states × transitions)O(n) → O(1)States × work per state: 70 is n × 1, 300 is n × n (or n log n by patience sorting), 322 is amount × coins.The table; a fixed lookback rolls into a few variables.
28Knapsack / Subset DPO(n × capacity)O(capacity)n items × capacity values, O(1) per cell — pseudo-polynomial, since it grows with the capacity's magnitude.One row, with capacity iterated downwards for 0/1 items so each is used once.
29Grid DPO(R·C)O(C)Each cell is computed once from O(1) neighbours.A rolling row; O(1) if overwriting the grid is allowed.
30String DP / Sequence DPO(m·n)O(min(m, n))One cell per pair of prefixes, O(1) each.Two rolling rows, laid along the shorter string.
