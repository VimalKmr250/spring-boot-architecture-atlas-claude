A greedy remembers two or three numbers, so it folds cleanly

A greedy algorithm scans once and remembers very little: a reach, a tank, a start. That is exactly a small record folded over the input with Stream.iterate, and the fold is as fast as the loop. Jump Game goes one better. Its reachable indices come in ranges, one per jump, so it is breadth-first search where each level is a range. 621 needs no scan at all, because its greedy has a closed form.

LC 55 · Jump Game · clean
class Solution {
    // indices reachable in exactly one more jump: [from, to]
    record Level(int from, int to) {
        Level next(int[] nums) {
            int reach = IntStream.rangeClosed(from, to)
                    .map(i -> i + nums[i]).max().getAsInt();
            return new Level(to + 1, reach);   // empty if stuck
        }
        boolean done(int n) { return to >= n - 1 || from > to; }
    }

    public boolean canJump(int[] nums) {
        int n = nums.length;
        // BFS where every level is a range. Stop when a level
        // reaches the end, or comes out empty.
        Level last = Stream.iterate(new Level(0, 0),
                                    l -> l.next(nums))
                .filter(l -> l.done(n))
                .findFirst().get();
        return last.to() >= n - 1;
    }
}
LC 45 · Jump Game II · clean
class Solution {
    // the indices reachable in exactly k jumps: [from, to]
    record Level(int from, int to) {
        Level next(int[] nums) {
            int reach = IntStream.rangeClosed(from, to)
                    .map(i -> i + nums[i]).max().getAsInt();
            return new Level(to + 1, reach);
        }
    }

    public int jump(int[] nums) {
        int n = nums.length;
        // Level k holds every index first reachable in k jumps,
        // so the answer is how many levels come before the end.
        return (int) Stream.iterate(new Level(0, 0),
                                    l -> l.next(nums))
                .takeWhile(l -> l.to() < n - 1)
                .count();
    }
}
LC 763 · Partition Labels · clean
class Solution {
    public List<Integer> partitionLabels(String s) {
        int n = s.length();
        int[] last = IntStream.range(0, 26)
                .map(c -> s.lastIndexOf('a' + c)).toArray();
        // A part ends at i when no letter seen so far appears
        // after i. n <= 500, so recomputing that prefix max per
        // i (O(n²)) is fine, and it keeps the pipeline pure.
        IntPredicate endsPart = i -> IntStream.rangeClosed(0, i)
                .map(j -> last[s.charAt(j) - 'a'])
                .max().getAsInt() == i;
        int[] ends = IntStream.concat(IntStream.of(-1),
                        IntStream.range(0, n).filter(endsPart))
                .toArray();
        return IntStream.range(1, ends.length)
                .mapToObj(k -> ends[k] - ends[k - 1])
                .toList();
    }
}
LC 406 · Queue Reconstruction by Height · clean
class Solution {
    // everyone placed so far, as an immutable list
    record Line(int i, List<int[]> people) {
        Line place(int[] p) {
            // Everyone already placed is taller or equal, so
            // p's k is exactly its index among them.
            int k = p[1];
            List<int[]> next = Stream.of(
                    people.subList(0, k).stream(),
                    Stream.of(p),
                    people.subList(k, people.size()).stream())
                    .flatMap(s -> s).toList();
            return new Line(i + 1, next);
        }
    }

    public int[][] reconstructQueue(int[][] people) {
        // Tallest first; among equals, fewest in front first.
        Comparator<int[]> tallFirst = Comparator
                .<int[]>comparingInt(p -> -p[0])
                .thenComparingInt(p -> p[1]);
        int[][] order = Arrays.stream(people).sorted(tallFirst)
                .toArray(int[][]::new);
        return Stream.iterate(new Line(0, List.of()),
                              l -> l.place(order[l.i()]))
                .skip(order.length)
                .findFirst().get().people()
                .toArray(int[][]::new);
    }
}
LC 621 · Task Scheduler · clean
class Solution {
    public int leastInterval(char[] tasks, int n) {
        Collection<Long> freq = new String(tasks).chars()
                .boxed()
                .collect(Collectors.groupingBy(
                        c -> c, Collectors.counting()))
                .values();
        long max = Collections.max(freq);
        long tied = freq.stream().filter(f -> f == max).count();
        // (max - 1) frames of n + 1 slots, plus one slot per
        // task tied at max; or no idling at all, if more.
        long framed = (max - 1) * (n + 1) + tied;
        return (int) Math.max(tasks.length, framed);
    }
}
LC 134 · Gas Station · clean
class Solution {
    // the greedy's state: station, fuel in the tank, where this
    // attempt began, and the net total over the whole loop
    record Trip(int i, int tank, int start, int total) {
        Trip next(int d) {
            int t = total + d;
            return tank + d < 0
                    ? new Trip(i + 1, 0, i + 1, t)
                    : new Trip(i + 1, tank + d, start, t);
        }
    }

    public int canCompleteCircuit(int[] gas, int[] cost) {
        // Running dry at i rules out every start up to i, so
        // the next attempt begins at i + 1. One pass decides.
        Trip end = Stream.iterate(new Trip(0, 0, 0, 0),
                        t -> t.next(gas[t.i()] - cost[t.i()]))
                .skip(gas.length)
                .findFirst().get();
        return end.total() >= 0 ? end.start() : -1;
    }
}
Why greedy suits streamsA greedy never looks back, so its state is a handful of numbers rather than a structure. That makes this the one pattern where every fold is both pure and as fast as the loop. The record holds the loop's local variables, and next() is the loop body.
Jump Game is BFSWriting 45 as levels of ranges shows why the greedy is optimal. Level k is exactly the set of indices first reachable in k jumps, and the answer is the first level that contains the end. The loop version tracks the same two boundaries under the names curEnd and farthest, and saying so in an interview is worth more than either version of the code.
