Top K is sorted().limit(k): you pay log n instead of log k

A heap is a mutable structure that a pipeline cannot own halfway through, but top-K has a direct substitute: sorted with the right comparator, then limit(k). It sorts everything, so it pays O(n log n) where the size-k heap pays O(n log k). That is fine at these limits, and the comparator is the same one you would hand the heap. The two exceptions are 703, where the heap is the design itself, and 1046, where n ≤ 30 lets a pure simulation replace the heap entirely.

LC 215 · Kth Largest Element in an Array · clean
class Solution {
    public int findKthLargest(int[] nums, int k) {
        // Sort ascending, then skip to the kth from the end.
        // sorted() on an IntStream stays primitive: no boxing.
        return Arrays.stream(nums).sorted()
                .skip(nums.length - k)
                .findFirst().getAsInt();
    }
}
LC 703 · Kth Largest Element in a Stream · stateful
class KthLargest {
    private final int k;
    // min-heap of the k largest values seen so far
    private final Queue<Integer> heap = new PriorityQueue<>();

    public KthLargest(int k, int[] nums) {
        this.k = k;
        // The stream only feeds the heap. The heap is the
        // design: it outlives every call, so no pipeline can
        // own it.
        Arrays.stream(nums).forEach(this::add);
    }

    public int add(int val) {
        heap.offer(val);
        if (heap.size() > k) heap.poll();
        return heap.peek();
    }
}
LC 973 · K Closest Points to Origin · clean
class Solution {
    public int[][] kClosest(int[][] points, int k) {
        // Squared distance keeps it in ints (at most 2·10⁸)
        // and needs no square root: the order is the same.
        return Arrays.stream(points)
                .sorted(Comparator.comparingInt(
                        p -> p[0] * p[0] + p[1] * p[1]))
                .limit(k)
                .toArray(int[][]::new);
    }
}
LC 347 · Top K Frequent Elements · clean
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        // Count, then sort the entries by count, descending.
        // The hashing slides do this in O(n) with buckets. This
        // is the O(n log n) form a heap cuts to O(n log k).
        return Arrays.stream(nums).boxed()
                .collect(Collectors.groupingBy(
                        v -> v, Collectors.counting()))
                .entrySet().stream()
                .sorted(Map.Entry
                        .<Integer, Long>comparingByValue()
                        .reversed())
                .limit(k)
                .mapToInt(Map.Entry::getKey)
                .toArray();
    }
}
LC 692 · Top K Frequent Words · clean
class Solution {
    public List<String> topKFrequent(String[] words, int k) {
        Map<String, Long> freq = Arrays.stream(words)
                .collect(Collectors.groupingBy(
                        w -> w, Collectors.counting()));
        // One comparator: count descending, then the word. The
        // heap version needs exactly this, reversed.
        Comparator<String> byCount =
                Comparator.comparing(freq::get);
        return freq.keySet().stream()
                .sorted(byCount.reversed().thenComparing(
                        Comparator.naturalOrder()))
                .limit(k)
                .toList();
    }
}
LC 1046 · Last Stone Weight · clean
class Solution {
    public int lastStoneWeight(int[] stones) {
        // n <= 30, so a pure simulation is fine: every smash
        // builds a fresh sorted list. No heap is mutated.
        List<Integer> start = Arrays.stream(stones).boxed()
                .sorted(Comparator.reverseOrder()).toList();
        return Stream.iterate(start, Solution::smash)
                .filter(l -> l.size() <= 1)
                .findFirst().get()
                .stream().findFirst().orElse(0);
    }

    // l is sorted heaviest first; its two heaviest collide
    static List<Integer> smash(List<Integer> l) {
        int left = l.get(0) - l.get(1);
        return Stream.concat(l.stream().skip(2),
                             Stream.of(left).filter(w -> w > 0))
                .sorted(Comparator.reverseOrder())
                .toList();
    }
}
Say the trade out loudsorted() is a full barrier: it takes in all n elements before limit sees a single one. At n = 10⁵ that is still milliseconds. Name it anyway: "this is O(n log n), and a size-k heap would make it O(n log k)". That sentence is the whole point of the pattern.
The comparator is the reusable part692's comparator (count descending, then the word) is exactly what the heap solution needs, reversed for a min-heap of size k. Writing it for sorted() and writing it for the PriorityQueue is the same decision. The stream version just lets you test that decision on its own before the heap arrives.
