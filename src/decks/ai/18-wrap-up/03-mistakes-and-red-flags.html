Mistakes that sink AI projects, and phrases that sink interviews

The left column is what goes wrong in real projects; every item has a slide in this tab with the fix. The right column is what interviewers hear as a red flag, with what to say instead.

In projects

  • No evaluation set. Changes judged by a few hand-picked questions; regressions found by customers.
  • Retrieval without access control. Every employee can read every document through the assistant.
  • The model chooses whose data it touches. Customer ids as tool arguments instead of ToolContext.
  • Free-text parsing. Regular expressions over prose instead of .entity() and validation.
  • Unbounded loops and retries. Default retry settings and no tool limits on a user-facing path.
  • Prompts in string concatenation. Untracked, untested, with volatile values that defeat caching.
  • Stale indexes. Deleted or updated documents still answering questions months later.
  • One shared ChatClient.Builder mutated for several clients, mixing their system prompts.
  • Prompts and answers in logs by default, with personal data and confidential context.
  • Fine-tuning to add knowledge that RAG would have provided, current and cited.
Red flag in an interviewSay instead
"Set temperature to 0 to stop hallucinations.""Ground answers in retrieved sources, require citations, allow 'I don't know', and measure faithfulness."
"The system prompt tells it not to reveal other customers' data.""The retrieval filter and tool authorisation make other customers' data unreachable."
"We'll fine-tune it on our documents.""RAG for knowledge; fine-tuning only for behaviour, after evaluation."
"It worked in my testing.""It scores 0.91 on a 150-question golden set that runs in CI."
"We'll use an agent.""A routing workflow; an agent only for the open-ended investigation step, bounded."
"The model calculates the totals.""Code computes figures; the model explains them, and a check rejects any number not in the data."
"We just call the OpenAI API.""Behind ChatClient, with timeouts, a fallback, metrics and a budget."
