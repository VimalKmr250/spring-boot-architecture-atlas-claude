Workflows follow paths you wrote; agents choose their own. Start with workflows.

An agent is a model in a loop: it decides which tool to call next, reads the result, and repeats until it judges the task done. A workflow is your code calling models at fixed steps. Workflows are predictable, testable and cheap; agents handle open-ended tasks at the price of variable cost, latency and behaviour. Five workflow patterns cover most enterprise needs, and each is ordinary Spring code around ChatClient.

Most "agents" should be workflows

If you can draw the flowchart, write it as code: each step is a ChatClient call with structured output, and the branches are if statements you can unit-test.

When an agent earns it

The steps genuinely cannot be known in advance (investigating an incident, researching across systems), the value justifies variable cost, and mistakes can be caught before they matter.

Spring AI building blocks

Tool calling and its limits for the loop, MCP for tools owned by other teams, structured output for decisions, memory for multi-turn tasks, observability for every step. The community spring-ai-agent-utils project adds higher-level agent primitives.
