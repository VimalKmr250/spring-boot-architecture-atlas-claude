Automated reports: code computes every number, the model only explains them

Weekly sales commentary, monthly operations reviews, board-pack narratives: analysts spend days turning dashboards into prose. An LLM drafts that prose in seconds, but a single invented percentage destroys trust in the whole report. The design rule is absolute: figures come from queries into a typed snapshot, the model writes only from the snapshot, code verifies that every number in the draft exists in the snapshot, and a person approves before it is sent.

Why not let the model query?

Text-to-SQL is tempting, but a wrong join produces a plausible wrong number with no signal. For recurring reports, fixed and reviewed queries are cheaper, faster and auditable. Keep text-to-SQL for ad-hoc analyst exploration with the generated SQL shown.

What the model is good at here

Choosing what matters this week, explaining movements in plain language, consistent structure and tone, and adapting the same snapshot for executives, store managers and finance.

Caveats are a feature

Ask for a caveats section: data gaps, unusual events, metrics that moved for known reasons. Analysts trust drafts that admit uncertainty more than drafts that sound certain.
