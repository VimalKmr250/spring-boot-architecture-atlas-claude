.entity(Record.class): the model fills in your type, Jackson does the rest

Most enterprise LLM calls feed code, not people: a classifier's label, extracted invoice fields, a routing decision. Parsing free text with regular expressions breaks on the first creative answer. Spring AI derives a JSON Schema from your record, tells the model to follow it, and converts the reply back into the record.

ReviewInsightService.java
package com.acme.ai.structured;

import com.fasterxml.jackson.annotation.JsonPropertyDescription;
import java.util.List;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Service
class ReviewInsightService {

    enum Sentiment { POSITIVE, NEGATIVE, MIXED }

    record ReviewInsight(
            @JsonPropertyDescription("Overall sentiment of the review")
            Sentiment sentiment,
            @JsonPropertyDescription("Product aspects mentioned, e.g. delivery, quality")
            List<String> aspects,
            @JsonPropertyDescription("1 = very unhappy, 5 = delighted")
            int score) {}

    private final ChatClient chatClient;

    ReviewInsightService(ChatClient.Builder builder) {
        this.chatClient = builder
                .defaultSystem("You analyse customer reviews for Acme Retail.")
                .build();
    }

    ReviewInsight analyse(String review) {
        return chatClient.prompt()
                .user(u -> u.text("Analyse this review: <review>{review}</review>")
                        .param("review", review))
                .call()
                .entity(ReviewInsight.class);
    }
}

Descriptions are prompt text@JsonPropertyDescription ends up in the schema the model reads. Use it to define each field precisely, including units and ranges. Enums become an enum list, the cheapest way to force a closed set of labels. The converter also strips markdown fences, as the second block shows.
