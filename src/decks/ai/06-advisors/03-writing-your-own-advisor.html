A custom advisor: redact personal data before anything else sees it

Implement BaseAdvisor when you only need to change the request on the way in or the response on the way out: it supplies both the blocking and the streaming paths from your before and after. Implement CallAdvisor and StreamAdvisor directly when you need to wrap the call, for example to time it, retry it, or skip the model entirely.

PiiRedactionAdvisor.java
package com.acme.ai.advisors;

import java.util.regex.Pattern;
import org.springframework.ai.chat.client.ChatClientRequest;
import org.springframework.ai.chat.client.ChatClientResponse;
import org.springframework.ai.chat.client.advisor.api.AdvisorChain;
import org.springframework.ai.chat.client.advisor.api.BaseAdvisor;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.core.Ordered;

/** Masks e-mail addresses, card numbers and phone numbers in the user's message. */
public class PiiRedactionAdvisor implements BaseAdvisor {

    public static final String REDACTED_COUNT = "pii.redacted.count";

    private static final Pattern EMAIL = Pattern.compile("[\\w.+-]+@[\\w-]+(\\.[\\w-]+)+");
    private static final Pattern CARD = Pattern.compile("\\b\\d(?:[ -]?\\d){12,18}\\b");
    private static final Pattern PHONE = Pattern.compile("\\+?\\d[\\d ()-]{7,}\\d");

    @Override
    public ChatClientRequest before(ChatClientRequest request, AdvisorChain chain) {
        int[] count = {0};
        Prompt redacted = request.prompt().augmentUserMessage(user -> user.mutate()
                .text(redact(user.getText(), count))
                .build());
        return request.mutate()
                .prompt(redacted)
                .context(REDACTED_COUNT, count[0])     // visible to later advisors
                .build();
    }

    @Override
    public ChatClientResponse after(ChatClientResponse response, AdvisorChain chain) {
        return response;                               // nothing to undo on the way out
    }

    /** Before memory (HIGHEST + 200), so raw values are never stored either. */
    @Override
    public int getOrder() {
        return Ordered.HIGHEST_PRECEDENCE + 100;
    }

    static String redact(String text, int[] count) {
        String out = text;
        for (var rule : new Object[][] {{CARD, "[CARD]"}, {EMAIL, "[EMAIL]"}, {PHONE, "[PHONE]"}}) {
            var matcher = ((Pattern) rule[0]).matcher(out);
            StringBuilder sb = new StringBuilder();
            while (matcher.find()) {
                count[0]++;
                matcher.appendReplacement(sb, (String) rule[1]);
            }
            out = matcher.appendTail(sb).toString();
        }
        return out;
    }
}

Good uses for a custom advisor
Redaction and data-classification checks
Per-tenant or per-user token budgets: check before, count after
A semantic cache: answer from a cache of similar questions, skip the model
Adding the user's locale, plan or permissions to the system message
Audit records: who asked what, which documents were used
Regex is a floor, not a ceilingPatterns catch well-formed e-mails and card numbers. Names, addresses and free-text identifiers need a proper PII detection service. Treat this advisor as the place where that service is called, not as the whole solution.
