Semantic search: retrieval without generation is often the whole feature

Many "AI search" requests do not need a chat model at all. Users want to type "warm light for a reading corner" and get lamps, or "parcel says delivered but isn't here" and get the right help article. Embedding-based search over a vector store delivers that with no hallucination risk, millisecond latency and almost no per-query cost. Add a generated answer on top only if users need one.

ProductSearchController.java
package com.acme.ai.usecases.search;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import java.util.List;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
class ProductSearchController {

    record Hit(String sku, String name, String category, double score) {}

    private final VectorStore vectorStore;

    ProductSearchController(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    @GetMapping("/api/products/search")
    List<Hit> search(@RequestParam @NotBlank @Size(max = 200) String q,
                     @RequestParam(required = false) String category,
                     @RequestParam(defaultValue = "12") @Min(1) @Max(50) int limit) {
        var f = new FilterExpressionBuilder();
        var filter = category == null
                ? f.eq("inStock", true)
                : f.and(f.eq("inStock", true), f.eq("category", category));
        return vectorStore.similaritySearch(SearchRequest.builder()
                        .query(q)
                        .topK(limit)
                        .similarityThreshold(0.3)
                        .filterExpression(filter.build())
                        .build())
                .stream()
                .map(ProductSearchController::toHit)
                .toList();
    }

    private static Hit toHit(Document d) {
        var md = d.getMetadata();
        return new Hit((String) md.get("sku"), (String) md.get("name"),
                (String) md.get("category"), d.getScore() == null ? 0 : d.getScore());
    }
}

Make it production-gradeHow
Exact SKUs and brand namesHybrid search: keyword plus vector, fused
Fresh indexRe-index on product change events, not nightly only
Business rankingBlend similarity with stock, margin or popularity after retrieval
LatencyCache embeddings of frequent queries; the query embedding is the slow part
QualityTrack zero-result and no-click searches; label them; tune
Say it in the interview"Semantic search is the lowest-risk AI feature: embeddings and a vector store, no generation. I'd ship it with hybrid retrieval for exact terms, metadata filters, and click-through metrics before adding any generated answers."
