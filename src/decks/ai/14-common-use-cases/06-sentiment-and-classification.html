Classifying millions of texts: small model, closed labels, batches, and a labelled sample

Sentiment analysis, topic tagging and intent detection are classification: a closed set of labels per item. At scale the economics dominate. Use the smallest model that meets your accuracy target, an enum so outputs cannot drift, several items per call to share the instructions, and a labelled sample to measure accuracy per class, because overall accuracy hides the class that matters.

ReviewSentimentClassifier.java
package com.acme.ai.usecases.sentiment;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.function.Function;
import java.util.stream.Collectors;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Service
class ReviewSentimentClassifier {

    enum Sentiment { POSITIVE, NEUTRAL, NEGATIVE, MIXED }

    enum Aspect { DELIVERY, QUALITY, PRICE, SERVICE, ASSEMBLY, OTHER }

    record Review(String id, String text) {}

    record Label(String id, Sentiment sentiment, List<Aspect> aspects) {}

    record LabelBatch(List<Label> labels) {}

    private static final int BATCH = 25;

    private final ChatClient chatClient;

    ReviewSentimentClassifier(ChatClient.Builder builder) {
        this.chatClient = builder
                .defaultSystem("""
                        Label each customer review. One label per input line, same id.
                        MIXED means clearly positive and negative points together.""")
                .build();
    }

    List<Label> classify(List<Review> reviews) {
        List<Label> out = new ArrayList<>();
        for (int i = 0; i < reviews.size(); i += BATCH) {
            List<Review> batch = reviews.subList(i, Math.min(i + BATCH, reviews.size()));
            String lines = batch.stream()
                    .map(r -> r.id() + "\t" + r.text().replaceAll("\\s+", " "))
                    .collect(Collectors.joining("\n"));
            LabelBatch result = chatClient.prompt()
                    .user(u -> u.text("Reviews (id TAB text):\n{lines}").param("lines", lines))
                    .call()
                    .entity(LabelBatch.class);

            // never trust the batch blindly: keep only ids we sent, flag the rest
            Map<String, Label> byId = result.labels().stream()
                    .collect(Collectors.toMap(Label::id, Function.identity(), (a, b) -> a));
            for (Review r : batch) {
                out.add(byId.getOrDefault(r.id(), new Label(r.id(), null, List.of())));
            }
        }
        return out;   // labels with a null sentiment go to a retry or review queue
    }
}

Measure per classA classifier that is 92% accurate overall can still miss half of the NEGATIVE reviews, which are the ones operations care about. Keep a few hundred human-labelled reviews, report precision and recall per label, and re-check monthly and after any model or prompt change.
Batches fail differentlyA malformed batch loses 25 labels at once, and models sometimes skip or merge lines. Match results to ids, as above; retry missing ones individually; cap batch size by tokens, not just count.
