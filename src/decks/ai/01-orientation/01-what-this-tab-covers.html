Spring AI: LLM features built like any other Spring Boot feature

This tab teaches you to add large language models to an enterprise Spring Boot application with the same habits you use everywhere else: an injected client, typed results, configuration properties, tests and metrics. It starts with what an LLM actually does, works through the Spring AI API, prompts, structured output, memory and tools, then grounds the model in your own data with embeddings, vector stores and RAG. It ends with fine-tuning, agents, nine use cases, production concerns and the interview.

2.0

Spring AI 2.0.1 on Spring Boot 4.1 and Java 21. Boxes tagged 1.x mark what is different in Spring AI 1.0/1.1, because many codebases have not upgraded yet.

How to use it

  • Arrow keys move through slides; C opens contents.
  • New to LLMs? Read LLM fundamentals first. Every later section assumes tokens, temperature and context windows.
  • Already shipping Spring AI? Start at the advisor chain and RAG, then read the migration slide.
  • Preparing for an interview? Each slide ends with a callout you can say out loud; the questions section links back here.
How the code is writtenA code label that starts with a file name, such as SupportController.java, is a complete file. Every one compiles against Spring AI 2.0.1 and Spring Boot 4.1.1 with javac --release 21 -Xlint:all, without warnings. Every spring.ai.* property on a slide is checked against the configuration metadata in the 2.0.1 jars. Blocks labelled with "verified" or "Spring AI 2.0.1 output" show what the code actually did, run against a stub model. Model replies are labelled Sample response: the same prompt gives different words on every run, so they show the shape, not exact output.
