One BOM, one starter per provider, and a profile that runs without an API key

Every example in this tab runs on this setup. OpenAI is the default for chat and embeddings, because most enterprises start there and its starter also talks to Azure OpenAI and OpenAI-compatible gateways. The ollama profile swaps both models for local ones, so you can run every slide on a laptop with no key and no cost.

pom.xml · the parts that matter (Maven)
<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>4.1.1</version>
</parent>

<properties>
  <java.version>21</java.version>
  <spring-ai.version>2.0.1</spring-ai.version>
</properties>

<dependencyManagement>
  <dependencies>
    <dependency>   <!-- one version for every Spring AI module -->
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>${spring-ai.version}</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>
  </dependency>
  <dependency>   <!-- ChatModel + EmbeddingModel + ChatClient.Builder -->
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-openai</artifactId>
  </dependency>
  <dependency>   <!-- local models for the ollama profile -->
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-ollama</artifactId>
  </dependency>
</dependencies>
src/main/resources/application.yml
spring:
  application:
    name: acme-assistant
  ai:
    model:
      chat: openai           # two starters on the classpath:
      embedding: openai      # say which one creates the beans
    openai:
      api-key: ${OPENAI_API_KEY}   # from the environment, never the repo
      chat:
        model: gpt-5-mini
      embedding:
        model: text-embedding-3-small
src/main/resources/application-ollama.yml
spring:
  ai:
    model:
      chat: ollama
      embedding: ollama
    ollama:
      base-url: http://localhost:11434
      init:
        pull-model-strategy: when_missing   # downloads on first start
      chat:
        model: qwen3:4b
      embedding:
        model: nomic-embed-text
Run it
export OPENAI_API_KEY=...          # or set it in your IDE run config
./mvnw spring-boot:run

# no key: install Ollama, then
./mvnw spring-boot:run -Dspring-boot.run.profiles=ollama

Why spring.ai.model.chat

Each provider's auto-configuration creates its ChatModel when that property is missing. With two starters you would get two ChatModel beans, and the auto-configured ChatClient.Builder needs exactly one. Naming the provider keeps one.

Gradle

implementation(platform("org.springframework.ai:spring-ai-bom:2.0.1")) then implementation("org.springframework.ai:spring-ai-starter-model-openai"). The BOM keeps every module on the same version.

1.x property names

Spring AI 1.x put model options under an extra segment: spring.ai.openai.chat.options.model. In 2.0 it is spring.ai.openai.chat.model. The old keys still bind in 2.0 but are deprecated, so the IDE flags them; move to the flat form before they are removed.
