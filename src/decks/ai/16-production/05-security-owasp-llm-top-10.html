Security: map the OWASP Top 10 for LLM applications onto your Spring code

The OWASP Top 10 for LLM Applications (2025 edition) is the checklist security teams will use to review your feature. Each risk maps to a control you have already seen in this tab. Walking through the list with the control that answers each item is a strong interview answer and a good design-review agenda.

RiskIn practiceControl in a Spring AI application
LLM01 Prompt injectionInstructions hidden in user input, documents, tool resultsDelimit and label untrusted text; least-privilege tools; confirm side effects; validate outputs
LLM02 Sensitive information disclosurePII or secrets in prompts, logs, answersRedaction advisor before memory; content kept out of telemetry; access filters on retrieval
LLM03 Supply chainUnvetted models, MCP servers, plugins, datasetsApproved providers and model ids; vetted MCP servers; dependency scanning
LLM04 Data and model poisoningMalicious content in the RAG corpus or training dataIngest only from trusted sources; review fine-tuning data; provenance metadata
LLM05 Improper output handlingModel output rendered as HTML, run as SQL or shellTreat output as untrusted: escape, structured output, never execute it directly
LLM06 Excessive agencyTools that can do more than the use case needsPer-role tool sets; ToolContext identity; pending actions; tool limits
LLM07 System prompt leakageUsers extract the system prompt and the secrets in itAssume prompts are public; no credentials, internal URLs or rules that only work if secret
LLM08 Vector and embedding weaknessesCross-tenant retrieval; stale ACLsFilters from the principal; ACL sync; isolation tests
LLM09 MisinformationConfident, wrong answers acted onGrounding with citations; "I don't know"; evaluation; human review for high stakes
LLM10 Unbounded consumptionCost or capacity exhausted by loops or abuseInput size limits, rate limits, token budgets, tool-call limits, timeouts

Data handling with providers

Use enterprise terms with no training on your data and a defined retention period; choose the region; prefer a cloud platform or self-hosted model where data must not leave your boundary.

Secrets

API keys from a vault, injected as environment variables or Spring Cloud config, rotated, scoped per environment. Never in application.yml in the repository, and never in a prompt.

Say it in the interview"I treat the model as an untrusted component: everything it reads may be hostile and everything it writes is unvalidated input. Identity, authorisation and limits live in code around it, and I can walk the OWASP LLM list control by control."
