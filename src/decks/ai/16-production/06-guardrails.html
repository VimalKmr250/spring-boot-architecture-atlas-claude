Guardrails: cheap checks before the model, strict checks after it

Guardrails are checks around the model call that block, rewrite or escalate. Input guards stop abusive, off-topic or oversized requests before you pay for them. Output guards stop harmful content, broken formats, unapproved links and leaked data from reaching users. Layer them from cheapest to most expensive, and log every block: blocks are both a security signal and a quality signal.

GuardedAssistant.java
package com.acme.ai.ops;

import java.util.List;
import java.util.Set;
import java.util.regex.Pattern;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.SafeGuardAdvisor;
import org.springframework.ai.moderation.Moderation;
import org.springframework.ai.moderation.ModerationModel;
import org.springframework.ai.moderation.ModerationPrompt;
import org.springframework.ai.moderation.ModerationResult;
import org.springframework.core.Ordered;
import org.springframework.stereotype.Service;

@Service
class GuardedAssistant {

    sealed interface Reply permits Answer, Blocked {}
    record Answer(String text) implements Reply {}
    record Blocked(String reason) implements Reply {}

    private static final Pattern LINK_HOST = Pattern.compile("https?://([\\w.-]+)");
    private static final Set<String> APPROVED_HOSTS = Set.of("acme.example", "help.acme.example");

    private final ChatClient chatClient;
    private final ModerationModel moderation;

    GuardedAssistant(ChatClient.Builder builder, ModerationModel moderation) {
        this.chatClient = builder
                .defaultSystem("You are Acme Retail's assistant. Link only to acme.example pages.")
                .defaultAdvisors(SafeGuardAdvisor.builder()                 // cheapest: a word list
                        .sensitiveWords(List.of("ignore previous instructions", "reveal your system prompt"))
                        .failureResponse("I can't help with that request.")
                        .order(Ordered.HIGHEST_PRECEDENCE)
                        .build())
                .build();
        this.moderation = moderation;
    }

    Reply ask(String question) {
        if (question.length() > 4_000) {
            return new Blocked("too long");                                  // free
        }
        if (flagged(question)) {
            return new Blocked("input flagged by moderation");               // cheap model
        }
        String text = chatClient.prompt().user(question).call().content();
        if (flagged(text)) {
            return new Blocked("output flagged by moderation");
        }
        boolean foreignLink = LINK_HOST.matcher(text).results()
                .map(m -> m.group(1).toLowerCase())
                .anyMatch(host -> !APPROVED_HOSTS.contains(host));
        if (foreignLink) {
            return new Blocked("answer links to an unapproved site");       // exfiltration guard
        }
        return new Answer(text);
    }

    private boolean flagged(String text) {
        Moderation result = moderation.call(new ModerationPrompt(text)).getResult().getOutput();
        return result.getResults().stream().anyMatch(ModerationResult::isFlagged);
    }
}
GuardCatchesCost
Size, rate and format limitsAbuse, accidental pastes, cost attacksFree
SafeGuardAdvisor word listKnown bad phrases; trivially bypassedFree
Moderation model (ModerationModel)Hate, harassment, self-harm, violenceLow; a separate fast model
Topic classifier (small LLM)Off-topic and out-of-scope requestsLow
Structured output + validationMalformed or out-of-range answersFree to cheap
Grounding and citation checksUnsupported claimsMedium
Human reviewHigh-stakes outputs, sampled outputsPeople's time
Guardrails reduce risk; they do not remove itWord lists and classifiers are bypassable, and output guards see only the text, not the consequences. The controls that hold under attack are structural: what the tools can do, whose data retrieval can reach, and which actions need a person.
Streaming changes output guardsWhen you stream, users see text before an output check can run. Stream only where the risk is low, buffer and check for sensitive use cases, or moderate in chunks and cut the stream when a chunk is flagged.
