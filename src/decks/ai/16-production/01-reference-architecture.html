An AI feature in production is a normal service with three extra dependencies

The AI parts are a model provider, a vector store and an ingestion pipeline. Everything else is the architecture you already run: an API gateway, identity, a stateless service, a database, observability and CI/CD. Most failures in AI projects come from treating the model call as special instead of applying those existing disciplines to it.

Why an LLM gateway

Large organisations put a gateway between apps and providers to centralise keys, quotas per team, logging, redaction and model routing. If it speaks the OpenAI API, Spring AI needs only a base-url change.

Keep the service stateless

Conversation state in the database, vectors in the store, configuration in config. Then the AI service scales horizontally and deploys like every other service.

The next seven slides

Observability, cost, resilience, security, guardrails, testing and performance: each is an existing discipline with an AI-specific twist.
