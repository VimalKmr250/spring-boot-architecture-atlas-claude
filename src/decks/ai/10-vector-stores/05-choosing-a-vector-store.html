Choose the store your team can operate, then check it meets the numbers

Spring AI 2.0 ships starters for more than twenty vector stores behind one VectorStore interface, so the decision is reversible in code, though not in data: switching means re-indexing. Start from what you already run and what your security team has approved; move to a dedicated engine when scale, query rate or hybrid search demand it.

StorePick it whenWatch out for

Qdrant · Milvus · WeaviateDedicated engine: hundreds of millions of vectors, high QPS, advanced filteringAnother system to run, secure and back up
PineconeFully managed, no operationsData leaves your network; per-usage pricing

SimpleVectorStoreUnit tests, demos, a few thousand documents in memoryNot for production: no persistence guarantees, linear search

The questions to ask

How many vectors in two years? Queries per second at peak? Do filters need to be fast and selective? Is hybrid keyword search needed? Where must the data reside? Who is on call for it?

Keep the source of truth elsewhere

A vector store is a derived index, like a search index. Keep original documents and metadata in their system of record so any index can be rebuilt from scratch, with a new model or a new store.

Say it in the interview

"I'd start with pgvector because we already run PostgreSQL and it keeps vectors next to the data with one security model. If we need hybrid search or outgrow it, the VectorStore abstraction lets us move to Elasticsearch or Qdrant with a re-index, not a rewrite."
