A user may only retrieve what they may read: enforce it in the query

A vector store has no idea who is asking. If tenant A's contract is the nearest neighbour to tenant B's question, it comes back, goes into the prompt, and the model happily quotes it. Access control must therefore be part of every search, built from the authenticated user on the server, never from anything the client or the model supplies.

SecureDocumentSearch.java
package com.acme.ai.vectors;

import java.util.List;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.filter.Filter;
import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Service;

@Service
class SecureDocumentSearch {

    private final VectorStore vectorStore;

    SecureDocumentSearch(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    List<Document> search(String question) {
        return vectorStore.similaritySearch(SearchRequest.builder()
                .query(question)
                .topK(8)
                .similarityThreshold(0.3)
                .filterExpression(accessFilter())
                .build());
    }

    /** tenant == current tenant AND the document is shared with one of the user's groups. */
    static Filter.Expression accessFilter() {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null || !auth.isAuthenticated()) {
            throw new IllegalStateException("search requires an authenticated user");
        }
        List<Object> groups = auth.getAuthorities().stream()
                .map(GrantedAuthority::getAuthority)
                .filter(a -> a.startsWith("GROUP_"))
                .map(a -> (Object) a)
                .toList();
        String tenant = tenantOf(auth);
        var f = new FilterExpressionBuilder();
        return groups.isEmpty()
                ? f.and(f.eq("tenant", tenant), f.eq("visibility", "TENANT")).build()
                : f.and(f.eq("tenant", tenant),
                        f.or(f.eq("visibility", "TENANT"), f.in("aclGroup", groups))).build();
    }

    private static String tenantOf(Authentication auth) {
        // e.g. from a JWT claim; here the first TENANT_ authority
        return auth.getAuthorities().stream()
                .map(GrantedAuthority::getAuthority)
                .filter(a -> a.startsWith("TENANT_"))
                .map(a -> a.substring("TENANT_".length()))
                .findFirst()
                .orElseThrow(() -> new IllegalStateException("user has no tenant"));
    }
}
IsolationHowTrade-off
Filter columnOne table; tenant in metadata; filter on every querySimplest; one forgotten filter leaks data; noisy neighbours share the index
Table or collection per tenantOne VectorStore bean per tenant, chosen per requestHard isolation, easy deletion; many indexes to build and monitor
Database or cluster per tenantSeparate infrastructureFor regulated or very large tenants; highest cost
Copy permissions at ingestion, keep them freshThe ACL metadata is a copy of permissions from SharePoint, Confluence or the file system. When a document's audience changes in the source, the vector store must change too, or revoked users keep retrieving it. Re-sync ACLs on change events or on a short schedule, and delete vectors when the source document is deleted.
Test the leak, not just the featureWrite an integration test that indexes a document for tenant A and asserts that tenant B's search, with the most similar possible question, returns nothing. Run it on every build.
Say it in the interview"Retrieval is where most RAG data leaks happen, so the filter is built server-side from the authenticated principal: tenant plus ACL groups copied from the source system, kept in sync, with a test that proves cross-tenant isolation."
