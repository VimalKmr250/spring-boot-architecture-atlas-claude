Exact search compares everything; an ANN index trades a little recall for speed

Finding the nearest vectors exactly means comparing the query with every stored vector: fine for ten thousand, too slow for ten million. Vector stores build an approximate nearest neighbour (ANN) index that visits only a small part of the data. The price is recall: occasionally the true nearest neighbour is missed. Knowing the two common index types, and the knobs that move that trade-off, is a standard interview topic.

Default to HNSWIt is the default in pgvector, Redis, Elasticsearch, OpenSearch and most dedicated stores, and the Spring AI PgVector default too. Raise ef_search when recall is too low; it costs latency, not rebuilds.
Measure recall, not just latencyCompare the ANN results with an exact search on a sample of queries. An index that answers in 5 ms but misses the right passage 10% of the time quietly degrades every RAG answer built on it.
Filters and ANN interactA selective metadata filter ("only tenant 42") applied after the ANN search can leave fewer than top-K results. Stores handle this differently (pre-filtering, iterative scans, partial indexes); test your filters with realistic selectivity.
