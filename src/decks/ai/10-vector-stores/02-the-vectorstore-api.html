VectorStore: add documents, search by meaning, filter by metadata

A Document is text plus a metadata map plus an id. add() embeds the text with the configured EmbeddingModel and stores all three. similaritySearch() embeds the query and returns the nearest documents, each with a score, after applying a metadata filter. The same code runs on PgVector, Redis, Elasticsearch, Qdrant and a dozen other stores.

ProductIndex.java
package com.acme.ai.vectors;

import java.math.BigDecimal;
import java.nio.charset.StandardCharsets;
import java.util.List;
import java.util.Map;
import java.util.UUID;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;
import org.springframework.stereotype.Service;

@Service
class ProductIndex {

    record Product(String sku, String name, String description,
                   String category, BigDecimal price, boolean inStock) {}

    private final VectorStore vectorStore;

    ProductIndex(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    /** A stable id per SKU makes add() an upsert: re-indexing replaces, never duplicates. */
    static String idFor(String sku) {
        return UUID.nameUUIDFromBytes(sku.getBytes(StandardCharsets.UTF_8)).toString();
    }

    void index(List<Product> products) {
        vectorStore.add(products.stream().map(p -> Document.builder()
                .id(idFor(p.sku()))
                .text(p.name() + "\n" + p.description())        // what gets embedded
                .metadata(Map.of(
                        "sku", p.sku(),
                        "category", p.category(),
                        "price", p.price().doubleValue(),
                        "inStock", p.inStock()))
                .build()).toList());
    }

    List<Document> search(String query, String category, double maxPrice) {
        var f = new FilterExpressionBuilder();
        return vectorStore.similaritySearch(SearchRequest.builder()
                .query(query)
                .topK(10)                      // default is 4
                .similarityThreshold(0.35)     // drop weak matches (default accepts all)
                .filterExpression(f.and(
                        f.and(f.eq("category", category), f.lte("price", maxPrice)),
                        f.eq("inStock", true)).build())
                .build());
    }

    /** The same filter in the portable text syntax. */
    List<Document> searchLighting(String query) {
        return vectorStore.similaritySearch(SearchRequest.builder()
                .query(query)
                .topK(10)
                .filterExpression("category == 'lighting' && price <= 80 && inStock == true")
                .build());
    }

    void remove(String sku) {
        vectorStore.delete(List.of(idFor(sku)));
    }

    void removeCategory(String category) {
        vectorStore.delete(new FilterExpressionBuilder().eq("category", category).build());
    }
}
Filter expression syntax (portable)
category == 'lighting'                     equality, also !=
price <= 80 && price > 20                   < <= > >=, AND
region in ['EU', 'UK']                      IN, NIN
tenant == 'acme' && (year >= 2024 || pinned == true)
NOT (status == 'archived')
discontinuedAt IS NULL                      IS NULL, IS NOT NULL
ConcernPractice
IdsDeterministic ids (from SKU, document path + chunk number) so re-ingestion upserts. PgVector's default id type is UUID, hence nameUUIDFromBytes.
MetadataOnly what you filter or cite on: tenant, source, ACL groups, dates, language. Every key is stored on every vector.
ScoresDocument.getScore() on results; log them to tune the threshold.
Embedded textEmbed what users will search for (name + description), not internal codes; keep codes in metadata for exact filters.
Upserts, verifiedOn PgVector, add() runs INSERT … ON CONFLICT (id) DO UPDATE (checked in the 2.0.1 jar), so the same id overwrites content, metadata and embedding.
