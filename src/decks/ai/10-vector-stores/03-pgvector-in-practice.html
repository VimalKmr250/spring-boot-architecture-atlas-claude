PgVector: vectors in the PostgreSQL you already run

For most enterprises the first vector store should be the database they already operate, back up and secure. The pgvector extension adds a vector column type and HNSW indexes to PostgreSQL; Spring AI's PgVector starter maps VectorStore onto one table. Let the starter create the schema on a laptop; in production, own it with Flyway like every other table.

pom.xml (excerpt)
<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-starter-vector-store-pgvector</artifactId>
</dependency>
<dependency>   <!-- starts compose.yaml with the app in development -->
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-docker-compose</artifactId>
  <optional>true</optional>
</dependency>
compose.yaml
services:
  postgres:
    image: pgvector/pgvector:pg17
    environment:
      POSTGRES_DB: acme
      POSTGRES_USER: acme
      POSTGRES_PASSWORD: secret
    ports: ["5432"]
    labels:
      # the image is not called "postgres", so tell Boot what it is
      org.springframework.boot.service-connection: postgres
application.yml
spring:
  ai:
    vectorstore:
      pgvector:
        dimensions: 1536              # must match the embedding model
        index-type: hnsw              # default
        distance-type: cosine-distance
        initialize-schema: false      # Flyway owns it
        schema-validation: true       # fail fast if the table does not match
src/main/resources/db/migration/V7__vector_store.sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- the shape Spring AI 2.0.1 creates itself, made explicit
CREATE TABLE IF NOT EXISTS vector_store (
    id        uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    content   text,
    metadata  json,
    embedding vector(1536)
);

CREATE INDEX IF NOT EXISTS vector_store_embedding_idx
    ON vector_store USING hnsw (embedding vector_cosine_ops);

-- serves metadata filters, which run as JSONPath on metadata::jsonb
CREATE INDEX IF NOT EXISTS vector_store_metadata_idx
    ON vector_store USING gin ((metadata::jsonb) jsonb_path_ops);
A filter as PgVector runs it · Spring AI 2.0.1
tenant == 'acme' && category in ['lighting','textiles'] && price <= 80
→ metadata::jsonb @@ '$."tenant" == "acme" && ($."category" == "lighting"
     || $."category" == "textiles") && $."price" <= 80'::jsonpath

When PgVector is enough

Up to tens of millions of vectors, transactional updates next to your business data, joins and backups you already understand. Most internal assistants never outgrow it.

When to look further

Hundreds of millions of vectors, very high query rates, built-in hybrid keyword search, or a team that does not run PostgreSQL. See choosing a store.
