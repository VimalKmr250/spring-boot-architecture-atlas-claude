Stream tokens to the browser so a 10-second answer starts in one second

Total generation time is set by the model, but perceived latency is time to first token. .stream() returns a Flux that emits text as the model produces it. Spring MVC writes a Flux as server-sent events, so you do not need WebFlux for this.

StreamingController.java
package com.acme.ai.streaming;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.http.MediaType;
import org.springframework.http.codec.ServerSentEvent;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@RestController
class StreamingController {

    private final ChatClient chatClient;

    StreamingController(ChatClient.Builder builder) {
        this.chatClient = builder
                .defaultSystem("You are Acme Retail's assistant. Use short paragraphs.")
                .build();
    }

    /** Plain text chunks; the simplest form. */
    @GetMapping(value = "/api/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    Flux<String> stream(@RequestParam @NotBlank @Size(max = 2_000) String q) {
        return chatClient.prompt().user(q).stream().content();
    }

    /** Named events, so the client can tell tokens, the end and errors apart. */
    @GetMapping(value = "/api/stream/events", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    Flux<ServerSentEvent<String>> events(@RequestParam @NotBlank @Size(max = 2_000) String q) {
        return chatClient.prompt().user(q).stream().content()
                .map(chunk -> ServerSentEvent.builder(chunk).event("token").build())
                .concatWith(Mono.just(ServerSentEvent.builder("").event("done").build()))
                .onErrorResume(e -> Mono.just(ServerSentEvent
                        .builder("The assistant is unavailable. Please try again.")
                        .event("error").build()));
    }
}
The browser side (excerpt)
const es = new EventSource('/api/stream/events?q=' + encodeURIComponent(q));
es.addEventListener('token', e => { answer.textContent += e.data; });
es.addEventListener('done',  () => es.close());
es.addEventListener('error', e => { showError(e.data); es.close(); });
ConcernWhat to do
Proxies buffer the streamDisable response buffering for the route (nginx: X-Accel-Buffering: no), or tokens arrive all at once.
Long answers time outRaise spring.mvc.async.request-timeout above your longest expected answer.
Structured outputYou cannot parse JSON until the stream ends. Stream prose to people; use call().entity() for code.
Errors after the first tokenThe HTTP status is already 200. Send an error event, as above.
Token usageArrives on the last chunk. For OpenAI, enable it with OpenAiChatOptions.builder().streamUsage(true).
The user leavesCancelling the subscription stops the upstream call, so you stop paying for tokens nobody reads.
Advisors and streamingEvery advisor on a streaming request must implement StreamAdvisor. The built-in ones do; a custom advisor that only implements CallAdvisor is skipped on streams, which is an easy way to lose a guardrail. See custom advisors.
