Use ChatClient; drop to ChatModel only when you are building plumbing

ChatModel is one round trip to a provider: a Prompt in, a ChatResponse out. ChatClient wraps it with defaults, advisors, the tool-calling loop, templates and structured output. In Spring AI 2.0 the difference is sharper than before: the tool loop moved out of the model and into ChatClient's advisor chain.

ModelLevelExamples.java · the same question, two ways
package com.acme.ai.levels;

import java.util.List;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.messages.SystemMessage;
import org.springframework.ai.chat.messages.UserMessage;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.prompt.ChatOptions;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.stereotype.Component;

@Component
class ModelLevelExamples {

    private final ChatModel chatModel;
    private final ChatClient chatClient;

    ModelLevelExamples(ChatModel chatModel, ChatClient.Builder builder) {
        this.chatModel = chatModel;
        this.chatClient = builder.build();
    }

    /** Low level: you assemble the Prompt and unwrap the response. */
    String withChatModel(String question) {
        Prompt prompt = new Prompt(
                List.of(new SystemMessage("Answer in one sentence."),
                        new UserMessage(question)),
                ChatOptions.builder().maxTokens(200).build());
        ChatResponse response = chatModel.call(prompt);
        return response.getResult().getOutput().getText();
    }

    /** High level: the same request, plus everything advisors add. */
    String withChatClient(String question) {
        return chatClient.prompt()
                .system("Answer in one sentence.")
                .user(question)
                .options(ChatOptions.builder().maxTokens(200))
                .call()
                .content();
    }
}

1.x a behaviour changeIn Spring AI 1.x, ChatModel.call() executed tool calls internally. In 2.0 it returns the model's raw response, tool requests included. Code that called ChatModel directly and relied on tools now needs ChatClient, or a loop driven by ToolCallingManager.
Options are builders now.options(…) on ChatClient takes a ChatOptions.Builder, not a built instance, so Spring AI can merge your partial options with the client's defaults. Prompt still takes a built ChatOptions.
