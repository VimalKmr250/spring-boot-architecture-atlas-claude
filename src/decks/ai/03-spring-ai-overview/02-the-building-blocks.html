Two dozen types cover almost everything you will write

Spring AI has a large surface, but day-to-day code touches a small set of types. Learn these names and what each is responsible for; the rest of the tab uses them constantly, and interviewers expect you to place each one in the request flow.

TypePackage (org.springframework.ai.…)Responsibility
ChatClientchat.clientThe fluent API you inject (via ChatClient.Builder) and call. Holds defaults: system prompt, advisors, tools, options.
ChatModel · StreamingChatModelchat.modelThe provider-neutral model interface. One implementation per provider.
Prompt · Message · ChatOptionschat.prompt · chat.messagesA request: messages (SystemMessage, UserMessage, AssistantMessage, ToolResponseMessage) plus options.
ChatResponse · Usagechat.model · chat.metadataThe reply: generations, finish reason, model id, token counts.
PromptTemplatechat.promptRenders {placeholders} into text, from a string or a resource.
BeanOutputConverterconverterTurns the reply into a record or list; behind .entity().
Advisor (CallAdvisor, StreamAdvisor)chat.client.advisor.apiInterceptors around the model call: memory, RAG, tool loop, logging, guardrails.
ChatMemory · ChatMemoryRepositorychat.memoryWhich messages to keep per conversation, and where to store them.
@Tool · ToolCallback · ToolContexttool.annotation · tool · chat.modelMethods the model may ask your code to run, and request-scoped data passed to them.
EmbeddingModelembeddingText in, float[] out.
Document · DocumentReader · DocumentTransformer · DocumentWriterdocumentThe ETL pipeline: read files, split and enrich them, write them to a store.
VectorStore · SearchRequestvectorstoreStores documents with their embeddings; similarity search with metadata filters.
Evaluatorevaluation · chat.evaluationJudges an answer: relevant to the question? supported by the context?
Where the beans come fromA model starter auto-configures a ChatModel, an EmbeddingModel where the provider has one, and a prototype-scoped ChatClient.Builder. A vector store starter adds a VectorStore. A chat memory starter adds ChatMemory. You inject the builder, add your defaults, and build one ChatClient per use case.
Say it in the interview"ChatClient is the API, advisors are the extension points, ChatModel is the provider seam. Retrieval and memory are advisors, so I add them per client or per request instead of hand-building prompts."
