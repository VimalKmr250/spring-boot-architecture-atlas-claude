Spring AI is a portable API over models, plus the plumbing around them

Spring AI does for AI models what Spring Data does for databases: one programming model across providers, auto-configured from properties, with the cross-cutting concerns (memory, retrieval, tools, observability, retries) handled by the framework. You write against ChatClient; the starter on your classpath decides whether it talks to OpenAI, Anthropic, Bedrock or a local Ollama.

Portable, not lowest-common-denominator

The common options (model, temperature, maxTokens) are portable. Provider features such as OpenAI's reasoning effort or Anthropic's prompt caching are reached through provider option classes, like OpenAiChatOptions, without leaving the API.

Spring idioms throughout

Starters and auto-configuration, application.yml, beans you can override, @Tool on ordinary methods, Micrometer observations, Testcontainers support. Nothing about it feels like a Python port.

1.x what 2.0 changed

2.0 needs Boot 4 and Jackson 3, made the tool-call loop an advisor (ToolCallingAdvisor) instead of code inside each model, and made options immutable builders. The migration slide lists what breaks.
