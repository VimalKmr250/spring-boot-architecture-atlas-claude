Every response tells you what it cost; read it and record it

content() throws the metadata away. When you need the model id, finish reason or token counts, ask for the ChatResponse, or for responseEntity() to get a typed result and the metadata together. Spring AI also records the same numbers as Micrometer metrics, so dashboards and alerts come for free.

UsageAwareSummarizer.java
package com.acme.ai.usage;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.ResponseEntity;
import org.springframework.ai.chat.metadata.Usage;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.stereotype.Service;

@Service
class UsageAwareSummarizer {

    private static final Logger log = LoggerFactory.getLogger(UsageAwareSummarizer.class);

    record Summary(String title, String body) {}

    private final ChatClient chatClient;

    UsageAwareSummarizer(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    String summarize(String text) {
        ChatResponse response = chatClient.prompt()
                .system("Summarise in at most five sentences.")
                .user(text)
                .call()
                .chatResponse();

        Usage usage = response.getMetadata().getUsage();
        String finish = response.getResult().getMetadata().getFinishReason();
        log.info("model={} in={} out={} finish={}",
                response.getMetadata().getModel(),
                usage.getPromptTokens(), usage.getCompletionTokens(), finish);

        if ("LENGTH".equalsIgnoreCase(finish)) {      // cut off by maxTokens
            log.warn("summary truncated; raise the output budget");
        }
        return response.getResult().getOutput().getText();
    }

    /** Typed result and metadata in one call. */
    Summary summarizeTyped(String text) {
        ResponseEntity<ChatResponse, Summary> result = chatClient.prompt()
                .user(u -> u.text("Summarise this with a title: {text}").param("text", text))
                .call()
                .responseEntity(Summary.class);
        log.info("total tokens={}", result.response().getMetadata().getUsage().getTotalTokens());
        return result.entity();
    }
}

Cost per feature, not per appToken metrics are tagged by model, not by business feature. To answer "what does the support bot cost?", add your own tag: wrap calls in an observation with a feature key, or log the usage with the feature name as above and aggregate in your log platform.
Finish reasons to alert onLENGTH means the answer was cut off by the output limit. A content-filter finish means the provider refused or redacted. Both look like a normal 200 to your HTTP client; only the metadata tells you. Exact values vary by provider, so compare case-insensitively.
Prompt caching shows up here tooUsage exposes getCacheReadInputTokens() and getCacheWriteInputTokens(). If the read count stays at zero on repeated, identical prefixes, something in your prompt changes on every call.
