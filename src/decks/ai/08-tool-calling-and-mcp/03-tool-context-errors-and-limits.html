What goes back to the model: results, error messages, and when to stop

A tool's return value is serialised to JSON and sent to the model as a tool message. An exception is caught and its message is sent instead, so the model can apologise or try something else. returnDirect skips the second model call and hands the result straight to your code. Limits stop a confused model from looping.

ReturnLabelTools.java · returnDirect
package com.acme.ai.tools;

import org.springframework.ai.chat.model.ToolContext;
import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;

@Component
class ReturnLabelTools {

    record ReturnLabel(String orderId, String labelUrl) {}

    interface Returns {
        ReturnLabel createLabel(String orderId, String customerId);
    }

    private final Returns returns;

    ReturnLabelTools(Returns returns) {
        this.returns = returns;
    }

    /** The label goes straight back to the caller; the model does not rephrase it. */
    @Tool(description = "Creates a prepaid return label for one of the current customer's orders.",
          returnDirect = true)
    ReturnLabel createReturnLabel(@ToolParam(description = "Order id") String orderId,
                                  ToolContext context) {
        return returns.createLabel(orderId, (String) context.getContext().get("customerId"));
    }
}
application.yml · errors and limits
spring:
  ai:
    tools:
      throw-exception-on-error: false   # default: message goes to the model
      limits:
        max-total-tool-calls: 10        # default 150
        max-calls-per-tool-default: 3   # default 40
        on-limit-exceeded: return-error-response   # or throw (default)
SituationDo this
Expected failure (not found, not allowed)Throw with a short, user-safe message; the model explains it. Never put stack traces, SQL or internal ids in the message: the model may repeat it.
Unexpected failure (database down)Set throw-exception-on-error: true, or rethrow from a wrapper, so it reaches your error handling and alerts instead of becoming a polite apology.
Result the user should see verbatimreturnDirect = true: a label URL, a generated file id. One model call saved.
Huge result (a 5,000-row report)Return a summary or the top rows; the whole result goes into the next prompt and is billed.
Model loops between toolsLower the limits; return return-error-response so the model can wrap up instead of failing the request.
Tool results are untrusted input tooA tool that reads an e-mail, a web page or a supplier's document returns text written by someone else, and it goes into the prompt. Indirect prompt injection usually arrives this way: see defences.
