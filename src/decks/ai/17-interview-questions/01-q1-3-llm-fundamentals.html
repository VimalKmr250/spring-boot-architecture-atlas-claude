Three fundamentals questions that open most AI interviews

These 24 questions cover what interviewers ask about LLMs and Spring AI, from concepts to design scenarios. Each has a 30-second answer to give first and a go deeper paragraph for the follow-up. The links go to the slides that cover the topic; the browser's Back button returns you here.

How to practise with theseRead the question, look away, and answer out loud for thirty seconds with a concrete example: a class name, a property, a number. "I'd put a QuestionAnswerAdvisor with a tenant filter on the client" beats a definition of RAG every time.
Q1

What is an LLM, and why does it hallucinate?

30-second answerA large language model is a neural network trained to predict the next token. It generates text one token at a time by sampling from a probability distribution, with no lookup of facts and no memory between calls. It hallucinates because it produces what is plausible given its training, not what is true; when it lacks the information, a fluent invention is often the most likely continuation. So I supply facts through retrieval or tools, ask for citations, and allow "I don't know".

Go deeper: Hallucination gets worse when the question is outside the training data (your company's policies), when the context is long and the key fact sits in the middle, and when the prompt pressures the model to answer. Mention that low temperature does not fix it: it makes the model consistently pick its most likely continuation, which can be consistently wrong. The fixes are grounding, citation checks, structured output with validation, and evaluation.

Q2

Explain tokens and context windows. How would you estimate the cost of a feature?

30-second answerTokens are the sub-word units a model reads and writes; in English one token is about four characters. The context window is the maximum input plus output per call. Cost is input tokens times the input price plus output tokens times the higher output price. I estimate requests per day times average input and output tokens, remembering that system prompt, retrieved context and resent history are all input on every turn, so input usually dominates the bill.

Go deeper: Walk a number: 100,000 turns a day at 4,000 input and 250 output tokens is 400M input and 25M output tokens. Then the levers: trim history, retrieve fewer and better chunks, route easy calls to a small model, cache the stable prefix, cap output. Say you would measure real usage from ChatResponse.getMetadata().getUsage() and the gen_ai.client.token.usage metric rather than trusting the estimate.

Q3

What does temperature do? Does temperature 0 make a model deterministic?

30-second answerTemperature scales the next-token probabilities: low values make the most likely token dominate, high values flatten the distribution and add variety. I use 0–0.2 for extraction and classification and higher values for creative text. Temperature 0 is near-deterministic, not deterministic: batching and floating-point effects on the provider's hardware still change outputs occasionally, so tests must not expect exact strings.

Go deeper: Reasoning models, such as OpenAI's gpt-5 family and Anthropic's current Opus and Sonnet, reject a custom temperature and use an effort setting instead, so sampling options are not universally portable. Mention topP as the alternative knob (change one, not both), maxTokens to bound cost, and that in Spring AI portable options go through ChatOptions.builder() while provider-specific ones use classes such as OpenAiChatOptions.
