Three RAG questions: explain it, fix it, measure it

RAG is the most asked-about enterprise LLM pattern. Interviewers listen for the two pipelines, for access control, and for a debugging method that is stage by stage rather than "try a bigger model".

Q13

Explain retrieval-augmented generation and how you would build it with Spring AI.

30-second answerRAG answers from your own content by retrieving relevant passages and putting them in the prompt. Ingestion reads documents with a DocumentReader, splits them with TokenTextSplitter, adds metadata such as source and ACL groups, and writes them to a VectorStore, which embeds them. At question time a QuestionAnswerAdvisor or RetrievalAugmentationAdvisor searches with the user's access filter and adds the top chunks with a grounding instruction. The answer cites its sources.

Go deeper: Contrast the simple advisor with the modular one: query compression for follow-ups, multi-query expansion, a custom DocumentRetriever for hybrid search, post-processors for re-ranking, and allowEmptyContext(false) so the model declines when nothing relevant is found. Mention idempotent ingestion with stable ids and deletion of stale chunks.

Q14

Your RAG assistant gives poor answers. How do you find and fix the problem?

30-second answerStage by stage, using the retrieved chunk ids I log with every answer. Was the right document ingested and parsed? Was the right passage retrieved? If not, fix chunking, add hybrid search for exact terms, rewrite follow-up queries, or tune top-K and the threshold. If it was retrieved but the answer is still wrong, tighten the grounding instruction, reduce irrelevant context, and require citations. I change one stage at a time and re-run the evaluation set.

Go deeper: Most failures are retrieval and ingestion, not the model: stale or duplicate versions of a policy, tables split mid-row, boilerplate crowding out content, missing ACL metadata filtering out the answer. Re-ranking and contextual chunk headers are common high-value fixes. Only after retrieval is measurably good does a model change make sense.

Q15

How do you evaluate a RAG system?

30-second answerWith a golden set of real questions, each linked to the passage that answers it or marked unanswerable. I measure retrieval separately, recall at K and context precision, and generation separately: faithfulness to the retrieved context and relevance to the question, using Spring AI's FactCheckingEvaluator and RelevancyEvaluator as LLM judges, plus correct refusal of unanswerable questions. It runs in CI with thresholds, and nightly against the real model.

Go deeper: Judges are models too: use a strong one, keep it fixed while comparing changes, and spot-check its verdicts by hand. Add production signals: thumbs-down rate, escalations, questions with no sources. Grow the golden set from real failures so the same mistake cannot return unnoticed.
