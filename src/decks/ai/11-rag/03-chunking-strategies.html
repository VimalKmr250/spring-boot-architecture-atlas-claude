Chunking decides what can be found: cut along the document's own structure

A chunk is the unit of retrieval: it is embedded as one vector and pasted into the prompt as one passage. Too small, and a chunk lacks the context to answer anything ("it must be returned within 30 days" — what must?). Too large, and its vector averages several topics, so it matches nothing well, while every retrieved chunk costs prompt tokens. Splitting on headings, sections and paragraphs beats splitting on a token count alone.

StrategyHowGood for
Fixed tokensTokenTextSplitter: N tokens, cut at a sentence endUniform prose; the baseline to beat

OverlapRepeat the last 10–20% of a chunk at the start of the nextProse where answers span boundaries (TokenTextSplitter has no overlap option: write a splitter)

HeadingAwareSplitter.java
package com.acme.ai.rag.ingest;

import java.util.ArrayList;
import java.util.List;
import org.springframework.ai.document.Document;
import org.springframework.ai.transformer.splitter.TextSplitter;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;

/**
 * Splits Markdown-like text at headings, prefixes every chunk with its heading,
 * and only cuts long sections further by token count.
 */
class HeadingAwareSplitter extends TextSplitter {

    private final TokenTextSplitter longSections = TokenTextSplitter.builder()
            .withChunkSize(400)
            .build();

    @Override
    protected List<String> splitText(String text) {
        List<String> chunks = new ArrayList<>();
        String heading = "";
        StringBuilder section = new StringBuilder();
        for (String line : text.split("\n")) {
            if (line.startsWith("#")) {
                flush(heading, section, chunks);
                heading = line.replaceFirst("^#+\\s*", "");
                section.setLength(0);
            } else {
                section.append(line).append('\n');
            }
        }
        flush(heading, section, chunks);
        return chunks;
    }

    private void flush(String heading, StringBuilder section, List<String> out) {
        String body = section.toString().strip();
        if (body.isEmpty()) {
            return;
        }
        for (Document part : longSections.split(new Document(body))) {
            out.add(heading.isEmpty() ? part.getText() : heading + "\n" + part.getText());
        }
    }
}

Starting numbers

300–500 tokens per chunk, top-K of 4–8, for policy-style prose. FAQ entries and product records: one item per chunk, whatever its size. Then tune on your evaluation set, not by eye.

Clean before you split

Headers, footers, page numbers, cookie banners and navigation menus repeated on every page become thousands of near-identical chunks that crowd out real content. Strip them in a transformer before splitting.

Tables and code

Splitting a table mid-row destroys it. Keep tables whole, or convert each row to a sentence ("Plan Gold: 30-day returns, free collection") before embedding.
