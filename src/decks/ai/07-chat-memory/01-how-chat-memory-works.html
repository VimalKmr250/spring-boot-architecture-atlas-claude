Memory is an advisor that loads history before the call and saves it after

The model is stateless, so "memory" means your application keeps each conversation's messages and sends the relevant ones on every call. Spring AI splits the job in three: ChatMemoryRepository stores messages, ChatMemory decides which ones to keep (by default the last 20), and MessageChatMemoryAdvisor moves them in and out of the prompt, keyed by a conversation id you supply on each request.

Where the id comes from

Create it on the server when a conversation starts (a UUID; the JDBC table holds 36 characters), store which user owns it, and check ownership on every request. An id taken blindly from the client lets one user read another's conversation through the model.

Messages, not summaries

This advisor adds history as real user and assistant messages, the format models are trained on. VectorStoreChatMemoryAdvisor instead retrieves the most relevant past turns from a vector store and adds them to the system text.

1.x what changed

2.0 removed ChatMemory.DEFAULT_CONVERSATION_ID and the builder's conversationId(...): the id must arrive with each request. PromptChatMemoryAdvisor is gone, and the JDBC table gained a sequence_id column that existing tables need a migration for.
