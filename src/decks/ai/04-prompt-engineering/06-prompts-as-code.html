A prompt change is a code change: review it, test it, measure it

One edited sentence in a system prompt can change thousands of answers a day. Treat prompts the way you treat SQL migrations: in version control, reviewed, covered by fast tests that need no model, and by a slower evaluation run against a real model before release. Log the prompt version with every call, so a quality drop can be traced to the change that caused it.

SupportPromptTest.java · fast, no model needed
package com.acme.ai.prompts;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import java.util.Map;
import org.junit.jupiter.api.Test;
import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.core.io.ClassPathResource;
import org.springframework.core.io.Resource;

class SupportPromptTest {

    private final Resource template = new ClassPathResource("prompts/support-system.st");

    @Test
    void rendersWithEveryVariableFilled() {
        String text = PromptTemplate.builder()
                .resource(template)
                .variables(Map.of("company", "Acme Retail", "tone", "friendly"))
                .build()
                .render();

        assertThat(text).contains("Acme Retail").doesNotContain("{");
        // rules that must survive every edit
        assertThat(text).contains("Never invent order details");
        assertThat(text).contains("connect the customer with a person");
    }

    @Test
    void failsFastWhenAVariableIsMissing() {
        assertThatThrownBy(() -> PromptTemplate.builder()
                .resource(template)
                .variables(Map.of("company", "Acme Retail"))
                .build()
                .render())
                .isInstanceOf(IllegalStateException.class)
                .hasMessageContaining("tone");
    }
}

What the eval run checks

A fixed set of 50–200 real questions with expected facts or labels. Score with exact match for labels, assertions for structured output, and an evaluator model for prose. See evaluation.

Version in the metadata

Name prompt files with a version (support-system-v4.st) or keep a version line in them, and add it to your logs and observation tags. "Escalations doubled on Tuesday" then points straight at a commit.
