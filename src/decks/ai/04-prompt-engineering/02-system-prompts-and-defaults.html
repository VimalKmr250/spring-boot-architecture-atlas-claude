Keep system prompts in resources, fill them from configuration

A system prompt is configuration that happens to be prose. Keep it in a file under src/main/resources/prompts, review changes in pull requests, and fill the parts that differ per environment or brand from @ConfigurationProperties. Org-wide defaults that every client should get, such as a logging advisor, belong in a ChatClientBuilderCustomizer.

SupportClientConfig.java
package com.acme.ai.prompts;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.ChatClientBuilderCustomizer;
import org.springframework.ai.chat.client.advisor.SimpleLoggerAdvisor;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.io.Resource;

@ConfigurationProperties("acme.support")
record SupportProperties(String companyName, String tone, Resource systemPrompt) {}

@Configuration
@EnableConfigurationProperties(SupportProperties.class)
class SupportClientConfig {

    /** Applied to every auto-configured ChatClient.Builder in the app. */
    @Bean
    ChatClientBuilderCustomizer loggingDefaults() {
        return builder -> builder.defaultAdvisors(new SimpleLoggerAdvisor());
    }

    @Bean
    ChatClient supportChatClient(ChatClient.Builder builder, SupportProperties props) {
        return builder
                .defaultSystem(s -> s.text(props.systemPrompt())
                        .param("company", props.companyName())
                        .param("tone", props.tone()))
                .build();
    }
}
src/main/resources/prompts/support-system.st
You are the customer support assistant for {company}.
Your tone is {tone}.

Answer only questions about orders, deliveries, returns and
Acme products. For anything else, say politely that you can
only help with Acme orders and products.

Never invent order details, prices or policies. If the
information you were given does not answer the question,
say so and offer to connect the customer with a person.
application.yml
acme:
  support:
    company-name: Acme Retail
    tone: friendly and concise
    system-prompt: classpath:prompts/support-system.st
Keep volatile values out of the system promptToday's date, the user's name or a request id in the system message make every prompt different, so the provider cannot reuse its cached prefix and you pay full price for the same 1,500 tokens on every call. Put per-request values in the user message, after the stable part.
Templates use {braces}The default renderer is StringTemplate. A prompt that contains literal JSON braces needs different delimiters: see Prompt templates.
