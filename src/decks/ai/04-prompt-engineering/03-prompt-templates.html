Templates keep prompt text and data apart, and fail loudly on a missing value

Never build prompts with string concatenation. A template keeps the wording in one reviewable place, fills it with named values, and with the default validation mode throws when a placeholder has no value instead of sending the model a prompt with a hole in it. Spring AI renders templates with StringTemplate, using {name} placeholders.

ProductCopyService.java
package com.acme.ai.templates;

import java.util.List;
import java.util.Map;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.ai.template.st.StTemplateRenderer;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.core.io.Resource;
import org.springframework.stereotype.Service;

@Service
class ProductCopyService {

    record Product(String name, List<String> features, String audience) {}

    private final ChatClient chatClient;
    private final Resource copyTemplate;

    ProductCopyService(ChatClient.Builder builder,
                       @Value("classpath:prompts/product-copy.st") Resource copyTemplate) {
        this.chatClient = builder.build();
        this.copyTemplate = copyTemplate;
    }

    /** A template from a resource, filled per request. */
    String describe(Product p) {
        return chatClient.prompt()
                .user(u -> u.text(copyTemplate)
                        .param("name", p.name())
                        .param("features", String.join(", ", p.features()))
                        .param("audience", p.audience()))
                .call()
                .content();
    }

    /** JSON in the prompt: switch delimiters so its braces stay literal. */
    String parseOrderNote(String note) {
        return chatClient.prompt()
                .templateRenderer(StTemplateRenderer.builder()
                        .startDelimiterToken('<')
                        .endDelimiterToken('>')
                        .build())
                .user(u -> u.text("""
                        Return JSON shaped like {"sku": "...", "qty": 0}
                        for this order note: <note>""")
                        .param("note", note))
                .call()
                .content();
    }

    /** Render without calling a model: handy in tests and logs. */
    static String preview(String template, Map<String, Object> values) {
        return PromptTemplate.builder()
                .template(template)
                .variables(values)
                .build()
                .render();
    }
}
src/main/resources/prompts/product-copy.st
Write a product description for {name}.
Audience: {audience}.
Features to cover, in this order: {features}.

Two short paragraphs. No superlatives such as "best" or
"revolutionary". Do not invent features that are not listed.
Rendering behaviour · run on Spring AI 2.0.1
preview("Hello {name}, {missing}", Map.of("name", "Ana"))
→ IllegalStateException: Not all variables were replaced in the
  template. Missing variable names are: [missing].

with < > delimiters:
"Return {\"sku\": \"...\"} for <note>" + note = "2 lamps"
→ Return {"sku": "..."} for 2 lamps

Validation modes

THROW (default) fails on a missing variable; WARN logs; NONE skips the check. Keep THROW: a silent hole in a prompt produces confident nonsense.

Values are data

A parameter value is inserted as text, never re-rendered as a template. Still, it is untrusted input to the model: delimit it and label it.
