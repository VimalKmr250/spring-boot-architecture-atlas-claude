Core Java: the language, the collections, concurrency and the JVM, with the failure behind each

A reference for the parts of Java that every Spring Boot service stands on and every Java interview probes: how the language resolves types and methods, how the collections work inside, how threads share memory, what the executors and concurrent collections do, and what the JVM does with your code at run time. Every claim comes with a program that shows it, and the output that program printed.

90

slides in fifteen sections. Concurrency, the largest part, takes 22 of them: the memory model, locks, atomics, executors, CompletableFuture, virtual threads and the concurrent collections.

30

interview questions, each with a 30-second answer and a follow-up, and eight coding drills solved in code that checks itself: an immutable class, a HashMap from scratch, two threads in turn, and more.

25

JDK 25, the current LTS, runs every program; the code compiles for Java 21. Anything added after Java 8 carries a since tag with its release.

How to use it

  • Arrow keys move through slides; C opens contents, where each topic is its own section.
  • Preparing for an interview? Start with topics by interview level, then the questions and the drills. Every answer links back to the slide that goes deeper.
  • Looking something up? The one-page index links every slide by topic.
  • Other tabs go further on neighbouring ground: lambdas and Optional in Java streams, design patterns in Low-level design, container memory and GC tuning in Spring Boot. This tab links to them rather than repeating them.
How the code is writtenA code label that starts with a file name, such as HashMapPeek.java, is a complete Java file. It compiles with javac --release 21 -Xlint:all without warnings, except where the slide shows the warning or the error on purpose, and the compiler's real output is then shown beside it. The block labelled Output on JDK 25 is what that file printed; a label says so when timings or counts vary between runs. Java25.java compiles with --release 25. Every program was also run on JDK 26.
