Java ships every six months, and the LTS releases are the ones codebases actually upgrade between

Since Java 10 there has been a feature release every March and September, and every two years one of them is a long-term-support release: 11, 17, 21 and 25 after 8. Most teams move from LTS to LTS, so what matters in practice is what changed between two of them. The table groups each step's non-LTS releases with the LTS that follows.

The interview version"What changed since 8 that you use?" Name one thing per LTS and why it mattered: var and HttpClient by 11; records, text blocks and sealed types by 17; virtual threads and pattern-matching switch by 21; scoped values and compact headers in 25. Then say which one your last project upgraded to, and what broke.
What breaks on upgradeReflection into JDK internals: 16 and 17 closed them, so old libraries fail with InaccessibleObjectException until updated. Removed modules: javax.xml.bind and friends went in 11. And the class file version: libraries built for a newer JDK will not load on an older one.
Preview featuresA feature can preview for several releases before it is final, and needs --enable-preview at compile and run time until then. Structured concurrency is still in preview in 25. This tab uses only final features, and tags each with its release.
