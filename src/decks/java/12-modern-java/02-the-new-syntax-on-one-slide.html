Ten years of syntax in one file: what Java 21 code looks like when it uses what it has

Code written against Java 8 still compiles on 25, so many codebases never adopt the newer forms. This file uses most of them at once, each commented with the release that made it final. Read it as a checklist: every line here replaces a longer pattern that reviewers still see every week.

ModernSyntax.java · sealed records, switch patterns, text blocks, sequenced collections
import java.util.*;
import java.util.stream.*;

public class ModernSyntax {
    static Map<String, Integer> stock;                                        // never assigned

    sealed interface Shipment permits Parcel, Pallet { }                       // 17
    record Parcel(String id, double kg) implements Shipment { }                // 16
    record Pallet(String id, int boxes, boolean hazardous) implements Shipment { }

    static String describe(Shipment s) {
        return switch (s) {                                                    // 21: patterns in switch
            case Parcel(var id, var kg) when kg > 20 -> id + ": heavy parcel";
            case Parcel p -> p.id() + ": parcel";
            case Pallet(var id, var boxes, var hazardous) when hazardous -> id + ": hazardous, " + boxes + " boxes";
            case Pallet p -> p.id() + ": pallet";
        };
    }

    static int workingHours(String day) {
        return switch (day) {                                                  // 14: switch expression
            case "SAT", "SUN" -> 0;
            case "FRI" -> 6;
            default -> {
                int base = 8;
                yield base;                                                    // a block yields its value
            }
        };
    }

    public static void main(String[] args) {
        var shipments = List.of(new Parcel("P-1", 4.5), new Parcel("P-2", 31),     // 10: var; 9: List.of
                new Pallet("L-1", 12, false), new Pallet("L-2", 40, true));
        shipments.stream().map(ModernSyntax::describe).forEach(System.out::println);

        String label = """
                Order %s
                  ships to: %s
                """.formatted("ORD-7", "Leeds");                                // 15: text blocks, formatted
        System.out.print(label);

        Object o = shipments.getFirst();                                       // 21: sequenced collections
        if (o instanceof Parcel p && p.kg() < 10)                              // 16: instanceof pattern
            System.out.println("light parcel " + p.id());

        System.out.println("hours: MON " + workingHours("MON") + ", FRI " + workingHours("FRI") + ", SUN " + workingHours("SUN"));
        List<String> ids = shipments.stream().map(s -> s instanceof Parcel p ? p.id() : ((Pallet) s).id()).toList();   // 16: toList
        System.out.println("ids " + ids + ", last " + ids.getLast() + ", reversed " + ids.reversed());
        System.out.println("blank? " + "  ".isBlank() + ", repeat " + "-".repeat(5) + ", strip [" + " x ".strip() + "]");   // 11
        System.out.println("clamp(130, 0, 100) = " + Math.clamp(130, 0, 100));                                         // 21
        Map<Boolean, Long> byKind = shipments.stream().collect(Collectors.partitioningBy(s -> s instanceof Parcel, Collectors.counting()));
        System.out.println("parcels " + byKind.get(true) + ", pallets " + byKind.get(false));
        try {
            stock.get("tea");
        } catch (NullPointerException e) {
            System.out.println("helpful NPE (14): " + e.getMessage());
        }
    }
}

var, used wellUse it where the type is obvious from the right-hand side, as in var shipments = List.of(…). Avoid it where the reader would have to look the type up, and for literals whose type matters: var total = 0 is an int, whatever the code later adds to it.
Helpful NullPointerExceptionsSince 14 the message names exactly what was null: here the field ModernSyntax.stock. For a local variable it gives only a slot number, such as "<local6>", unless the class was compiled with -g, which Maven and Gradle builds do by default.
Patterns need a sealed type to shineA switch over an open interface needs a default, which hides the case you forgot. Over a sealed one it needs none, and a new subtype breaks the build. More on sealed types and pattern matching.
