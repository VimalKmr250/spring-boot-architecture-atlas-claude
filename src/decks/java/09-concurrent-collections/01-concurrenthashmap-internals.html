ConcurrentHashMap locks one bin at a time, and its compound methods are atomic per key

Since Java 8 a ConcurrentHashMap is a hash table much like HashMap, made safe bin by bin. Reads take no lock at all. A write into an empty bin is a single compare-and-set; a write into a non-empty bin locks only that bin's first node. A resize is shared out among the threads that write during it. What it cannot make atomic is two separate calls, such as get followed by put.

ChmDemo.java · HashMap against ConcurrentHashMap, then the atomic methods
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class ChmDemo {
    static void inParallel(int threads, Runnable work) throws InterruptedException {
        try (ExecutorService pool = Executors.newFixedThreadPool(threads)) {
            for (int t = 0; t < threads; t++) pool.submit(work);
        }
    }

    // Eight daemon threads write one plain HashMap. Any of three things can happen; report which did.
    static String racyHashMap() throws InterruptedException {
        Map<Integer, Integer> plain = new HashMap<>();
        AtomicInteger next = new AtomicInteger();
        Queue<String> errors = new ConcurrentLinkedQueue<>();
        List<Thread> writers = new ArrayList<>();
        for (int t = 0; t < 8; t++) {
            Thread w = Thread.ofPlatform().daemon().unstarted(() -> {
                for (int i = 0; i < 50_000; i++) { int k = next.getAndIncrement(); plain.put(k, k); }
            });
            w.setUncaughtExceptionHandler((th, e) -> errors.add(e.getClass().getSimpleName()));
            writers.add(w);
            w.start();
        }
        long deadline = System.nanoTime() + 5_000_000_000L;
        for (Thread w : writers) w.join(Math.max(1, (deadline - System.nanoTime()) / 1_000_000));
        long stuck = writers.stream().filter(Thread::isAlive).count();
        if (stuck > 0) return stuck + " writer(s) still running after 5 s, looping in a corrupted bin";
        if (!errors.isEmpty()) return "writers threw " + new TreeSet<>(errors);
        return String.format("size %,d", plain.size());
    }

    public static void main(String[] args) throws Exception {
        System.out.println("HashMap, 400,000 distinct keys from 8 threads: " + racyHashMap());
        Map<Integer, Integer> concurrent = new ConcurrentHashMap<>();
        AtomicInteger next = new AtomicInteger();
        inParallel(8, () -> { for (int i = 0; i < 50_000; i++) { int k = next.getAndIncrement(); concurrent.put(k, k); } });
        System.out.printf("ConcurrentHashMap, the same keys: size %,d%n", concurrent.size());

        Map<String, Integer> racy = new ConcurrentHashMap<>(), atomic = new ConcurrentHashMap<>();
        inParallel(8, () -> {
            for (int i = 0; i < 100_000; i++) {
                Integer old = racy.get("hits");                   // get, then put: two steps
                racy.put("hits", old == null ? 1 : old + 1);
                atomic.merge("hits", 1, Integer::sum);            // one atomic step per key
            }
        });
        System.out.printf("800,000 increments: get-then-put %,d, merge %,d%n", racy.get("hits"), atomic.get("hits"));

        AtomicInteger loads = new AtomicInteger();
        Map<String, String> cache = new ConcurrentHashMap<>();
        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 1_000; i++)
                pool.submit(() -> cache.computeIfAbsent("rates", k -> { loads.incrementAndGet(); return "loaded"; }));
        }
        System.out.println("1,000 concurrent computeIfAbsent calls ran the loader " + loads.get() + " time(s)");

        try {
            concurrent.put(null, 1);
        } catch (NullPointerException e) {
            System.out.println("put(null, ...) -> NullPointerException");
        }
        Map<String, Integer> nested = new ConcurrentHashMap<>();
        try {
            nested.computeIfAbsent("a", k -> nested.computeIfAbsent("a", k2 -> 1));   // the map, from inside itself
        } catch (IllegalStateException e) {
            System.out.println("computeIfAbsent inside computeIfAbsent: IllegalStateException: " + e.getMessage());
        }

        ConcurrentHashMap<String, Long> sales = new ConcurrentHashMap<>(Map.of("tea", 40L, "milk", 75L, "jam", 12L));
        long total = sales.reduceValuesToLong(1, Long::longValue, 0L, Long::sum);    // parallel bulk operation
        String best = sales.search(1, (k, v) -> v > 50 ? k : null);
        System.out.println("reduceValues " + total + ", search " + best + ", mappingCount " + sales.mappingCount());
    }
}

HashMap between threadsIt lost a large share of 400,000 distinct keys in the run above, with no exception. It can also throw from inside a resize, or corrupt a bin into a loop: in one run while this tab was written, a writer never finished, which is why the demo now gives them five seconds and reports what happened. Hashtable and Collections.synchronizedMap are correct, with one lock for the whole map.
Keep compute functions shortcomputeIfAbsent calls the loader once per absent key, while it holds that bin's lock. A slow remote call inside it stalls every writer to that bin. Touching the same map from inside the function is illegal: IllegalStateException: Recursive update.
Why no nullsA get returning null must mean absent. In a HashMap you can follow up with containsKey, but in a concurrent map the answer may change in between. mappingCount() returns a long estimate; the bulk methods take a parallelism threshold.
