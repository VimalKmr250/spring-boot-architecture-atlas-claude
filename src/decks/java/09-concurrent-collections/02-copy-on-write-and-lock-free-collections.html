Copy-on-write makes reads free by making every write copy the whole array

CopyOnWriteArrayList never changes its array: each write builds a new one and swaps a volatile reference. Readers and iterators work on whichever array they started with, with no lock and no ConcurrentModificationException. The bill arrives on writes: 10,000 appends allocated 200 MB below. The other concurrent collections trade differently, using CAS-based linked structures.

CowDemo.java · snapshots, the write cost, a lock-free queue, a concurrent sorted map
import java.lang.management.ManagementFactory;
import java.util.*;
import java.util.concurrent.*;

public class CowDemo {
    static final com.sun.management.ThreadMXBean MX =
            (com.sun.management.ThreadMXBean) ManagementFactory.getThreadMXBean();

    static long bytesFor(List<Integer> list, int adds) {
        long before = MX.getCurrentThreadAllocatedBytes();
        for (int i = 0; i < adds; i++) list.add(i);
        return MX.getCurrentThreadAllocatedBytes() - before;
    }

    public static void main(String[] args) throws Exception {
        List<String> listeners = new CopyOnWriteArrayList<>(List.of("audit", "email"));
        Iterator<String> snapshot = listeners.iterator();
        listeners.add("sms");                                  // a write copies the array
        List<String> seen = new ArrayList<>();
        snapshot.forEachRemaining(seen::add);
        System.out.println("iterator made before add(\"sms\") sees " + seen + "; list is " + listeners);
        try {
            listeners.iterator().remove();
        } catch (UnsupportedOperationException e) {
            System.out.println("CopyOnWriteArrayList iterator.remove -> UnsupportedOperationException");
        }

        System.out.printf("10,000 adds allocate: ArrayList %,d bytes, CopyOnWriteArrayList %,d bytes%n",
                bytesFor(new ArrayList<>(), 10_000), bytesFor(new CopyOnWriteArrayList<>(), 10_000));

        Queue<Integer> jobs = new ConcurrentLinkedQueue<>();
        try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
            for (int p = 0; p < 4; p++) {
                int base = p * 1_000;
                pool.submit(() -> { for (int i = 0; i < 1_000; i++) jobs.offer(base + i); });   // lock-free
            }
        }
        System.out.println("ConcurrentLinkedQueue after 4 producers: " + jobs.size() + " jobs (size() walks the whole queue)");

        ConcurrentSkipListMap<Integer, String> slots = new ConcurrentSkipListMap<>();
        try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
            for (int h = 9; h <= 17; h++) { int hour = h; pool.submit(() -> slots.put(hour * 100, "free")); }
        }
        System.out.println("ConcurrentSkipListMap: next slot after 12:30 is " + slots.ceilingKey(1230)
                + ", first " + slots.firstKey() + ", afternoon " + slots.tailMap(1300).keySet());

        List<Integer> shared = Collections.synchronizedList(new ArrayList<>(List.of(1, 2, 3)));
        int sum = 0;
        synchronized (shared) {                               // required: iteration is many calls
            for (int n : shared) sum += n;
        }
        System.out.println("synchronizedList iterated under its own lock: sum " + sum);
    }
}

The write cost is quadraticEach add copies n references, so n appends copy about n²/2 of them: 10,000 adds made 200 MB of garbage against 327 KB for an ArrayList. Fine for a list of 12 listeners changed at startup; a disaster for a log of events.
Snapshot means staleThe iterator made before add("sms") never saw it. That is the point, and also the trap: a reader can act on an element that was removed a moment ago. Snapshot iterators cannot remove either.
size() is not free everywhereConcurrentLinkedQueue.size() walks the whole queue, and its answer may be stale before it returns. Use isEmpty(), or keep a separate counter. A queue that needs a bound or blocking is a BlockingQueue.
