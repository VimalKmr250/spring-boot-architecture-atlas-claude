Latches, barriers, semaphores and phasers coordinate threads so you never write wait and notify

Five classes in java.util.concurrent exist only to make threads wait for each other in a particular shape. Pick by the shape: one event that many threads wait for, a group that meets repeatedly, a limit on how many may proceed, a group whose size changes, or two threads swapping data. Each is built on the same internal queue as ReentrantLock.

Synchronizers.java · all five, each in its typical shape
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class Synchronizers {
    public static void main(String[] args) throws Exception {
        // CountDownLatch: a start gate for N workers, and a finish line for the coordinator.
        CountDownLatch startGate = new CountDownLatch(1), finished = new CountDownLatch(5);
        AtomicInteger started = new AtomicInteger();
        try (ExecutorService pool = Executors.newFixedThreadPool(5)) {
            for (int i = 0; i < 5; i++)
                pool.submit(() -> {
                    startGate.await();                         // everyone waits for the gun
                    started.incrementAndGet();
                    finished.countDown();
                    return null;
                });
            System.out.println("before countDown: " + started.get() + " started");
            startGate.countDown();
            finished.await();
            System.out.println("after the gate opened and all finished: " + started.get() + " started; latch count " + finished.getCount());
        }

        // CyclicBarrier: 3 parties meet each round; the barrier action runs once per round.
        List<String> rounds = Collections.synchronizedList(new ArrayList<>());
        AtomicInteger round = new AtomicInteger();
        CyclicBarrier barrier = new CyclicBarrier(3, () -> rounds.add("round " + round.incrementAndGet() + " merged"));
        try (ExecutorService pool = Executors.newFixedThreadPool(3)) {
            for (int p = 0; p < 3; p++)
                pool.submit(() -> {
                    for (int r = 0; r < 2; r++) barrier.await();   // reused: no reset needed
                    return null;
                });
        }
        System.out.println("CyclicBarrier: " + rounds);

        // Semaphore: at most 3 callers inside at any moment.
        Semaphore permits = new Semaphore(3);
        AtomicInteger inside = new AtomicInteger(), peak = new AtomicInteger();
        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 50; i++)
                pool.submit(() -> {
                    permits.acquire();
                    try {
                        peak.accumulateAndGet(inside.incrementAndGet(), Math::max);
                        Thread.sleep(10);
                        inside.decrementAndGet();
                    } finally { permits.release(); }
                    return null;
                });
        }
        System.out.println("Semaphore(3): 50 tasks, at most " + peak.get() + " inside at once");

        // Phaser: parties register and leave between phases.
        Phaser phaser = new Phaser(1);                          // the coordinator
        List<String> log = Collections.synchronizedList(new ArrayList<>());
        try (ExecutorService pool = Executors.newFixedThreadPool(3)) {
            for (int w = 1; w <= 3; w++) {
                int id = w;
                phaser.register();
                pool.submit(() -> {
                    phaser.arriveAndAwaitAdvance();             // phase 0: everyone loaded
                    if (id == 3) { phaser.arriveAndDeregister(); return; }   // leaves after phase 0
                    log.add("worker " + id + " in phase " + phaser.getPhase());
                    phaser.arriveAndDeregister();
                });
            }
            phaser.arriveAndAwaitAdvance();                     // wait for phase 0
            phaser.arriveAndAwaitAdvance();                     // and phase 1
            phaser.arriveAndDeregister();
        }
        Collections.sort(log);
        System.out.println("Phaser: " + log + ", terminated " + phaser.isTerminated());

        // Exchanger: two threads swap buffers.
        Exchanger<String> exchanger = new Exchanger<>();
        try (ExecutorService pool = Executors.newFixedThreadPool(2)) {
            Future<String> a = pool.submit(() -> exchanger.exchange("full buffer"));
            Future<String> b = pool.submit(() -> exchanger.exchange("empty buffer"));
            System.out.println("Exchanger: filler got the " + a.get() + ", drainer got the " + b.get());
        }
    }
}

ClassShapeReusable
CountDownLatchWait until a count reaches zero: a start gate, or "these N tasks are done"No
CyclicBarrierN threads wait for each other, then an optional action runs once per roundYes
SemaphoreAt most N permits out at once: a concurrency limitYes
PhaserLike a barrier, but parties register and leave between phasesYes
ExchangerTwo threads meet and swap one object eachYes
Semaphore with virtual threadsThe natural way to bound a downstream: 50 virtual threads, a Semaphore(3), and never more than three calls in flight. Release in finally. A permit has no owner, so any thread can release it, which also means a missing release is never caught for you.
Broken barriersIf one party of a CyclicBarrier is interrupted or times out, every other party gets BrokenBarrierException and the barrier stays broken until reset(). A latch has no such failure mode, and also no way back: it cannot count up again.
Often there is a simpler toolWaiting for N submitted tasks is invokeAll, or allOf on CompletableFutures. Waiting for one thread is join. Reach for a latch when the threads are not yours to join, such as in a test that starts a server.
