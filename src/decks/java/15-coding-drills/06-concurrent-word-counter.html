Drill: "count word frequencies across many lines, using all the cores"

There are three good answers and one common wrong one. The wrong one shares a HashMap, or does get then put on a ConcurrentHashMap, and loses counts. The good ones either share nothing (a parallel stream that collects), or share a concurrent map updated atomically. The answer that scores best checks itself: all three results below are compared against a plain sequential count.

WordCount.java · sequential, parallel stream, pool plus LongAdder, all compared
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.LongAdder;
import java.util.function.Function;
import java.util.stream.*;

public class WordCount {
    static List<String> lines() {                                    // 20,000 lines of seeded random words
        String[] vocab = {"order", "ship", "pay", "refund", "cart", "stock", "price", "tax", "the", "a"};
        Random r = new Random(42);
        return IntStream.range(0, 20_000)
                .mapToObj(i -> IntStream.range(0, 12).mapToObj(j -> vocab[r.nextInt(vocab.length)]).collect(Collectors.joining(" ")))
                .toList();
    }

    static Stream<String> words(String line) { return Arrays.stream(line.toLowerCase().split("\\s+")).filter(w -> !w.isEmpty()); }

    public static void main(String[] args) throws Exception {
        List<String> lines = lines();

        Map<String, Long> sequential = new HashMap<>();                 // 1 the baseline
        for (String line : lines) words(line).forEach(w -> sequential.merge(w, 1L, Long::sum));

        Map<String, Long> parallel = lines.parallelStream()             // 2 a parallel stream, no shared state
                .flatMap(WordCount::words)
                .collect(Collectors.groupingByConcurrent(Function.identity(), Collectors.counting()));

        ConcurrentHashMap<String, LongAdder> counts = new ConcurrentHashMap<>();   // 3 a pool and a shared map
        int chunk = 1_000;
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int from = 0; from < lines.size(); from += chunk) {
                List<String> part = lines.subList(from, Math.min(from + chunk, lines.size()));
                pool.submit(() -> part.forEach(line -> words(line)
                        .forEach(w -> counts.computeIfAbsent(w, k -> new LongAdder()).increment())));
            }
        }
        Map<String, Long> pooled = new HashMap<>();
        counts.forEach((w, n) -> pooled.put(w, n.sum()));

        System.out.println("words counted: " + sequential.values().stream().mapToLong(Long::longValue).sum()
                + ", distinct " + sequential.size());
        System.out.println("parallel stream matches: " + sequential.equals(parallel) + ", pool + LongAdder matches: " + sequential.equals(pooled));

        List<Map.Entry<String, Long>> top3 = sequential.entrySet().stream()
                .sorted(Map.Entry.<String, Long>comparingByValue().reversed().thenComparing(Map.Entry.comparingByKey()))
                .limit(3).toList();
        System.out.println("top 3: " + top3);
    }
}

ApproachWhy it is correctWhen
1 merge into a HashMapOne threadSmall input; and always as the reference answer
2 groupingByConcurrent in a parallel streamThe collector owns the concurrent map; your code shares nothingThe data is already in memory
3 computeIfAbsent(…).increment() on LongAdderscomputeIfAbsent is atomic per key; LongAdder handles contention on hot wordsWork arrives from many producers, or from files, or over time
The answer that loses countsmap.put(w, map.getOrDefault(w, 0L) + 1) from several threads: two threads read 41 and both write 42. It loses nothing in a single-threaded test. On a ConcurrentHashMap use merge(w, 1L, Long::sum); with very hot keys, the LongAdder version.
Follow-up: the top k wordsSort the entries by count descending, with a tie-break on the word so the order is stable, and take k: shown above. For millions of distinct words, keep a min-heap of size k instead: O(n log k).
Follow-up: the input is 50 GBStream it line by line with Files.lines, in chunks handed to a bounded pool, so memory holds the counts and not the file. Beyond one machine, the same shape is map-reduce, or a Kafka Streams aggregation.
