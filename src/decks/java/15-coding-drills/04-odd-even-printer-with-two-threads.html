Drill: "print 1 to 10 with two threads, one odd and one even, in order"

The classic hand-off problem. Each thread must wait for its turn and then pass the turn on, with no busy-waiting and no missed signals. Give two solutions: one with a monitor and wait/notifyAll, which shows you understand the mechanism, and one with two semaphores, which shows you would not write the first in production.

OddEven.java · wait/notify, then semaphores, then 200 repeat runs
import java.util.*;
import java.util.concurrent.*;

public class OddEven {
    static final int MAX = 10;

    // Solution 1: one monitor, a shared counter, wait in a loop.
    static final class Printer {
        private int next = 1;
        private final List<String> out = new ArrayList<>();
        synchronized void print(boolean odd) throws InterruptedException {
            while (true) {
                while (next <= MAX && (next % 2 == 1) != odd) wait();   // not my turn
                if (next > MAX) { notifyAll(); return; }
                out.add(Thread.currentThread().getName() + ":" + next++);
                notifyAll();                                            // wake the other thread
            }
        }
    }

    // Solution 2: two semaphores pass the turn back and forth.
    static List<String> withSemaphores() throws InterruptedException {
        Semaphore oddTurn = new Semaphore(1), evenTurn = new Semaphore(0);
        List<String> out = Collections.synchronizedList(new ArrayList<>());
        Thread odd = new Thread(() -> {
            try {
                for (int i = 1; i <= MAX; i += 2) { oddTurn.acquire(); out.add("odd:" + i); evenTurn.release(); }
            } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        }, "odd");
        Thread even = new Thread(() -> {
            try {
                for (int i = 2; i <= MAX; i += 2) { evenTurn.acquire(); out.add("even:" + i); oddTurn.release(); }
            } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        }, "even");
        odd.start(); even.start();
        odd.join(); even.join();
        return out;
    }

    public static void main(String[] args) throws Exception {
        Printer p = new Printer();
        Thread odd = new Thread(() -> { try { p.print(true); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } }, "odd");
        Thread even = new Thread(() -> { try { p.print(false); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } }, "even");
        odd.start(); even.start();
        odd.join(); even.join();
        System.out.println("wait/notify: " + p.out);
        System.out.println("semaphores:  " + withSemaphores());

        boolean allInOrder = true;
        for (int run = 0; run < 200; run++) {                            // repeat: races show up in repetition
            List<String> r = withSemaphores();
            for (int i = 0; i < MAX; i++) if (!r.get(i).endsWith(":" + (i + 1))) allInOrder = false;
        }
        System.out.println("200 more runs, every one in order: " + allInOrder);
    }
}

What to say while writing it

  • The invariant: next is the number to print, and only the thread whose parity matches may print it.
  • while, not if: a thread can wake spuriously, or wake when it is still not its turn.
  • notifyAll: with only two threads notify works, but notifyAll stays correct when the problem grows to three.
  • Termination: the last thread must wake the other, or it waits forever; the next > MAX check handles both.
  • Semaphores: a permit is the turn. Odd starts with it; each thread releases the other's.
Follow-up: three threads, round robinGeneralise the monitor version: thread k of n prints when next % n == k. Or use n semaphores in a ring, or one ReentrantLock with a Condition per thread, so each signal wakes exactly the next thread.
Why repeat the runA concurrency bug can pass a single run and fail one time in a hundred. Two hundred repeated runs, all in order, is evidence; one run is a hope. Say this, and the interviewer hears that you have debugged threads before.
