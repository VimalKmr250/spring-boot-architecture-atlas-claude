Drill: "a product page needs price, stock and reviews; call them in parallel, within 300 ms"

The question is really about failure. Price is required: without it the page cannot render, so a late price is an error. Stock and reviews are optional: a failure or a timeout should give a fallback, not a broken page. The answer starts all three calls at once, gives each its own policy, and combines them, so the page takes as long as its slowest permitted wait.

ParallelCalls.java · three services, three failure policies, one deadline
import java.util.concurrent.*;

public class ParallelCalls {
    record ProductPage(long priceCents, int stock, String reviews) { }

    static final ExecutorService IO = Executors.newFixedThreadPool(8, Thread.ofPlatform().name("io-", 1).factory());

    static <T> CompletableFuture<T> call(String name, long ms, T result, boolean fails) {
        return CompletableFuture.supplyAsync(() -> {
            try { Thread.sleep(ms); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
            if (fails) throw new IllegalStateException(name + " is down");
            return result;
        }, IO);
    }

    static ProductPage load(boolean stockDown) {
        CompletableFuture<Long> price = call("pricing", 150, 1299L, false)
                .orTimeout(300, TimeUnit.MILLISECONDS);                       // required: fail if late
        CompletableFuture<Integer> stock = call("inventory", 100, 7, stockDown)
                .exceptionally(ex -> -1);                                     // optional: -1 means unknown
        CompletableFuture<String> reviews = call("reviews", 800, "4.6 stars", false)
                .completeOnTimeout("reviews unavailable", 300, TimeUnit.MILLISECONDS);   // optional: default
        return price.thenCombine(stock, (p, s) -> new long[] {p, s})
                .thenCombine(reviews, (ps, r) -> new ProductPage(ps[0], (int) ps[1], r))
                .join();
    }

    public static void main(String[] args) {
        load(false);                                                        // warm up the pool
        for (boolean stockDown : new boolean[] {false, true}) {
            long t0 = System.nanoTime();
            ProductPage page = load(stockDown);
            long ms = Math.round((System.nanoTime() - t0) / 1e8) * 100;
            System.out.println(page + " in ~" + ms + " ms" + (stockDown ? " (inventory failed)" : ""));
        }
        try {
            call("pricing", 600, 1L, false).orTimeout(300, TimeUnit.MILLISECONDS).join();
        } catch (CompletionException e) {
            System.out.println("a required call past its deadline: " + e.getCause().getClass().getSimpleName());
        }
        IO.shutdownNow();
    }
}

Reading the resultBoth pages took about 300 ms: the reviews call is slow, so the page waits for its deadline and uses the placeholder. Sequential calls would have taken 150 + 100 + 800 = 1,050 ms. The second page shows the inventory failure absorbed as stock=-1.
Use your own executorThese calls block, so they run on a dedicated IO pool, never the common ForkJoinPool. Name its threads, size it for the calls in flight, and shut it down. With virtual threads, Executors.newVirtualThreadPerTaskExecutor() fits too.
