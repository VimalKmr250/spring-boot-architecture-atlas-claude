Reflection reads classes at run time, and a dynamic proxy is how a framework puts code around your calls

Reflection lists a class's fields, methods and annotations and calls them by name. A dynamic proxy is a class generated at run time that implements your interfaces and routes every call to one handler. Spring's @Transactional, @Cacheable and @Async work this way: the bean you inject is a proxy, and the annotation is read by reflection. Both limits that surprise people follow from that.

ProxyDemo.java · an annotation, a proxy that reads it, and reflection's limits
import java.lang.annotation.*;
import java.lang.reflect.*;
import java.util.*;

public class ProxyDemo {
    @Retention(RetentionPolicy.RUNTIME)                 // without this, reflection cannot see it
    @Target(ElementType.METHOD)
    @interface Audited { String value(); }

    interface OrderService {
        String place(String sku);
        String placeTwice(String sku);
    }

    static class DefaultOrderService implements OrderService {
        private int placed;
        @Audited("order.place")
        @Override public String place(String sku) { placed++; return "ORD-" + placed + ":" + sku; }
        @Override public String placeTwice(String sku) { return place(sku) + " " + place(sku); }   // this.place
    }

    // What a framework does: wrap the target in a proxy that adds behaviour around calls.
    @SuppressWarnings("unchecked")
    static <T> T audited(T target, Class<T> type, List<String> log) {
        InvocationHandler handler = (proxy, method, args) -> {
            Method impl = target.getClass().getMethod(method.getName(), method.getParameterTypes());
            Audited a = impl.getAnnotation(Audited.class);
            if (a != null) log.add("audit " + a.value() + " " + Arrays.toString(args));
            try {
                return method.invoke(target, args);
            } catch (InvocationTargetException e) {
                throw e.getCause();                     // unwrap, as Spring does
            }
        };
        return (T) Proxy.newProxyInstance(type.getClassLoader(), new Class<?>[] {type}, handler);
    }

    public static void main(String[] args) throws Exception {
        List<String> log = new ArrayList<>();
        DefaultOrderService target = new DefaultOrderService();
        OrderService service = audited(target, OrderService.class, log);

        System.out.println(service.place("tea"));
        System.out.println(service.placeTwice("milk"));
        System.out.println("audit log: " + log + "  <- placeTwice's inner calls were not audited");
        System.out.println("proxy class " + service.getClass().getName() + ", is an OrderService "
                + (service instanceof OrderService) + ", is a DefaultOrderService " + (service instanceof DefaultOrderService));

        Field placed = DefaultOrderService.class.getDeclaredField("placed");
        placed.setAccessible(true);                     // fine for your own classes
        System.out.println("private field read by reflection: placed = " + placed.getInt(target));

        try {
            Field value = String.class.getDeclaredField("value");
            value.setAccessible(true);                  // the JDK's internals are closed since 17
        } catch (InaccessibleObjectException e) {
            System.out.println("InaccessibleObjectException: " + e.getMessage().replaceAll(" @[0-9a-f]+", ""));
        }

        Method m = DefaultOrderService.class.getMethod("place", String.class);
        System.out.println("@Audited on place: " + m.getAnnotation(Audited.class).value()
                + "; parameter count " + m.getParameterCount() + "; return type " + m.getReturnType().getSimpleName());
    }
}

LineWhy
One audit entry, not threeplaceTwice calls this.place on the real object, never through the proxy. Spring's self-invocation problem, exactly.
Not a DefaultOrderServiceA JDK proxy implements only the interfaces. Spring Boot proxies classes with CGLIB subclasses by default, so injection by class works, but final methods cannot be intercepted.
InaccessibleObjectExceptionThe JDK's own internals are closed to reflection since JDK 17 (JEP 403). --add-opens reopens one package, as the HashMap slides do.
RetentionPolicy.RUNTIMEWithout it the annotation stays in the class file but is invisible to reflection, and the framework silently ignores it.
The Spring consequencesSelf-invocation skips @Transactional; private and final methods cannot be advised; the proxy, not your bean, is what other beans hold. All of it is on AOP limits.
Reflection's costsEach call checks access and boxes arguments, and it hides calls from the compiler, the IDE and tree shaking. Cache Method objects, or use MethodHandles, which the JIT inlines once the handle is constant.
Records and reflectiongetRecordComponents() lists a record's components in order, which is how Jackson and other serialisers bind records through the canonical constructor without setters.
