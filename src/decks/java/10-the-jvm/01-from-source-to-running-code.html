javac compiles to bytecode for an abstract stack machine; the JVM interprets it, then compiles the hot parts

A .class file holds bytecode: instructions for a stack machine that exists only in the JVM specification. The JVM loads it, verifies it, links it, and starts by interpreting it. Methods that turn out to be hot are compiled to machine code, first quickly by C1 and then thoroughly by C2. If an assumption behind compiled code stops being true, the JVM throws that code away and interprets again.

Bytecode.java · a small method, and the class file's own header
import java.io.DataInputStream;
import java.io.InputStream;

public class Bytecode {
    static int total(int[] prices, int discount) {
        int sum = 0;
        for (int p : prices) sum += p;
        return sum - discount;
    }

    public static void main(String[] args) throws Exception {
        System.out.println("total = " + total(new int[] {250, 120, 90}, 60));
        try (InputStream raw = Bytecode.class.getResourceAsStream("Bytecode.class");
             DataInputStream in = new DataInputStream(raw)) {
            int magic = in.readInt();
            int minor = in.readUnsignedShort(), major = in.readUnsignedShort();
            System.out.printf("class file: magic %X, version %d.%d (%d = Java %d)%n",
                    magic, major, minor, major, major - 44);
        }
        System.out.println("running on " + System.getProperty("java.vm.name") + " " + Runtime.version());
    }
}

Reading the bytecodeMeans
iconst_0, istore_2Push the int 0, pop it into local slot 2 (sum). Slot 0 is prices, slot 1 discount.
arraylength, ialoadThe enhanced for became an index loop over a copy of the array reference.
if_icmpge 35, goto 11The loop test and the jump back: no structured loops in bytecode.
iadd, isub, ireturnPop two ints, push the result; return the top of the stack.

Class file versionsThe major version is the Java release plus 44: 52 is Java 8, 55 is 11, 61 is 17, 65 is 21, 69 is 25. A JVM runs any older version and refuses newer ones, so build with --release set to the oldest JDK you deploy on. --release also checks the API you call, which -target alone does not.
