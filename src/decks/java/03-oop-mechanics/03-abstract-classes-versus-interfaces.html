Interfaces carry behaviour since Java 8; abstract classes still own the state and the constructor

Default, static and private methods let an interface ship code, so "an interface has no implementation" is out of date. What an interface still cannot have is instance state or a constructor, which means it cannot protect an invariant. When two interfaces supply the same default, three rules decide which one runs, and if none applies the class must choose.

Interfaces.java · default-method conflicts, and what only a class can do
public class Interfaces {
    interface Shippable {
        int MAX_KG = 30;                                    // implicitly public static final
        default String label() { return "ship: " + describe(); }
        private String describe() { return "parcel up to " + MAX_KG + " kg"; }   // since 9
        static Shippable standard() { return new Shippable() { }; }             // since 8
    }
    interface Giftable {
        default String label() { return "gift"; }
    }

    // Two defaults with the same signature: the class must choose.
    static class Order implements Shippable, Giftable {
        @Override public String label() { return Shippable.super.label() + " + " + Giftable.super.label(); }
    }

    // Rule 1: a method from a class beats any default.
    static class Base { public String label() { return "Base.label"; } }
    static class Special extends Base implements Giftable { }

    // Rule 2: the more specific interface wins.
    interface FragileGift extends Giftable {
        @Override default String label() { return "fragile gift"; }
    }
    static class Vase implements Giftable, FragileGift { }

    // Abstract classes keep state and constructors; interfaces cannot.
    abstract static class Payment {
        private final long cents;
        protected Payment(long cents) {
            if (cents <= 0) throw new IllegalArgumentException("cents must be positive");
            this.cents = cents;
        }
        final String receipt() { return method() + " " + cents; }   // template method
        abstract String method();
    }
    static class Card extends Payment {
        Card(long cents) { super(cents); }
        @Override String method() { return "card"; }
    }

    public static void main(String[] args) {
        System.out.println(new Order().label());
        System.out.println(new Special().label());
        System.out.println(new Vase().label());
        System.out.println(Shippable.standard().label());
        System.out.println(new Card(1250).receipt());
        try {
            new Card(0);
        } catch (IllegalArgumentException e) {
            System.out.println("rejected: " + e.getMessage());
        }
    }
}

Which default runs

  1. A class wins. A method inherited from a superclass beats any default: Special prints Base.label.
  2. The more specific interface wins. FragileGift extends Giftable, so its default is used.
  3. Otherwise it does not compile. Override the method, and call Shippable.super.label() to reuse one.
