A record is a final class whose state is its components, and the compact constructor guards it

Declare the components and javac writes the private final fields, the canonical constructor, the accessors and value-based equals, hashCode and toString since 16. The compact constructor runs before the fields are assigned, so it can validate and normalise the arguments. What a record cannot do is hide a mutable component: it is only as immutable as the types it holds.

Records.java · validation, normalisation, generic records, the two traps
import java.util.*;

public class Records {
    record Money(long cents, String currency) {
        static final Money ZERO_EUR = new Money(0, "EUR");      // static fields are allowed
        Money {                                                // compact canonical constructor
            if (cents < 0) throw new IllegalArgumentException("negative amount: " + cents);
            currency = currency.toUpperCase(Locale.ROOT);      // normalise before assignment
        }
        Money(long cents) { this(cents, "EUR"); }               // others must delegate
        Money plus(Money other) {
            if (!currency.equals(other.currency)) throw new IllegalArgumentException("currency mismatch");
            return new Money(cents + other.cents, currency);
        }
        @Override public String toString() { return String.format("%d.%02d %s", cents / 100, cents % 100, currency); }
    }

    record Batch(String sku, int[] quantities) { }             // array component: a trap
    record Basket(List<String> items) { }                      // no defensive copy
    record Pair<A, B>(A first, B second) { }                   // records can be generic

    public static void main(String[] args) {
        Money a = new Money(1250, "eur");
        System.out.println(a + " plus " + new Money(99) + " = " + a.plus(new Money(99)));
        System.out.println("equal by value: " + a.equals(new Money(1250, "EUR"))
                + ", same hash: " + (a.hashCode() == new Money(1250, "EUR").hashCode()));
        try {
            new Money(-1, "EUR");
        } catch (IllegalArgumentException e) {
            System.out.println("rejected: " + e.getMessage());
        }

        Batch b1 = new Batch("A-1", new int[] {1, 2});
        Batch b2 = new Batch("A-1", new int[] {1, 2});
        System.out.println("batches with equal arrays equal? " + b1.equals(b2));
        System.out.println("batch toString: " + b1.toString().replaceAll("@[0-9a-f]+", "@…"));

        var items = new ArrayList<>(List.of("tea"));
        Basket basket = new Basket(items);
        items.add("milk");
        System.out.println("basket after the caller's add: " + basket);

        var pair = new Pair<>("SKU-1", 3);
        System.out.println(pair + ", components: " + Arrays.stream(Pair.class.getRecordComponents())
                .map(c -> c.getName() + ":" + c.getType().getSimpleName()).toList());
        System.out.println("is a record, final: " + Money.class.isRecord() + ", "
                + java.lang.reflect.Modifier.isFinal(Money.class.getModifiers())
                + ", superclass " + Money.class.getSuperclass().getName());
    }
}

Array componentsThe generated equals compares each component with equals, and for an array that means identity. Two batches with equal contents are unequal, and toString prints [I@…. Hold a List instead, or override all three methods.
Shallow immutabilityBasket kept the caller's list, so the caller's later add changed the record. Copy in the compact constructor: items = List.copyOf(items), as on writing an immutable class.
Where records fitDTOs, API payloads, query projections, map keys, events and messages. Not JPA entities, which need a no-argument constructor, mutable state and subclassing proxies. Jackson binds records through the canonical constructor, and Java serialization calls it too, so validation also runs on deserialization.
