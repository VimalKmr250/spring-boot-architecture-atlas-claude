A sealed hierarchy lets the compiler prove that a switch handles every case

A sealed interface lists every type allowed to implement it since 17. A switch over it can then match on type, deconstruct records and add guards since 21, with no default branch. Add a new permitted type and every switch that forgot it stops compiling, instead of falling into a default that hides the gap.

Sealed.java · type patterns, record patterns, guards, case null
import java.util.List;

public class Sealed {
    sealed interface Payment permits Card, Wallet, BankTransfer { long cents(); }
    record Card(long cents, String network) implements Payment { }
    record Wallet(long cents, String provider) implements Payment { }
    record BankTransfer(long cents, String iban, boolean instant) implements Payment { }

    static long feeCents(Payment p) {
        return switch (p) {                                  // exhaustive: no default needed
            case Card c when c.network().equals("AMEX") -> c.cents() * 3 / 100;
            case Card c                                  -> c.cents() * 2 / 100;
            case Wallet w                                -> 25;
            case BankTransfer(long cents, String iban, boolean instant) when instant -> 50;
            case BankTransfer t                          -> 0;
        };
    }

    static String describe(Object o) {
        return switch (o) {
            case null                    -> "nothing";       // since 21: null gets a case
            case Integer i when i > 100  -> "big int " + i;
            case Integer i               -> "int " + i;
            case String s                -> "string of " + s.length();
            case Payment p               -> "payment of " + p.cents();
            default                      -> "other " + o.getClass().getSimpleName();
        };
    }

    public static void main(String[] args) {
        List<Payment> payments = List.of(new Card(10_000, "VISA"), new Card(10_000, "AMEX"),
                new Wallet(4_000, "PayPal"), new BankTransfer(90_000, "DE89...", true),
                new BankTransfer(90_000, "DE89...", false));
        for (Payment p : payments) System.out.println(p + " -> fee " + feeCents(p));

        for (Object o : new Object[] {null, 7, 500, "refund", new Wallet(1, "X"), 2.5})
            System.out.println(describe(o));

        Object order = "ORD-42";
        if (order instanceof String id && id.startsWith("ORD-"))   // pattern variable in scope
            System.out.println("order number " + id.substring(4));
    }
}

public class SealedMissing {
    sealed interface Payment permits Card, Wallet, Voucher { long cents(); }
    record Card(long cents) implements Payment { }
    record Wallet(long cents) implements Payment { }
    record Voucher(long cents) implements Payment { }        // the new type

    static long feeCents(Payment p) {
        return switch (p) {
            case Card c   -> c.cents() * 2 / 100;
            case Wallet w -> 25;
        };                                                     // Voucher is not handled
    }
}

RuleDetail
Who may be permittedSubtypes in the same module, or the same package when there is no module. Each must be final, sealed or non-sealed; records are final already. permits may be left out when they are all in the same file.
ExhaustivenessRequired for every switch expression, and for any switch that uses patterns or case null.
Order and dominanceCases are tried top to bottom. A case that can never match because an earlier one covers it is an error, shown below.
nullA switch without case null throws NullPointerException on null, as switches always have.
Separate compilationIf a new permitted type arrives in a jar and the switch is not recompiled, it throws MatchException at run time.
