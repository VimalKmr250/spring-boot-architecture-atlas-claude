Six concurrency bugs from real code reviews, each one forced into the open

Concurrency bugs hide because they need an unlucky interleaving, and a single-threaded test never provides one. Each case below runs with enough threads to make the race likely, so the wrong answer appears on an ordinary laptop. The counts change from run to run; that they are wrong does not.

ConcurrencyBugs.java · shared formatters, check-then-act, pool starvation, boxed locks
import java.text.SimpleDateFormat;
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.stream.IntStream;

public class ConcurrencyBugs {
    static final SimpleDateFormat FORMAT = new SimpleDateFormat("yyyy-MM-dd");    // shared and mutable
    static Map<String, String> config;                                             // lazily loaded, unsafely
    static final AtomicInteger loads = new AtomicInteger();

    static Map<String, String> config() {
        if (config == null) {                                                      // check...
            loads.incrementAndGet();
            config = Map.of("region", "eu");                                       // ...then act
        }
        return config;
    }

    public static void main(String[] args) throws Exception {
        AtomicInteger wrong = new AtomicInteger(), failed = new AtomicInteger();
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int i = 0; i < 10_000; i++) {
                String day = String.format("2026-%02d-%02d", 1 + i % 12, 1 + i % 28);
                pool.submit(() -> {
                    try {
                        if (!FORMAT.format(FORMAT.parse(day)).equals(day)) wrong.incrementAndGet();
                    } catch (Exception e) {
                        failed.incrementAndGet();
                    }
                });
            }
        }
        System.out.println("1 shared SimpleDateFormat: " + wrong.get() + " wrong results, " + failed.get() + " exceptions in 10,000 parses");

        Map<String, Integer> initCalls = new ConcurrentHashMap<>();
        AtomicInteger inits = new AtomicInteger();
        CountDownLatch go = new CountDownLatch(1);
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int i = 0; i < 8; i++)
                pool.submit(() -> {
                    go.await();
                    if (!initCalls.containsKey("rates")) {                         // check-then-act on a concurrent map
                        inits.incrementAndGet();
                        initCalls.put("rates", 1);
                    }
                    return null;
                });
            go.countDown();
        }
        System.out.println("2 containsKey then put: the expensive init ran " + inits.get() + " times for one key");

        List<Integer> unsafe = new ArrayList<>();
        try {
            IntStream.range(0, 100_000).parallel().forEach(unsafe::add);           // ArrayList from many threads
            System.out.println("3 parallel forEach into ArrayList: " + unsafe.size() + " of 100000 elements kept");
        } catch (RuntimeException e) {
            System.out.println("3 parallel forEach into ArrayList threw " + e.getClass().getSimpleName());
        }
        System.out.println("  collect instead: " + IntStream.range(0, 100_000).parallel().boxed().toList().size());

        CountDownLatch start = new CountDownLatch(1);
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int i = 0; i < 8; i++) pool.submit(() -> { start.await(); return config(); });
            start.countDown();
        }
        System.out.println("4 unsynchronised lazy init: loaded " + loads.get() + " time(s) (varies; can be 1)");

        ExecutorService small = Executors.newFixedThreadPool(2);
        List<Future<String>> outer = new ArrayList<>();
        for (int i = 0; i < 2; i++)
            outer.add(small.submit(() -> small.submit(() -> "inner").get()));    // waits on its own pool
        try {
            outer.get(0).get(1, TimeUnit.SECONDS);
        } catch (TimeoutException e) {
            System.out.println("5 tasks waiting on subtasks in the same full pool: stuck (TimeoutException after 1 s)");
        }
        small.shutdownNow();

        Integer counterLock = 42;
        synchronized (counterLock) {                                               // javac warns: value-based class
            System.out.println("6 locked a boxed Integer, shared with every other 42 in the JVM");
        }
    }
}

Testing for racesRun the code with many threads released together by a latch, as here, and repeat it. For memory-model bugs, OpenJDK's jcstress tool runs millions of trials on purpose. A passing single-threaded test proves nothing about any of these.
