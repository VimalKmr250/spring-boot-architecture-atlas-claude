Files and Path do most file work in one line, and every stream over a file must be closed

The java.nio.file API 7 replaced java.io.File: Path names a file, and the static methods on Files read, write, copy, move, list and walk. Two rules prevent most bugs. Bytes become text only through a charset, so name one or know the default. And anything that keeps a file open, including the streams from Files.lines and Files.walk, goes in try-with-resources.

FilesDemo.java · read, write, a wrong charset, copy, move, walk, clean up
import java.io.*;
import java.nio.charset.*;
import java.nio.file.*;
import java.util.Comparator;
import java.util.stream.Stream;

public class FilesDemo {
    static String slash(Path p) { return p.toString().replace('\\', '/'); }   // the same on every OS

    public static void main(String[] args) throws IOException {
        System.out.println("default charset " + Charset.defaultCharset() + " (UTF-8 by default since JDK 18)");
        Path dir = Files.createTempDirectory("orders");
        try {
            Path csv = dir.resolve("orders.csv");
            Files.writeString(csv, "id,customer,total\nORD-1,Zoë,12.50\nORD-2,Ana,7.00\n");   // UTF-8
            System.out.println("orders.csv: " + Files.size(csv) + " bytes, " + Files.readString(csv).length() + " chars");

            try (Stream<String> lines = Files.lines(csv)) {               // holds a file handle until closed
                lines.skip(1).map(l -> l.split(",")).forEach(f -> System.out.println("  " + f[0] + " " + f[1] + " " + f[2]));
            }
            String wrong = Files.readString(csv, StandardCharsets.ISO_8859_1);
            System.out.println("read as ISO-8859-1: " + wrong.lines().skip(1).findFirst().orElseThrow());

            try (BufferedWriter w = Files.newBufferedWriter(dir.resolve("report.txt"))) {
                w.write("2 orders, 19.50");
                w.newLine();
            }
            try (BufferedReader r = Files.newBufferedReader(dir.resolve("report.txt"))) {
                System.out.println("report.txt: " + r.readLine());
            }

            Path p = Path.of("data", "2026", "..", "orders.csv");
            System.out.println("path " + slash(p) + " normalises to " + slash(p.normalize()) + ", file name " + p.getFileName());

            Path archive = Files.createDirectories(dir.resolve("archive/2026"));
            Files.copy(csv, archive.resolve("orders.csv"));
            try {
                Files.copy(csv, archive.resolve("orders.csv"));
            } catch (FileAlreadyExistsException e) {
                System.out.println("copy onto an existing file: FileAlreadyExistsException");
            }
            Files.copy(csv, archive.resolve("orders.csv"), StandardCopyOption.REPLACE_EXISTING);
            Files.move(dir.resolve("report.txt"), dir.resolve("archive/report.txt"), StandardCopyOption.ATOMIC_MOVE);
            try (Stream<Path> all = Files.walk(dir)) {                     // also must be closed; the first entry is dir itself
                System.out.println("tree: " + all.skip(1).map(dir::relativize).map(FilesDemo::slash).sorted().toList());
            }
        } finally {
            try (Stream<Path> all = Files.walk(dir)) {
                all.sorted(Comparator.reverseOrder()).forEach(path -> path.toFile().delete());   // children first
            }
            System.out.println("temp directory removed: " + !Files.exists(dir));
        }
    }
}

ZoÃ«The file holds UTF-8, where ë is two bytes, so 50 bytes held 49 characters. Read as ISO-8859-1, each of those bytes became a character. Before JDK 18 the default charset was the platform's (windows-1252 on Windows), so the same code printed different text on a laptop and on a Linux server. JDK 18 made UTF-8 the default (JEP 400).
Unclosed streamsFiles.lines reads lazily and keeps the file open until the stream is closed. Leaked handles end in "too many open files" on Linux; on Windows an open file also cannot be deleted or moved. The stream from Files.walk has the same rule, which is why the clean-up uses try-with-resources too.
Bytes, characters, buffersInputStream and OutputStream carry bytes; Reader and Writer carry characters through a charset. Always buffer: an unbuffered stream makes a system call per read. For very large files or high throughput, use FileChannel, ByteBuffer and memory-mapped files.
