Store an Instant, show a ZonedDateTime, and let the zone rules handle the hours that do not exist

java.time 8 separates what the old Date mixed together: a point on the timeline (Instant), a wall-clock reading with no zone (LocalDateTime), and a wall-clock reading in a zone, which knows that London's clocks jump at 01:00 on 29 March 2026 (ZonedDateTime). Every type is immutable and thread-safe. Most date bugs come from choosing the wrong one of them.

TimeDemo.java · a fixed clock, two DST changes, calendar against elapsed time
import java.time.*;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;
import java.util.Locale;

public class TimeDemo {
    public static void main(String[] args) {
        Clock clock = Clock.fixed(Instant.parse("2026-03-28T23:30:00Z"), ZoneOffset.UTC);   // inject, so tests are repeatable
        Instant now = Instant.now(clock);
        ZoneId london = ZoneId.of("Europe/London"), kolkata = ZoneId.of("Asia/Kolkata");
        System.out.println("Instant        " + now + "  (a point on the timeline, in UTC)");
        System.out.println("in London      " + now.atZone(london));
        System.out.println("in Kolkata     " + now.atZone(kolkata));
        System.out.println("LocalDateTime  " + LocalDateTime.now(clock) + "  (no zone: not a point in time)");

        ZonedDateTime gap = ZonedDateTime.of(LocalDateTime.of(2026, 3, 29, 1, 30), london);
        System.out.println("01:30 on 29 Mar 2026 in London does not exist; it becomes " + gap);
        ZonedDateTime overlap = ZonedDateTime.of(LocalDateTime.of(2026, 10, 25, 1, 30), london);
        System.out.println("01:30 on 25 Oct 2026 happens twice: " + overlap.getOffset() + " first, then "
                + overlap.withLaterOffsetAtOverlap().getOffset());

        ZonedDateTime saturdayNoon = ZonedDateTime.of(2026, 3, 28, 12, 0, 0, 0, london);
        System.out.println("plusDays(1)                " + saturdayNoon.plusDays(1));
        System.out.println("plus(Duration.ofHours(24)) " + saturdayNoon.plus(Duration.ofHours(24)));
        System.out.println("hours in that 'day': " + ChronoUnit.HOURS.between(saturdayNoon, saturdayNoon.plusDays(1)));

        System.out.println("31 Jan plusMonths(1) = " + LocalDate.of(2026, 1, 31).plusMonths(1)
                + "; Period 15 Jan -> 20 Mar = " + Period.between(LocalDate.of(2026, 1, 15), LocalDate.of(2026, 3, 20))
                + "; Duration of 90 min = " + Duration.ofMinutes(90));

        DateTimeFormatter shown = DateTimeFormatter.ofPattern("dd MMM uuuu HH:mm", Locale.UK);
        LocalDateTime parsed = LocalDateTime.parse("07 Oct 2026 14:05", shown);
        System.out.println("parsed " + parsed + ", as ISO with an offset " + parsed.atOffset(ZoneOffset.ofHours(2)));

        LocalDate monday = LocalDate.of(2025, 12, 29);
        System.out.println("29 Dec 2025 as yyyy-MM-dd " + monday.format(DateTimeFormatter.ofPattern("yyyy-MM-dd", Locale.UK))
                + ", as YYYY-MM-dd " + monday.format(DateTimeFormatter.ofPattern("YYYY-MM-dd", Locale.UK)) + "  (week-based year)");
    }
}

A day is not 24 hoursNoon Saturday plus one day is noon Sunday; plus 24 hours is 13:00, because that Sunday in London had 23 hours. Use plusDays for "same time tomorrow" and a Duration for "in 24 hours". The non-existent 01:30 was moved forward to 02:30, and the repeated one defaults to the earlier offset.
YYYY is not yyyyYYYY is the week-based year, so 29 December 2025, in the first week of 2026, printed as 2026-12-29. It passes every test that does not run in the last days of December. Use yyyy or uuuu.
The legacy classesDate and Calendar are mutable, SimpleDateFormat is not thread-safe, and Calendar months start at 0. Convert at the boundary: date.toInstant(), Date.from(instant). JDBC 4.2 and JPA read and write java.time types directly.
