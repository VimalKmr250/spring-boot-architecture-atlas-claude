A deadlock is a cycle of threads each holding the lock the next one needs, and the JVM can find it

Thread 1 holds account A's lock and waits for B's; thread 2 holds B's and waits for A's. Neither can move, and nothing will ever time out. A deadlock needs four conditions at once: exclusive locks, holding one while waiting for another, no way to take a lock away, and a cycle. Breaking any one prevents it. In practice you break the cycle with a global lock order.

Deadlock.java · a guaranteed deadlock, detected, then the ordered fix
import java.lang.management.*;
import java.util.concurrent.*;
import java.util.concurrent.locks.ReentrantLock;

public class Deadlock {
    static final class Account {
        final String id;
        final ReentrantLock lock = new ReentrantLock();
        long balance = 100;
        Account(String id) { this.id = id; }
    }

    // Locks in argument order: transfer(a, b) and transfer(b, a) can deadlock.
    static void transferUnordered(Account from, Account to, CyclicBarrier bothHoldFirst) throws Exception {
        from.lock.lock();
        try {
            bothHoldFirst.await();                         // make the bad interleaving certain
            to.lock.lock();
            try { from.balance -= 10; to.balance += 10; } finally { to.lock.unlock(); }
        } finally { from.lock.unlock(); }
    }

    // Always lock in one global order, here by id: no cycle is possible.
    static void transferOrdered(Account from, Account to) {
        Account first = from.id.compareTo(to.id) < 0 ? from : to;
        Account second = first == from ? to : from;
        first.lock.lock();
        try {
            second.lock.lock();
            try { from.balance -= 10; to.balance += 10; } finally { second.lock.unlock(); }
        } finally { first.lock.unlock(); }
    }

    public static void main(String[] args) throws Exception {
        Account a = new Account("ACC-A"), b = new Account("ACC-B");
        CyclicBarrier barrier = new CyclicBarrier(2);
        Thread t1 = Thread.ofPlatform().name("transfer-A-to-B").daemon().start(() -> {
            try { transferUnordered(a, b, barrier); } catch (Exception e) { }
        });
        Thread t2 = Thread.ofPlatform().name("transfer-B-to-A").daemon().start(() -> {
            try { transferUnordered(b, a, barrier); } catch (Exception e) { }
        });

        ThreadMXBean mx = ManagementFactory.getThreadMXBean();
        long[] ids;
        while ((ids = mx.findDeadlockedThreads()) == null) Thread.sleep(10);
        for (ThreadInfo info : mx.getThreadInfo(ids)) {
            String lock = info.getLockName().replaceAll("@[0-9a-f]+", "");
            System.out.println(info.getThreadName() + " is " + info.getThreadState() + " on " + lock
                    + ", held by " + info.getLockOwnerName());
        }
        System.out.println("both still alive: " + (t1.isAlive() && t2.isAlive()));

        Account c = new Account("ACC-C"), d = new Account("ACC-D");
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int i = 0; i < 10_000; i++) {
                pool.submit(() -> transferOrdered(c, d));
                pool.submit(() -> transferOrdered(d, c));
            }
        }
        System.out.println("ordered locking: 20,000 opposite transfers finished, balances " + c.balance + " and " + d.balance);
    }
}

Stuck.java · the same deadlock with synchronized, left running
public class Stuck {
    static final Object ACC_A = new Object(), ACC_B = new Object();
    public static void main(String[] args) throws Exception {
        Thread t1 = new Thread(() -> { synchronized (ACC_A) { pause(); synchronized (ACC_B) { } } }, "transfer-A-to-B");
        Thread t2 = new Thread(() -> { synchronized (ACC_B) { pause(); synchronized (ACC_A) { } } }, "transfer-B-to-A");
        t1.start(); t2.start(); t1.join();
    }
    static void pause() { try { Thread.sleep(200); } catch (InterruptedException e) { } }
}

Preventing it

Lock order: always acquire in one global order, by id as in transferOrdered. Timeouts: tryLock(timeout), release everything and retry. Fewer locks: one lock per aggregate, or a single-threaded owner fed through a queue. The database version, row locks taken in different orders, has the same cure.

Finding it

jcmd <pid> Thread.print or jstack <pid> prints "Found one Java-level deadlock" with every thread in the cycle. ThreadMXBean.findDeadlockedThreads() sees ReentrantLock cycles too, which is why the demo above found one with no synchronized in it. Take three dumps a few seconds apart for anything slow.

Its relatives

Livelock: threads keep reacting to each other and get nowhere, such as two tryLock loops backing off in step; add random back-off. Starvation: a thread never gets the lock or the CPU. Pool starvation: tasks in a bounded pool block on other tasks queued in the same pool, and every thread waits.
