Compare-and-set updates a value without a lock, by retrying whenever it loses a race

A CAS is one CPU instruction (lock cmpxchg on x86): if the value is still what I read, set it to my new value, and tell me whether that worked. Wrap it in a loop and you have a lock-free update. Under heavy contention many threads keep failing and retrying, which is what LongAdder avoids by giving each thread its own cell to increment.

Atomics.java · a CAS loop, the helpers, LongAdder, ABA, VarHandle
import java.lang.invoke.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.*;

public class Atomics {
    static final AtomicLong highest = new AtomicLong(Long.MIN_VALUE);

    static void recordMax(long value) {              // the compare-and-set loop
        long current;
        do {
            current = highest.get();
            if (value <= current) return;
        } while (!highest.compareAndSet(current, value));   // lost a race: read again, retry
    }

    static final class Seat {                        // CAS on an ordinary field, via a VarHandle
        volatile String holder;
        static final VarHandle HOLDER;
        static {
            try { HOLDER = MethodHandles.lookup().findVarHandle(Seat.class, "holder", String.class); }
            catch (ReflectiveOperationException e) { throw new ExceptionInInitializerError(e); }
        }
        boolean claim(String who) { return HOLDER.compareAndSet(this, null, who); }
    }

    static long time(int threads, Runnable work) throws InterruptedException {
        long t0 = System.nanoTime();
        try (ExecutorService pool = Executors.newFixedThreadPool(threads)) {
            for (int i = 0; i < threads; i++) pool.submit(work);
        }
        return (System.nanoTime() - t0) / 1_000_000;
    }

    public static void main(String[] args) throws Exception {
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int i = 0; i < 10_000; i++) { long v = (i * 7919L) % 10_007; pool.submit(() -> recordMax(v)); }
        }
        System.out.println("max recorded by 10,000 racing tasks: " + highest.get());

        AtomicInteger stock = new AtomicInteger(5);
        int left = stock.updateAndGet(s -> s > 0 ? s - 1 : s);          // never below zero
        int total = stock.accumulateAndGet(10, Integer::sum);
        System.out.println("updateAndGet " + left + ", accumulateAndGet " + total);

        AtomicLong atomic = new AtomicLong();
        LongAdder adder = new LongAdder();
        int threads = 8, each = 5_000_000;
        long atomicMs = time(threads, () -> { for (int i = 0; i < each; i++) atomic.incrementAndGet(); });
        long adderMs = time(threads, () -> { for (int i = 0; i < each; i++) adder.increment(); });
        System.out.printf("8 threads x 5M increments: AtomicLong %,d in %d ms, LongAdder %,d in %d ms (one run)%n",
                atomic.get(), atomicMs, adder.sum(), adderMs);

        // ABA: the value went A -> B -> A, and a plain CAS cannot tell.
        AtomicReference<String> top = new AtomicReference<>("A");
        AtomicStampedReference<String> stamped = new AtomicStampedReference<>("A", 0);
        String seen = top.get();
        int[] stampHolder = new int[1];
        String seenStamped = stamped.get(stampHolder);
        top.set("B"); top.set("A");                                     // another thread's changes
        stamped.set("B", 1); stamped.set("A", 2);
        System.out.println("plain CAS after A->B->A: " + top.compareAndSet(seen, "C")
                + ", stamped CAS: " + stamped.compareAndSet(seenStamped, "C", stampHolder[0], stampHolder[0] + 1));

        Seat seat = new Seat();
        System.out.println("VarHandle CAS: alice " + seat.claim("alice") + ", bob " + seat.claim("bob") + ", holder " + seat.holder);
    }
}

ClassUse it for
AtomicInteger, AtomicLongA counter or sequence that is also read often; incrementAndGet, compareAndSet
LongAdder, LongAccumulatorHot counters written by many threads and read rarely: metrics, request counts
AtomicReference<V>Swapping an immutable object: a config snapshot, a lock-free stack's top
AtomicStampedReferenceThe same, when A → B → A must be detected
VarHandle 9CAS on a field of your own class, with no wrapper object per instance
The function may run twiceupdateAndGet and accumulateAndGet retry the function each time the CAS fails, so it must be pure: no logging, no I/O, no counters of its own. ConcurrentHashMap.compute is the opposite case: it locks the bin and calls the function exactly once, so there the rule is to keep the function short.
ABAThe plain CAS succeeded because the value was A again, although two changes happened in between. That matters when the value stands for a version of something, such as a lock-free stack's top node. A stamp, or a fresh object for every state, makes each change distinct.
When a lock is betterSeveral variables that must change together, an invariant across fields, or long critical sections. A CAS covers one memory location. LongAdder's sum() is not an atomic snapshot either: it adds the cells while they keep changing.
