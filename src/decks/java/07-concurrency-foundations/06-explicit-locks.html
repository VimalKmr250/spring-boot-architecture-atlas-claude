ReentrantLock does what synchronized does, plus timeouts, interruption, fairness and several conditions

The locks in java.util.concurrent.locks are ordinary objects. You lock and unlock them yourself, which means you must unlock in finally, and in return you can give up after a timeout, abandon the wait when interrupted, and hold several wait queues on one lock. Read-write locks and StampedLock go further for data that is read far more often than written.

Locks.java · tryLock, lockInterruptibly, re-entrancy, readers together, optimistic reads
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.locks.*;

public class Locks {
    static final class Point {                       // StampedLock's optimistic read
        private final StampedLock sl = new StampedLock();
        private double x, y;
        void move(double dx, double dy) {
            long stamp = sl.writeLock();
            try { x += dx; y += dy; } finally { sl.unlockWrite(stamp); }
        }
        double distance(Runnable between) {
            long stamp = sl.tryOptimisticRead();     // no lock taken at all
            double cx = x, cy = y;
            between.run();                           // lets the demo slip a write in here
            if (!sl.validate(stamp)) {               // a write happened: fall back to a real read lock
                System.out.println("optimistic read invalidated, retrying under the read lock");
                stamp = sl.readLock();
                try { cx = x; cy = y; } finally { sl.unlockRead(stamp); }
            }
            return Math.hypot(cx, cy);
        }
    }

    public static void main(String[] args) throws Exception {
        ReentrantLock lock = new ReentrantLock();
        CountDownLatch held = new CountDownLatch(1), done = new CountDownLatch(1);
        Thread holder = new Thread(() -> {
            lock.lock();
            try { held.countDown(); done.await(); }
            catch (InterruptedException e) { Thread.currentThread().interrupt(); }
            finally { lock.unlock(); }
        });
        holder.start();
        held.await();
        long t0 = System.nanoTime();
        boolean got = lock.tryLock(100, TimeUnit.MILLISECONDS);
        System.out.printf("tryLock(100 ms) while another thread holds it: %b after ~%d ms%n",
                got, Math.round((System.nanoTime() - t0) / 1e8) * 100);

        Thread impatient = new Thread(() -> {
            try {
                lock.lockInterruptibly();
                lock.unlock();
            } catch (InterruptedException e) {
                System.out.println("lockInterruptibly gave up when interrupted");
            }
        });
        impatient.start();
        while (!lock.hasQueuedThread(impatient)) Thread.sleep(1);
        impatient.interrupt();
        impatient.join();
        done.countDown();
        holder.join();

        lock.lock();
        lock.lock();
        System.out.println("held twice by one thread: holdCount " + lock.getHoldCount());
        lock.unlock();
        lock.unlock();

        ReadWriteLock rw = new ReentrantReadWriteLock();
        AtomicInteger reading = new AtomicInteger(), peak = new AtomicInteger();
        CountDownLatch allIn = new CountDownLatch(3);
        try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
            for (int i = 0; i < 3; i++)
                pool.submit(() -> {
                    rw.readLock().lock();
                    try {
                        peak.accumulateAndGet(reading.incrementAndGet(), Math::max);
                        allIn.countDown();
                        allIn.await();                    // all three readers hold the lock at once
                        reading.decrementAndGet();
                    } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
                    finally { rw.readLock().unlock(); }
                    return null;
                });
            allIn.await();
            Future<Integer> writer = pool.submit(() -> {
                rw.writeLock().lock();                   // waits until every reader is gone
                try { return reading.get(); } finally { rw.writeLock().unlock(); }
            });
            System.out.println("readers inside together: " + peak.get() + "; readers left when the writer got in: " + writer.get());
        }

        var p = new Point();
        p.move(3, 4);
        System.out.println("distance " + p.distance(() -> { }));
        System.out.println("distance " + p.distance(() -> p.move(3, 4)));
    }
}

ReentrantReadWriteLock

Any number of readers together, or one writer alone: three readers held it at once above, and the writer waited until they left. A read lock can be taken while holding the write lock (downgrading), never the reverse: upgrading deadlocks. Only worth it when reads are long and frequent.

StampedLock

tryOptimisticRead() takes no lock: read the fields, then validate(stamp). If a write slipped in, as the demo forced, retry under a real read lock. Fastest for tiny read-mostly sections. Not re-entrant, and it has no conditions.

Which to picksynchronized by default. ReentrantLock when you need a timeout, interruption or two conditions, such as notFull and notEmpty in a bounded buffer. The LLD tab's locks, atomics and collections puts them to work in designs.
