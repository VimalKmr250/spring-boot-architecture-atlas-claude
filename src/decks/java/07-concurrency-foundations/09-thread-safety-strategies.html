Thread safety comes from not sharing, not mutating, or synchronising, in that order of preference

State that only one thread can reach needs no protection. State that never changes needs none either. Only shared, mutable state needs locks, atomics or concurrent collections, and each piece of it is a place where bugs and contention gather. The best concurrent design keeps that part small, and publishes everything else safely.

SafetyStrategies.java · a ThreadLocal leaking between pooled tasks, and the safe shapes
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.util.*;
import java.util.concurrent.*;

public class SafetyStrategies {
    static final ThreadLocal<String> CURRENT_USER = new ThreadLocal<>();

    static String handle(String user, boolean cleanUp) {
        if (user != null) CURRENT_USER.set(user);
        try {
            return "request for " + user + " runs as " + CURRENT_USER.get();
        } finally {
            if (cleanUp) CURRENT_USER.remove();               // always, in finally
        }
    }

    // Immutable and safely published through a final field: shareable as it is.
    record PriceList(Map<String, Long> cents) {
        PriceList { cents = Map.copyOf(cents); }
    }

    // Shared, mutable, published safely: a concurrent map in a final field.
    static final Map<String, Long> VIEWS = new ConcurrentHashMap<>();

    // DateTimeFormatter is immutable and thread-safe; SimpleDateFormat is neither.
    static final DateTimeFormatter ISO = DateTimeFormatter.ISO_LOCAL_DATE;

    public static void main(String[] args) throws Exception {
        try (ExecutorService pool = Executors.newSingleThreadExecutor()) {   // one reused thread
            System.out.println(pool.submit(() -> handle("alice", false)).get());
            System.out.println(pool.submit(() -> handle(null, false)).get() + "  <- leaked from the last task");
        }
        try (ExecutorService pool = Executors.newSingleThreadExecutor()) {
            System.out.println(pool.submit(() -> handle("alice", true)).get());
            System.out.println(pool.submit(() -> handle(null, true)).get());
        }

        var prices = new PriceList(Map.of("tea", 250L, "milk", 120L));
        List<String> totals = Collections.synchronizedList(new ArrayList<>());
        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            for (String sku : List.of("tea", "milk", "tea")) {
                pool.submit(() -> {
                    long sum = 0;                                  // stack-confined: no sharing at all
                    for (int i = 0; i < 3; i++) sum += prices.cents().get(sku);
                    totals.add(sku + "=" + sum);
                    VIEWS.merge(sku, 1L, Long::sum);
                });
            }
        }
        Collections.sort(totals);
        System.out.println("totals " + totals + ", views " + new TreeMap<>(VIEWS)
                + ", parsed " + LocalDate.parse("2026-10-07", ISO).getDayOfWeek());
    }
}

StrategyHow
Stack confinementLocals belong to one call on one thread: sum above is safe with no effort.
Thread confinementThreadLocal, or one owner thread fed through a queue (the actor style).
ImmutabilityRecords with copied components, final fields, List.copyOf: PriceList.
Thread-safe typesConcurrent collections, atomics, DateTimeFormatter instead of SimpleDateFormat.
LockingA lock around each invariant that spans more than one variable.
ThreadLocal in a poolPool threads live for the whole application, so a value set by one task is still there for the next one, here another user's identity. In an application server the same leak pins a whole web app's class loader in memory after a redeploy. Set and remove() in the same try / finally.
Publishing safelyAn object handed to another thread through a plain field may be seen half-built. Safe routes: a static initialiser, a volatile or AtomicReference field, a final field of a properly constructed object, a concurrent collection, or a lock both threads use.
ScopedValue replaces most ThreadLocalsFinal in JDK 25 (JEP 506): a value bound for the duration of one call, inherited by subtasks forked in a StructuredTaskScope, and impossible to leak because it is unbound when the call returns. With a million virtual threads, a ThreadLocal also means a million copies. See virtual threads under the hood.
