synchronized is a re-entrant lock on an object, and wait and notify are its waiting room

Every object has a monitor. A synchronized block takes it on entry and releases it on exit, even when an exception leaves the block, and each release happens-before the next acquire. wait() releases the monitor and sleeps until another thread calls notify or notifyAll on the same object. Together they build any blocking structure, which is why the JDK built BlockingQueue so you do not have to.

WaitNotify.java · a bounded buffer from one monitor, re-entrancy, the owner rule
import java.util.*;

public class WaitNotify {
    // A bounded buffer built from the monitor alone.
    static final class Buffer<T> {
        private final Deque<T> items = new ArrayDeque<>();
        private final int capacity;
        private int maxSeen;
        Buffer(int capacity) { this.capacity = capacity; }

        synchronized void put(T item) throws InterruptedException {
            while (items.size() == capacity) wait();   // a loop, never an if
            items.addLast(item);
            maxSeen = Math.max(maxSeen, items.size());
            notifyAll();                               // wake consumers (and other producers)
        }
        synchronized T take() throws InterruptedException {
            while (items.isEmpty()) wait();
            T item = items.removeFirst();
            notifyAll();
            return item;
        }
        synchronized int maxSeen() { return maxSeen; }
    }

    static final class Counter {
        private int n;
        synchronized void add() { n++; }
        synchronized void addTwice() { add(); add(); }   // re-entrant: the same thread holds the lock
        synchronized int get() { return n; }
    }

    public static void main(String[] args) throws Exception {
        var buffer = new Buffer<Integer>(2);
        List<Integer> consumed = Collections.synchronizedList(new ArrayList<>());
        Thread producer = new Thread(() -> {
            try {
                for (int i = 1; i <= 20; i++) buffer.put(i);
                buffer.put(-1);
                buffer.put(-1);                            // one stop signal per consumer
            } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        });
        Runnable consumer = () -> {
            try {
                for (int item; (item = buffer.take()) != -1; ) consumed.add(item);
            } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        };
        Thread c1 = new Thread(consumer), c2 = new Thread(consumer);
        producer.start(); c1.start(); c2.start();
        producer.join(); c1.join(); c2.join();
        List<Integer> sorted = new ArrayList<>(consumed);
        Collections.sort(sorted);
        System.out.println("consumed " + sorted.size() + " items, sum " + sorted.stream().mapToInt(i -> i).sum()
                + ", buffer never held more than " + buffer.maxSeen());

        var counter = new Counter();
        counter.addTwice();
        System.out.println("re-entrant addTwice: " + counter.get());

        Object monitor = new Object();
        try {
            monitor.wait();                                // without holding the monitor
        } catch (IllegalMonitorStateException e) {
            System.out.println("IllegalMonitorStateException: " + e.getMessage());
        }
        synchronized (monitor) {
            System.out.println("holdsLock inside synchronized: " + Thread.holdsLock(monitor));
            monitor.wait(10);                              // releases the monitor while it waits
        }
    }
}

The rules

  • A synchronized instance method locks this; a static one locks the Class object. They are different locks.
  • The lock is re-entrant: the thread that holds it can enter it again, so addTwice calling add works.
  • Call wait, notify and notifyAll only while holding that object's monitor, or get IllegalMonitorStateException.
  • Always wait in a loop that rechecks the condition. Wakeups can be spurious, and another thread may take the item between the notify and your return from wait.
  • Prefer notifyAll. notify wakes one arbitrary waiter, which may be a producer when only a consumer can make progress.
Lock on a private objectLocking this in a public class lets any caller take your lock too. Use private final Object lock = new Object(). Never lock a string literal or a boxed number: they are shared across the JVM, and javac's lint flags the boxed case ([synchronization] on JDK 21, [identity] on 25), as concurrency bugs shows.
Virtual threads and synchronizedOn JDK 21 to 23, blocking inside synchronized pinned a virtual thread to its carrier. JDK 24 removed that (JEP 491), so synchronized is fine again on 24 and later. Virtual threads under the hood measures both.
When to use it todaysynchronized is still the simplest correct lock for short critical sections. For waiting, use BlockingQueue, CountDownLatch or a Condition. Hand-written wait and notify belong in interviews and in libraries.
