ArrayList grows by half when full; LinkedList pays 24 bytes and a pointer chase per element

An ArrayList is an array with spare room. When it fills, it copies everything into an array 1.5 times larger, so appends are O(1) amortised. A LinkedList allocates a node per element, with links both ways. The textbook says linked lists win at inserts. On a modern CPU the array wins almost everything, because it is contiguous and the nodes are scattered across the heap.

ListGrowth.java · reads elementData by reflection, counts bytes per thread
// Run with: java --add-opens java.base/java.util=ALL-UNNAMED ListGrowth.java
import java.lang.management.ManagementFactory;
import java.lang.reflect.Field;
import java.util.*;

public class ListGrowth {
    static final com.sun.management.ThreadMXBean MX =
            (com.sun.management.ThreadMXBean) ManagementFactory.getThreadMXBean();
    static Field elementData;

    static int capacity(ArrayList<?> list) throws IllegalAccessException {
        return ((Object[]) elementData.get(list)).length;
    }

    public static void main(String[] args) throws Exception {
        elementData = ArrayList.class.getDeclaredField("elementData");
        elementData.setAccessible(true);

        var list = new ArrayList<Integer>();
        var growth = new StringBuilder("capacity " + capacity(list));
        for (int i = 0; i < 100; i++) {
            int before = capacity(list);
            list.add(i);
            if (capacity(list) != before) growth.append(" -> ").append(capacity(list));
        }
        System.out.println(growth + " (size " + list.size() + ")");
        list.trimToSize();
        System.out.println("after trimToSize: " + capacity(list));

        int n = 1_000_000;
        Integer[] boxes = new Integer[n];                   // box once, outside the measurements
        for (int i = 0; i < n; i++) boxes[i] = i + 1_000;

        long t = MX.getCurrentThreadAllocatedBytes();
        var grown = new ArrayList<Integer>();
        for (Integer b : boxes) grown.add(b);
        long grownBytes = MX.getCurrentThreadAllocatedBytes() - t;

        t = MX.getCurrentThreadAllocatedBytes();
        var presized = new ArrayList<Integer>(n);
        for (Integer b : boxes) presized.add(b);
        long presizedBytes = MX.getCurrentThreadAllocatedBytes() - t;

        t = MX.getCurrentThreadAllocatedBytes();
        var linked = new LinkedList<Integer>();
        for (Integer b : boxes) linked.add(b);
        long linkedBytes = MX.getCurrentThreadAllocatedBytes() - t;

        System.out.printf("bytes allocated per element: ArrayList grown %.1f, presized %.1f, LinkedList %.1f%n",
                grownBytes / (double) n, presizedBytes / (double) n, linkedBytes / (double) n);

        long sum = 0;
        long t0 = System.nanoTime();
        for (int i = 0; i < 1_000; i++) sum += presized.get(n / 2);
        long arrayNs = System.nanoTime() - t0;
        t0 = System.nanoTime();
        for (int i = 0; i < 1_000; i++) sum += linked.get(n / 2);
        long linkedNs = System.nanoTime() - t0;
        System.out.printf("1,000 x get(n/2): ArrayList %.2f ms, LinkedList %.0f ms (one run, sum %d)%n",
                arrayNs / 1e6, linkedNs / 1e6, sum);
    }
}

LineWhy
0 → 10 → 15 → 22A new list shares one empty array and allocates 10 slots on the first add. Each growth is old + old/2.
grown 14.6Each growth copies into a new array and discards the old one. The live list costs 4 to 6 bytes per element; the garbage costs the rest.
presized 4.0One reference per element, 4 bytes with compressed pointers. new ArrayList<>(n) when you know n.
LinkedList 24.0One node per element: a 12-byte object header and three 4-byte references (item, next, prev).
get(n/2)get(n/2) walks 500,000 nodes per call, from the nearer end, missing the cache at almost every step.
Default to ArrayListIteration, random access and appends are all fast, and the list itself needs a quarter or less of a linked list's memory. Even inserting into the middle is a System.arraycopy that moves bytes at memory speed, which beats walking to the node for most sizes.
Not a queue, eitherRemoving from the front of an ArrayList shifts every element: O(n). For a queue or a stack use ArrayDeque, which is a circular array and beats LinkedList at both ends too.
The one case for LinkedListMany inserts and removals in the middle of a long list, through a ListIterator you already hold. It is rare enough that Joshua Bloch, who wrote LinkedList, has said he never uses it.
