Change a collection while iterating it and the iterator throws, except when it silently skips

Every non-concurrent collection counts its structural changes in a field called modCount. An iterator remembers the count it started with and checks it on each next(); a mismatch throws ConcurrentModificationException. The name misleads: one thread is enough. And the check is best-effort, as the second case below shows.

FailFast.java · what throws, what silently skips, and the safe ways
import java.util.*;
import java.util.concurrent.*;

public class FailFast {
    public static void main(String[] args) {
        List<String> basket = new ArrayList<>(List.of("tea", "milk", "sugar", "eggs"));
        try {
            for (String item : basket)
                if (item.equals("milk")) basket.remove(item);           // structural change mid-loop
        } catch (ConcurrentModificationException e) {
            System.out.println("remove(\"milk\") in for-each: ConcurrentModificationException");
        }

        List<String> quiet = new ArrayList<>(List.of("tea", "milk", "sugar", "eggs"));
        List<String> visited = new ArrayList<>();
        for (String item : quiet) {
            visited.add(item);
            if (item.equals("sugar")) quiet.remove(item);              // the second-to-last element
        }
        System.out.println("remove(\"sugar\"): no exception, visited " + visited + ", left " + quiet);

        List<String> viaIterator = new ArrayList<>(List.of("tea", "milk", "sugar", "eggs"));
        for (Iterator<String> it = viaIterator.iterator(); it.hasNext(); )
            if (it.next().startsWith("s")) it.remove();                // the iterator's own remove
        List<String> viaRemoveIf = new ArrayList<>(List.of("tea", "milk", "sugar", "eggs"));
        viaRemoveIf.removeIf(s -> s.length() == 3);
        System.out.println("Iterator.remove " + viaIterator + ", removeIf " + viaRemoveIf);

        ListIterator<String> li = viaIterator.listIterator();
        while (li.hasNext()) {
            String s = li.next();
            li.set(s.toUpperCase());
            if (s.equals("tea")) li.add("lemon");                      // insert after the current one
        }
        System.out.println("ListIterator set/add " + viaIterator);

        Map<String, Integer> stock = new HashMap<>(Map.of("tea", 0, "milk", 4, "eggs", 0));
        try {
            for (String sku : stock.keySet()) if (stock.get(sku) == 0) stock.remove(sku);
        } catch (ConcurrentModificationException e) {
            System.out.println("HashMap remove during keySet loop: ConcurrentModificationException");
        }
        stock.entrySet().removeIf(e -> e.getValue() == 0);
        System.out.println("entrySet().removeIf " + stock);

        Map<String, Integer> live = new ConcurrentHashMap<>(Map.of("a", 1, "b", 2));
        for (String key : live.keySet()) live.put(key + key, 0);       // weakly consistent: no exception
        System.out.println("ConcurrentHashMap put during iteration: size " + live.size());

        List<String> listeners = new CopyOnWriteArrayList<>(List.of("audit", "email"));
        int seen = 0;
        for (String l : listeners) { listeners.add(l + "-copy"); seen++; }   // iterates a snapshot
        System.out.println("CopyOnWriteArrayList: iterated " + seen + ", now holds " + listeners.size());
    }
}

Why "sugar" did not throwFor-each calls hasNext() before every next(), and ArrayList.hasNext() is just cursor != size. Removing the second-to-last element makes size 3 just as cursor reaches 3, so the loop ends. next(), which does the check, is never called, and eggs is never visited. No exception, wrong result.
To change while iteratingUse
Remove matching elementsremoveIf 8, or Iterator.remove()
Replace or insert in a listListIterator.set, add; or replaceAll
Remove map entriesentrySet().removeIf, or computeIfPresent returning null
Add to what you iterateCollect into a new list, then addAll after the loop
Fail-fast is not a safety netThe Javadoc calls the exception best-effort: use it to find bugs, never to rely on for correctness. Between threads a plain collection may not throw at all, and give wrong data or corrupt itself instead. That needs a concurrent collection or a lock, not an iterator check.
Weakly consistent and snapshot iteratorsConcurrentHashMap's iterators never throw and may or may not show changes made during the loop: it grew to 4 entries while being iterated. CopyOnWriteArrayList iterates the array as it was when the loop started, so it saw 2 elements and the list ended with 4.
