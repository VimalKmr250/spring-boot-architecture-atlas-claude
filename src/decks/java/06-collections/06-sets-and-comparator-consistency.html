A TreeSet decides equality with compareTo, so a careless comparator deletes data

HashSet is a HashMap whose values are all one shared dummy object, so it uses hashCode and equals. TreeSet is a TreeMap, and it never calls equals: two elements that compare as 0 are the same element. Sort by length and every word of the same length is a duplicate.

SetsDemo.java · three orders, two vanishing acts, BigDecimal
import java.math.BigDecimal;
import java.util.*;

public class SetsDemo {
    public static void main(String[] args) {
        List<String> fruit = List.of("pear", "Apple", "fig", "apple", "plum", "kiwi");
        System.out.println("HashSet       " + new HashSet<>(fruit));
        System.out.println("LinkedHashSet " + new LinkedHashSet<>(fruit));
        System.out.println("TreeSet       " + new TreeSet<>(fruit) + "  (uppercase sorts first)");

        Set<String> byLength = new TreeSet<>(Comparator.comparing(String::length));
        byLength.addAll(fruit);
        System.out.println("TreeSet by length          " + byLength + "  <- three fruits vanished");
        Set<String> byLengthThenName = new TreeSet<>(Comparator.comparing(String::length)
                .thenComparing(Comparator.naturalOrder()));
        byLengthThenName.addAll(fruit);
        System.out.println("by length, then by name    " + byLengthThenName);

        Set<String> ignoreCase = new TreeSet<>(String.CASE_INSENSITIVE_ORDER);
        ignoreCase.addAll(fruit);
        Set<String> exact = new HashSet<>(fruit);
        System.out.println("case-insensitive TreeSet   " + ignoreCase + ", contains(\"APPLE\") " + ignoreCase.contains("APPLE")
                + "; HashSet contains(\"APPLE\") " + exact.contains("APPLE"));

        List<BigDecimal> prices = List.of(new BigDecimal("2.0"), new BigDecimal("2.00"));
        System.out.println("BigDecimal 2.0 and 2.00: HashSet size " + new HashSet<>(prices).size()
                + ", TreeSet size " + new TreeSet<>(prices).size()
                + "  (equals " + prices.get(0).equals(prices.get(1)) + ", compareTo " + prices.get(0).compareTo(prices.get(1)) + ")");

        try {
            Set.of("a", "b", "a");
        } catch (IllegalArgumentException e) {
            System.out.println("Set.of with a duplicate: " + e.getMessage());
        }
    }
}

Three fruits vanishedpear, plum and kiwi all have four letters, so to the length comparator they are one element: the first is kept and the others are dropped without an error. Always break ties down to a total order: .thenComparing(Comparator.naturalOrder()).
BigDecimal disagrees with itself2.0 and 2.00 have different scales, so equals is false while compareTo is 0. The same two prices make a HashSet of 2 and a TreeSet of 1. Normalise with stripTrailingZeros(), or choose one collection on purpose.
When inconsistency is the pointA TreeSet with String.CASE_INSENSITIVE_ORDER is a case-insensitive set by design: it found "APPLE" where the HashSet did not. That is legitimate, but it breaks the Set contract, so do not pass it to code that expects equals semantics.
