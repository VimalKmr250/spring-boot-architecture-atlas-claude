The utility classes save a loop each, and each one has a trap that comes up in interviews

Arrays and Collections hold the sorting, searching, copying and wrapping methods. Most are one-liners you should reach for instead of writing loops. A few behave in ways that look like bugs until you know the rule: Arrays.asList on an int[], a binary search on unsorted data, and equals on arrays.

Utilities.java · asList, stable sorting, binary search, array equality
import java.util.*;

public class Utilities {
    record Order(String id, String status, int day) {
        @Override public String toString() { return id + "/" + status + "/d" + day; }
    }

    public static void main(String[] args) {
        int[] ids = {3, 1, 2};
        List<int[]> oops = Arrays.asList(ids);                  // one element: the int[] itself
        List<Integer> boxed = Arrays.stream(ids).boxed().toList();
        System.out.println("Arrays.asList(int[]) size " + oops.size() + "; boxed " + boxed);

        String[] codes = {"b", "a", "c"};
        List<String> fixed = Arrays.asList(codes);              // fixed-size, backed by the array
        fixed.set(0, "z");
        System.out.println("set through the list changed the array: " + Arrays.toString(codes));
        try { fixed.add("d"); } catch (UnsupportedOperationException e) { System.out.println("Arrays.asList(...).add -> UnsupportedOperationException"); }

        List<Order> orders = new ArrayList<>(List.of(new Order("o1", "PAID", 3), new Order("o2", "NEW", 1),
                new Order("o3", "PAID", 1), new Order("o4", "NEW", 2), new Order("o5", "PAID", 2)));
        orders.sort(Comparator.comparingInt(Order::day));
        orders.sort(Comparator.comparing(Order::status));        // stable: day order kept within a status
        System.out.println("stable sort by status after day " + orders);

        int[] sorted = {10, 20, 30, 40};
        System.out.println("binarySearch 30 -> " + Arrays.binarySearch(sorted, 30)
                + ", 25 -> " + Arrays.binarySearch(sorted, 25) + " (= -(insertion point 2) - 1)");
        int[] unsorted = {40, 10, 30, 20};
        System.out.println("binarySearch on unsorted data for 40 -> " + Arrays.binarySearch(unsorted, 40));

        int[] a = {1, 2}, b = {1, 2};
        System.out.println("a == b " + (a == b) + ", a.equals(b) " + a.equals(b) + ", Arrays.equals " + Arrays.equals(a, b));
        System.out.println("2-D toString " + Arrays.toString(new int[][] {{1}, {2}}).replaceAll("@[0-9a-f]+", "@…")
                + ", deepToString " + Arrays.deepToString(new int[][] {{1}, {2}}));

        List<String> tags = new ArrayList<>(List.of("x", "y", "x", "z", "x"));
        Collections.shuffle(tags, new Random(42));               // seeded: the same order every run
        System.out.println("frequency(x) " + Collections.frequency(tags, "x") + ", nCopies " + Collections.nCopies(3, "-")
                + ", shuffled " + tags + ", max " + Collections.max(tags) + ", disjoint " + Collections.disjoint(tags, List.of("q")));

        List<String> withNulls = new ArrayList<>(Arrays.asList("b", null, "a"));
        withNulls.sort(Comparator.nullsFirst(Comparator.naturalOrder()));
        System.out.println("nullsFirst " + withNulls);
    }
}

MethodThe rule
Arrays.asList(T...)A fixed-size list backed by the array: set writes through, add and remove throw. On an int[], T is int[], so you get a list of one array.
Arrays.sortPrimitives: dual-pivot quicksort. Objects: TimSort, which is stable, so sorting by day and then by status keeps the day order within each status.
Arrays.binarySearchRequires sorted input; on unsorted data the answer is meaningless. A miss returns -(insertion point) - 1, always negative.
Array equals, hashCode, toStringInherited from Object: identity. Use Arrays.equals, Arrays.hashCode, Arrays.toString, and the deep versions for nested arrays.
Collections.shuffle(list, rnd)Pass a seeded Random when a test needs the same order every run.

Arrays, worth knowing

fill, setAll, copyOf, copyOfRange, stream, parallelSort, mismatch 9, compare 9. System.arraycopy is the fast primitive under most of them.

Collections, worth knowing

frequency, nCopies, disjoint, max and min with a comparator, reverse, swap, rotate, and the empty…, singleton…, unmodifiable…, checked… and synchronized… wrappers.

synchronizedList is half the jobEach method takes a lock, but iteration is many calls, so you must hold synchronized (list) around the whole loop yourself or risk ConcurrentModificationException. A concurrent collection is usually the better fix: see copy-on-write and lock-free collections.
