A HashMap is an array of buckets, and the key's hash picks one bucket to search

put and get do the same three steps. Call hashCode(). Mix the high 16 bits into the low 16. Keep the low bits as the array index. Then only that one bucket is searched, comparing the stored hash first and calling equals only when the hashes match. That is why a lookup is O(1) on average, and why equals and hashCode must agree.

HashMapPeek.java · the index arithmetic, then the table itself
// Run with: java --add-opens java.base/java.util=ALL-UNNAMED HashMapPeek.java
import java.lang.reflect.Field;
import java.util.*;

public class HashMapPeek {
    static Field table, next, key;

    static int spread(Object k) {                       // what HashMap.hash(key) computes
        if (k == null) return 0;
        int h = k.hashCode();
        return h ^ (h >>> 16);                          // fold the high bits into the low ones
    }

    static void dump(HashMap<?, ?> map) throws Exception {
        Object[] tab = (Object[]) table.get(map);
        System.out.println("table length " + tab.length + ", size " + map.size());
        for (int i = 0; i < tab.length; i++) {
            if (tab[i] == null) continue;
            List<Object> keys = new ArrayList<>();
            for (Object node = tab[i]; node != null; node = next.get(node)) keys.add(key.get(node));
            System.out.println("  bucket " + String.format("%2d", i) + ": " + keys);
        }
    }

    public static void main(String[] args) throws Exception {
        table = HashMap.class.getDeclaredField("table");
        table.setAccessible(true);
        Class<?> node = Class.forName("java.util.HashMap$Node");
        next = node.getDeclaredField("next");
        next.setAccessible(true);
        key = node.getDeclaredField("key");
        key.setAccessible(true);

        String k = "SKU-17";
        int h = k.hashCode();
        System.out.printf("hashCode     %32s  (%d)%n", Integer.toBinaryString(h), h);
        System.out.printf("h >>> 16     %32s%n", Integer.toBinaryString(h >>> 16));
        System.out.printf("spread       %32s%n", Integer.toBinaryString(spread(k)));
        System.out.printf("& (16 - 1)   %32s  -> bucket %d%n", Integer.toBinaryString(spread(k) & 15), spread(k) & 15);

        var stock = new HashMap<String, Integer>();
        for (String s : List.of("SKU-17", "apple", "banana", "cherry", "Aa", "BB", "plum"))
            stock.put(s, s.length());
        stock.put(null, 0);                             // allowed, always bucket 0
        dump(stock);
        System.out.println("iteration order: " + stock.keySet());
    }
}

Design choiceWhy
Power-of-two tablehash & (n - 1) is a single AND, where hash % n is a division.
Spreading the hashThe mask keeps only the low bits. Keys whose hash codes differ only in high bits, such as many Float values, would all collide without it.
Hash stored in the nodeComparing two ints rejects most keys in a bucket before any equals call, and a resize never calls hashCode again.
Null keyHashes to 0, so it always lives in bucket 0. Hashtable and ConcurrentHashMap reject it.
Iteration order is bucket orderThe keys came out as bucket 0, then 1, then 12: neither insertion order nor sorted, and it changes when the table resizes, on the next slide. Code that depends on HashMap order breaks on a JDK upgrade or a larger data set.
