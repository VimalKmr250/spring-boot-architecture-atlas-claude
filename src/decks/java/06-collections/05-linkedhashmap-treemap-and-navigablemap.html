LinkedHashMap remembers order; TreeMap keeps keys sorted and answers range questions

LinkedHashMap is a HashMap with a doubly linked list threaded through its entries, in insertion order or, if you ask, access order. That second mode plus one overridden method is an LRU cache. TreeMap is a red-black tree: every operation is O(log n), and in exchange it can find the nearest key, the first or last entry, or a whole range.

OrderedMaps.java · three orders, an LRU cache, price bands by weight
import java.util.*;

public class OrderedMaps {
    // An LRU cache in eight lines: access order plus an eviction hook.
    static class LruCache<K, V> extends LinkedHashMap<K, V> {
        private static final long serialVersionUID = 1L;
        private final int capacity;
        LruCache(int capacity) {
            super(16, 0.75f, true);                       // true = access order, not insertion
            this.capacity = capacity;
        }
        @Override protected boolean removeEldestEntry(Map.Entry<K, V> eldest) { return size() > capacity; }
    }

    public static void main(String[] args) {
        List<String> skus = List.of("tea", "apple", "milk", "bread", "eggs");
        Map<String, Integer> hash = new HashMap<>(), linked = new LinkedHashMap<>(), tree = new TreeMap<>();
        for (String s : skus) { hash.put(s, s.length()); linked.put(s, s.length()); tree.put(s, s.length()); }
        System.out.println("HashMap       " + hash.keySet());
        System.out.println("LinkedHashMap " + linked.keySet() + "  insertion order");
        System.out.println("TreeMap       " + tree.keySet() + "  sorted");

        var cache = new LruCache<String, String>(3);
        cache.put("a", "A");
        cache.put("b", "B");
        cache.put("c", "C");
        cache.get("a");                                   // a becomes the most recently used
        cache.put("d", "D");                              // evicts the eldest: b
        System.out.println("LRU after get(a), put(d): " + cache.keySet());

        // Shipping price by weight band: the band starts at the key, in kg.
        NavigableMap<Double, Integer> bands = new TreeMap<>(Map.of(0.0, 4, 2.0, 7, 5.0, 12, 10.0, 20, 30.0, 45));
        for (double kg : new double[] {0.4, 2.0, 7.5, 31})
            System.out.println(kg + " kg -> band " + bands.floorKey(kg) + " costs " + bands.floorEntry(kg).getValue());
        System.out.println("ceilingKey(7.5) " + bands.ceilingKey(7.5) + ", higherKey(10.0) " + bands.higherKey(10.0)
                + ", lowerKey(0.0) " + bands.lowerKey(0.0));
        System.out.println("headMap(5.0) " + bands.headMap(5.0) + ", tailMap(10.0, true) " + bands.tailMap(10.0, true));
        System.out.println("subMap(2.0, 10.0) " + bands.subMap(2.0, 10.0) + ", descending " + bands.descendingKeySet());
        System.out.println("pollFirstEntry " + bands.pollFirstEntry() + ", now first " + bands.firstKey());
    }
}

Access order makes get a writeIn access-order mode every get moves an entry, so it is a structural change. Iterating while calling get throws ConcurrentModificationException, and two threads that only read can still corrupt the list. The thread-safe version is on the LLD tab's LRU cache.
floorEntry is a lookup tableTax brackets, shipping bands, rate cards, time-based price lists: store each band's start as a key and floorEntry(x) finds the band for any x in O(log n). That replaces a chain of ifs that someone has to keep in order.
Views write throughheadMap, tailMap and subMap are views: removing from one removes from the map, and putting a key outside the range throws IllegalArgumentException: key out of range. For a sorted map shared between threads, use ConcurrentSkipListMap.
