A virtual thread is a continuation run on a few carrier threads, and blocking takes it off its carrier

A virtual thread since 21 is a java.lang.Thread whose stack lives on the heap. The JDK schedules virtual threads onto a ForkJoinPool of carrier threads, one per core by default. When a virtual thread blocks in sleep, socket I/O, a lock or a queue, its frames are saved to the heap and the carrier is free to run another. That is how 100,000 threads each sleeping for a second finish in about two seconds on 20 carriers.

VirtualInternals.java · carriers change, and few carriers serve many threads
import java.time.Duration;
import java.util.*;
import java.util.concurrent.*;

public class VirtualInternals {
    static String carrier() {                       // "VirtualThread[#29]/runnable@ForkJoinPool-1-worker-3"
        String s = Thread.currentThread().toString();
        return s.substring(s.indexOf('@') + 1);
    }

    public static void main(String[] args) throws Exception {
        var moved = new java.util.concurrent.atomic.AtomicInteger();
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 20; i++)
                ex.submit(() -> {
                    String before = carrier();
                    Thread.sleep(Duration.ofMillis(50));      // unmount, then mount again later
                    if (!carrier().equals(before)) moved.incrementAndGet();
                    return null;
                });
        }
        System.out.println("virtual threads that woke up on a different carrier: " + moved.get() + " of 20 (varies by run)");

        Set<String> carriers = ConcurrentHashMap.newKeySet();
        long t0 = System.nanoTime();
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 100_000; i++)
                ex.submit(() -> {
                    Thread.sleep(Duration.ofSeconds(1));      // unmounts: the carrier runs others
                    carriers.add(carrier());
                    return null;
                });
        }
        System.out.printf("100,000 virtual threads slept 1 s each: %.1f s in total, on %d carrier threads (%d cores)%n",
                (System.nanoTime() - t0) / 1e9, carriers.size(), Runtime.getRuntime().availableProcessors());
    }
}

Pinning.java · one carrier, ten threads each sleeping 100 ms while holding a lock
// Run with: java -Djdk.virtualThreadScheduler.parallelism=1 Pinning.java
import java.time.Duration;
import java.util.concurrent.*;
import java.util.concurrent.locks.ReentrantLock;

// One carrier thread, ten virtual threads, each sleeping 100 ms while holding its own lock.
public class Pinning {
    static long run(boolean useSynchronized) throws InterruptedException {
        long t0 = System.nanoTime();
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 10; i++) {
                Object monitor = new Object();
                ReentrantLock lock = new ReentrantLock();
                ex.submit(() -> {
                    if (useSynchronized) {
                        synchronized (monitor) { sleep(); }        // pinned on JDK 21 to 23
                    } else {
                        lock.lock();
                        try { sleep(); } finally { lock.unlock(); }
                    }
                });
            }
        }
        return (System.nanoTime() - t0) / 1_000_000;
    }

    static void sleep() {
        try { Thread.sleep(Duration.ofMillis(100)); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }

    public static void main(String[] args) throws InterruptedException {
        System.out.println(Runtime.version().feature() + ": synchronized " + run(true) + " ms, ReentrantLock " + run(false) + " ms");
    }
}

PinningA virtual thread that cannot unmount holds its carrier while it waits. On JDK 21 to 23 that happened inside synchronized: with one carrier, ten 100 ms sleeps ran one after another, for over a second. JDK 24 fixed it (JEP 491), and on 25 they overlap again. Native code and foreign calls still pin. The JFR event jdk.VirtualThreadPinned reports where.
Where they do not helpCPU-bound work: there are still only as many carriers as cores. Pooling them: they are cheap, so create one per task. Unlimited fan-out: 100,000 threads can open 100,000 connections, so bound the downstream with a Semaphore or a connection pool, as the LLD slide does.
The companionsScopedValue is final in JDK 25 (JEP 506) and replaces most ThreadLocal use. StructuredTaskScope runs subtasks as one unit that fails and cancels together; it is still a preview API in 25 (JEP 505), so this tab's code does not use it.
