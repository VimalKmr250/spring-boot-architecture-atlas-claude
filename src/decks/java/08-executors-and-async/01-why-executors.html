An executor separates submitting work from running it, so threads become a resource you size once

A platform thread costs an OS thread, a reserved stack and tens of microseconds to start. Creating one per task pays that every time, and lets the load decide how many threads exist. An ExecutorService keeps a set of threads and a queue, so the same 10,000 tasks start 8 threads instead of 10,000. The factory methods in Executors each make a different trade-off, and some hide an unbounded queue or an unbounded thread count.

WhyExecutors.java · thread per task against a pool, named threads, what each factory builds
import java.lang.management.ManagementFactory;
import java.util.*;
import java.util.concurrent.*;

public class WhyExecutors {
    static long threadsStarted() { return ManagementFactory.getThreadMXBean().getTotalStartedThreadCount(); }

    static String describe(ExecutorService e) {
        if (!(e instanceof ThreadPoolExecutor p)) return e.getClass().getSimpleName();
        int cap = p.getQueue().remainingCapacity();
        return String.format("core %d, max %s, queue %s (capacity %s)", p.getCorePoolSize(),
                p.getMaximumPoolSize() == Integer.MAX_VALUE ? "unbounded" : p.getMaximumPoolSize(),
                p.getQueue().getClass().getSimpleName(), cap == Integer.MAX_VALUE ? "unbounded" : cap);
    }

    public static void main(String[] args) throws Exception {
        int tasks = 10_000;
        long before = threadsStarted(), t0 = System.nanoTime();
        List<Thread> started = new ArrayList<>();
        for (int i = 0; i < tasks; i++) {
            Thread t = new Thread(() -> Math.sqrt(42));
            t.start();
            started.add(t);
        }
        for (Thread t : started) t.join();
        System.out.printf("new Thread per task: %,d threads started, %d ms%n",
                threadsStarted() - before, (System.nanoTime() - t0) / 1_000_000);

        before = threadsStarted();
        t0 = System.nanoTime();
        try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
            for (int i = 0; i < tasks; i++) pool.submit(() -> Math.sqrt(42));
        }                                                      // close() waits for every task (19+)
        System.out.printf("fixed pool of 8:     %,d threads started, %d ms (one run)%n",
                threadsStarted() - before, (System.nanoTime() - t0) / 1_000_000);

        ThreadFactory named = Thread.ofPlatform().name("order-worker-", 1).factory();
        Set<String> names = new ConcurrentSkipListSet<>();
        try (ExecutorService pool = Executors.newFixedThreadPool(3, named)) {
            for (int i = 0; i < 30; i++) pool.submit(() -> names.add(Thread.currentThread().getName()));
        }
        System.out.println("named threads that ran 30 tasks: " + names);

        try (ExecutorService fixed = Executors.newFixedThreadPool(4);
             ExecutorService cached = Executors.newCachedThreadPool();
             ExecutorService scheduled = Executors.newScheduledThreadPool(2);
             ExecutorService stealing = Executors.newWorkStealingPool();
             ExecutorService virtual = Executors.newVirtualThreadPerTaskExecutor()) {
            System.out.println("newFixedThreadPool(4)       " + describe(fixed));
            System.out.println("newCachedThreadPool()       " + describe(cached));
            System.out.println("newScheduledThreadPool(2)   " + describe(scheduled));
            System.out.println("newWorkStealingPool()       " + describe(stealing));
            System.out.println("newVirtualThreadPerTask...  " + describe(virtual));
        }
    }
}

FactoryWhat it hides
newFixedThreadPool(n)An unbounded queue. Under overload it grows until OutOfMemoryError, and latency grows with it.
newSingleThreadExecutor()The same unbounded queue, with one thread: tasks run strictly in order.
newCachedThreadPool()No queue and no thread limit: a burst of slow tasks creates a thread for each one.
newScheduledThreadPool(n)A delay queue; see scheduled executors.
newWorkStealingPool()A ForkJoinPool sized to the cores, for CPU-bound work.
newVirtualThreadPerTaskExecutor() 21A new virtual thread per task: no queue, no limit. Bound the resource it calls instead.
Build production pools by handnew ThreadPoolExecutor(…) with a bounded queue, a named ThreadFactory and an explicit rejection policy makes overload visible as rejections instead of a growing heap. The next slide takes one apart.
Name your threadsA thread dump full of pool-7-thread-3 says nothing. Thread.ofPlatform().name("order-worker-", 1).factory() 21 makes the dump, the logs and the profiler point at the right pool.
