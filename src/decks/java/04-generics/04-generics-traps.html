Every unchecked warning is a ClassCastException somewhere else, later

Raw types, unchecked casts and generic varargs all switch the compiler's checks off for one line. The program still compiles. The wrong object then travels until some code that trusts the generic type reads it, and the ClassCastException names that innocent line, not the one that caused it. javac warns about every one of them if you let it.

GenericsTraps.java · heap pollution, three ways
import java.time.LocalTime;
import java.util.*;

public class GenericsTraps {
    static void legacyAdd(List list) {                    // a raw type: generics switched off
        list.add(42);
    }

    @SuppressWarnings("unchecked")
    static <T> T unsafeCast(Object o) { return (T) o; }   // erased to Object: checks nothing

    static <T> T[] toArray(T... items) { return items; }  // hands out the varargs array
    static <T> T[] pair(T a, T b) { return toArray(a, b); }   // here T[] is made as Object[]

    @SafeVarargs                                          // safe: it only reads the array
    static <T> List<T> listOf(T... items) {
        List<T> list = new ArrayList<>(items.length);
        for (T item : items) list.add(item);
        return list;
    }

    static String brief(ClassCastException e) {           // drop the module details
        return e.getMessage().substring(0, e.getMessage().indexOf(" ("));
    }

    public static void main(String[] args) {
        List<String> names = new ArrayList<>(List.of("ana"));
        legacyAdd(names);                                 // compiles, with a warning
        System.out.println("names holds " + names.size() + " elements: " + names);
        try {
            String second = names.get(1);                 // the failure surfaces here, later
            System.out.println(second);
        } catch (ClassCastException e) {
            System.out.println("1 " + brief(e));
        }

        try {
            String text = unsafeCast(LocalTime.NOON);     // javac's checkcast sits on this line
            System.out.println(text);
        } catch (ClassCastException e) {
            System.out.println("2 " + brief(e));
        }

        try {
            String[] both = pair("a", "b");
            System.out.println(both.length);
        } catch (ClassCastException e) {
            System.out.println("3 " + brief(e));
        }

        System.out.println("4 " + listOf("a", "b") + " " + listOf(1, 2));
    }
}

#The causeWhere it fails
1A raw List parameter lets 42 into a List<String>. Printing the list works, because toString treats elements as Object.The first line that reads an element as a String
2(T) o erases to (Object) o and checks nothing. javac puts the real checkcast String at the call site.The caller's assignment, nowhere near the cast
3Inside pair, T is unknown, so the varargs array is created as Object[] and returned as a T[].The caller, when it treats the array as a String[]
4@SafeVarargs on a method that only reads the array is a true promise, so there is no warning and no failure.Nowhere
@SuppressWarnings is a promiseSuppress an unchecked warning only on the smallest scope, a single variable declaration as in Erasure.newArray, with a comment saying why it is safe. A class-level suppression hides the next one too.
Make the build enforce itCompile with -Xlint:all -Werror, or set options.compilerArgs in Gradle, and none of these reach main. In legacy code, wrap raw APIs once at the boundary with a checked copy: Collections.checkedList(list, String.class) fails at the bad add instead of the later read.
