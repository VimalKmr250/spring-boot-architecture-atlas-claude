Generic methods declare their own type parameters, and inference fills them in from the call

A generic method puts <T> before its return type and can be generic in a class that is not. javac infers T from the arguments and from the type the result is assigned to (target typing), which is what lets Comparator.comparing(String::length) compile without a single type written. var uses the same inference, and with a diamond it falls back to Object.

Inference.java · inference, witnesses, var, self-typed builders
import java.util.*;
import java.util.function.*;

public class Inference {
    static <T> T firstOr(List<? extends T> items, T fallback) {
        return items.isEmpty() ? fallback : items.get(0);
    }

    static <K, V extends Comparable<? super V>> Optional<K> keyOfMax(Map<K, V> map) {
        return map.entrySet().stream().max(Map.Entry.comparingByValue()).map(Map.Entry::getKey);
    }

    // A self-referential bound lets a base builder return the subclass type.
    abstract static class Builder<B extends Builder<B>> {
        final Map<String, String> fields = new LinkedHashMap<>();
        B with(String k, String v) { fields.put(k, v); return self(); }
        abstract B self();
    }
    static final class OrderBuilder extends Builder<OrderBuilder> {
        OrderBuilder express() { fields.put("shipping", "express"); return this; }
        @Override OrderBuilder self() { return this; }
    }

    public static void main(String[] args) {
        String s = firstOr(List.of(), "none");                 // T inferred as String
        Number n = firstOr(List.of(1, 2), 2.5);                // T inferred from both: Number
        System.out.println(s + " " + n);

        List<String> empty = Collections.<String>emptyList();  // an explicit type witness
        System.out.println("witness " + empty + ", max key " + keyOfMax(Map.of("a", 3, "b", 9)));

        var orders = new ArrayList<String>();                  // var + explicit type argument
        var anything = new ArrayList<>();                      // var + diamond: ArrayList<Object>
        anything.add(1);
        anything.add("two");
        orders.add("ORD-1");
        System.out.println("var with diamond holds " + anything + ", orders " + orders);

        Comparator<String> byLength = Comparator.comparing(String::length);  // target typing
        Function<Integer, String> label = i -> "#" + i;
        System.out.println(byLength.compare("aa", "b") + " " + label.apply(7));

        Iterator<Integer> countdown = new Iterator<>() {        // diamond on anonymous classes: 9
            int left = 3;
            @Override public boolean hasNext() { return left > 0; }
            @Override public Integer next() { return left--; }
        };
        while (countdown.hasNext()) System.out.print(countdown.next() + " ");
        System.out.println();

        var order = new OrderBuilder().with("id", "ORD-7").express().with("note", "gift");
        System.out.println(order.getClass().getSimpleName() + " " + order.fields);
    }
}

Self-referential boundsB extends Builder<B> lets a base class return the subclass type from fluent methods. The JDK uses the same shape in Enum<E extends Enum<E>> and Comparable<T> bounds.
When inference gives upLong chains such as Comparator.comparing(o -> o.total()).reversed() lose the target type, because reversed() is called on the result before anything is assigned. Use a method reference, a typed lambda parameter or a witness. The comparator slide shows the fix.
