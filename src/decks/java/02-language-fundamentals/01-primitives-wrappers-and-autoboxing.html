Eight primitives, eight wrappers, and boxing that converts between them without a word

A primitive holds a value. A wrapper is an object: it can be null, it lives in collections, and it has identity. The compiler boxes and unboxes for you, so a == that compares objects, an unboxed null and a remove(1) that removes the wrong element all compile cleanly.

Boxing.java · the cache, unboxing null, the overload, silent narrowing
import java.util.*;

public class Boxing {
    static Integer discount;                          // a field nobody set: null

    public static void main(String[] args) {
        Integer a = 127, b = 127, c = 128, d = 128;
        System.out.println("127 == 127     " + (a == b));      // the same cached object
        System.out.println("128 == 128     " + (c == d));      // two different objects
        System.out.println("128 equals 128 " + c.equals(d));

        Long total = 128L;
        System.out.println("Long 128 equals int 128   " + total.equals(128));   // 128 boxes to Integer
        System.out.println("Long 128 equals long 128  " + total.equals(128L));

        Map<String, Integer> stock = new HashMap<>();
        try {
            int left = stock.get("SKU-1");                   // auto-unboxing a null
            System.out.println(left);
        } catch (NullPointerException e) {
            System.out.println("NPE: " + e.getMessage());
        }

        boolean member = false;
        try {
            Integer off = member ? 10 : discount;            // int ? int : Integer is an int
            System.out.println(off);
        } catch (NullPointerException e) {
            System.out.println("NPE: " + e.getMessage());
        }

        List<Integer> ids = new ArrayList<>(List.of(10, 20, 30));
        ids.remove(1);                                       // remove(int index): drops 20
        ids.remove(Integer.valueOf(10));                     // remove(Object): drops 10
        System.out.println("after both removes " + ids);

        System.out.println("(byte) 200      " + (byte) 200);
        System.out.println("'a' + 1         " + ('a' + 1));
        System.out.println("(char) ('a' + 1) " + (char) ('a' + 1));
        System.out.println("7 / 2 = " + (7 / 2) + ", 7 / 2.0 = " + (7 / 2.0));
        short s = 1;
        s += 70_000;                                         // compound assignment narrows silently
        System.out.println("short 1 += 70000 " + s);
    }
}

== on wrappersIt passes every test that uses small numbers, because Integer.valueOf returns cached objects from −128 to 127. Real order IDs are bigger, and == compares two different objects. Compare wrappers with equals, or unbox first.
The ternary that unboxesmember ? 10 : discount mixes an int and an Integer, so the whole expression is an int and discount is unboxed even though only the else branch was chosen. The helpful NPE message (Java 14+) names the field.
Long is not IntegerLong.equals(128) is false because 128 boxes to an Integer. The same bug makes Map<Long, Order>.get(5) return null. Boxing in a hot loop costs allocations too: see resource and memory bugs.
