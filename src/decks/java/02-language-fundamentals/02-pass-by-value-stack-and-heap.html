Java passes everything by value; for an object, the value is a reference

A call copies each argument into the new stack frame. For an int the copy is the number. For an object the copy is the reference, so caller and callee point at the same object: the callee can change that object, but reassigning its parameter only moves its own copy. There is no way to write swap(a, b) in Java.

PassByValue.java · every method gets copies
import java.util.*;

public class PassByValue {
    static void bump(int n) { n++; }                                  // changes the copy
    static void rename(StringBuilder sb) { sb = new StringBuilder("renamed"); }
    static void append(StringBuilder sb) { sb.append(" + appended"); }  // through the copy
    static void swap(Integer x, Integer y) { Integer t = x; x = y; y = t; }
    static void replace(List<String> list) { list = new ArrayList<>(List.of("new")); }
    static void clear(List<String> list) { list.clear(); }

    public static void main(String[] args) {
        int count = 1;
        bump(count);
        System.out.println("int after bump        " + count);

        var sb = new StringBuilder("original");
        rename(sb);
        System.out.println("after rename          " + sb);
        append(sb);
        System.out.println("after append          " + sb);

        Integer a = 1, b = 2;
        swap(a, b);
        System.out.println("after swap            a=" + a + " b=" + b);

        List<String> items = new ArrayList<>(List.of("x", "y"));
        replace(items);
        System.out.println("after replace         " + items);
        clear(items);
        System.out.println("after clear           " + items);
    }
}

after rename          original

after swap            a=1 b=2
after replace         [x, y]
after clear           []
Inside the methodDoes the caller see it?
Change a primitive parameterNo. It changed a copy.
Call a mutating method on an object parameterYes. Both references point at that object.
Assign a new object to the parameterNo. Only the callee's copy now points elsewhere.
Swap two parametersNo, and it cannot be done. Return a value, or pass a holder object.
What lives whereLocals and parameters live in the frame: primitives as values, objects as references. Every object lives on the heap, as far as your code can tell. The JIT may allocate a non-escaping object on the stack or remove it altogether, which changes the speed but never the result: see the JIT compiler.
