Initialisation runs in a fixed order, and a constructor that calls an overridable method sees null

A class is initialised once, lazily, the first time it is really used: static initialisers in source order, superclass first. Each new then runs the superclass constructor, then this class's field initialisers and instance blocks in source order, then the rest of the constructor. A method called from the superclass constructor runs before the subclass has assigned a single field.

InitOrder.java · numbered in the order the lines run
public class InitOrder {
    static String log(String step, String value) { System.out.println(step); return value; }
    static void log(String step) { System.out.println(step); }

    static class Base {
        static { log("1  Base static block"); }
        private final String tag = log("3  Base field initialiser", "B");
        { log("4  Base instance block"); }
        Base() {
            log("5  Base constructor body, tag=" + tag);
            describe();                          // calls the subclass override
        }
        void describe() { log("   Base.describe"); }
    }

    static class Order extends Base {
        static final String PREFIX = "ORD-";     // compile-time constant: inlined by javac
        static String region = log("2  Order static field", "EU");
        private final String id = log("7  Order field initialiser", PREFIX + 1);
        Order() { log("8  Order constructor body, id=" + id); }
        @Override void describe() { log("6  Order.describe sees id=" + id); }
    }

    public static void main(String[] args) {
        log("main reads Order.PREFIX = " + Order.PREFIX + " (no class initialised yet)");
        log("-- new Order()");
        new Order();
        log("-- new Order() again: no static lines this time");
        new Order();
        log("Order.region was set once: " + Order.region);
    }
}

Line 6: id=nullBase() calls describe(), which dispatches to Order.describe before Order's field initialiser has run. Never call an overridable method from a constructor. javac 21 can catch it: -Xlint:this-escape warns when a public class's constructor lets this escape to code a subclass could override.
The first line: no initialisationPREFIX is a compile-time constant, so javac copied "ORD-" into main. Reading it does not touch Order. The catch: change a constant and every class that uses it must be recompiled, or it keeps the old value.

finallocal, parameterAssigned once. Lambdas and inner classes may capture only final or effectively final locals.That the object it refers to is immutable
finalfieldAssigned exactly once, by the end of the constructor. The memory model guarantees other threads see it fully set once construction finishes (happens-before).A final List cannot be modified
finalmethod, classCannot be overridden, cannot be extended: String, the wrappers and every record are final.Faster: the JIT inlines non-final methods as well
staticfield, methodOne per class (per class loader), shared by every instance. Static methods are hidden, never overridden.Thread-safe: a static mutable field is shared state
staticnested classNo hidden reference to an outer instance: the default for nested types.
