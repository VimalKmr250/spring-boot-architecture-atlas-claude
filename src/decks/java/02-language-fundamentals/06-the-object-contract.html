equals and hashCode are a contract with every hash-based collection, and the compiler only warns

Every class inherits equals, hashCode, toString and clone from Object. The defaults use identity. Override equals and you must override hashCode to match, or HashSet and HashMap stop working for that type. The four bugs below compile; only the first gets a warning, and only with -Xlint.

ObjectContract.java · four ways to break the contract
import java.util.*;

public class ObjectContract {
    static final class Sku {                         // equals, but no hashCode
        final String code;
        Sku(String code) { this.code = code; }
        @Override public boolean equals(Object o) { return o instanceof Sku s && s.code.equals(code); }
    }

    static class Point {
        final int x, y;
        Point(int x, int y) { this.x = x; this.y = y; }
        @Override public boolean equals(Object o) { return o instanceof Point p && p.x == x && p.y == y; }
        @Override public int hashCode() { return Objects.hash(x, y); }
    }
    static class ColorPoint extends Point {
        final String color;
        ColorPoint(int x, int y, String color) { super(x, y); this.color = color; }
        @Override public boolean equals(Object o) {
            return o instanceof ColorPoint c && super.equals(c) && c.color.equals(color);
        }
        @Override public int hashCode() { return Objects.hash(x, y, color); }
    }

    static class Basket implements Cloneable {
        List<String> items = new ArrayList<>(List.of("tea"));
        @Override public Basket clone() {
            try { return (Basket) super.clone(); }     // field-by-field copy: shares the list
            catch (CloneNotSupportedException e) { throw new AssertionError(e); }
        }
    }

    public static void main(String[] args) {
        Set<Sku> skus = new HashSet<>(List.of(new Sku("A-1"), new Sku("A-1")));
        System.out.println("equal Skus in a HashSet: " + skus.size());

        Point p = new Point(1, 2);
        ColorPoint cp = new ColorPoint(1, 2, "red");
        System.out.println("p.equals(cp) " + p.equals(cp) + ", cp.equals(p) " + cp.equals(p));

        List<String> key = new ArrayList<>(List.of("a"));
        Set<List<String>> seen = new HashSet<>();
        seen.add(key);
        key.add("b");                                  // its hashCode just changed
        System.out.println("mutated key: contains " + seen.contains(key) + ", size " + seen.size());

        Basket original = new Basket();
        Basket copy = original.clone();
        copy.items.add("milk");
        System.out.println("clone shares state: original now " + original.items);
    }
}

The rules

equals is reflexive, symmetric, transitive, consistent, and false for null. Equal objects must have equal hash codes; unequal ones may collide. Neither may depend on a field that changes while the object sits in a hash collection.

The practical fix

Use a record for anything compared by value: it generates all three methods from its components. For a class, make it final and use the same fields in both methods. Value objects in the LLD tab shows the pattern.

The other two

Default toString is getClass().getName() + "@" + Integer.toHexString(hashCode()). Avoid clone: write a copy constructor or factory. finalize is deprecated for removal 18; use try-with-resources or a Cleaner.
