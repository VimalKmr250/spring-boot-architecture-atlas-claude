Immutable means nothing can change it after construction, including the caller who passed the list in

final fields and no setters are not enough. If the constructor keeps the caller's list, the caller can still change it; if a getter returns that list, every reader can. An immutable class copies every mutable input on the way in and never hands out anything mutable on the way out.

Immutable.java · the leaky version, the fixed class, the record
import java.time.Instant;
import java.util.*;

public class Immutable {
    // Looks immutable: final fields, no setters. It is not.
    static final class LeakyOrder {
        private final List<String> lines;
        private final Date placed;
        LeakyOrder(List<String> lines, Date placed) { this.lines = lines; this.placed = placed; }
        List<String> lines() { return lines; }
        Date placed() { return placed; }
        @Override public String toString() { return lines + " @ " + placed.toInstant(); }
    }

    // Immutable: final class, final fields, copies in, nothing mutable out.
    static final class Order {
        private final List<String> lines;
        private final Instant placed;              // immutable type instead of Date
        Order(List<String> lines, Instant placed) {
            this.lines = List.copyOf(lines);       // copy in (and reject nulls)
            this.placed = Objects.requireNonNull(placed);
        }
        List<String> lines() { return lines; }    // already unmodifiable: safe to return
        Instant placed() { return placed; }
        Order withLine(String line) {              // "modification" returns a new object
            var next = new ArrayList<>(lines);
            next.add(line);
            return new Order(next, placed);
        }
        @Override public String toString() { return lines + " @ " + placed; }
    }

    // The same guarantees as a record
    record OrderRecord(List<String> lines, Instant placed) {
        OrderRecord {
            lines = List.copyOf(lines);
            Objects.requireNonNull(placed);
        }
    }

    public static void main(String[] args) {
        var input = new ArrayList<>(List.of("tea"));
        var when = new Date(0);
        var leaky = new LeakyOrder(input, when);
        input.add("milk");                         // the caller still holds the list
        leaky.lines().add("sugar");                // and the getter hands it out
        when.setTime(86_400_000L);                 // Date is mutable too
        System.out.println("leaky   " + leaky);

        var input2 = new ArrayList<>(List.of("tea"));
        var order = new Order(input2, Instant.EPOCH);
        input2.add("milk");
        try {
            order.lines().add("sugar");
        } catch (UnsupportedOperationException e) {
            System.out.println("order.lines().add -> UnsupportedOperationException");
        }
        System.out.println("order   " + order);
        System.out.println("with    " + order.withLine("milk") + "  (original " + order.lines() + ")");

        var input3 = new ArrayList<>(List.of("tea"));
        var rec = new OrderRecord(input3, Instant.EPOCH);
        input3.add("milk");
        System.out.println("record  " + rec);
    }
}

The checklist

  1. Final class, or a private constructor with factories, so no subclass can add mutable state or override accessors.
  2. Private final fields, all assigned in the constructor.
  3. No setters. A change is a method that returns a new object, like withLine.
  4. Copy mutable inputs in: List.copyOf, Map.copyOf. Prefer immutable types such as Instant over Date.
  5. Never return mutable internals. A list from List.copyOf is already unmodifiable, so it is safe to return as it is.
  6. Check the elements. List.copyOf copies the list, not the objects in it. Immutability is only as deep as the types you hold.
What it buysThread safety with no locks, because there is nothing to race on. Safe sharing and caching. Stable hashCode, so it is a safe map key. Final fields also make it safely published to other threads once the constructor returns.
Records do most of itA record is final with private final fields and no setters. You still write the defensive copy, in the compact constructor, as OrderRecord does. Without it, the record holds the caller's list.
copyOf is not a viewCollections.unmodifiableList wraps the original, so changes to the original show through. List.copyOf takes a snapshot, and returns its argument unchanged if that is already an unmodifiable list. See unmodifiable collections.
