Three questions on how Java resolves methods and types

Interviewers use these to tell apart candidates who know the rules from those who know the vocabulary. Each answer has a mechanism behind it, and saying the mechanism is what scores: compile time against run time, and what erasure leaves behind.

Q4

What is the difference between overloading and overriding, and what cannot be overridden?

30-second answerOverloading is several methods with one name and different parameters; javac chooses one at compile time from the declared types of the arguments. Overriding is a subclass redefining an inherited method with the same signature; the JVM chooses at run time from the receiver's actual class. Static methods cannot be overridden, only hidden; private methods are not inherited; final methods and constructors cannot be overridden. Fields are never polymorphic.

Go deeper: Overload resolution has three phases: widening only, then boxing, then varargs, so pay(5) calls pay(long) rather than pay(Integer). An override may return a subtype (covariant), may not narrow access, and may not throw broader checked exceptions. In bytecode, overrides are reached through invokevirtual or invokeinterface, which look up the receiver's class; static calls are invokestatic.

Q5

Abstract class or interface: which, and when, now that interfaces have default methods?

30-second answerAn interface is a type any class can adopt, any number at once. It can have default, static and private methods, but no instance state and no constructor, so it cannot enforce an invariant. An abstract class can hold state and a constructor, and a class can extend only one. Make the type callers depend on an interface; add an abstract class only when implementations share state or a fixed algorithm, the template method pattern.

Go deeper: Default methods exist so interfaces can grow without breaking implementers: that is how Java 8 added stream() to Collection. When two defaults collide, a superclass method wins, then the more specific interface, and otherwise the class must override and choose with X.super.m(). The JDK pairs both: List and AbstractList. Mention composition over inheritance as the usual alternative to both.

Q6

What is type erasure, and what is PECS?

30-second answerjavac checks generic types, inserts the casts, and then erases the type arguments, so List<String> and List<Integer> are the same ArrayList class at run time. You therefore cannot write new T(), create a T[], or test instanceof List<String>. PECS is how to type parameters: producer extends, consumer super. Read Ts from a ? extends T; write Ts into a ? super T.

Go deeper: Erasure was chosen so generic code could run alongside pre-Java-5 code. Declarations keep their generic signatures in the class file, which is how Jackson's TypeReference recovers Map<String, List<Integer>>. Generics are invariant while arrays are covariant, so arrays check every store at run time (ArrayStoreException). Raw types and unchecked casts cause heap pollution, and the ClassCastException appears far from the cause.
