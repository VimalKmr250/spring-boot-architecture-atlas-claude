Checked exceptions are a compiler rule, not a JVM one, and Errors are not yours to catch

Everything throwable descends from Throwable, which splits into Error, meaning the JVM itself is in trouble, and Exception. javac forces every caller to catch or declare an Exception, unless it is a RuntimeException. The JVM never checks this. That is why Kotlin, and Lombok's @SneakyThrows, can throw an IOException that no signature declares.

Hierarchy.java · ancestry, a failing static initialiser, multi-catch
import java.io.*;
import java.util.*;
import java.util.concurrent.*;

public class Hierarchy {
    static String chain(Class<?> c) {
        List<String> names = new ArrayList<>();
        for (Class<?> k = c; k != Object.class; k = k.getSuperclass()) names.add(k.getSimpleName());
        return String.join(" < ", names);
    }

    static class TaxTable {                                   // a static initialiser that fails
        static final Map<String, Integer> RATES = load();
        static Map<String, Integer> load() { throw new IllegalStateException("rates file missing"); }
    }

    static int parseQuantity(String raw) throws IOException {
        try {
            return Integer.parseInt(raw);
        } catch (NumberFormatException | NullPointerException e) {   // multi-catch: unrelated types
            throw new IOException("bad quantity: " + raw, e);
        }
    }

    public static void main(String[] args) {
        for (Class<?> c : List.of(FileNotFoundException.class, InterruptedException.class,
                TimeoutException.class, NumberFormatException.class, ConcurrentModificationException.class,
                UncheckedIOException.class, OutOfMemoryError.class, StackOverflowError.class))
            System.out.println(chain(c));

        for (int attempt = 1; attempt <= 2; attempt++) {
            try {
                System.out.println(TaxTable.RATES);
            } catch (Throwable t) {
                System.out.println("attempt " + attempt + ": " + t.getClass().getSimpleName() + ": " + t.getMessage()
                        + (t.getCause() != null ? " / cause: " + t.getCause().getMessage() : ""));
            }
        }

        try {
            parseQuantity("12x");
        } catch (IOException e) {
            System.out.println(e.getMessage() + " <- " + e.getCause());
        }
    }
}

UseFor
CheckedA condition the caller can reasonably handle, at a boundary that can fail: I/O, a remote call, a timeout.
UncheckedProgramming errors (IllegalArgumentException, IllegalStateException) and failures no caller can fix. Spring translates checked JDBC exceptions into unchecked DataAccessExceptions for this reason.
ErrorDo not catch it, except once at the top of a thread to log it. After an OutOfMemoryError the program may be in an inconsistent state.
A failed static initialiser is permanentThe first access throws ExceptionInInitializerError with the real cause. Every later access throws NoClassDefFoundError: Could not initialize class, and the class stays unusable until the JVM restarts. Recent JDKs attach the first failure as the cause; older ones leave you only the second error, so search the log for the first.
Multi-catchcatch (NumberFormatException | NullPointerException e) 7 handles unrelated types in one block; listing a type together with its subclass is a compile error. Catch blocks are tried in order, so a subclass must come before its superclass, or it does not compile.
