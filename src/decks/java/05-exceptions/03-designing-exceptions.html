A good exception carries a cause, the data to act on, and no more cost than it needs

Exceptions cross layers: a SQLException from the repository becomes a domain failure in the service, and an HTTP status at the edge. Each translation must keep the cause, or the stack trace that explains the incident stops at the layer that translated it. Creating an exception is also not free: filling in the stack trace costs far more than the allocation.

ExceptionDesign.java · translation, lost causes, interrupts, cost
import java.io.*;
import java.sql.SQLException;

public class ExceptionDesign {
    // A domain exception: unchecked, with the data a caller needs, and always a cause.
    static class PaymentDeclinedException extends RuntimeException {
        private static final long serialVersionUID = 1L;
        private final String orderId;
        PaymentDeclinedException(String orderId, String reason, Throwable cause) {
            super("payment declined for " + orderId + ": " + reason, cause);
            this.orderId = orderId;
        }
        String orderId() { return orderId; }
    }

    // An exception used for flow control: no stack trace to capture.
    static class OutOfStock extends RuntimeException {
        private static final long serialVersionUID = 1L;
        OutOfStock(String sku) { super(sku, null, false, false); }   // no suppression, no trace
    }

    static void gatewayCall() throws SQLException { throw new SQLException("connection reset", "08S01"); }

    static void chargeKeepingCause(String orderId) {
        try {
            gatewayCall();
        } catch (SQLException e) {
            throw new PaymentDeclinedException(orderId, "gateway unavailable", e);   // translate, keep cause
        }
    }

    static void chargeLosingCause() {
        try {
            gatewayCall();
        } catch (SQLException e) {
            throw new RuntimeException(e.getMessage());       // the original stack trace is gone
        }
    }

    static void waitForStock() {
        try {
            Thread.sleep(10_000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();               // restore the flag before translating
            throw new IllegalStateException("interrupted while waiting for stock", e);
        }
    }

    public static void main(String[] args) throws Exception {
        try {
            chargeKeepingCause("ORD-9");
        } catch (PaymentDeclinedException e) {
            var trace = new StringWriter();
            e.printStackTrace(new PrintWriter(trace));
            trace.toString().lines().filter(l -> !l.contains("ExceptionDesign.main")).forEach(System.out::println);
        }
        try {
            chargeLosingCause();
        } catch (RuntimeException e) {
            System.out.println("lost: " + e + ", cause " + e.getCause());
        }

        Thread waiter = new Thread(ExceptionDesign::waitForStock);
        waiter.setUncaughtExceptionHandler((t, e) -> System.out.println(
                "uncaught in " + t.getName() + ": " + e.getMessage() + ", interrupted flag restored: " + t.isInterrupted()));
        waiter.setName("stock-waiter");
        waiter.start();
        waiter.interrupt();
        waiter.join();

        long t0 = System.nanoTime();
        for (int i = 0; i < 1_000_000; i++) new IllegalStateException("x");
        long withTrace = System.nanoTime() - t0;
        t0 = System.nanoTime();
        for (int i = 0; i < 1_000_000; i++) new OutOfStock("x");
        long without = System.nanoTime() - t0;
        System.out.printf("1M exceptions: %d ms with stack traces, %d ms without (one run)%n",
                withTrace / 1_000_000, without / 1_000_000);
    }
}

DoInstead of
Translate at a boundary, passing the cause: new X(msg, e)new X(e.getMessage()): "cause null" above, and no trace to follow
Put identifiers in the message and in fields: orderId()"Payment failed", with no way to find which one
Restore the flag before translating InterruptedExceptionSwallowing it, so the thread keeps running after a shutdown request
Log once, where the exception is handledLog and rethrow, so the same failure appears five times
Catch the specific type you can handlecatch (Exception e) {}, which hides the next bug too
Exceptions as control flowCapturing a stack trace walks the whole stack: more than ten times the cost of the object itself here. For an expected outcome such as out of stock, return a result type (a sealed Result, an Optional), or use the four-argument constructor with writableStackTrace = false, as OutOfStock does.
Checked or unchecked for domain errorsUnchecked, as most modern Java code and every Spring API does, with the class name stating the business meaning. A checked exception in a widely used signature forces every caller, and every lambda that calls it, to deal with it.
