try-with-resources closes in reverse order and keeps both failures; finally keeps only the last

When the body throws and then close() throws too, there are two exceptions and one can propagate. try-with-resources 7 propagates the body's, which is the one that explains what happened, and attaches the other with addSuppressed. A hand-written finally lets the close failure replace the original, so the log shows the symptom and loses the cause.

Resources.java · close order, suppressed exceptions, two finally traps
public class Resources {
    static final class Res implements AutoCloseable {
        private final String name;
        private final boolean failOnClose;
        Res(String name, boolean failOnClose) {
            this.name = name;
            this.failOnClose = failOnClose;
            System.out.println("open  " + name);
        }
        @Override public void close() {
            System.out.println("close " + name);
            if (failOnClose) throw new IllegalStateException("close " + name + " failed");
        }
    }

    static void withResources() {
        try (Res conn = new Res("connection", false);
             Res stmt = new Res("statement", true)) {        // closed first: reverse order
            System.out.println("body  uses " + conn.name + " and " + stmt.name);
            throw new RuntimeException("query failed");
        }
    }

    static void withFinally() {                               // the pre-Java 7 way
        Res stmt = new Res("statement", true);
        try {
            throw new RuntimeException("query failed");
        } finally {
            stmt.close();                                     // its exception replaces the real one
        }
    }

    static int returnsFromFinally() {
        try {
            throw new IllegalStateException("lost forever");
        } finally {
            return -1;                                        // discards the exception
        }
    }

    static String finallyOnReturn() {
        try {
            return "from try";
        } finally {
            System.out.println("finally runs before the return completes");
        }
    }

    public static void main(String[] args) {
        try {
            withResources();
        } catch (RuntimeException e) {
            System.out.println("caught: " + e.getMessage());
            for (Throwable s : e.getSuppressed()) System.out.println("  suppressed: " + s.getMessage());
        }
        try {
            withFinally();
        } catch (RuntimeException e) {
            System.out.println("caught: " + e.getMessage() + " (the query failure is gone)");
        }
        System.out.println("returnsFromFinally() = " + returnsFromFinally());
        System.out.println(finallyOnReturn());
    }
}

The rules

  • Resources close in reverse order of opening, after the body and before that try's own catch and finally run.
  • A resource whose constructor threw was never opened, so it is not closed; the ones opened before it are.
  • An effectively final variable can be the resource: try (conn) 9.
  • finally runs on normal exit, on exceptions and on return. It does not run on System.exit, a JVM crash or kill -9.
return in finallyA return, break or throw in finally throws away whatever exception was in flight. returnsFromFinally returned -1, and nobody ever learns about the failure. javac's [finally] lint is the only warning you get.
Write close() to be idempotentCloseable.close must do nothing if called twice; AutoCloseable.close is only encouraged to. Wrappers often close what they wrap, so the inner resource can be closed twice.
