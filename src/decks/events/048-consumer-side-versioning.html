Living with three versions in flight

During a migration — and after a replay — a consumer sees several versions of the same event type. Handling that deliberately is what keeps the migration a background activity rather than an event.

Upcasting: normalise on the way in, handle one shape
@Component
class OrderPlacedUpcaster {

    /** Every version is converted to the current internal shape at the boundary.
     *  The handler below never sees a v1 payload. */
    OrderPlaced upcast(JsonNode raw) {
        int version = raw.path("eventVersion").asInt(1);
        return switch (version) {
            case 1 -> fromV1(raw);      // v1 had 'total' in major units, no currency
            case 2 -> fromV2(raw);      // v2 added currency, still 'total'
            case 3 -> fromV3(raw);      // v3 renamed to totalMinor
            default -> throw new UnknownEventVersion(version);   // → DLT, loudly
        };
    }

    private OrderPlaced fromV1(JsonNode n) {
        return new OrderPlaced(
            n.get("orderId").asText(),
            Money.ofMajor(n.get("total").asDouble(), "GBP"),    // the assumption, documented
            n.path("occurredAt").asText());
    }
}

One class holds every historical shape, and the business logic holds none. That is the property worth paying for: your handler stays readable even when the topic has four years of history in it.

The tolerant-reader rules

  • Ignore unknown fields. Never fail on a field you did not expect — that turns every additive producer change into your outage.
  • Never assume field order or the absence of new ones.
  • Read only what you need. A consumer that deserialises the whole payload into a mirror of the producer's model is coupled to all of it.
  • Fail loudly on an unknown version, not on an unknown field. One is a real incompatibility; the other is normal evolution.
Upcasters are permanentYou can never delete one while the topic still holds events of that version — and with compaction or long retention, that can be indefinitely. This is the hidden long-term cost of event-driven systems, and it is the main reason event sourcing is a heavier commitment than a plain event stream.
Test every versionKeep a fixture file per historical version and a test that upcasts each one. It takes minutes, it documents the history better than any wiki page, and it is what makes a four-year-old replay safe to run.
