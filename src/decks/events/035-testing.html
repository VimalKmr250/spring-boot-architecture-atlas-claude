Testing event-driven code at four levels

You cannot unit-test a topology, and end-to-end tests of one are slow and flaky. Match the level to what you are actually trying to prove.

LevelToolProvesSpeed
Handler logicPlain JUnit — call the method directlyThe business rule, including idempotency on a repeat call< 1 ms
Serialization@JsonTest / Avro round-tripThe payload serialises, deserialises and matches the schemams
IntegrationTestcontainers Kafka + @SpringBootTestReal producer, broker, consumer group, offsets, error handler, DLT~5 s
ContractSchema registry compatibility check in CIYou have not broken a consumer you cannot names — a gate
Integration test with Testcontainers and Awaitility
@SpringBootTest
@Import(KafkaContainerConfig.class)
class OrderEventFlowIT {

    @Test
    void placingAnOrderReservesStock() {
        var orderId = orders.place(aValidOrder());

        await().atMost(Duration.ofSeconds(10))         // async: poll, never Thread.sleep
               .untilAsserted(() ->
                   assertThat(reservations.findByOrderId(orderId)).isPresent());
    }

    @Test
    void aDuplicateEventIsIgnored() {
        kafka.send(TOPIC, orderId, event);
        kafka.send(TOPIC, orderId, event);            // same event twice

        await().during(Duration.ofSeconds(2))          // and STAYS at one
               .atMost(Duration.ofSeconds(10))
               .untilAsserted(() ->
                   assertThat(reservations.countByOrderId(orderId)).isEqualTo(1));
    }

    @Test
    void aPoisonRecordLandsInTheDlt() {
        kafka.send(TOPIC, orderId, "{ not json");
        await().atMost(Duration.ofSeconds(10))
               .untilAsserted(() -> assertThat(dltRecords()).hasSize(1));
    }
}
Testcontainers over @EmbeddedKafkaEmbedded Kafka is faster to start but is not the broker you run — it diverges on version, on configuration, and on transactional behaviour. With container reuse, Testcontainers costs a few seconds once per build and tests the real thing.
Thread.sleep in an async testToo short and it is flaky; too long and the suite crawls. Awaitility polls until the condition holds and fails fast with a useful message. The during() form above is the one people miss — it is how you assert that something stays true, which is the whole point of a duplicate test.
Test the three properties, not the happy pathEvery consumer deserves three tests: it works, a duplicate changes nothing, and a poison record reaches the DLT without stalling. Those two extra tests are what make the consumer safe to operate.
