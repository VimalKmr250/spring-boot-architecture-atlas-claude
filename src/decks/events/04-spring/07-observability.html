Making an event flow observable

The hardest part of running event-driven systems is answering "what happened to order 88421". Three mechanisms make that a query instead of an investigation.

1 · Trace propagation across the async hop — two lines
spring.kafka:
  template.observation-enabled: true      # producer span, injects traceparent header
  listener.observation-enabled: true      # consumer span, continues the SAME trace
management.tracing.sampling.probability: 0.1
2 · The metrics that matter
# Exposed by Micrometer's Kafka binders, plus your own:
kafka_consumer_fetch_manager_records_lag_max   # per partition — the key SLI
kafka_consumer_coordinator_rebalance_total     # rising = instability
spring_kafka_listener_seconds{result="failure"} # handler latency + error rate
events_staleness_seconds                        # now() - event.occurredAt, a histogram
outbox_oldest_unsent_seconds                    # producer-side health
dlt_depth{topic="..."}                          # must be zero
3 · Correlation in the payload, not just the headers
// correlationId = the user action that started everything
// causationId   = the event that directly caused this one
// Together they let you reconstruct the whole causal tree from a log query,
// even for events that crossed a system with no tracing.
The four dashboards for an event systemFlow — throughput and staleness per topic, end to end. Lag — per consumer group, per partition. Errors — retry rate and DLT depth per consumer. Broker — under-replicated partitions, ISR shrinks, disk. More than four and nobody opens any of them during an incident.
Lag per partition, never per topicThe topic average hides a single hot or stuck partition completely. A group showing 200 average lag might have eleven partitions at zero and one at 2,400 — and that one is the customer complaint.
The question to design for"What happened to order 88421?" should be one query. Trace id in every log line, event id in every record, correlation id in every payload, and a UI or saved query that joins them. Build it before the first incident, not during.
