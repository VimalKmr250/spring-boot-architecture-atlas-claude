Backpressure: what happens when consumers cannot keep up

A queue between two systems does not remove the mismatch in speed — it stores it. Where that storage fills, and what happens when it does, is a design decision you should make rather than discover.

Scale the consumer

Add instances up to the partition count, then increase partitions. The first is instant; the second is disruptive, which is the argument for over-provisioning partitions early.

Make handling cheaper

Batch listener with bulk database writes instead of one row per message; drop an N+1 inside the handler. Usually a 5–10× win and no infrastructure change.

Shed or prioritise

Split into a high-priority and a bulk topic, or sample low-value events. Better to consciously drop telemetry than to have retention silently drop orders.
