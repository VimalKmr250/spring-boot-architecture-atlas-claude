The analytics path: one stream, two destinations

Events serve operational consumers and analytical ones, and the two want completely different things. Trying to satisfy both from one pipeline is a common and expensive mistake.

Sink connectors, not custom code

Kafka Connect has maintained sinks for S3, BigQuery, Snowflake, Iceberg and Elasticsearch. Writing your own consumer to land Parquet files is a solved problem you would be re-solving badly.

Schema carries through

Avro plus a registry means the lake gets typed, evolving data rather than untyped JSON blobs. This is where the registry pays back a second time, and where JSON topics become an analytics tax.

Do not let analytics drive the event design

"Can you add these twelve fields so the warehouse doesn't need a join" turns a domain event into a database dump. Give analytics a separate enriched topic if they need one — built by a Streams job you own.
