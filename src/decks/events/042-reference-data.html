Compacted topics as shared reference data

A pattern worth knowing on its own: publish the current state of every entity to a compacted topic, and any service can hold a local, always-current copy without calling you.

Good fit

Bounded, slow-changing reference data: products, currencies, tax rates, feature configuration, tenant settings. Thousands to low millions of keys.

Bad fit

High-cardinality, fast-changing data. A compacted topic of every customer's live session state is a lot of traffic and a lot of duplicated storage for data nobody needs a copy of.

Watch for

Publish the whole current value each time, never a delta — a consumer starting from offset 0 must be able to build correct state from what it reads. And decide what a missing key means before the first consumer guesses.
