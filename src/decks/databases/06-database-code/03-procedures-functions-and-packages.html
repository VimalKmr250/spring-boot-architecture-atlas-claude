Stored procedures move logic next to the data; the question is which logic belongs there

A procedure performs an action and may return values through output parameters; it is called with EXEC or from a PL/SQL block. A function returns a value and can be used inside SQL. A function used in a query should read, not write. Oracle groups related procedures, functions, types and exceptions into a package: a specification that callers compile against, and a body that can change without invalidating them. Both procedures below reserve stock with one conditional UPDATE and raise an error when there is not enough: the same check-and-act pattern as Preventing lost updates.

procedures.ora.sql · Oracle 26ai
-- a package groups related procedures and functions behind one specification
CREATE OR REPLACE PACKAGE stock AS
  insufficient_stock EXCEPTION;
  PRAGMA EXCEPTION_INIT(insufficient_stock, -20001);
  PROCEDURE reserve(p_product_id IN NUMBER, p_qty IN NUMBER);
  FUNCTION available(p_product_id IN NUMBER) RETURN NUMBER;
END stock;
/
CREATE OR REPLACE PACKAGE BODY stock AS
  PROCEDURE reserve(p_product_id IN NUMBER, p_qty IN NUMBER) IS
  BEGIN
    UPDATE inventory
    SET    reserved = reserved + p_qty
    WHERE  product_id = p_product_id
    AND    on_hand - reserved >= p_qty;
    IF SQL%ROWCOUNT = 0 THEN
      RAISE_APPLICATION_ERROR(-20001, 'not enough stock for product ' || p_product_id);
    END IF;
  END reserve;

  FUNCTION available(p_product_id IN NUMBER) RETURN NUMBER IS
    v_available NUMBER;
  BEGIN
    SELECT on_hand - reserved INTO v_available FROM inventory WHERE product_id = p_product_id;
    RETURN v_available;
  END available;
END stock;
/
-- call the procedure from a block, and the function from SQL
BEGIN
  stock.reserve(109, 2);
  DBMS_OUTPUT.PUT_LINE('reserved 2 of product 109');
  stock.reserve(109, 5);
EXCEPTION
  WHEN stock.insufficient_stock THEN
    DBMS_OUTPUT.PUT_LINE('caught: ' || SQLERRM);
END;
/
SELECT product_id, stock.available(product_id) AS available FROM inventory WHERE product_id IN (107, 109);
ROLLBACK;
DROP PACKAGE stock;

procedures.mss.sql · SQL Server 2025
CREATE OR ALTER PROCEDURE reserve_stock @product_id INT, @qty INT
AS
BEGIN
  SET NOCOUNT ON;
  UPDATE inventory
  SET    reserved = reserved + @qty
  WHERE  product_id = @product_id
  AND    on_hand - reserved >= @qty;
  IF @@ROWCOUNT = 0
    THROW 50001, 'not enough stock', 1;
END;
GO
CREATE OR ALTER FUNCTION available_stock (@product_id INT) RETURNS INT
AS
BEGIN
  RETURN (SELECT on_hand - reserved FROM inventory WHERE product_id = @product_id);
END;
GO
-- call the procedure, catch its error, and use the function in a query
BEGIN TRANSACTION;
BEGIN TRY
  EXEC reserve_stock @product_id = 109, @qty = 2;
  PRINT 'reserved 2 of product 109';
  EXEC reserve_stock @product_id = 109, @qty = 5;
END TRY
BEGIN CATCH
  PRINT CONCAT('caught: ', ERROR_NUMBER(), ' ', ERROR_MESSAGE());
END CATCH;
SELECT product_id, dbo.available_stock(product_id) AS available FROM inventory WHERE product_id IN (107, 109);
ROLLBACK;
GO
DROP PROCEDURE reserve_stock;
DROP FUNCTION available_stock;

Put it in the database whenKeep it in the application when
It is set-based and touches many rows: a month-end recalculation, an archiving jobIt is business logic that changes often and needs unit tests, code review and feature flags
Round trips dominate: a loop of dependent statements over a slow networkIt calls other services, queues or files
Several applications in different languages must apply one rule identicallyThe team cannot debug, version and deploy database code as well as application code
Security: callers get EXECUTE on a procedure, not access to the tablesYou may need to scale it out: application servers scale horizontally, the database does not
Scalar functions in queriesA function called in a WHERE or SELECT list runs once per row, and a query inside it runs once per call. SQL Server 2019+ can inline simple scalar functions; Oracle offers RESULT_CACHE and inlining for some. Prefer a join or a CASE when the logic is simple.
User errorsRaise application errors in the reserved ranges: RAISE_APPLICATION_ERROR(-20000 … -20999) in Oracle, THROW with numbers of 50000 and above in SQL Server. The Java side can then map the error number to a business exception; see exception translation.
Say it in the interview"Procedure: performs an action, called with EXEC, can have output parameters and manage transactions. Function: returns a value, usable in SQL, and should not change data. I keep business rules in the application, and use procedures for set-based work and to save round trips."
