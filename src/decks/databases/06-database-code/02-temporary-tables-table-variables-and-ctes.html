A CTE is a named query, a temporary table is real storage, and a table variable ignores ROLLBACK

All three hold an intermediate result, and they behave very differently. A CTE is part of one statement: it is not stored, and the optimiser may evaluate it once or several times. A temporary table is a real table with statistics and indexes, private to the session. In SQL Server it is #name, created on the fly. In Oracle a global temporary table is created once, like any table, and each session sees only its own rows; since 18c there is also a session-only private temporary table. SQL Server's table variable, @name, lives for one batch and is not part of the transaction.

temp-tables.mss.sql · SQL Server 2025
-- a #temp table and a @table variable, filled inside a transaction that is rolled back
CREATE TABLE #recent (order_id INT PRIMARY KEY);
DECLARE @recent TABLE (order_id INT PRIMARY KEY);
BEGIN TRANSACTION;
INSERT INTO #recent  SELECT order_id FROM orders WHERE placed_at >= '2026-03-01';
INSERT INTO @recent  SELECT order_id FROM orders WHERE placed_at >= '2026-03-01';
ROLLBACK;
SELECT (SELECT COUNT(*) FROM #recent) AS temp_table_rows,
       (SELECT COUNT(*) FROM @recent) AS table_variable_rows;
DROP TABLE #recent;

temp-tables.ora.sql · Oracle 26ai
-- 1  a global temporary table: the definition is permanent, the rows are private to the session
CREATE GLOBAL TEMPORARY TABLE recent_orders_gtt (order_id NUMBER PRIMARY KEY) ON COMMIT DELETE ROWS;
INSERT INTO recent_orders_gtt SELECT order_id FROM orders WHERE placed_at >= DATE '2026-03-01';
SELECT COUNT(*) AS before_commit FROM recent_orders_gtt;
COMMIT;
SELECT COUNT(*) AS after_commit FROM recent_orders_gtt;
DROP TABLE recent_orders_gtt PURGE;

-- 2  a private temporary table (18c): created and gone with the session, name must start ORA$PTT_
CREATE PRIVATE TEMPORARY TABLE ora$ptt_recent (order_id NUMBER) ON COMMIT PRESERVE DEFINITION;
INSERT INTO ora$ptt_recent SELECT order_id FROM orders WHERE placed_at >= DATE '2026-03-01';
SELECT COUNT(*) AS private_rows FROM ora$ptt_recent;

DDL at run time in OracleCreating and dropping tables inside application code, as a SQL Server developer does with #temp, is wrong in Oracle. DDL commits, invalidates dependent code and takes locks. Create the global temporary table once in a migration, and let each session use its own rows.
A CTE is not a cacheReferencing a CTE three times in a query can run it three times. If an expensive intermediate result is reused, materialise it in a temporary table. Oracle's /*+ MATERIALIZE */ hint does it inside one query.
Say it in the interview"CTE for readability within one statement; temporary table when a large intermediate result needs indexes, statistics or reuse; table variable for small sets. And the trick question: a table variable keeps its rows after ROLLBACK."
