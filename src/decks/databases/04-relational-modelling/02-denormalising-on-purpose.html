Copy a fact on purpose when it records history or saves a hot join, and know what keeps the copy correct

Not every repeated value is a normalisation failure. The running example stores two copies deliberately. order_items.unit_price repeats products.price, but it means something else: the price the customer actually paid, which must not change when the catalogue does. orders.total could be computed from the lines every time, but it is read on every order list, so it is stored. The first copy is a snapshot and should never be synchronised. The second is a derived value, and something must keep it equal to its source.

denormalised.mss.sql · SQL Server 2025 (the Oracle file is the same without BEGIN TRANSACTION)
-- 1  the stored order total must equal the sum of its lines: check it
SELECT o.order_id, o.total, SUM(i.qty * i.unit_price) AS from_lines
FROM   orders o
JOIN   order_items i ON i.order_id = o.order_id
GROUP  BY o.order_id, o.total
HAVING o.total <> SUM(i.qty * i.unit_price);

-- 2  the price snapshot: products.price changes, past order lines do not
BEGIN TRANSACTION;
UPDATE products SET price = 1199.00 WHERE product_id = 101;
SELECT i.order_id, i.unit_price AS paid, p.price AS price_today
FROM   order_items i
JOIN   products p ON p.product_id = i.product_id
WHERE  i.product_id = 101
ORDER  BY i.order_id;
ROLLBACK;

The snapshot that is not oneJoining order lines to products.price to print an old invoice would show 1199.00 for an item sold at 1299.00. Anything with legal or financial meaning (prices, tax, addresses, names on an invoice) is copied at the moment of the transaction.
Counters cost concurrencycustomers.order_count = order_count + 1 on every order makes every concurrent order for that customer queue on one row lock. For hot counters, insert rows and aggregate, or update the count asynchronously.
Say it in the interview"Every copy I add is either a snapshot, which never changes, or derived data with a named owner that updates it, in the same transaction or through events. And I keep a reconciliation query that proves the copy still matches."
