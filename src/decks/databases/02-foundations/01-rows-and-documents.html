A relational database splits an order into rows and joins them on read; a document database stores the order as one document

Both models hold the same facts; they differ in where the work happens. A relational schema is normalised: each fact lives in one row of one table, and a query joins the tables back together. Any question can be asked later, and updating a product's name touches one row. A document schema is shaped by the access pattern. The order and its lines are read and written together, so they are stored together, and the common read is a single lookup. Questions that cut across documents need more work or another shape.

one-order.sql · runs on Oracle 26ai and SQL Server 2025
-- order 1001 is spread over three tables; a join puts it back together
SELECT o.order_id, o.status, i.line_no, p.sku, i.qty, i.unit_price
FROM   orders o
JOIN   order_items i ON i.order_id = o.order_id
JOIN   products p    ON p.product_id = i.product_id
WHERE  o.order_id = 1001
ORDER  BY i.line_no;

The four families of SQL statements

DDL
Definition: CREATE, ALTER, DROP, TRUNCATE. In Oracle each DDL statement commits first; in SQL Server DDL can be rolled back.
DML
Manipulation: SELECT, INSERT, UPDATE, DELETE, MERGE.
DCL
Control: GRANT, REVOKE. A DBA's tool, but know the word.
TCL
Transaction control: COMMIT, ROLLBACK, SAVEPOINT.
The wrong reason to pick documents"No schema" is not a feature. The schema still exists in the code that reads the data, and every old document shape must still be handled years later. Choose documents because the data is read and written as a unit. Flexibility is a side effect.
When rows winMany-to-many relationships, ad-hoc reporting across entities, and facts shared by many parents, such as a product's current price. Normalised tables answer questions nobody planned for.
Say it in the interview"Relational modelling starts from the data and normalises it; document modelling starts from the queries and embeds what is read together. Both can be right for one system: orders in documents, the ledger in tables." Choosing between them is in the case-studies section.
