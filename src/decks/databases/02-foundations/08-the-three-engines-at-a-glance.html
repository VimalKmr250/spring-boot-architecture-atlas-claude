The same question in three dialects: most of SQL is shared, and the differences sit in the details you type every day

Oracle and SQL Server share the SQL standard's core: SELECT, joins, grouping, window functions, CTEs and MERGE. They differ in everyday functions, limiting rows, string handling, the default transaction behaviour and the procedural language: PL/SQL for Oracle, T-SQL for SQL Server. MongoDB's query language (MQL) is a set of JSON-like filter and pipeline documents, sent through a driver. Below, "the three cheapest active products" in each, then the differences worth knowing before an interview.

dialect.ora.sql · Oracle 26ai
-- the three cheapest active products, with a computed label
SELECT product_id,
       sku || ' / ' || name                AS label,
       NVL(TO_CHAR(price, 'FM9990.00'), 'n/a') AS price_text
FROM   products
WHERE  active = 1
ORDER  BY price
FETCH  FIRST 3 ROWS ONLY;

-- no FROM clause needed since 23ai, and BOOLEAN is a SQL type
SELECT UPPER('shop') AS shouted, 1 = 1 AS is_true;

dialect.mss.sql · SQL Server 2025
-- the three cheapest active products, with a computed label
SELECT TOP (3)
       product_id,
       sku + ' / ' + name                         AS label,
       ISNULL(CAST(price AS VARCHAR(12)), 'n/a')  AS price_text
FROM   products
WHERE  active = 1
ORDER  BY price;

-- no FROM clause needed, and no BOOLEAN type: comparisons are not values
SELECT UPPER('shop') AS shouted, CASE WHEN 1 = 1 THEN 1 ELSE 0 END AS is_true;

What production actually runsMany systems are a version or two behind. Oracle 19c is still the most common long-term release, so FETCH FIRST works but BOOLEAN and SELECT without FROM do not. SQL Server 2019 and 2022 are common. MongoDB 7.0 and 8.0 are the common majors. Features newer than those carry a release tag in this tab.
String concatenation and NULL'a' || NULL is 'a' in Oracle, because NULL and '' are the same thing there. 'a' + NULL is NULL in SQL Server. A label built with + from a nullable column silently disappears; use CONCAT, which skips NULLs.
Say it in the interview"The core SQL is portable: I write standard joins, CASE, window functions and OFFSET/FETCH, and keep dialect functions to the edges. The behaviours that differ, such as empty strings, collation, commit defaults and isolation, are what I check first on an unfamiliar database."
