One small shop, its payments and its servers: every query in this tab runs against these tables and collections

The data is small enough to read in a result grid: 10 customers, 12 products in a 3-level category tree, 18 orders from January to March 2026, 21 payment attempts (some failed, one refunded), 12 employees and 30 minutes of CPU samples from 3 hosts, with one host going silent. The same rows are loaded into all three engines from one generator, so results can be compared. Three bulk tables, generated in each engine with the same integer formulas, are there for execution plans and pagination, where row counts matter.

seed/ora.sql (excerpt) · the orders table in Oracle
CREATE TABLE orders (
  order_id     NUMBER(10)     GENERATED BY DEFAULT AS IDENTITY (START WITH 1019) CONSTRAINT orders_pk PRIMARY KEY,
  customer_id  NUMBER(10)     NOT NULL CONSTRAINT orders_customer_fk REFERENCES customers,
  status       VARCHAR2(10)   NOT NULL CONSTRAINT orders_status_ck
                 CHECK (status IN ('PENDING', 'PAID', 'SHIPPED', 'CANCELLED', 'REFUNDED')),
  placed_at    TIMESTAMP(0)   NOT NULL,
  total        NUMBER(12,2)   NOT NULL,
  currency     CHAR(3)        DEFAULT 'USD' NOT NULL
);
CREATE INDEX orders_customer_ix ON orders (customer_id);
seed/mss.sql (excerpt) · the same table in SQL Server
CREATE TABLE orders (
  order_id     INT            IDENTITY(1001, 1) CONSTRAINT orders_pk PRIMARY KEY,
  customer_id  INT            NOT NULL CONSTRAINT orders_customer_fk REFERENCES customers,
  status       VARCHAR(10)    NOT NULL CONSTRAINT orders_status_ck
                 CHECK (status IN ('PENDING', 'PAID', 'SHIPPED', 'CANCELLED', 'REFUNDED')),
  placed_at    DATETIME2(0)   NOT NULL,
  total        DECIMAL(12,2)  NOT NULL,
  currency     CHAR(3)        NOT NULL CONSTRAINT orders_currency_df DEFAULT 'USD'
);
CREATE INDEX orders_customer_ix ON orders (customer_id);

How it was run

Oracle
Oracle AI Database 26ai Free, release 23.26.3, in the container-registry.oracle.com/database/free image; scripts run in SQL*Plus as user shop
SQL Server
SQL Server 2025 CU9 (17.0.5005.3), Developer edition, in mcr.microsoft.com/mssql/server:2025-latest; scripts run in sqlcmd, database shop
MongoDB
MongoDB 8.3.11 in mongo:8, as a one-node replica set so transactions and change streams work; scripts run in mongosh 2.12
Java
JDK 25; Spring Boot 4.1.1 with its managed driver versions
Integer ids in MongoDBThe seed gives orders and customers small integer _ids, so results can be compared with SQL and read at a glance. A real collection would usually keep the default ObjectId; Keys and generated ids compares the options.
Prices are copied into linesorder_items.unit_price repeats products.price on purpose: it records what the customer paid, and the product's price may change tomorrow. That is deliberate denormalisation, covered in its own slide.
Run it yourselfEach engine runs as one Docker container on a laptop. The script and output on every slide come from that setup; when a slide shows one engine's output and says another agrees, both were run and compared.
