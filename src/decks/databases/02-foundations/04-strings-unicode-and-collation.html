Is 'abc' equal to 'ABC'? Is '' NULL? Oracle and SQL Server give opposite answers to both

String behaviour is set by the column type and the collation, the rules for comparing and sorting text. Oracle compares bytes by default, so 'abc' and 'ABC' differ. A SQL Server database created with the default collation, SQL_Latin1_General_CP1_CI_AS, is case-insensitive (CI) and accent-sensitive (AS). Unicode adds two more traps. In Oracle, column sizes count bytes unless you say CHAR. In SQL Server, a literal without the N prefix is squeezed into a single-byte code page before it reaches an NVARCHAR column.

strings.ora.sql · Oracle 26ai, AL32UTF8
-- 1  the empty string is NULL in Oracle
SELECT CASE WHEN '' IS NULL THEN 'NULL' ELSE 'not NULL' END AS empty_string,
       LENGTH('')                                         AS its_length
FROM   dual;

-- 2  comparisons are case-sensitive, and VARCHAR2 does not pad
SELECT CASE WHEN 'abc' = 'ABC'    THEN 'equal' ELSE 'different' END AS case_test,
       CASE WHEN 'abc' = 'abc   ' THEN 'equal' ELSE 'different' END AS trailing_spaces
FROM   dual;

-- 3  VARCHAR2(10) means 10 bytes by default, and AL32UTF8 needs 2 bytes for ë and ü
CREATE TABLE name_test (name VARCHAR2(10), name_chars VARCHAR2(10 CHAR));
INSERT INTO name_test (name_chars) VALUES ('Zoë Müller');
INSERT INTO name_test (name) VALUES ('Zoë Müller');
SELECT name_chars, LENGTH(name_chars) AS chars, LENGTHB(name_chars) AS bytes FROM name_test;
DROP TABLE name_test PURGE;

-- 4  the unique index on email compares bytes, so a different case is a different email
INSERT INTO customers (customer_id, name, email, country, tier, created_at)
VALUES (11, 'Asha Rao', 'ASHA@example.com', 'IN', 'GOLD', TIMESTAMP '2026-04-01 10:00:00');
ROLLBACK;

strings.mss.sql · SQL Server 2025
-- 1  the empty string is an empty string
SELECT CASE WHEN '' IS NULL THEN 'NULL' ELSE 'not NULL' END AS empty_string,
       LEN('')                                            AS its_length;

-- 2  the default collation ignores case, and = ignores trailing spaces
SELECT CASE WHEN 'abc' = 'ABC'    THEN 'equal' ELSE 'different' END AS case_test,
       CASE WHEN 'abc' = 'abc   ' THEN 'equal' ELSE 'different' END AS trailing_spaces,
       DATABASEPROPERTYEX('shop', 'Collation')                     AS collation;

-- 3  without the N prefix a literal is VARCHAR in the database's code page
SELECT 'Łódź 東京'  AS without_n,
       N'Łódź 東京' AS with_n,
       DATALENGTH(N'Łódź 東京') AS nvarchar_bytes;

-- 4  the unique index on email uses the collation, so a different case is a duplicate
INSERT INTO customers (customer_id, name, email, country, tier, created_at)
VALUES (11, N'Asha Rao', 'ASHA@example.com', 'IN', 'GOLD', '2026-04-01 10:00:00');

The N prefix'Łódź 東京' without N came back as Lódz ??. SQL Server converted the literal to code page 1252 first: Ł and ź got their nearest Latin-1 letters, and the kanji became question marks. Microsoft's JDBC driver sends string parameters as Unicode by default, so this bites mostly in hand-written SQL and stored procedures. The opposite setting is a performance trap, shown on Why the optimiser ignores your index.
Bytes are not charactersZoë Müller is 10 characters but 12 bytes in UTF-8, so it fails in VARCHAR2(10) with ORA-12899 and fits in VARCHAR2(10 CHAR). The client must also declare UTF-8 (NLS_LANG for SQL*Plus), or the bytes are miscounted before they arrive. Size Oracle text columns in CHAR. Never let an application validate "max 10" in characters against a column that counts bytes.
Say it in the interview"In Oracle, the empty string is NULL, so a NOT NULL column rejects ''. SQL Server's default collation is case-insensitive, so the unique email index rejected ASHA@example.com as a duplicate; Oracle accepted it. To get that in Oracle I add a unique function-based index on LOWER(email)."
