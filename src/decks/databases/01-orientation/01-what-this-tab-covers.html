SQL and NoSQL for developers: Oracle, SQL Server and MongoDB, from the first query to the interview

A reference for the database work a backend developer actually does: writing queries, modelling data for an application, reading a plan, getting transactions right, and choosing between a relational and a document store. Every query in this tab was run on the real engine, and the output beside it is what the engine printed. The examples come from one shop with payments and monitoring, so the same orders, payments and metrics appear in SQL and in MongoDB.

113

slides in eighteen sections. It is written for developers, not DBAs: installation, backups, users and storage internals appear only where they change a developer's decision.

30

interview questions, each with a 30-second answer and a follow-up, and 13 coding drills: 8 in SQL, run on both engines, and 5 in MongoDB, each with the follow-up questions that usually come next.

3

How to use it

  • Arrow keys move through slides; C opens contents, where each topic is its own section.
  • Preparing for an interview? Start with topics by interview level, then the questions and the drills. Every answer links back to the slide that goes deeper.
  • Looking something up? The one-page index links every slide with the fact it shows.
  • Other tabs go further on neighbouring ground: JPA and transactions in Spring Boot, replication and partitioning in System design, idempotent consumers in Event-driven. This tab links to them rather than repeating them.
How the code is writtenA label that names a file, such as top-n.sql, means the block is the complete file that was run; an Output on… block is what that engine printed, and a label says so when timings or counts vary. Not shown: a fixed SQL*Plus prelude that sets date formats, UTC and (null) for NULLs, and per-script COLUMN formats so headings are not truncated. Result grids from SQL*Plus and sqlcmd were re-padded to line up, changing whitespace only. MongoDB scripts print through a small show() helper that writes one document per line. Java programs compile with javac --release 21 -Xlint:all, run on JDK 25, and run with framework logging turned down. Oracle 26ai is release 23.26, so a 23ai tag means "available from 23ai on".
