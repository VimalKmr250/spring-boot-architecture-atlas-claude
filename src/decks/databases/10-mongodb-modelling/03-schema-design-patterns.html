A handful of named patterns cover most document designs; each trades write work for cheaper reads

MongoDB's documentation names a set of recurring schema patterns, and interviews use the names. The script shows three of them. The attribute pattern stores varying properties as key-value pairs, so one index serves them all. The bucket pattern groups many small time-series entries into one document per period. Schema versioning lets old and new shapes coexist while the application migrates them lazily. The table covers the others, all of which appear elsewhere in this tab.

patterns.js · MongoDB 8.3, mongosh
// 1  attribute pattern: varying product specs as key-value pairs, one index serves every key
db.specs.drop();
db.specs.insertMany([
  { _id: 101, name: 'Aero 14 Laptop', specs: [{ k: 'ram_gb', v: 16 }, { k: 'weight_kg', v: 1.2 }] },
  { _id: 102, name: 'Forge 16 Laptop', specs: [{ k: 'ram_gb', v: 32 }, { k: 'weight_kg', v: 2.1 }] },
  { _id: 109, name: 'Burr Grinder', specs: [{ k: 'burr_mm', v: 40 }, { k: 'weight_kg', v: 2.9 }] }
]);
db.specs.createIndex({ 'specs.k': 1, 'specs.v': 1 });
const light = db.specs.find({ specs: { $elemMatch: { k: 'weight_kg', v: { $lt: 2.5 } } } }, { name: 1 });
show(light);
print('plan:', stages(light.explain()));

// 2  bucket pattern: one document per host per hour instead of one per sample
db.cpu_buckets.drop();
for (const [m, v] of [[0, 41], [1, 44], [2, 93]]) {
  db.cpu_buckets.updateOne(
    { host: 'db-1', hour: ISODate('2026-03-01T10:00:00Z'), count: { $lt: 60 } },
    { $push: { samples: { m, v } }, $inc: { count: 1, sum: v }, $max: { peak: v } },
    { upsert: true });
}
show(db.cpu_buckets.find({}, { _id: 0 }));

// 3  schema versioning: old and new shapes live side by side, the reader handles both
db.people.drop();
db.people.insertMany([
  { _id: 1, name: 'Asha Rao', phone: '+91 98450 00001' },                                   // version 1
  { _id: 2, schemaVersion: 2, name: 'Ben Clark', phones: [{ type: 'mobile', n: '+44 7700 900002' }] }
]);
db.people.find().sort({ _id: 1 }).forEach(p =>
  print(p.name, '->', (p.schemaVersion ?? 1) >= 2 ? p.phones.map(x => x.n) : [p.phone]));
db.specs.drop(); db.cpu_buckets.drop(); db.people.drop();

The bucket's upsertcount: { $lt: 60 } in the filter means a full bucket no longer matches, so the next sample's upsert starts a new document. One statement either appends to the current bucket or opens the next. The running sum, count and peak answer most dashboard queries without reading the samples.
Versioned shapes need testsThe reader above handles phone and phones. Every query and index must handle both until the old shape is gone, so track how many documents still carry version 1, and finish the migration.
Say it in the interview"Bucket for time series, computed and subset to keep a page to one read, extended reference instead of a join, attribute for sparse properties, and a schema version field for evolution. Each one moves work from read time to write time, so I apply it where reads dominate."
