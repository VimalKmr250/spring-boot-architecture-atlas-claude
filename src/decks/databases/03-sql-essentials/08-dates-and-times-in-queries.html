Reports by month need a calendar to join against; otherwise a month with no sales is simply missing

Most reporting queries group by a time bucket: a day, a week, a month. Truncate each timestamp to the start of its bucket, then group. Grouping alone only produces buckets that contain rows, so a report that must show "April: 0" needs a generated calendar left-joined to the facts. Date arithmetic differs by engine, and so do the edge cases. Adding a month to 31 January gives 28 February in both. SQL Server's DATEDIFF counts boundaries crossed, not elapsed time. Time zones belong at the edges: store UTC, convert for display.

dates.ora.sql · Oracle 26ai
-- 1  orders and revenue per month, every month shown even if empty
WITH months AS (
  SELECT ADD_MONTHS(DATE '2026-01-01', LEVEL - 1) AS month_start
  FROM   dual CONNECT BY LEVEL <= 4
)
SELECT TO_CHAR(m.month_start, 'YYYY-MM') AS month,
       COUNT(o.order_id)                  AS orders,
       COALESCE(SUM(o.total), 0)          AS revenue
FROM   months m
LEFT   JOIN orders o
       ON  o.placed_at >= m.month_start
       AND o.placed_at <  ADD_MONTHS(m.month_start, 1)
       AND o.status IN ('PAID', 'SHIPPED')
GROUP  BY m.month_start
ORDER  BY m.month_start;

-- 2  truncating, adding and differencing dates
SELECT TRUNC(TIMESTAMP '2026-02-27 21:10:00', 'MM')         AS month_start,
       ADD_MONTHS(DATE '2026-01-31', 1)                     AS jan31_plus_1_month,
       DATE '2026-01-01' - DATE '2025-12-31'                AS days_between,
       MONTHS_BETWEEN(DATE '2026-01-01', DATE '2025-12-31') AS months_between
FROM   dual;

-- 3  a UTC timestamp shown in another time zone
SELECT placed_at,
       FROM_TZ(placed_at, 'UTC') AT TIME ZONE 'Asia/Kolkata' AS in_kolkata
FROM   orders WHERE order_id = 1011;

dates.mss.sql · SQL Server 2025
-- 1  orders and revenue per month, every month shown even if empty
WITH months AS (
  SELECT DATEADD(MONTH, value, CAST('2026-01-01' AS DATE)) AS month_start
  FROM   GENERATE_SERIES(0, 3)
)
SELECT FORMAT(m.month_start, 'yyyy-MM') AS month,
       COUNT(o.order_id)                AS orders,
       COALESCE(SUM(o.total), 0)        AS revenue
FROM   months m
LEFT   JOIN orders o
       ON  o.placed_at >= m.month_start
       AND o.placed_at <  DATEADD(MONTH, 1, m.month_start)
       AND o.status IN ('PAID', 'SHIPPED')
GROUP  BY m.month_start
ORDER  BY m.month_start;

-- 2  truncating, adding and differencing dates
SELECT DATETRUNC(MONTH, CAST('2026-02-27 21:10:00' AS DATETIME2(0)))  AS month_start,
       DATEADD(MONTH, 1, CAST('2026-01-31' AS DATE))                   AS jan31_plus_1_month,
       DATEDIFF(DAY, '2025-12-31', '2026-01-01')                       AS days_between,
       DATEDIFF(YEAR, '2025-12-31', '2026-01-01')                      AS years_between;

-- 3  a UTC timestamp shown in another time zone
SELECT placed_at,
       placed_at AT TIME ZONE 'UTC' AT TIME ZONE 'India Standard Time' AS in_kolkata
FROM   orders WHERE order_id = 1011;

dates.js · MongoDB 8.3, mongosh
// revenue per month: $dateTrunc buckets each order by calendar month
show(db.orders.aggregate([
  { $match: { status: { $in: ['PAID', 'SHIPPED'] } } },
  { $group: { _id: { $dateTrunc: { date: '$placedAt', unit: 'month' } },
              orders: { $sum: 1 }, revenue: { $sum: '$total' } } },
  { $sort: { _id: 1 } }
]));
// the same instant, shown in Kolkata time
show(db.orders.aggregate([
  { $match: { _id: 1011 } },
  { $project: { placedAt: 1, inKolkata: { $dateToString: { date: '$placedAt', timezone: 'Asia/Kolkata', format: '%Y-%m-%d %H:%M' } } } }
]));

DATEDIFF counts boundariesDATEDIFF(YEAR, '2025-12-31', '2026-01-01') is 1, after one day. It counts year boundaries crossed. An age or tenure computed this way is wrong for most of the year. Oracle's MONTHS_BETWEEN returns a fraction, 0.032 here, which is closer to what people mean.
The missing monthThe MongoDB pipeline returned three months and no April, because grouping cannot invent an empty bucket. Both SQL queries show April with 0 because they start from a generated list of months. In MongoDB, follow $group with $densify and $fill.
Say it in the interview"I store instants in UTC, filter with half-open ranges on the raw column so an index can be used, and truncate only in the select list and GROUP BY. Zone names, not fixed offsets, so daylight saving is handled; Windows zone names in SQL Server, IANA names elsewhere."
