A LEFT JOIN keeps unmatched rows, until a WHERE condition on the right-hand table throws them away again

An inner join keeps pairs of rows that match the ON condition. A left outer join also keeps every left-hand row that matched nothing, with NULLs in the right-hand columns. Right and full outer joins do the same for the other side, or for both. Two mistakes cause most wrong join results. The first: a filter on the right-hand table placed in WHERE, where it rejects the NULL-padded rows and turns the outer join back into an inner one. The second: joining a one-to-many relationship and then summing a column of the "one" side, which counts that column once per child row.

joins.sql · runs unchanged on Oracle 26ai and SQL Server 2025
-- 1  every customer with the number of cancelled orders, or so it seems
SELECT c.customer_id, c.name, COUNT(o.order_id) AS cancelled
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id
WHERE  o.status = 'CANCELLED'
GROUP  BY c.customer_id, c.name
ORDER  BY c.customer_id;

-- 2  the condition on the right-hand table belongs in ON
SELECT c.customer_id, c.name, COUNT(o.order_id) AS cancelled
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id AND o.status = 'CANCELLED'
GROUP  BY c.customer_id, c.name
ORDER  BY c.customer_id;

-- 3  fan-out: joining the lines repeats each order total once per line
SELECT SUM(o.total) AS revenue_wrong
FROM   orders o
JOIN   order_items i ON i.order_id = o.order_id
WHERE  o.status IN ('PAID', 'SHIPPED');

SELECT SUM(o.total) AS revenue_right
FROM   orders o
WHERE  o.status IN ('PAID', 'SHIPPED');

Fan-out doubles the moneySUM(o.total) after joining order_items gave 12,748.60 instead of 8,190.70: every order with two lines was counted twice. Aggregate the child table in a subquery first, or sum child columns (qty * unit_price) rather than parent ones. If a DISTINCT "fixes" a join, suspect fan-out.
ON or WHEREFor an inner join it makes no difference. For an outer join, a condition in ON decides which right-hand rows match; a condition in WHERE filters the joined result, NULL-padded rows included. Conditions on the preserved, left-hand side belong in WHERE.
Say it in the interview"For 'every customer, with or without orders', I use a LEFT JOIN, put conditions on the orders table in the ON clause, and count a column of the right-hand table, COUNT(o.order_id), not COUNT(*), which would count 1 for a customer with no orders."
