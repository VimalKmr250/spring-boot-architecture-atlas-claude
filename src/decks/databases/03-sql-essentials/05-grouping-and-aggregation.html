One GROUP BY, many answers: conditional aggregation turns a status column into a column per status

GROUP BY collapses rows into one row per group, and every selected column must either be grouped or aggregated. Four techniques cover most reporting questions. The COUNT variants count different things. Wrapping a CASE in SUM or AVG (conditional aggregation) computes several filtered totals in a single pass. LISTAGG (Oracle) and STRING_AGG (SQL Server) build a list per group. ROLLUP adds subtotal and grand-total rows. Here they report on payment failures per method, which is the first query anyone runs on a payment system.

grouping.ora.sql · Oracle 26ai
-- 1  three different counts
SELECT COUNT(*) AS payments, COUNT(DISTINCT order_id) AS orders_paid_for, COUNT(DISTINCT method) AS methods
FROM   payments;

-- 2  conditional aggregation: one pass, one row per method, a column per outcome
SELECT method,
       COUNT(*)                                             AS attempts,
       SUM(CASE WHEN status = 'FAILED' THEN 1 ELSE 0 END)   AS failed,
       ROUND(100 * AVG(CASE WHEN status = 'FAILED' THEN 1 ELSE 0 END), 1) AS failed_pct
FROM   payments
GROUP  BY method
ORDER  BY method;

-- 3  a list per group
SELECT o.order_id,
       LISTAGG(p.sku, ', ') WITHIN GROUP (ORDER BY i.line_no) AS skus
FROM   orders o
JOIN   order_items i ON i.order_id = o.order_id
JOIN   products p    ON p.product_id = i.product_id
WHERE  o.customer_id = 1
GROUP  BY o.order_id
ORDER  BY o.order_id;

-- 4  subtotals and a grand total in one query
SELECT CASE WHEN GROUPING(c.tier) = 1 THEN '(all)' ELSE c.tier END       AS tier,
       CASE WHEN GROUPING(o.status) = 1 THEN '(all)' ELSE o.status END   AS status,
       COUNT(*) AS orders, SUM(o.total) AS total
FROM   orders o
JOIN   customers c ON c.customer_id = o.customer_id
WHERE  o.status IN ('PAID', 'SHIPPED')
GROUP  BY ROLLUP (c.tier, o.status)
ORDER  BY GROUPING(c.tier), c.tier, GROUPING(o.status), o.status;

SQL Server 2025 agreesgrouping.mss.sql is the same file with two changes: STRING_AGG instead of LISTAGG, and 100.0 * AVG(… THEN 1.0 …). Without the decimals, SQL Server would average the 0s and 1s as integers and report 0% failed. It prints the same rows.
grouping.js · MongoDB 8.3, mongosh
// conditional aggregation in a pipeline: $group with $cond
show(db.payments.aggregate([
  { $group: { _id: '$method',
              attempts: { $sum: 1 },
              failed:   { $sum: { $cond: [{ $eq: ['$status', 'FAILED'] }, 1, 0] } } } },
  { $sort: { _id: 1 } }
]));

The non-grouped columnSELECT customer_id, name, COUNT(*) … GROUP BY customer_id fails in both engines: ORA-00979 and SQL Server error 8120. Group by the name as well, or aggregate it with MAX(name). Some engines, such as MySQL in its old mode, return an arbitrary value instead, which is worse.
Reading ROLLUP rowsA subtotal row has NULL in the rolled-up columns. GROUPING(col) = 1 tells it apart from a real NULL, which is how the query labelled them (all). Use CUBE for every combination of subtotals, and GROUPING SETS to list exactly the ones you want.
Say it in the interview"For counts by status as columns I use conditional aggregation: one scan, one row per group, and it works in every engine. PIVOT is shorthand for the same thing; the pivot drill shows both."
