A recursive CTE walks a tree one level per iteration, until a level returns no rows, or a cycle makes it run forever

A common table expression (WITH name AS (…)) names a subquery so the main query reads top to bottom. A recursive CTE has two parts joined by UNION ALL. The anchor selects the starting rows. The recursive member joins the table to the rows produced by the previous iteration, until an iteration adds nothing. That is how SQL walks hierarchies stored as a parent pointer: category trees, org charts, bills of materials. MongoDB's equivalent is the $graphLookup stage.

ctes.ora.sql · Oracle 26ai
-- 1  a recursive CTE walks the category tree from the roots down
WITH tree (category_id, name, depth, path) AS (
  SELECT category_id, name, 1, CAST(name AS VARCHAR2(200))
  FROM   categories
  WHERE  parent_id IS NULL
  UNION ALL
  SELECT c.category_id, c.name, t.depth + 1, t.path || ' > ' || c.name
  FROM   categories c
  JOIN   tree t ON c.parent_id = t.category_id
)
SELECT category_id, depth, path FROM tree ORDER BY path;

-- 2  the same walk with CONNECT BY, Oracle's older syntax
SELECT category_id, LEVEL AS depth, SYS_CONNECT_BY_PATH(name, ' > ') AS path
FROM   categories
START  WITH parent_id IS NULL
CONNECT BY PRIOR category_id = parent_id
ORDER  SIBLINGS BY name;

-- 3  a cycle: make Electronics a child of Laptops, then walk again
UPDATE categories SET parent_id = 3 WHERE category_id = 1;
WITH tree (category_id, depth) AS (
  SELECT category_id, 1 FROM categories WHERE category_id = 1
  UNION ALL
  SELECT c.category_id, t.depth + 1 FROM categories c JOIN tree t ON c.parent_id = t.category_id
)
SELECT MAX(depth) AS deepest FROM tree;

--    the CYCLE clause marks the row that closes the loop and stops there
WITH tree (category_id, depth) AS (
  SELECT category_id, 1 FROM categories WHERE category_id = 1
  UNION ALL
  SELECT c.category_id, t.depth + 1 FROM categories c JOIN tree t ON c.parent_id = t.category_id
) CYCLE category_id SET is_cycle TO 'Y' DEFAULT 'N'
SELECT category_id, depth, is_cycle FROM tree;
ROLLBACK;

ctes.mss.sql · SQL Server 2025
-- 1  a recursive CTE walks the category tree from the roots down
WITH tree (category_id, name, depth, path) AS (
  SELECT category_id, name, 1, CAST(name AS NVARCHAR(200))
  FROM   categories
  WHERE  parent_id IS NULL
  UNION ALL
  SELECT c.category_id, c.name, t.depth + 1, CAST(t.path + N' > ' + c.name AS NVARCHAR(200))
  FROM   categories c
  JOIN   tree t ON c.parent_id = t.category_id
)
SELECT category_id, depth, path FROM tree ORDER BY path;

-- 2  a cycle: make Electronics a child of Laptops, then walk again
BEGIN TRANSACTION;
UPDATE categories SET parent_id = 3 WHERE category_id = 1;
WITH tree (category_id, depth) AS (
  SELECT category_id, 1 FROM categories WHERE category_id = 1
  UNION ALL
  SELECT c.category_id, t.depth + 1 FROM categories c JOIN tree t ON c.parent_id = t.category_id
)
SELECT MAX(depth) AS deepest FROM tree;
ROLLBACK;

ctes.js · MongoDB 8.3, mongosh
// $graphLookup: every ancestor of the Coffee category, nearest first
show(db.categories.aggregate([
  { $match: { _id: 8 } },
  { $graphLookup: { from: 'categories', startWith: '$parentId', connectFromField: 'parentId',
                    connectToField: '_id', as: 'ancestors', depthField: 'hops' } },
  { $project: { name: 1, ancestors: { $sortArray: { input: '$ancestors', sortBy: { hops: 1 } } } } },
  { $project: { name: 1, 'ancestors.name': 1, 'ancestors.hops': 1 } }
]));

CyclesWith Electronics made a child of Laptops, the walk never ends. SQL Server stopped it at its default limit of 100 levels with error 530; OPTION (MAXRECURSION n) changes the limit, and 0 removes it. Oracle detected the loop (ORA-32044). Its CYCLE clause instead flags the row that closes the loop and stops there. Parent-pointer data from users will eventually contain a cycle.
Types in the recursive memberThe anchor's column types fix the CTE's types, and SQL Server requires the recursive member to match them exactly (error 240), hence the CAST(… AS NVARCHAR(200)) on both sides. Oracle needs the column list after the CTE name. CONNECT BY is Oracle's older syntax legacy, still common in existing code.
Say it in the interview"An adjacency list, a parent_id column, is easy to update and needs a recursive query to read a subtree. If subtrees are read far more often than the tree changes, I store a materialised path or a closure table instead." The trade-off is on Many-to-many, polymorphism and trees.
