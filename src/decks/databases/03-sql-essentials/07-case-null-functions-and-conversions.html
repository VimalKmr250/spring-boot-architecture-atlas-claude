COALESCE, NVL and ISNULL all replace a NULL, but they disagree on evaluation and on the result's type

CASE is SQL's if-then-else, and it works anywhere an expression is allowed: in SELECT, WHERE, ORDER BY and inside aggregates. The NULL functions look interchangeable but are not. COALESCE is standard: it takes any number of arguments, evaluates them only until one is not NULL, and returns the widest of their types. Oracle's NVL evaluates both arguments. SQL Server's ISNULL returns the type of its first argument. Conversions have their own trap: CAST of bad text is an error in both engines, unless you ask for NULL instead.

functions.ora.sql · Oracle 26ai
-- 1  CASE: the searched form tests any condition; the first true branch wins
SELECT order_id, total,
       CASE WHEN total >= 1000 THEN 'large'
            WHEN total >= 100  THEN 'medium'
            ELSE 'small' END AS size_band
FROM   orders
WHERE  customer_id = 1
ORDER  BY order_id;

-- 2  NVL evaluates both arguments; COALESCE stops at the first non-NULL
SELECT COALESCE(1, 1 / 0) AS coalesce_short_circuits FROM dual;
SELECT NVL(1, 1 / 0) AS nvl_does_not FROM dual;

-- 3  NULLIF turns a zero divisor into NULL instead of an error
SELECT 100 / NULLIF(0, 0) AS safe_division FROM dual;

-- 4  converting text that may not be a number
SELECT CAST('42' AS NUMBER)                                  AS good,
       CAST('4x2' AS NUMBER DEFAULT NULL ON CONVERSION ERROR) AS bad_becomes_null,
       VALIDATE_CONVERSION('4x2' AS NUMBER)                  AS is_valid
FROM   dual;
SELECT CAST('4x2' AS NUMBER) AS fails FROM dual;

-- 2  ISNULL takes the type of its first argument; COALESCE takes the widest
DECLARE @code VARCHAR(3) = NULL;
SELECT ISNULL(@code, 'unknown') AS isnull_result, COALESCE(@code, 'unknown') AS coalesce_result;

-- 3  NULLIF turns a zero divisor into NULL instead of an error
SELECT 100 / NULLIF(0, 0) AS safe_division;

-- 4  converting text that may not be a number
SELECT CAST('42' AS INT) AS good, TRY_CAST('4x2' AS INT) AS bad_becomes_null;
SELECT CAST('4x2' AS INT) AS fails;

ISNULL truncatesISNULL(@code, 'unknown') returned unk: the result took @code's type, VARCHAR(3), and the default was cut to fit, with no error. COALESCE returned unknown. Any NULL default of a different length or type should use COALESCE.
NVL is not lazyNVL(1, 1 / 0) raised ORA-01476 although the first argument was not NULL, because NVL evaluates both. COALESCE stopped at the 1. It matters when the second argument is expensive, a function call or a scalar subquery, or can fail.
Say it in the interview"I default to CASE and COALESCE because they are standard and behave the same everywhere. A CASE without ELSE returns NULL for unmatched rows, which matters inside SUM or COUNT. And NULLIF(divisor, 0) is the one-line fix for division by zero."
