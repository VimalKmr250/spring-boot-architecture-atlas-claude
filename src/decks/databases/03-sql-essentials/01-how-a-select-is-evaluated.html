SQL is written SELECT first but evaluated FROM first, and that order explains most "invalid column" errors

A query's clauses are evaluated in a fixed logical order: the rows come from FROM and the joins, WHERE filters them, GROUP BY collapses them into groups, HAVING filters the groups, SELECT computes the output columns, and ORDER BY and the row limit come last. A clause can only use names that exist at its step. The optimiser may execute the query in a different physical order, but it must give the same result as this logical one.

order-of-evaluation.ora.sql · Oracle 26ai
-- 1  WHERE runs before SELECT, so the alias does not exist yet
SELECT order_id, total * 0.18 AS tax
FROM   orders
WHERE  tax > 100;

-- 2  ORDER BY runs after SELECT, so the alias is fine there
SELECT order_id, total * 0.18 AS tax
FROM   orders
ORDER  BY tax DESC
OFFSET 0 ROWS FETCH NEXT 3 ROWS ONLY;

-- 3  WHERE filters rows before grouping, HAVING filters the groups after
SELECT customer_id, COUNT(*) AS orders, SUM(total) AS spent
FROM   orders
WHERE  status <> 'CANCELLED'
GROUP  BY customer_id
HAVING COUNT(*) >= 3
ORDER  BY spent DESC;

-- 4  an aggregate cannot appear in WHERE: the groups do not exist yet
SELECT customer_id
FROM   orders
WHERE  COUNT(*) >= 3
GROUP  BY customer_id;

An aggregate may not appear in the WHERE clause unless it is in a subquery contained in a HAVING clause or a select list, and the column being aggregated is an outer reference.
One error, whole batchWithout the GO lines, SQL Server reported only the two errors and ran nothing else. A compile error such as an unknown column fails the entire batch before any statement in it runs. SQL*Plus runs each statement on its own, so Oracle printed the error and carried on.
WHERE or HAVINGFilter rows in WHERE whenever the condition does not need an aggregate. HAVING status <> 'CANCELLED' would also run, but it groups every row first and discards the cancelled ones only afterwards. Use HAVING for conditions on aggregates, such as COUNT(*) >= 3.
Say it in the interview"Logical order is FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, then the row limit. That is why a select alias works in ORDER BY but not in WHERE, and why window functions, computed at SELECT, cannot be filtered in WHERE: wrap the query in a subquery and filter outside."
