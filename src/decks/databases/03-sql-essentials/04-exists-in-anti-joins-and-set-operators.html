"Customers who never ordered" has three spellings, and one of them returns nothing once a NULL appears

A semi-join keeps rows that have a match (EXISTS, IN). An anti-join keeps rows that have none; you can write it as NOT EXISTS, as an outer join filtered to the misses, or as NOT IN. The first two give the same rows, though not always the same plan. NOT IN is different: one NULL in the subquery makes every comparison UNKNOWN, and no row survives. The set operators at the end compare whole result sets: they answer "in this list but not that one" without a join.

anti-joins.sql · runs unchanged on Oracle 26ai and SQL Server 2025
-- 1  customers who never placed an order: NOT EXISTS
SELECT c.customer_id, c.name
FROM   customers c
WHERE  NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id)
ORDER  BY c.customer_id;

-- 2  the same anti-join as an outer join that keeps only the misses
SELECT c.customer_id, c.name
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id
WHERE  o.order_id IS NULL
ORDER  BY c.customer_id;

-- 3  customers who never referred anyone: referred_by contains NULLs
SELECT COUNT(*) AS not_in_rows
FROM   customers c
WHERE  c.customer_id NOT IN (SELECT r.referred_by FROM customers r);

SELECT COUNT(*) AS not_exists_rows
FROM   customers c
WHERE  NOT EXISTS (SELECT 1 FROM customers r WHERE r.referred_by = c.customer_id);

-- 4  set operators: who cancelled, who had something shipped
SELECT customer_id FROM orders WHERE status = 'CANCELLED'
EXCEPT
SELECT customer_id FROM orders WHERE status = 'SHIPPED'
ORDER  BY customer_id;

SELECT customer_id FROM orders WHERE status = 'CANCELLED'
INTERSECT
SELECT customer_id FROM orders WHERE status = 'SHIPPED'
ORDER  BY customer_id;

SELECT (SELECT COUNT(*) FROM (SELECT customer_id FROM orders WHERE status = 'CANCELLED'
                              UNION ALL
                              SELECT customer_id FROM orders WHERE status = 'SHIPPED') a) AS union_all_rows,
       (SELECT COUNT(*) FROM (SELECT customer_id FROM orders WHERE status = 'CANCELLED'
                              UNION
                              SELECT customer_id FROM orders WHERE status = 'SHIPPED') u) AS union_rows;

The trapcustomer_id NOT IN (SELECT referred_by …) returned 0 rows, not 6. x NOT IN (1, 3, NULL) means x <> 1 AND x <> 3 AND x <> NULL, and the last comparison is UNKNOWN for every x. Filter the NULLs out in the subquery, or write NOT EXISTS.
Set operators, brieflyUNION removes duplicates, which costs a sort or a hash: 10 rows became 7 above. Use UNION ALL unless you need that. EXCEPT works in both engines (Oracle 21c; MINUS before that). Set operators treat two NULLs as equal, unlike =.
Say it in the interview"I write anti-joins as NOT EXISTS. It is NULL-safe, and both Oracle and SQL Server plan it as an anti-join; the outer-join spelling stays an outer join on Oracle. NOT IN silently returns nothing if the subquery yields a NULL."
