"The top three" means sort first, then limit: ROWNUM and a TOP without ORDER BY both limit first

Without ORDER BY, rows come back in whatever order the plan produces, and that order can change when the data or the plan changes. Oracle assigns ROWNUM as rows leave WHERE, before any sort. So WHERE ROWNUM <= 3 ORDER BY total DESC sorts three arbitrary rows; it does not find the three largest. The standard FETCH FIRST and SQL Server's TOP with an ORDER BY sort first. WITH TIES returns every row that ties with the last one. Dates need the half-open range again: BETWEEN includes the end point, and for a timestamp that end point is midnight.

limiting.ora.sql · Oracle 26ai
-- 1  ROWNUM is assigned before ORDER BY: these are 3 arbitrary orders, then sorted
SELECT order_id, total FROM orders WHERE ROWNUM <= 3 ORDER BY total DESC;

--    sort first, then keep 3
SELECT order_id, total FROM orders ORDER BY total DESC FETCH FIRST 3 ROWS ONLY;

-- 2  FETCH FIRST sorts first; WITH TIES keeps rows equal to the last one
SELECT emp_id, name, salary FROM employees ORDER BY salary DESC FETCH FIRST 6 ROWS ONLY;
SELECT emp_id, name, salary FROM employees ORDER BY salary DESC FETCH FIRST 6 ROWS WITH TIES;

-- 3  BETWEEN on a timestamp stops at midnight of the last day
SELECT COUNT(*) AS between_feb_1_and_27
FROM   orders WHERE placed_at BETWEEN DATE '2026-02-01' AND DATE '2026-02-27';
SELECT COUNT(*) AS half_open_to_feb_28
FROM   orders WHERE placed_at >= DATE '2026-02-01' AND placed_at < DATE '2026-02-28';

limiting.mss.sql · SQL Server 2025
-- 1  TOP without ORDER BY: whichever 3 rows come first
SELECT TOP (3) order_id, total FROM orders;

--    sort first, then keep 3
SELECT TOP (3) order_id, total FROM orders ORDER BY total DESC;

-- 2  TOP with ORDER BY; WITH TIES keeps rows equal to the last one
SELECT TOP (6) emp_id, name, salary FROM employees ORDER BY salary DESC;
SELECT TOP (6) WITH TIES emp_id, name, salary FROM employees ORDER BY salary DESC;

-- 3  BETWEEN on a timestamp stops at midnight of the last day
SELECT COUNT(*) AS between_feb_1_and_27
FROM   orders WHERE placed_at BETWEEN '2026-02-01' AND '2026-02-27';
SELECT COUNT(*) AS half_open_to_feb_28
FROM   orders WHERE placed_at >= '2026-02-01' AND placed_at < '2026-02-28';

The ROWNUM trapQuery 1 returned orders 1001 to 1003, the first three rows read, sorted among themselves. The real top three by total are 1007, 1013 and 1005. Old code that pages with ROWNUM needs the sort in an inner query: SELECT * FROM (SELECT … ORDER BY total DESC) WHERE ROWNUM <= 3.
BETWEEN and timestampsBETWEEN '2026-02-01' AND '2026-02-27' found 5 orders, because order 1011 at 21:10 on the 27th falls after the upper bound, midnight. The half-open range found all 6. Never write 23:59:59 as an upper bound either: it misses the last second's fractions.
Say it in the interview"Row order is undefined without ORDER BY, so any limit needs one, and a unique tie-breaker such as the primary key to make paging stable. Then I use FETCH FIRST or TOP, never ROWNUM with an outer sort."
