MongoDB can join, flatten, fan out and materialise inside one pipeline; whether it should is a modelling question

$lookup is a left outer join: for each input document it finds matching documents in another collection and adds them as an array. $unwind turns an array into one document per element, the shape SQL would return. $facet runs several sub-pipelines over the same input, which suits a dashboard that needs counts, a top list and a total from one query. $merge writes the result into a collection, inserting or replacing by key: a materialised view that you refresh by running the pipeline again.

lookup-facet.js · MongoDB 8.3, mongosh
// 1  $lookup joins another collection; $unwind turns the array into one document per element
show(db.orders.aggregate([
  { $match: { _id: { $in: [1003, 1005] } } },
  { $lookup: { from: 'payments', localField: '_id', foreignField: 'orderId', as: 'attempts' } },
  { $unwind: '$attempts' },
  { $project: { _id: 1, status: 1, attempt: '$attempts.idempotencyKey', result: '$attempts.status' } }
]));

// 2  $facet runs several pipelines over the same input, for a dashboard in one round trip
show(db.orders.aggregate([
  { $facet: {
      byStatus:     [{ $group: { _id: '$status', n: { $sum: 1 } } }, { $sort: { _id: 1 } }],
      topCustomers: [{ $group: { _id: '$customer.name', spent: { $sum: '$total' } } },
                     { $sort: { spent: -1 } }, { $limit: 2 }],
      totalOrders:  [{ $count: 'n' }]
  } }
]));

// 3  $merge writes the result into a collection: a materialised view, refreshed by re-running it
db.orders.aggregate([
  { $unwind: '$items' },
  { $group: { _id: '$items.productId', units: { $sum: '$items.qty' } } },
  { $merge: { into: 'product_sales', whenMatched: 'replace', whenNotMatched: 'insert' } }
]);
show(db.product_sales.find().sort({ units: -1 }).limit(3));
db.product_sales.drop();

StageSQL analogue
$lookupLEFT JOIN, results nested as an array
$unwindOne row per child; drops parents with an empty array unless preserveNullAndEmptyArrays
$facetSeveral GROUP BY queries in one statement
$merge / $outMERGE INTO a summary table / CREATE TABLE AS
$graphLookupA recursive CTE: see CTEs
$lookup on the hot pathA $lookup runs a query against the other collection for each input document, so it needs an index on foreignField; here that is payments.orderId. It is fine for reports and admin screens. If every order page needs the payments, embed a summary of them in the order instead.
$unwind multipliesOrder 1005 became three documents, one per payment attempt: the fan-out of a SQL join. A $group after $unwind that sums an order-level field would count it three times, the same trap as fan-out in SQL.
Say it in the interview"$lookup gives MongoDB joins, but a design that needs them on every read is a relational design in the wrong database. I embed what is read together and use $lookup for occasional queries, with an index on the joined field."
