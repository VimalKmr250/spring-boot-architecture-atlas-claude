Two conditions on an array can be met by two different elements, unless you say they must be the same one

Embedding order lines in the order document is the point of the document model, so queries and updates on arrays are everyday work. A filter on 'items.qty' asks whether any line matches, and each condition is checked against the array separately. $elemMatch pins several conditions to one element. For updates, $ changes the element the filter matched, $[name] with arrayFilters changes every element that matches, and $pull and $push remove and add elements without rewriting the document in your code.

arrays.js · MongoDB 8.3, mongosh
// 1  "an order with a line over $100 bought two or more at a time"
//    Without $elemMatch, each condition may be met by a different line.
show(db.orders.find({ 'items.unitPrice': { $gt: 100 }, 'items.qty': { $gte: 2 } }, { 'items.qty': 1, 'items.unitPrice': 1 }));
print('--');
//    With $elemMatch, one line must meet both.
show(db.orders.find({ items: { $elemMatch: { unitPrice: { $gt: 100 }, qty: { $gte: 2 } } } }, { 'items.qty': 1, 'items.unitPrice': 1 }));

// 2  $ updates the first array element the filter matched
show(db.orders.updateOne({ _id: 1015, 'items.productId': 103 }, { $inc: { 'items.$.qty': 1 } }));
show(db.orders.findOne({ _id: 1015 }, { 'items.productId': 1, 'items.qty': 1 }));

// 3  $[name] with arrayFilters updates every element that matches, in every matching document
show(db.orders.updateMany(
  { 'items.productId': 110 },
  { $set: { 'items.$[line].backordered': true } },
  { arrayFilters: [{ 'line.productId': 110 }] }));
show(db.orders.find({ 'items.backordered': true }, { _id: 1, 'items.productId': 1, 'items.backordered': 1 }));

// 4  $pull removes elements by condition; $push with $each and $slice keeps an array bounded
show(db.orders.updateOne({ _id: 1015 }, { $pull: { items: { productId: 103 } } }));
show(db.customers.updateOne({ _id: 1 }, { $push: { recentSearches: { $each: ['kettle', 'grinder', 'beans'], $slice: -2 } } }));
show(db.customers.findOne({ _id: 1 }, { recentSearches: 1 }));

// put the data back for the next slide
db.orders.updateOne({ _id: 1015 }, { $set: { items: [
  { productId: 107, sku: 'PHN-C2', name: 'Clam C2 Phone', qty: 1, unitPrice: Decimal128('449.00') },
  { productId: 103, sku: 'ACC-MSE', name: 'Quiet Mouse', qty: 1, unitPrice: Decimal128('29.90') }] } });
db.orders.updateMany({}, { $unset: { 'items.$[].backordered': '' } });
db.customers.updateOne({ _id: 1 }, { $unset: { recentSearches: '' } });

The trapQuery 1 matched order 1003, whose grinder costs 139.00 but is bought once, and whose beans are bought twice but cost 24.00. No single line is "over $100, two or more". With $elemMatch only 1007 remains. The same rule applies to an index: a compound index on two fields of one array can only be used fully with $elemMatch.
Arrays must stay boundedEvery $push grows the document, and documents are capped at 16 MB. $each with $slice: -2 kept only the two latest searches above. An array that grows without limit, such as every event for a customer, belongs in its own collection.
Say it in the interview"Conditions on array fields match independently; I use $elemMatch when they must hold for the same element. To change embedded lines I use the positional operators, which update inside one document atomically, so there is no read-modify-write race."
