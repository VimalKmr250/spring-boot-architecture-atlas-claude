A MongoDB query is itself a document, which makes it easy to build and easy to inject into

find(filter, projection) returns a cursor, to which sort, skip and limit are applied on the server. A filter field with a plain value means equality. A value that is an object of operators, such as $gt, $in, $regex or $exists, applies those operators. Fields listed together are combined with AND; $or takes a list of alternatives. A projection keeps or removes fields, but not both, except that _id can always be excluded. Because the filter is data, an attacker who controls part of it can supply operators instead of values.

finding.js · MongoDB 8.3, mongosh
// 1  filters, a projection, a sort and a limit: the five largest paid or shipped orders since February
show(db.orders.find(
  { status: { $in: ['PAID', 'SHIPPED'] }, placedAt: { $gte: ISODate('2026-02-01') } },
  { _id: 1, 'customer.name': 1, total: 1 }
).sort({ total: -1 }).limit(5));

// 2  OR across fields, and a regular expression anchored at the start
show(db.customers.find(
  { $or: [{ tier: 'GOLD' }, { name: /^E/ }] },
  { _id: 0, name: 1, tier: 1 }
).sort({ name: 1 }));

// 3  operator injection: a request body parsed straight into the filter
db.api_keys.drop();
db.api_keys.insertOne({ key: 'k-7f3a9', owner: 'reporting-service' });
const body = JSON.parse('{ "key": { "$ne": "" } }');          // sent by an attacker instead of a string
show(db.api_keys.find({ key: body.key }, { _id: 0 }));         // matches any key at all
print('with $eq:', db.api_keys.countDocuments({ key: { $eq: body.key } }), 'matches');  // compares the object as a value
db.api_keys.drop();

Operator injectionThe request body put { "$ne": "" } where a string key was expected, and find({ key: body.key }) returned the stored API key. It is MongoDB's SQL injection. Validate that input fields have the expected type before building a filter, or wrap untrusted values in $eq, which compares the object as a literal value: 0 matches.
Unanchored regular expressions/^E/ can use an index because it fixes the start of the string; /son$/ or a case-insensitive /e/i examines every document. For text search use an Atlas Search or text index, and for case-insensitive equality a collation index.
Say it in the interview"find takes a filter document and a projection; sort and limit run on the server. I project only the fields I need, and I treat request bodies as untyped input: a JSON object where a string was expected is an injection attempt."
