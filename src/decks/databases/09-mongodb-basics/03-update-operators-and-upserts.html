Update operators change fields in place on the server; a replacement document overwrites everything else

updateOne(filter, update) takes either a document of update operators ($set, $inc, $push, $unset, $min, $max…) or, with replaceOne, a whole new document. Operators modify the matched document atomically on the server, so two clients incrementing a counter never lose an update, with no read first. With upsert: true, a filter that matches nothing inserts a new document built from the filter's equality fields plus the update. $setOnInsert sets fields only on that insert. A shopping cart is the classic case.

updates.js · MongoDB 8.3, mongosh
db.carts.drop();
// 1  upsert with $setOnInsert: fields set only when the document is created
show(db.carts.updateOne(
  { _id: 'cart-asha' },
  { $setOnInsert: { customerId: 1, createdAt: ISODate('2026-04-01T10:00:00Z') },
    $push: { items: { sku: 'COF-BNS', qty: 1 } }, $inc: { itemCount: 1 } },
  { upsert: true }));
show(db.carts.updateOne(
  { _id: 'cart-asha' },
  { $setOnInsert: { customerId: 1, createdAt: ISODate('2026-04-02T09:00:00Z') },
    $push: { items: { sku: 'KIT-KTL', qty: 1 } }, $inc: { itemCount: 1 } },
  { upsert: true }));
show(db.carts.findOne());

// 2  $min, $max and $unset: conditional and removing updates in one round trip
show(db.carts.updateOne({ _id: 'cart-asha' },
  { $min: { cheapestSeen: Decimal128('24.00') }, $max: { biggestQty: 1 }, $unset: { createdAt: '' } }));
show(db.carts.findOne({}, { items: 0 }));

// 3  replaceOne swaps the whole document: every field you did not send is gone
show(db.carts.replaceOne({ _id: 'cart-asha' }, { itemCount: 3 }));
show(db.carts.findOne());

// 4  findOneAndUpdate returns the document, before or after the change
show(db.carts.findOneAndUpdate({ _id: 'cart-asha' }, { $inc: { itemCount: -1 } }, { returnDocument: 'after' }));
db.carts.drop();

OperatorDoes
$set / $unsetSet or remove fields, including nested paths
$incAdd atomically: counters, stock
$min / $maxSet only if lower / higher than the current value
$setOnInsertApply only when an upsert inserts
$push, $pull, $addToSetArray changes: see Arrays
$currentDateServer time, for updatedAt
replaceOne deletes what you did not sendReplacing the cart with { itemCount: 3 } removed the customer id, the items and everything else. The same happens in application code that loads a document, changes one field and saves the whole object back: concurrent changes to other fields are lost. Update the fields that changed with operators.
Reading the resultmatchedCount is how many documents the filter found; modifiedCount is how many actually changed. A $set to the current value matches but does not modify. upsertedCount: 1 and an insertedId mean the upsert created the document.
Say it in the interview"I update with operators, not by replacing documents, so the change is atomic on the server and other fields are untouched. Upsert plus $setOnInsert is the create-or-update idiom, backed by a unique index on the filter field. findOneAndUpdate returns the document in the same round trip."
