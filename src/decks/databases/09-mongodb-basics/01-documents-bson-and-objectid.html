A MongoDB document looks like JSON but is stored as BSON: typed values, ordered fields, and a mandatory _id

MongoDB stores documents in collections. A document is a set of fields whose values can be scalars, arrays or nested documents, encoded as BSON, a binary format with richer types than JSON: 32- and 64-bit integers, doubles, Decimal128, dates, binary data and ObjectId. Every document has an _id that is unique in its collection and indexed automatically. If the application does not supply one, the driver generates an ObjectId. A document may be at most 16 MB, and the fields in it keep the order in which they were written.

bson.js · MongoDB 8.3, mongosh
// 1  every value has a BSON type; the shell shows the non-JSON ones with constructors
const order = db.orders.findOne({ _id: 1001 });
show(db.orders.aggregate([{ $match: { _id: 1001 } }, { $project: {
  _id: { $type: '$_id' }, customer: { $type: '$customer' }, placedAt: { $type: '$placedAt' },
  items: { $type: '$items' }, total: { $type: '$total' } } }]));
print('document size in bytes:', bsonsize(order));

// 2  an ObjectId is 12 bytes: a 4-byte timestamp, 5 random bytes, a 3-byte counter
const id = new ObjectId();
print(id.getTimestamp() instanceof Date, id.toHexString().length, 'hex digits');

// 3  matching a whole embedded document compares field order too
print('{ name, id }:', db.orders.countDocuments({ customer: { name: 'Asha Rao', id: 1 } }));
print('{ id, name }:', db.orders.countDocuments({ customer: { id: 1, name: 'Asha Rao' } }));
print('dot notation:', db.orders.countDocuments({ 'customer.id': 1 }));

Matching a whole sub-document{ customer: { name: …, id: … } } matched nothing, because an embedded document is compared as a whole, field order included, and the stored order is id, then name. Query embedded fields with dot notation, 'customer.id': 1, which matched all 4 orders.
JavaScript numbersIn mongosh a literal such as 19.99 is stored as a double, and an integer literal as an int. Drivers map types from the language: a Java BigDecimal becomes Decimal128, a long becomes long. Mixed types in one field, an int here and a double there, are legal and easily created by accident.
Say it in the interview"Documents are BSON: typed, ordered, up to 16 MB, with a unique _id. An ObjectId embeds its creation second, so it sorts roughly by insert time, and the driver generates it, so the client knows the id before the write reaches the server."
