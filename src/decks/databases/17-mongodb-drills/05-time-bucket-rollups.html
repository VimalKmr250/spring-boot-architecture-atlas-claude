Drill: "average and peak CPU per host in 5-minute buckets", and make the minutes with no data visible

The monitoring question: raw samples arrive every minute, and the dashboard wants one point per host every five minutes. $dateTrunc with binSize: 5 rounds each timestamp down to its bucket, and $group on host and bucket does the rest. Then the follow-up every monitoring interviewer asks: what about the minutes a host did not report? A plain $group skips them silently. $densify inserts a document for each missing step, so the gap shows up as rows.

rollups.js · MongoDB 8.3, mongosh
// 1  5-minute averages and peaks per host from the minute samples
show(db.metric_samples.aggregate([
  { $match: { 'meta.host': { $in: ['web-2', 'db-1'] }, ts: { $lt: ISODate('2026-03-01T10:20:00Z') } } },
  { $group: { _id: { host: '$meta.host', bucket: { $dateTrunc: { date: '$ts', unit: 'minute', binSize: 5 } } },
              avg: { $avg: '$value' }, peak: { $max: '$value' }, samples: { $sum: 1 } } },
  { $sort: { '_id.host': 1, '_id.bucket': 1 } },
  { $project: { _id: 0, host: '$_id.host', at: { $dateToString: { date: '$_id.bucket', format: '%H:%M' } },
                avg: { $round: ['$avg', 1] }, peak: 1, samples: 1 } }
]));

// 2  $densify fills the minutes web-2 never reported, so gaps are visible rather than silently skipped
show(db.metric_samples.aggregate([
  { $match: { 'meta.host': 'web-2', ts: { $gte: ISODate('2026-03-01T10:10:00Z'), $lt: ISODate('2026-03-01T10:19:00Z') } } },
  { $project: { _id: 0, ts: 1, value: 1 } },
  { $densify: { field: 'ts', range: { step: 1, unit: 'minute', bounds: 'full' } } },
  { $project: { at: { $dateToString: { date: '$ts', format: '%H:%M' } }, value: { $ifNull: ['$value', 'missing'] } } }
]));

Complexity

The $match on host and time range is what makes this cheap: a time-series collection stores samples in buckets per host and time, so a bounded range reads only the buckets it needs. Without the time bound, every dashboard refresh reads the whole history. Storage and retention are on Time-series collections and TTL indexes.

Follow-ups

"Bucket boundaries in a time zone?" $dateTrunc takes a timezone, which matters for daily buckets. "95th percentile, not the peak?" $percentile 7.0. "Weeks of data on one chart?" Query hourly rollups built by $merge, not raw samples, as in the monitoring case study.

Say it in the interview"$match a bounded time range first, then $group by the series and $dateTrunc of the timestamp, with the average, the maximum and a sample count. $densify if the chart must show gaps, and rollups via $merge for long ranges."
