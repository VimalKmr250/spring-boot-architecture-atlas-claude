Drill: "each customer's order count and spend", then "customers who never ordered", without a JOIN keyword

$lookup is MongoDB's left outer join: every input document comes out, with an array of the matching documents from the other collection, empty when nothing matches. Counting and summing that array answers the first question. An empty array is the anti-join, which answers the second. The third query answers it with no join at all: the customer ids found in orders, then the customers not in that list. Each of the three has a cost worth naming.

customers-orders.js · MongoDB 8.3, mongosh
// 1  each customer with order count and spend: $lookup from customers into orders
show(db.customers.aggregate([
  { $match: { _id: { $in: [1, 3, 8] } } },
  { $lookup: { from: 'orders', localField: '_id', foreignField: 'customer.id', as: 'orders' } },
  { $project: { _id: 0, name: 1, orders: { $size: '$orders' }, spent: { $sum: '$orders.total' } } }
]));

// 2  customers without any order: $lookup, then keep the empty arrays
show(db.customers.aggregate([
  { $lookup: { from: 'orders', localField: '_id', foreignField: 'customer.id', as: 'orders', pipeline: [{ $limit: 1 }] } },
  { $match: { orders: { $size: 0 } } },
  { $project: { _id: 1, name: 1 } }
]));

// 3  the same answer without a join: the ids that appear in orders, then the rest
const ordered = db.orders.distinct('customer.id');
show(db.customers.find({ _id: { $nin: ordered } }, { name: 1 }));

0 is not 0.00Hugo's spent is the integer 0: $sum over an empty array returns an int, while the others are Decimal128. Java code that maps spent to BigDecimal must accept both, or the pipeline should convert with $toDecimal.

Complexity

Each $lookup runs one query against orders per customer, so the index on customer.id from the seed is what keeps it fast; without it, every customer scans every order. The $limit: 1 in query 2 stops after the first match, because only "any?" matters. Query 3 is two round trips, and distinct must return its whole list in one 16 MB document.

Follow-ups

"Only paid orders?" Use $lookup with a pipeline that adds a $match on status. "Show the customer's name on each order?" It is already there: the order embeds customer.name, an extended reference, so no join is needed. "What if the name changes?" That is the trade-off of copying it, see Schema design patterns.

Say it in the interview"$lookup from customers into orders on customer.id, which needs an index there. Then $size and $sum over the joined array, or $match on $size: 0 for customers without orders. If this runs often, I'd keep a counter on the customer instead."
