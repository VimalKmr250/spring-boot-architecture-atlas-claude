Drill: "the five products with the most revenue", when the order lines live inside each order

In SQL this is a join of orders to order_items and a GROUP BY. In MongoDB the lines are already inside the order, so the pipeline filters orders, unwinds the items array into one document per line, groups by product, then sorts and limits. The product name is not stored in the line, so it comes from products with a $lookup. That lookup goes after the $limit, so it runs five times instead of once per line.

revenue-per-product.js · MongoDB 8.3, mongosh
// units and revenue per product from paid and shipped orders, with the current product name
show(db.orders.aggregate([
  { $match: { status: { $in: ['PAID', 'SHIPPED'] } } },
  { $unwind: '$items' },
  { $group: { _id: '$items.productId',
              units:   { $sum: '$items.qty' },
              revenue: { $sum: { $multiply: ['$items.qty', '$items.unitPrice'] } } } },
  { $sort: { revenue: -1 } },
  { $limit: 5 },
  { $lookup: { from: 'products', localField: '_id', foreignField: '_id', as: 'product',
               pipeline: [{ $project: { _id: 0, name: 1 } }] } },
  { $project: { _id: 0, productId: '$_id', name: { $first: '$product.name' }, units: 1, revenue: 1 } }
]));

Doubles for moneyThe prices are Decimal128, so $multiply and $sum stay exact and keep two decimal places. Stored as doubles, they would not: 0.1 + 0.2 is 0.30000000000000004 in a double, and such errors add up across thousands of lines and show in reports. Decimal128 is on Schema validation, Decimal128 and dates.

Follow-ups

"Revenue at today's price or the price paid?" The line's unitPrice is the price paid, a snapshot on purpose, as on Denormalising on purpose. "Products that never sold?" Start from products and $lookup into orders instead. "Very large collection?" Index status for the $match, or keep running totals with a $merge into a summary collection.

Say it in the interview"$match the orders that count, $unwind the lines, $group by product with $sum of quantity times price, $sort and $limit, and only then $lookup the names, so the join runs five times, not once per line."
