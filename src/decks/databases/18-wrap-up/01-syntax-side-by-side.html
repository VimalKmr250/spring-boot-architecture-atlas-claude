The same task in three dialects: one table to revise before an interview on an unfamiliar engine

Most interview SQL is standard and runs on both engines unchanged, as the drills show. The differences cluster in a few places: limiting rows, dates, string functions, generated keys, locking and plans. Every form below was run on Oracle 26ai, SQL Server 2025 or MongoDB 8.3 while this tab was written. A 23ai or 2022 tag marks the release that introduced it, so code for older versions needs the older form.

Version check firstSeveral rows changed recently: Oracle's IN-list limit is 65,535 on 26ai but 1,000 on 19c, and BOOLEAN, IF EXISTS and SELECT without FROM arrived in 23ai. Ask which version production runs before writing dialect-specific code. The traps that leak through JDBC are on Dialect traps.
