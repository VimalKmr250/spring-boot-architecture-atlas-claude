MongoDB indexes are B-trees like SQL ones, with extras for documents: array elements, partial sets, collations and expiry

Every collection has a unique index on _id. Further indexes are single-field or compound, ascending or descending, and the same reasoning applies as in SQL: selectivity, column order, covering. What is different comes from the document model. An index on a field inside an array is multikey: one entry per element. A partial index includes only documents matching a filter. A collation makes comparisons, uniqueness included, case-insensitive. A TTL option turns a date index into an expiry rule.

index-types.js · MongoDB 8.3, mongosh
// 1  multikey: an index on a field inside an array has one entry per element
db.orders.createIndex({ 'items.productId': 1 });
const mk = db.orders.find({ 'items.productId': 110 }).explain('executionStats');
print('items.productId = 110:', mk.executionStats.nReturned, 'orders |', stages(mk),
      '| multikey:', mk.queryPlanner.winningPlan.inputStage.isMultiKey);

// 2  partial: only FAILED orders are indexed, so only queries that include that condition can use it
db.big_orders.createIndex({ customerId: 1 }, { partialFilterExpression: { status: 'FAILED' }, name: 'failed_by_customer' });
print('with status FAILED:   ', stages(db.big_orders.find({ customerId: 4242, status: 'FAILED' }).explain()));
print('without the condition:', stages(db.big_orders.find({ customerId: 4242 }).explain()));

// 3  unique with a case-insensitive collation: 'ASHA@example.com' counts as a duplicate
db.customers.createIndex({ email: 1 }, { unique: true, name: 'email_ci', collation: { locale: 'en', strength: 2 } });
try { db.customers.insertOne({ _id: 11, name: 'Asha R', email: 'ASHA@example.com' }); }
catch (e) { print(e.message); }

// 4  sizes: what each index costs
show(db.big_orders.aggregate([{ $collStats: { storageStats: {} } },
  { $project: { _id: 0, indexSizesKB: { $arrayToObject: { $map: { input: { $objectToArray: '$storageStats.indexSizes' },
      in: { k: '$$this.k', v: { $round: [{ $divide: ['$$this.v', 1024] }, 0] } } } } } } }]));

db.orders.dropIndex({ 'items.productId': 1 });
db.big_orders.dropIndex('failed_by_customer');
db.customers.dropIndex('email_ci');

A partial index needs its conditionThe query for customer 4242 without status: 'FAILED' could not use failed_by_customer, because the index does not contain the customer's other orders, and fell back to a collection scan. The query's filter must imply the index's filter expression.
Size and write costThe partial index took 32 KB against 14,440 KB for the _id index on the same 500,000 orders. Every index adds work to every insert, and a multikey index adds one entry per array element. $indexStats on the next slide finds the ones nobody uses.
Say it in the interview"Compound indexes in ESR order for the main queries; a unique index, with a collation if case should not matter, for anything that must be unique; partial indexes for hot subsets; TTL for expiry. Indexing an array field makes the index multikey, one entry per element."
