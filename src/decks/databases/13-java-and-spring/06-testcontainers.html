An in-memory database cannot reproduce Oracle's empty string or SQL Server's collation; a throwaway container of the real engine can

Every trap in this tab is engine-specific: NULL handling, collations, parameter limits, locking, isolation. A test suite on H2 passes and production fails. Testcontainers starts a real database in Docker for the duration of a test class, with a random port, and removes it afterwards. The JUnit test below starts Oracle, SQL Server and MongoDB and checks one behaviour on each that an in-memory database would get wrong. With Spring Boot, @ServiceConnection on a container field also wires the application's DataSource or MongoClient to it automatically.

EngineBehaviourTest.java · JUnit 6.0.3, Testcontainers 2.0.5
import static org.junit.jupiter.api.Assertions.*;

import com.mongodb.client.MongoClients;
import com.mongodb.client.MongoCollection;
import com.mongodb.client.model.Filters;
import com.mongodb.client.model.Updates;
import java.sql.*;
import java.util.List;
import org.bson.Document;
import org.junit.jupiter.api.Test;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;
import org.testcontainers.mongodb.MongoDBContainer;
import org.testcontainers.mssqlserver.MSSQLServerContainer;
import org.testcontainers.oracle.OracleContainer;

/** Behaviour an in-memory database would get wrong, checked against the real engines in throwaway containers. */
@Testcontainers
class EngineBehaviourTest {
    @Container static final MongoDBContainer mongo = new MongoDBContainer("mongo:8");
    @Container static final MSSQLServerContainer mssql =
            new MSSQLServerContainer("mcr.microsoft.com/mssql/server:2025-latest")
                    .acceptLicense()
                    .withEnv("MSSQL_MEMORY_LIMIT_MB", "1536");
    @Container static final OracleContainer oracle = new OracleContainer("gvenzl/oracle-free:slim");

    @Test
    void conditionalIncrementNeverOversells() {
        try (var client = MongoClients.create(mongo.getConnectionString())) {
            MongoCollection<Document> stock = client.getDatabase("test").getCollection("stock");
            stock.insertOne(new Document("_id", "PHN-C2").append("onHand", 3).append("reserved", 0));
            long granted = 0;
            for (int i = 0; i < 5; i++) {
                granted += stock.updateOne(
                        Filters.and(Filters.eq("_id", "PHN-C2"),
                                    Filters.expr(new Document("$lt", List.of("$reserved", "$onHand")))),
                        Updates.inc("reserved", 1)).getModifiedCount();
            }
            assertEquals(3, granted);
        }
    }

    @Test
    void emailUniquenessIgnoresCaseOnSqlServer() throws SQLException {
        try (Connection c = DriverManager.getConnection(mssql.getJdbcUrl(), mssql.getUsername(), mssql.getPassword());
             Statement s = c.createStatement()) {
            s.execute("CREATE TABLE users (email VARCHAR(100) CONSTRAINT users_email_uk UNIQUE)");
            s.execute("INSERT INTO users VALUES ('kai@example.com')");
            SQLException e = assertThrows(SQLException.class, () -> s.execute("INSERT INTO users VALUES ('KAI@example.com')"));
            assertEquals(2627, e.getErrorCode());
        }
    }

    @Test
    void emptyStringIsNullOnOracle() throws SQLException {
        try (Connection c = DriverManager.getConnection(oracle.getJdbcUrl(), oracle.getUsername(), oracle.getPassword());
             Statement s = c.createStatement()) {
            s.execute("CREATE TABLE users (name VARCHAR2(50) NOT NULL)");
            try (PreparedStatement ps = c.prepareStatement("INSERT INTO users VALUES (?)")) {
                ps.setString(1, "");
                SQLException e = assertThrows(SQLException.class, ps::executeUpdate);
                assertEquals(1400, e.getErrorCode());              // ORA-01400: cannot insert NULL
            }
        }
    }
}

About a minute for three enginesOracle took about 42 seconds to start, SQL Server about 17 and MongoDB about 4; the whole run, with the tests, took 72 seconds. Share containers across test classes, for example with a static base class or Spring's context caching, and the start-up is paid once per build.
ResourcesThree databases at once need several gigabytes of memory in Docker. The SQL Server container is capped here with MSSQL_MEMORY_LIMIT_MB. In CI, run the engine-specific suites in separate jobs if memory is tight.
Say it in the interview"Repository and SQL tests run against the same engine and major version as production, in Testcontainers, so dialect traps fail in the build. Unit tests of business logic don't touch a database at all." The wider strategy is on Testing strategy.
