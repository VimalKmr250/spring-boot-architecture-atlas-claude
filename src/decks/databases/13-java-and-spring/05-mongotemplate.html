When a repository method name cannot say it, MongoTemplate can: atomic updates, pipelines and transactions in Java

Repositories cover simple finds and saves. MongoTemplate exposes the rest of MongoDB with typed builders. Query and Update express a conditional atomic update, so stock is reserved only if available, without loading the document. Aggregation.newAggregation(…) builds a pipeline whose results map onto a record. Registering a MongoTransactionManager makes Spring transactions, @Transactional or a TransactionTemplate, run as MongoDB multi-document transactions. Below, the same three jobs as earlier slides did in mongosh, now from a Spring Boot application.

TemplateApp.java · Spring Boot 4.1.1, Spring Data MongoDB 5.1.1
package shop;

import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;
import static org.springframework.data.mongodb.core.query.Criteria.where;

import java.math.BigDecimal;
import java.util.List;

import org.bson.types.Decimal128;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.WebApplicationType;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.builder.SpringApplicationBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.data.domain.Sort;
import org.springframework.data.mongodb.MongoDatabaseFactory;
import org.springframework.data.mongodb.MongoTransactionManager;
import org.springframework.data.mongodb.core.FindAndModifyOptions;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.query.Query;
import org.springframework.data.mongodb.core.query.Update;
import org.springframework.transaction.support.TransactionTemplate;
import org.bson.Document;

@SpringBootApplication
public class TemplateApp {

    record CustomerRevenue(int id, String name, int orders, BigDecimal revenue) {}

    public static void main(String[] args) {
        new SpringApplicationBuilder(TemplateApp.class)
            .web(WebApplicationType.NONE)
            .properties(
                "spring.mongodb.uri=mongodb://localhost:27017/shop?directConnection=true",
                "spring.main.banner-mode=off",
                "logging.pattern.console=%-5level %logger{0} - %msg%n",
                "logging.level.root=warn")
            .run(args)
            .close();
    }

    @Bean
    MongoTransactionManager transactionManager(MongoDatabaseFactory factory) {
        return new MongoTransactionManager(factory);                  // makes @Transactional work for MongoDB
    }

    @Bean
    CommandLineRunner demo(MongoTemplate mongo, MongoTransactionManager txManager) {
        return args -> {
            // 1  an update built with Query and Update: reserve one unit only if one is available
            Query available = Query.query(where("_id").is(109))
                    .addCriteria(where("$expr").is(new Document("$lt", List.of("$reserved", "$onHand"))));
            Document after = mongo.findAndModify(available, new Update().inc("reserved", 1),
                    FindAndModifyOptions.options().returnNew(true), Document.class, "inventory");
            System.out.println("1 reserved one grinder: " + after);

            // 2  an aggregation pipeline, mapped onto a record
            List<CustomerRevenue> top = mongo.aggregate(newAggregation(
                    match(where("status").in("PAID", "SHIPPED")),
                    group("customer.id").first("customer.name").as("name").count().as("orders").sum("total").as("revenue"),
                    sort(Sort.Direction.DESC, "revenue"),
                    limit(3),
                    project("name", "orders", "revenue").and("_id").as("id")),
                    "orders", CustomerRevenue.class).getMappedResults();
            top.forEach(r -> System.out.println("2 top customer: " + r));

            // 3  a transaction across two documents; an exception rolls both back
            Query wallets = new Query().addCriteria(where("_id").in(1, 2));
            System.out.println("3 before: " + mongo.find(wallets, Document.class, "accounts").stream()
                    .map(d -> d.get("_id") + "=" + d.get("balance")).toList());
            TransactionTemplate tx = new TransactionTemplate(txManager);
            try {
                tx.executeWithoutResult(status -> {
                    mongo.updateFirst(Query.query(where("_id").is(1)), new Update().inc("balance", new Decimal128(new BigDecimal("-100"))), "accounts");
                    mongo.updateFirst(Query.query(where("_id").is(2)), new Update().inc("balance", new Decimal128(new BigDecimal("100"))), "accounts");
                    throw new IllegalStateException("fraud check failed");
                });
            } catch (IllegalStateException e) {
                System.out.println("  rolled back: " + e.getMessage());
            }
            System.out.println("  after:  " + mongo.find(wallets, Document.class, "accounts").stream()
                    .map(d -> d.get("_id") + "=" + d.get("balance")).toList());

            mongo.updateFirst(Query.query(where("_id").is(109)), new Update().inc("reserved", -1), "inventory");
        };
    }
}

The rollback really happenedBoth updateFirst calls ran inside the transaction, then the callback threw. The balances after, 350.00 and 390.00, are the balances before: neither debit nor credit was committed. Without the transaction manager the two updates would have committed one by one, and the exception would have left money moved.
Transactions are opt-inSpring Boot does not register a MongoTransactionManager by default, so @Transactional on a MongoDB service silently does nothing until you add the bean, as here. Once added, it needs a replica set, and every transaction should be retried on TransientTransactionError.
Say it in the interview"Repositories for the simple cases, MongoTemplate for atomic updates with operators and for aggregations. I never load-modify-save a document that is edited concurrently: I send an Update with a condition, or use @Version." See Spring Data MongoDB repositories.
