A repository method name becomes a MongoDB filter; turn on the query log once and check it says what you meant

Spring Data MongoDB maps records to documents and derives queries from method names, the same way Spring Data JPA does. The things that go wrong are mapping details. A field named id is the document's _id, even inside an embedded object. A Page costs a second, counting query. A @Version field turns save into a conditional update. The program below runs against the running example's orders collection, with MongoTemplate's debug log switched on so each query is visible.

ShopMongoApp.java · Spring Boot 4.1.1, Spring Data MongoDB 5.1.1
package shop;

import java.math.BigDecimal;
import java.time.Instant;
import java.util.List;

import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.WebApplicationType;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.builder.SpringApplicationBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.dao.OptimisticLockingFailureException;
import org.springframework.data.annotation.Id;
import org.springframework.data.annotation.Version;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Pageable;
import org.springframework.data.domain.Sort;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.mapping.Document;
import org.springframework.data.mongodb.core.mapping.Field;
import org.springframework.data.mongodb.repository.MongoRepository;
import org.springframework.data.mongodb.repository.Query;
import org.springframework.data.mongodb.repository.config.EnableMongoRepositories;

@SpringBootApplication
@EnableMongoRepositories(considerNestedRepositories = true)
public class ShopMongoApp {

    @Document("orders")
    record Order(@Id int id, Customer customer, String status, Instant placedAt, List<Line> items, BigDecimal total) {}
    record Customer(@Field("id") int id, String name) {}     // without @Field, "id" maps to "_id"
    record Line(int productId, String sku, int qty, BigDecimal unitPrice) {}

    interface OrderRepository extends MongoRepository<Order, Integer> {
        List<Order> findByCustomerIdAndStatusOrderByPlacedAtDesc(int customerId, String status);

        @Query("{ 'items': { $elemMatch: { 'productId': ?0, 'qty': { $gte: ?1 } } } }")
        List<Order> withLine(int productId, int minQty);

        Page<Order> findByStatus(String status, Pageable page);
    }

    @Document("wallets")
    record Wallet(@Id String id, BigDecimal balance, @Version Long version) {
        Wallet withBalance(BigDecimal newBalance) { return new Wallet(id, newBalance, version); }
    }
    interface WalletRepository extends MongoRepository<Wallet, String> {}

    public static void main(String[] args) {
        new SpringApplicationBuilder(ShopMongoApp.class)
            .web(WebApplicationType.NONE)
            .properties(
                "spring.mongodb.uri=mongodb://localhost:27017/shop?directConnection=true",
                "spring.main.banner-mode=off",
                "logging.pattern.console=%-5level %logger{0} - %msg%n",
                "logging.level.root=warn",
                "logging.level.org.springframework.data.mongodb.core.MongoTemplate=debug")
            .run(args)
            .close();
    }

    @Bean
    CommandLineRunner demo(OrderRepository orders, WalletRepository wallets, MongoTemplate mongo) {
        return args -> {
            // 1  a derived query: the method name becomes the filter and the sort
            orders.findByCustomerIdAndStatusOrderByPlacedAtDesc(1, "PAID")
                  .forEach(o -> System.out.println("  paid by customer 1: " + o.id() + " " + o.total()));

            // 2  a hand-written query for what a method name cannot say
            orders.withLine(110, 2).forEach(o -> System.out.println("  2+ bags of beans: " + o.id()));

            // 3  paging: one query for the slice, and a count query for the total
            Page<Order> shipped = orders.findByStatus("SHIPPED", PageRequest.of(0, 3, Sort.by("placedAt")));
            System.out.println("  shipped page 1 of " + shipped.getTotalPages() + ": "
                    + shipped.map(Order::id).getContent() + " of " + shipped.getTotalElements());

            // 4  @Version: saving a stale copy fails instead of overwriting
            wallets.deleteAll();
            Wallet saved = wallets.save(new Wallet("asha", new BigDecimal("500.00"), null));
            Wallet copyA = wallets.findById("asha").orElseThrow(), copyB = wallets.findById("asha").orElseThrow();
            wallets.save(copyA.withBalance(copyA.balance().subtract(new BigDecimal("100"))));
            try {
                wallets.save(copyB.withBalance(copyB.balance().subtract(new BigDecimal("100"))));
            } catch (OptimisticLockingFailureException e) {
                System.out.println("  stale save rejected: " + e.getClass().getSimpleName());
            }
            System.out.println("  saved version " + saved.version() + ", now " + wallets.findById("asha").orElseThrow());

            // 5  how the BigDecimal balance was stored
            System.out.println("  stored as: " + mongo.getCollection("wallets").find().first().toJson());
        };
    }
}

In the logWhat it tells you
"customer.id" : 1findByCustomerId was resolved to the nested path, and the sort came from OrderByPlacedAtDesc.
Executing countPage runs a count on every request. Return Slice or List when the total is not shown.
"_id" : "asha", "version" : 0save on a versioned entity is an update conditioned on the version. Matching nothing raises OptimisticLockingFailureException.
"_class"Spring writes the Java type name into every document, for polymorphic reads. Other services reading the collection will see it.
The trap this program hit firstWithout @Field("id") on Customer.id, the first query was logged as { "customer._id" : 1, … } and found nothing. Reading the next result then failed with Parameter id must not be null. Spring Data treats any property named id as the identifier, embedded or not. Name it customerId, or map it explicitly as here.
Money survives the round tripThe last line shows the BigDecimal stored as $numberDecimal, which is BSON Decimal128, exact and sortable. A double field would have stored binary floating point; see Decimal128 and dates.
Say it in the interview"Derived queries are fine for simple filters; for $elemMatch, projections or aggregations I use @Query or MongoTemplate. I check the generated filter in the debug log or with explain, and I put @Version on documents that are edited concurrently."
