Window functions compute across related rows without collapsing them; the three ranking functions differ only on ties

A window function sees a window of rows related to the current one, defined by OVER (PARTITION BY … ORDER BY …), and returns one value per row; GROUP BY would return one row per group. The ranking functions number rows within each partition. ROW_NUMBER gives every row a distinct number, breaking ties arbitrarily. RANK gives tied rows the same number, then skips. DENSE_RANK gives tied rows the same number and does not skip. Ravi and Sara both earn 150,000, which is where the three disagree.

ranking.sql · runs unchanged on Oracle 26ai and SQL Server 2025
-- 1  three ways to number rows within each department, highest salary first
SELECT dept, name, salary,
       ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS row_num,
       RANK()       OVER (PARTITION BY dept ORDER BY salary DESC) AS rnk,
       DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS dense_rnk
FROM   employees
WHERE  dept IN ('Engineering', 'Payments')
ORDER  BY dept, salary DESC, name;

-- 2  a window function cannot go in WHERE: filter it one level up
SELECT dept, name, salary
FROM  (SELECT dept, name, salary,
              DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS dense_rnk
       FROM   employees) ranked
WHERE  dense_rnk <= 2
ORDER  BY dept, salary DESC, name;

QuestionUseBecause
Exactly one row per group: the latest payment per orderROW_NUMBER() … = 1Ties must not produce two rows. Add a unique tie-breaker to the ORDER BY so the choice is repeatable
Top 3 salaries per department, ties includedDENSE_RANK() <= 3Three distinct salary levels, however many people share them
Competition ranking: 1, 2, 2, 4RANK()The position after a tie reflects how many rows came before
Remove duplicates, keep oneROW_NUMBER() OVER (PARTITION BY the duplicate key …) > 1Numbers each copy; delete all but number 1. See the duplicates drill
Non-deterministic ROW_NUMBERRavi and Sara got row numbers 3 and 4 because the outer ORDER BY sorted by name; inside the window, the order between them is arbitrary. A query that keeps "row 1" with a tie in the window's ORDER BY can return a different row tomorrow. Always end the window's sort with a unique column.
Filtering on a windowWindow functions run at the SELECT step, after WHERE, so WHERE dense_rnk <= 2 is not allowed in the same query level. Wrap it in a subquery or CTE, as query 2 does. Oracle 26ai also accepts QUALIFY ROW_NUMBER() OVER (…) = 1, a clause that filters on a window function directly; SQL Server 2025 rejects it, and so do older Oracle releases.
Say it in the interview"Top N per group is a ranking window partitioned by the group, filtered in an outer query. I pick DENSE_RANK when ties should share a place and ROW_NUMBER when I need exactly N rows." It is the most common SQL coding question: see Top N per group.
