LAG and LEAD compare a row with its neighbour, which turns "find the outage" and "find the hot streak" into one pass

LAG(col) returns col from the previous row in the window's order, and LEAD(col) from the next. Comparing neighbours answers questions that are otherwise self-joins: the time between payment retries, the minutes a host stayed silent. A gap is where the next row is further away than expected. An island is a run of consecutive rows that meet a condition, such as minutes above 90% CPU. The trick for islands: within a run, timestamp minus row number is constant, so it can be grouped on.

gaps-islands.ora.sql · Oracle 26ai
-- 1  LAG: seconds since the previous payment attempt on the same order
SELECT order_id, payment_id, status,
       ROUND((CAST(created_at AS DATE)
            - CAST(LAG(created_at) OVER (PARTITION BY order_id ORDER BY created_at) AS DATE)) * 86400) AS secs_since_prev
FROM   payments
WHERE  order_id IN (1003, 1005, 1011)
ORDER  BY order_id, created_at;

-- 2  gaps: a host whose next sample arrives more than a minute later went silent
SELECT host, ts AS last_seen, next_ts AS back_at,
       ROUND((CAST(next_ts AS DATE) - CAST(ts AS DATE)) * 1440) - 1 AS missing_minutes
FROM  (SELECT host, ts, LEAD(ts) OVER (PARTITION BY host ORDER BY ts) AS next_ts
       FROM   metric_samples
       WHERE  metric = 'cpu')
WHERE  next_ts > ts + INTERVAL '1' MINUTE;

-- 3  islands: consecutive hot minutes; ts minus the row number is constant within a run
SELECT host, MIN(ts) AS started, MAX(ts) AS ended, COUNT(*) AS minutes, MAX(value) AS peak
FROM  (SELECT host, ts, value,
              ts - NUMTODSINTERVAL(ROW_NUMBER() OVER (PARTITION BY host ORDER BY ts), 'MINUTE') AS run_key
       FROM   metric_samples
       WHERE  metric = 'cpu' AND value > 90)
GROUP  BY host, run_key
ORDER  BY host, started;

SQL Server 2025 agreesgaps-islands.mss.sql uses DATEDIFF and DATEADD instead of date subtraction and NUMTODSINTERVAL, and prints the same rows.
How the island key worksThe hot minutes of db-1 are 08, 09, …, 13, then 21, …, 24. Number them 1, 2, 3 … and subtract: 08 − 1 = 07, 09 − 2 = 07, …, 13 − 6 = 07, then 21 − 7 = 14 and so on. Each run has its own constant, so GROUP BY run_key collapses each run into one row with its start, end and length.
The first row has no neighbourLAG returns NULL on the first row of each partition: the first attempt of each order above. Supply a default with LAG(col, 1, default) when NULL would break the arithmetic. And partition by the entity: without PARTITION BY host, the last sample of one host would be compared with the first of the next.
Say it in the interview"Gaps: LEAD the timestamp and keep rows where the difference exceeds the interval. Islands: subtract a ROW_NUMBER from the sequence value and group by the result." The drill applies it to consecutive failed payments.
