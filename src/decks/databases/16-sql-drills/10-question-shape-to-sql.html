Read the question for its shape, and the SQL construct follows

Interview SQL questions are a few shapes with different table names. Recognise the shape from the wording and the first line of the answer is decided. The third column holds the edge case the interviewer is waiting for. This is the table to revise from the night before.

If the question saysReach forWatch out for
"…the Nth highest / second largest"DENSE_RANK() = N in an outer query, or DISTINCT … OFFSET N-1 FETCH 1Ties; no Nth value should give NULL, not no row
"…the top N in each group"ROW_NUMBER() OVER (PARTITION BY …), then rn <= N; CROSS APPLY per outer rowA tie-breaker in the ORDER BY; ranking before filtering
"…that have no / never"NOT EXISTSNOT IN over a nullable column returns nothing
"…all of their X are Y"EXISTS plus NOT EXISTS with the opposite condition, or HAVING SUM(CASE …) = 0Entities with no X at all pass a bare NOT EXISTS
"…duplicates"GROUP BY the normalised key HAVING COUNT(*) > 1; delete ROW_NUMBER() > 1Case and spaces in the key; add a unique index afterwards
"…per X, including X with none"Start from X, LEFT JOIN, COUNT(child.id)COUNT(*) counts the NULL row as 1; filters in WHERE undo the outer join
"…running total / cumulative"SUM(…) OVER (ORDER BY … ROWS UNBOUNDED PRECEDING)The default RANGE frame on duplicate sort values
"…compared with the previous / growth"LAG after aggregating to one row per periodMissing periods; division by zero (NULLIF)
"…consecutive / in a row / streak"Two ROW_NUMBERs and group by their differenceNon-deterministic order when timestamps tie
"…gaps / missing / silent for"LEAD the timestamp, keep differences above the interval; or a calendar and an anti-joinPartition by the entity, or hosts bleed into each other
"…manager / parent / hierarchy / all levels"Self-join for one level; recursive CTE for any depthCycles; SQL Server's 100-level default; anchor and member types
"…one column per month / status"Conditional aggregation; PIVOTZero or NULL for empty cells; columns fixed at parse time
"…latest row per X"ROW_NUMBER() … ORDER BY ts DESC = 1; Oracle's KEEP (DENSE_RANK LAST …)MAX(ts) joined back returns two rows on a tie
"…page through / next 20"Keyset: ts < :ts OR (ts = :ts AND id < :id) with an index on (ts, id)OFFSET reads and discards every skipped row. Oracle 26ai also accepts (ts, id) < (:ts, :id); SQL Server rejects it (error 4145)
"…insert or update"MERGE, or UPDATE then INSERT, under a unique constraintTwo sessions both see "not found"; catch the duplicate and retry
"…between two dates"Half-open: >= start AND < next_startBETWEEN on a timestamp loses the last day; functions on the column
Where each one is explainedThe constructs come from ranking, window frames, anti-joins, upserts and keyset pagination; the traps in the third column are on NULL and three-valued logic and Dates and times in queries.
