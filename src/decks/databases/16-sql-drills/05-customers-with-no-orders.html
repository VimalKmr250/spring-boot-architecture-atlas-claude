Drill: "customers who never ordered", then "whose orders were all cancelled", then "who did not order this month"

The first question is a plain anti-join, and the answer to give is NOT EXISTS, for the NULL reasons on EXISTS, IN, anti-joins and set operators. Interviewers then vary it. "Every order cancelled" is an EXISTS combined with a NOT EXISTS: at least one order, and no order that is not cancelled. "Nothing this month, and when did they last order" adds a date-bounded anti-join to an outer join that keeps the customers with no orders at all.

no-orders.ora.sql · Oracle 26ai (no-orders.mss.sql differs only in the date literals)
-- 1  customers who have never ordered: the anti-join
SELECT c.customer_id, c.name
FROM   customers c
WHERE  NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id)
ORDER  BY c.customer_id;

-- 2  customers who ordered, but whose every order was cancelled
SELECT c.customer_id, c.name
FROM   customers c
WHERE  EXISTS     (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id)
AND    NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id AND o.status <> 'CANCELLED')
ORDER  BY c.customer_id;

-- 3  customers with no order in March 2026, and when they last ordered at all
SELECT c.customer_id, c.name, MAX(o.placed_at) AS last_order
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id
WHERE  NOT EXISTS (SELECT 1 FROM orders m
                   WHERE m.customer_id = c.customer_id
                   AND   m.placed_at >= TIMESTAMP '2026-03-01 00:00:00'
                   AND   m.placed_at <  TIMESTAMP '2026-04-01 00:00:00')
GROUP  BY c.customer_id, c.name
ORDER  BY c.customer_id;

SQL Server 2025 agreesno-orders.mss.sql returns the same rows. Its first draft used CAST(… AS TIMESTAMP) and failed with error 206: in SQL Server, TIMESTAMP is the old name of ROWVERSION, a row-version counter, not a date type.

Complexity

An anti-join is one hash or merge pass over both tables, or a seek per customer with an index on orders.customer_id. Query 3's LEFT JOIN with MAX keeps customers with no orders (last order NULL) instead of dropping them.

Follow-ups

"Why not NOT IN?" A NULL in the subquery returns nothing. "Why not LEFT JOIN … IS NULL?" It is fine on SQL Server, and stays an outer join on Oracle. "All orders cancelled, in one pass?" GROUP BY customer with HAVING SUM(CASE WHEN status <> 'CANCELLED' THEN 1 ELSE 0 END) = 0.

Say it in the interview"Anti-join with NOT EXISTS. For 'only cancelled', EXISTS plus NOT EXISTS with the opposite condition, which is the shape of every 'all X are Y' question. And I check the time boundary: half-open, start of month inclusive, start of next month exclusive."
