Drill: "find the third highest salary", and the follow-ups about ties, missing values and departments

The most asked SQL question of all. Clarify first. "Third highest" usually means the third distinct salary: two people on 150,000 are one value. And the answer for a company with only two salaries should be NULL, not an error. Three standard answers follow, all returning 180,000. Window functions are the modern answer, OFFSET is the shortest, and the correlated subquery works on any SQL engine ever made.

nth-salary.sql · runs unchanged on Oracle 26ai and SQL Server 2025
-- the 3rd highest distinct salary, three ways (salaries can tie: 150,000 and 140,000 appear twice)

-- 1  DENSE_RANK: ties share a rank and leave no gaps, so rank 3 is the 3rd distinct value
SELECT DISTINCT salary AS third_highest
FROM  (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk FROM employees) ranked
WHERE  rnk = 3;

-- 2  skip the two highest distinct values, take the next
SELECT DISTINCT salary AS third_highest
FROM   employees
ORDER  BY salary DESC
OFFSET 2 ROWS FETCH NEXT 1 ROW ONLY;

-- 3  correlated subquery: exactly two distinct salaries are higher (works on any SQL engine)
SELECT DISTINCT e.salary AS third_highest
FROM   employees e
WHERE  2 = (SELECT COUNT(DISTINCT x.salary) FROM employees x WHERE x.salary > e.salary);

-- follow-up: return NULL rather than no row when there is no Nth value (N = 20)
SELECT (SELECT DISTINCT salary FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk FROM employees) r
        WHERE rnk = 20) AS twentieth_highest;

-- follow-up: the 2nd highest salary in each department
SELECT dept, salary AS second_highest
FROM  (SELECT dept, salary, DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rnk FROM employees) r
WHERE  rnk = 2
GROUP  BY dept, salary
ORDER  BY dept;

Complexity

O(n log n) for the sort, or a walk down an index on salary that stops after N distinct values. The correlated version is O(n²) without an index.

Follow-ups

"What if N is larger than the number of salaries?" Wrap it in a scalar subquery so it returns NULL, as the 20th does above. "Per department?" Add PARTITION BY dept. "And the people earning it?" Select the rows instead of DISTINCT salary.

Say it in the interview"I'd use DENSE_RANK so tied salaries count once, filter it in an outer query, and wrap the result to return NULL when there is no Nth value." Java's version of the same question is Streams · Employees: ranking.
