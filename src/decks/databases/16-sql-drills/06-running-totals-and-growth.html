Drill: "monthly revenue with growth against the previous month and a year-to-date total", in one query

Aggregate to one row per month in a CTE, then let window functions look across months. LAG(revenue) is the previous month's value. Growth is (this − previous) / previous, NULL for the first month. A running total is SUM over an explicit ROWS UNBOUNDED PRECEDING frame. Engines differ only in how they truncate to a month: TRUNC(…, 'MM') on Oracle, DATETRUNC(MONTH, …) on SQL Server 2022 and later.

growth.ora.sql · Oracle 26ai
-- monthly revenue, month-over-month growth, and the running total for the year
WITH monthly AS (
  SELECT TRUNC(placed_at, 'MM') AS month_start, SUM(total) AS revenue
  FROM   orders
  WHERE  status IN ('PAID', 'SHIPPED')
  GROUP  BY TRUNC(placed_at, 'MM')
)
SELECT TO_CHAR(month_start, 'YYYY-MM')                                       AS month,
       revenue,
       LAG(revenue) OVER (ORDER BY month_start)                               AS prev_month,
       ROUND(100 * (revenue - LAG(revenue) OVER (ORDER BY month_start))
                 / LAG(revenue) OVER (ORDER BY month_start), 1)               AS growth_pct,
       SUM(revenue) OVER (ORDER BY month_start ROWS UNBOUNDED PRECEDING)     AS running_total
FROM   monthly
ORDER  BY month_start;

growth.mss.sql · SQL Server 2025
-- monthly revenue, month-over-month growth, and the running total for the year
WITH monthly AS (
  SELECT DATETRUNC(MONTH, placed_at) AS month_start, SUM(total) AS revenue
  FROM   orders
  WHERE  status IN ('PAID', 'SHIPPED')
  GROUP  BY DATETRUNC(MONTH, placed_at)
)
SELECT FORMAT(month_start, 'yyyy-MM')                                        AS month,
       revenue,
       LAG(revenue) OVER (ORDER BY month_start)                               AS prev_month,
       CAST(100 * (revenue - LAG(revenue) OVER (ORDER BY month_start))
                / LAG(revenue) OVER (ORDER BY month_start) AS DECIMAL(6,1))   AS growth_pct,
       SUM(revenue) OVER (ORDER BY month_start ROWS UNBOUNDED PRECEDING)     AS running_total
FROM   monthly
ORDER  BY month_start;

Complexity

One scan of the orders to aggregate, then a sort of a few month rows for the windows. On a large table, an index on (status, placed_at) that includes total feeds the aggregation without touching the table.

Follow-ups

"A month with no orders?" It is missing here; generate a calendar and left-join, as on Dates and times, or LAG compares with the wrong month. "Previous month was zero?" Wrap the divisor in NULLIF(…, 0). "Per category?" Add PARTITION BY category to every window.

Say it in the interview"Aggregate first, then window: LAG for the previous period, SUM … ROWS UNBOUNDED PRECEDING for the running total, and a calendar so missing periods are zero rather than skipped. I guard the division with NULLIF."
