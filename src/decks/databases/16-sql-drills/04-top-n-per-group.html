Drill: "the two best-selling products in each category", the question every analytics interview asks in some form

The pattern: compute the measure per item, number the items within each group with a window function, keep the first N in an outer query. The interesting work here is the grouping key. Products sit at different depths of the category tree, so COALESCE over two parent joins climbs to the top-level category. The second query shows the other classic form, CROSS APPLY: for each customer, run a small "top 2 orders" query. Both engines support it.

top-n.sql · runs unchanged on Oracle 26ai and SQL Server 2025
-- the two best-selling products (by revenue) in each top-level category
WITH product_revenue AS (
  SELECT top_cat.name AS category, p.sku, SUM(i.qty * i.unit_price) AS revenue
  FROM   order_items i
  JOIN   orders o       ON o.order_id = i.order_id AND o.status IN ('PAID', 'SHIPPED')
  JOIN   products p     ON p.product_id = i.product_id
  JOIN   categories c   ON c.category_id = p.category_id
  LEFT   JOIN categories mid ON mid.category_id = c.parent_id
  JOIN   categories top_cat  ON top_cat.category_id = COALESCE(mid.parent_id, c.parent_id, c.category_id)
  GROUP  BY top_cat.name, p.sku
)
SELECT category, sku, revenue, rn
FROM  (SELECT category, sku, revenue,
              ROW_NUMBER() OVER (PARTITION BY category ORDER BY revenue DESC, sku) AS rn
       FROM   product_revenue) ranked
WHERE  rn <= 2
ORDER  BY category, rn;

-- the same question per customer with CROSS APPLY: "for each customer, their two largest orders"
SELECT c.name, t.order_id, t.total
FROM   customers c
CROSS  APPLY (SELECT o.order_id, o.total FROM orders o
              WHERE  o.customer_id = c.customer_id
              ORDER  BY o.total DESC
              OFFSET 0 ROWS FETCH NEXT 2 ROWS ONLY) t
WHERE  c.customer_id IN (1, 3)
ORDER  BY c.name, t.total DESC;

VariantUse
Exactly N, ties brokenROW_NUMBER with a tie-breaker (here sku)
Top N values, ties includedDENSE_RANK
Per row of another table, with an indexCROSS APPLY (… OFFSET 0 ROWS FETCH NEXT 2 ROWS ONLY): a seek per customer
Just the maximum per groupGROUP BY with MAX, or Oracle's KEEP (DENSE_RANK FIRST …)

Complexity

The window version sorts all rows once by group and measure: O(n log n). CROSS APPLY runs one small query per outer row, so it wins with few outer rows and an index on (customer_id, total), and loses badly without one.

Follow-ups

"Ties for second place?" Switch to DENSE_RANK and say how many rows that can return. "Include categories with no sales?" Start from categories with a LEFT JOIN. "Only this month?" Filter before ranking, not after.

Say it in the interview"ROW_NUMBER() OVER (PARTITION BY group ORDER BY measure DESC) in a CTE, then WHERE rn <= N. If I need it per row of another table with a good index, CROSS APPLY with OFFSET 0 ROWS FETCH NEXT N ROWS ONLY, which both engines accept." The window functions are on ROW_NUMBER, RANK and DENSE_RANK.
