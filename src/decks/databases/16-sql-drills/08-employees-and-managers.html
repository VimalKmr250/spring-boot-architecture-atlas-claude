Drill: "employees who earn more than their manager", then "print the org chart", then "how many people report to each manager"

One table, employees(emp_id, name, salary, manager_id), and three questions of rising difficulty. The first needs a self-join: the same table twice under two aliases, one row for the employee and one for the manager. The second and third need the hierarchy, so a recursive CTE walks it from the root, one level per iteration. The third has a twist: it starts every walk at a manager–employee pair and carries the manager down, so each person is counted once under every manager above them.

org-chart.ora.sql · Oracle 26ai
-- 1  self-join: employees who earn more than their manager
SELECT e.name AS employee, e.salary, m.name AS manager, m.salary AS manager_salary
FROM   employees e
JOIN   employees m ON m.emp_id = e.manager_id
WHERE  e.salary > m.salary
ORDER  BY e.name;

-- 2  recursive CTE: the whole chart, with each person's level and chain of command
WITH chart (emp_id, name, lvl, chain) AS (
  SELECT emp_id, name, 1, CAST(name AS VARCHAR2(200)) FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.emp_id, e.name, c.lvl + 1, c.chain || ' > ' || e.name
  FROM   employees e JOIN chart c ON e.manager_id = c.emp_id
)
SELECT LPAD(' ', 2 * (lvl - 1)) || name AS org_chart, lvl FROM chart ORDER BY chain;

-- 3  head count under each manager, direct and indirect
WITH reports (manager_id, emp_id) AS (
  SELECT manager_id, emp_id FROM employees WHERE manager_id IS NOT NULL
  UNION ALL
  SELECT r.manager_id, e.emp_id FROM reports r JOIN employees e ON e.manager_id = r.emp_id
)
SELECT m.name AS manager, COUNT(*) AS total_reports
FROM   reports r JOIN employees m ON m.emp_id = r.manager_id
GROUP  BY m.name ORDER BY total_reports DESC, m.name;

Complexity

The self-join is one lookup per employee by primary key. Each recursive iteration joins one level to employees, so an index on manager_id matters. Query 3 produces one row per manager–descendant pair: 20 here, and up to n² for a deep, narrow tree.

Follow-ups

"Who has no manager?" manager_id IS NULL. "Managers with no reports?" An anti-join. "Sort siblings by salary?" Ordering by the name path only works while names sort the way you want; build the path from zero-padded sort keys instead. "A bad row makes a cycle?" See CTEs and recursive queries.

Say it in the interview"Self-join for one level up. A recursive CTE for anything deeper: the anchor is the root, the recursive member joins children to the previous level, and I carry a level and a path. To count everyone under a manager, I anchor on every manager–report pair and carry the manager down."
