Drill: "one row per category, one column per month": turn rows into columns, then explain why the columns must be known in advance

There are two ways to answer, and the interviewer wants to hear both. Conditional aggregation, a SUM(CASE …) per column, works on every engine, can mix measures, and is what most production code uses. PIVOT is shorter, and Oracle and SQL Server both have it with slightly different syntax. Either way, the list of columns is fixed when the query is written. A pivot whose columns depend on the data ("one column per month, however many there are") needs dynamic SQL, or is better done in the application.

pivot.ora.sql · Oracle 26ai
-- revenue by top-level category and month, one column per month
WITH lines AS (
  SELECT top_cat.name AS category, TO_CHAR(o.placed_at, 'MM') AS mon, i.qty * i.unit_price AS amount
  FROM   order_items i
  JOIN   orders o     ON o.order_id = i.order_id AND o.status IN ('PAID', 'SHIPPED')
  JOIN   products p   ON p.product_id = i.product_id
  JOIN   categories c ON c.category_id = p.category_id
  LEFT   JOIN categories mid ON mid.category_id = c.parent_id
  JOIN   categories top_cat  ON top_cat.category_id = COALESCE(mid.parent_id, c.parent_id, c.category_id)
)
-- 1  conditional aggregation: portable, and easy to extend
SELECT category,
       SUM(CASE WHEN mon = '01' THEN amount ELSE 0 END) AS jan,
       SUM(CASE WHEN mon = '02' THEN amount ELSE 0 END) AS feb,
       SUM(CASE WHEN mon = '03' THEN amount ELSE 0 END) AS mar
FROM   lines GROUP BY category ORDER BY category;

-- 2  the same with PIVOT
WITH lines AS (
  SELECT top_cat.name AS category, TO_CHAR(o.placed_at, 'MM') AS mon, i.qty * i.unit_price AS amount
  FROM   order_items i
  JOIN   orders o     ON o.order_id = i.order_id AND o.status IN ('PAID', 'SHIPPED')
  JOIN   products p   ON p.product_id = i.product_id
  JOIN   categories c ON c.category_id = p.category_id
  LEFT   JOIN categories mid ON mid.category_id = c.parent_id
  JOIN   categories top_cat  ON top_cat.category_id = COALESCE(mid.parent_id, c.parent_id, c.category_id)
)
SELECT * FROM lines
PIVOT (SUM(amount) FOR mon IN ('01' AS jan, '02' AS feb, '03' AS mar))
ORDER  BY category;

pivot.mss.sql · SQL Server 2025
-- revenue by top-level category and month, one column per month
WITH lines AS (
  SELECT top_cat.name AS category, FORMAT(o.placed_at, 'MM') AS mon, i.qty * i.unit_price AS amount
  FROM   order_items i
  JOIN   orders o     ON o.order_id = i.order_id AND o.status IN ('PAID', 'SHIPPED')
  JOIN   products p   ON p.product_id = i.product_id
  JOIN   categories c ON c.category_id = p.category_id
  LEFT   JOIN categories mid ON mid.category_id = c.parent_id
  JOIN   categories top_cat  ON top_cat.category_id = COALESCE(mid.parent_id, c.parent_id, c.category_id)
)
SELECT category, [01] AS jan, [02] AS feb, [03] AS mar
FROM   lines
PIVOT (SUM(amount) FOR mon IN ([01], [02], [03])) AS p
ORDER  BY category;

Engine differences

Oracle names the pivoted columns with '01' AS jan and also has PIVOT XML for a data-driven column list. SQL Server names them [01] and requires an alias on the pivot. FORMAT() is convenient but slow on large sets in SQL Server; MONTH(placed_at) or DATETRUNC is cheaper.

Follow-ups

"Add a total column?" One more SUM(amount) in the conditional version; with PIVOT, add the month columns together in the outer SELECT. "Two measures per month?" Oracle's PIVOT takes several aggregates, SQL Server's takes one, and conditional aggregation handles any number. "Columns to rows?" UNPIVOT, or CROSS APPLY (VALUES …) on SQL Server. "Months from the data?" Build the column list in code and say why that is dynamic SQL.

Say it in the interview"GROUP BY the row key, and one SUM(CASE WHEN month = … THEN amount END) per column. PIVOT is the shorthand. The columns are fixed at parse time, so for a variable set I'd return rows and pivot in the report layer."
