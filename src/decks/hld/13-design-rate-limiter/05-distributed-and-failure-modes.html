Deep dive 2: trade accuracy against dependency, and decide how to fail

A shared counter is exact but puts a network hop and a dependency in front of every request. Local counters are free but inaccurate. Real systems pick a point between the two, and then state what happens when Redis, or a whole region, is unreachable.

Multi-region

A synchronous cross-region check on every request would add 60–150 ms, which is unacceptable. Give each region its own counters and a share of the global budget, e.g. split by that region's traffic share, and rebalance the shares every few seconds from an aggregated view. Global limits become approximately right, which is almost always fine.

Say the default

"Central Redis counter with an atomic Lua token bucket, since 0.5 ms is affordable. A 5 ms timeout with a circuit breaker around it. Fail open to a local limiter for protective rules and fail closed for login and OTP. Per-region counters with budget shares. Token leasing only if Redis load or latency becomes a problem."
