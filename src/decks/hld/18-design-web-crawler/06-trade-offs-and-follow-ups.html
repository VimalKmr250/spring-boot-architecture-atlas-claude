Partition by host so politeness stays local, and recrawl each page on its own clock

To scale out, give every host to exactly one crawler node. Its frontier, politeness timers, robots cache and DNS cache then need no coordination. Then spend the fetch budget where change actually happens: a news front page changes hourly, an archived page almost never.

JavaScript-heavy sitesA separate pool of headless browsers for pages whose HTML is an empty shell; it costs 10–100× per page, so detect first and render selectively.
Freshness vs coverageSplit the fetch budget explicitly: a share for recrawls ranked by expected change × importance, and the rest for discovery.
GeographyRun crawler nodes in several regions and assign hosts to the closest one to cut latency and cross-ocean bandwidth.
Hostile contentSize and time limits, parsing in a sandbox, and never executing downloaded code outside the render sandbox.
Summarise"A per-node crawl loop in which the frontier separates priority from per-host politeness, a Bloom filter answers 'URL seen?', fingerprints answer 'content seen?', and budgets defuse traps. Hosts are partitioned across nodes by consistent hashing, pages are appended to WARC files in object storage, and a Kafka stream feeds everything downstream."
