Deep dive 2: don't fetch it twice, don't store it twice, don't fall into a hole

Most discovered links are duplicates, and a large share of fetched pages are copies of other pages. A few sites generate infinitely many URLs, some deliberately. Three cheap structures handle it: a Bloom filter for URLs, fingerprints for content, and hard budgets for traps.

robots.txt, properly

Fetch /robots.txt before a host's first page and cache it for about 24 hours. Obey Disallow and Crawl-delay for your user agent. Under RFC 9309, a 4xx means no restrictions, but a 5xx or unreachable file means assume everything is disallowed until you can read it. Identify yourself with a user agent that includes a contact URL.

Bloom filter trade-offs

A false positive means you skip a new URL, and at 1% that's acceptable for a crawler. A false negative is impossible. Standard Bloom filters can't delete, so rebuild per crawl cycle or use a counting or cuckoo filter. Shard the filter by URL hash across nodes, the same way as url_state.

Where each check sits

The URL check comes before fetching, saves bandwidth, and runs at about 20 k lookups/s. The content check comes after fetching and saves storage and index quality. Trap rules run in the URL filter, cheaply, before a URL ever reaches the frontier.
