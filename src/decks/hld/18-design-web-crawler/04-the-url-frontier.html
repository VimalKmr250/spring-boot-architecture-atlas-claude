Deep dive 1: front queues decide what matters, back queues decide when a host may be hit

A plain FIFO queue fails twice. It crawls unimportant pages as eagerly as important ones, and because pages link mostly within their own site, it fires bursts of requests at a single host. The classic fix, from the Mercator crawler, splits the frontier into two layers: priority in front and politeness behind.

Priority

Score each URL by link-based importance (PageRank from the link graph), domain quality, depth from a seed, and for recrawls how likely the page is to have changed. A biased selector pulls from F1 most often but never starves F3, so low-priority URLs still get crawled eventually.

Politeness

One back queue per host plus a ready-time heap enforces a gap between hits. The adaptive gap, ten times the last response time, backs off automatically when a server slows down. A robots.txt Crawl-delay overrides it when larger, and 429 or 503 responses double the gap.

It doesn't fit in memory

Billions of queued URLs live on disk: append-only files or a KV store per queue, with only the heads buffered in RAM. Reads and writes are sequential at each end, so disk is fast enough. The frontier is also checkpointed so a node can restart without losing its place.
