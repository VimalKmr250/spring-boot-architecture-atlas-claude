Defence in depth: every layer assumes the one in front of it failed

Security in an HLD answer is a set of layers, each stopping a different class of attack. Volumetric floods stop at the edge, malicious payloads at the WAF, and unauthenticated calls at the gateway. Unauthorised access to someone else's data is stopped in the service, and a stolen disk is useless because the data is encrypted. Naming each layer and what it blocks is what interviewers are looking for.

Secrets

No secrets in code, images or environment files in git. Use a secrets manager (Vault, a cloud secrets manager) with short-lived, automatically rotated credentials, and workload identity instead of static keys wherever the platform supports it.

Zero trust inside

A request from inside the network is not trusted for that reason alone. Every service authenticates its callers (mTLS), authorises each call, and logs it. Segment the network so that a compromised pod can't reach the database of another domain.

Privacy by design

Collect less. Keep PII in a few well-guarded stores and pass references or tokens elsewhere. Encrypt sensitive fields at the application level. Build deletion (GDPR erasure) into the design from the start, including caches, search indexes, logs and backups.
