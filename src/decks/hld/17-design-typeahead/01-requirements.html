Design search autocomplete: a million prefix lookups a second, each answered in milliseconds

As the user types "how to b", show the eight most popular completions. It has to feel instant, so suggestions must arrive before the next keystroke, and it's called on nearly every keystroke. That makes this a read-latency problem, solved by precomputing answers offline and serving them from memory.

Functional

  • Given a prefix, return the top 8 completions by popularity.
  • Reflect trending queries within about an hour.
  • Filter offensive or legally blocked suggestions.

Non-functional

  • Server p99 < 20 ms; highly available. If it fails, the search box still works, just without suggestions.
  • Eventual consistency is fine: suggestions may be hours old.
  • Heavily read-dominated: suggestions are rebuilt offline.

Clarify

  • Personalised or global? Global first, with a personal blend as a follow-up.
  • Prefix only, or typo-tolerant? Prefix only; fuzzy is a follow-up.
  • One language to start (lowercased, normalised).
