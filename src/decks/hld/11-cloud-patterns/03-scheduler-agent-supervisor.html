Make multi-step work finish, or undo it, even when steps fail silently

Distributed workflows fail in awkward ways: a step times out, a remote service accepts a request and never answers, a worker dies mid-step. Scheduler Agent Supervisor gives such a workflow a durable memory and a watchdog. Compensating transaction gives each completed step an undo, so a workflow that can't finish can leave the system consistent.

Make every step idempotent

The supervisor will retry steps whose outcome is unknown, so "book hotel" might run twice. Pass a stable request id per step, so the remote service (or your agent) recognises a repeat.

Deadlines, not just failures

The dangerous case is the step that never answers. Record a deadline for each step. When the supervisor finds it expired, it queries the remote system for the real status before deciding to retry or compensate.

Buy it rather than build it

This is what workflow engines implement: Temporal, AWS Step Functions, Azure Durable Functions, Camunda. They give you durable state, timers, retries and compensation handlers as code. Build your own only if the workflow is trivial.
