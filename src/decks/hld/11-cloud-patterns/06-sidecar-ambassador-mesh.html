Move cross-cutting plumbing out of the app and into a helper beside it

Every service needs the same plumbing: TLS, retries, metrics, log shipping, config reload. Rebuilding that in every language and framework doesn't scale. A sidecar runs next to the app, in the same pod or host, and provides it. An ambassador is a sidecar specialised in outbound calls. A service mesh is sidecars everywhere, configured centrally.

What a mesh buys

mTLS and service identity everywhere without code changes. Retries, timeouts and circuit breaking as configuration. Traffic splitting for canaries. Uniform golden-signal metrics and traces for every hop, in every language.

What it costs

An extra proxy hop per call (roughly 1 ms of p99 each way), CPU and memory per pod, and a complex control plane to run and upgrade. Debugging now spans app, proxy and configuration. Worth it with dozens of services, rarely with five.

Lighter options

Proxyless gRPC with xDS, eBPF-based meshes (Cilium) that avoid per-pod proxies, or simply shared client libraries when there is a single language. Choose on the number of services, languages, and how badly you need zero-trust networking.
