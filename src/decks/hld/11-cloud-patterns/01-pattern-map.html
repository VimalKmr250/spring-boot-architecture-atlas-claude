The cloud design patterns, grouped by the problem they solve

The roadmap ends with the catalogue of cloud design patterns (popularised by Microsoft's Azure Architecture Center). They are named, reusable answers to recurring distributed-systems problems. Many have already appeared in this deck under their mechanism. This map puts the names on them, so you can use the vocabulary interviewers expect.

How to use pattern namesName the pattern and then say what it does in this design, in one breath: "I'd use a claim check here. The 20 MB document goes to object storage, and the message carries only its key." A name without the mechanism sounds memorised, and the mechanism without the name is fine too. Together they sound senior.
