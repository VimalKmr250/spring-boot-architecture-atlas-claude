Deep dive 2: a redirect in under 10 ms, and clicks counted without slowing it

The read path carries 99% of the traffic, and every millisecond is someone else's page-load time. Keep it to one memory lookup, keep the database off it, record clicks asynchronously, and decide deliberately what the browser and CDN are allowed to cache.

What may be cached where

Redis: everything, with a long TTL (links are immutable; delete on expiry or takedown). Browser/CDN: only for links marked "no stats", via 301 or max-age. Tracked links use 302 + no-store, or the clicks would vanish into caches.

Counting clicks at 20k/s

Don't UPDATE clicks = clicks + 1 per redirect. That's a hot-row write storm. Stream raw events, aggregate per code per minute in a consumer, and write the rollups to a columnar store. For a live counter, use Redis INCR on sharded keys, flushed periodically.

Hot links

A link shared by a celebrity can take 50k/s on one key, which means one Redis shard. Add a 1–5 s in-process cache in the redirect service (links never change, so staleness is harmless) or replicate hot keys. For "no stats" links, let the CDN absorb it entirely.
