Split the write path from the read path, and keep redirects in memory

Two services with very different shapes share one table. Shorten is low-volume and needs unique keys. Redirect is 100× busier, needs single-digit-millisecond lookups, and scales independently. Clicks go onto a stream, so analytics never slows a redirect.

Walk the write

① POST /v1/urls reaches Shorten. ② Shorten validates the URL (scheme, length, blocklist) and takes the next id from its in-memory block, fetched from the key generation service 1,000 ids at a time. ③ It encodes the id as base62, inserts (code, long_url, owner), and returns 201. It doesn't write to the cache; the first redirect warms it.

Walk the read

① GET /Ab3xK9q reaches Redirect. ② GET url:Ab3xK9q in Redis: on a hit, go to ④. ③ On a miss, read a DB replica and set the cache with a 24 h TTL (links are immutable). ④ Return 302 plus Cache-Control: private, max-age=0. ⑤ Publish a click event asynchronously, with ip hash, UA and referrer.
