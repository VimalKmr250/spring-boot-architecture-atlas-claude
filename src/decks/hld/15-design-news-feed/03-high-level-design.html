Precompute feeds on write, then assemble, hydrate and rank on read

The write path stores a post and hands it to fan-out workers, which push its id into each follower's cached feed. The read path takes the precomputed ids, merges in posts from any celebrities the user follows, fetches the post bodies in one batch, ranks, and returns a page. The expensive work happens asynchronously, off the user's critical path.

Post → visible

① Store the post (durable) and return 201. ② Publish PostCreated. ③ Fan-out workers page through the followers in batches of 1,000 and ZADD into each active follower's feed. A normal author's followers see the post in seconds.

Open the feed

① ZREVRANGE feed:u 0 499. ② Merge the latest posts of followed celebrities, cached per celebrity. ③ Multi-get post bodies, authors and counters. ④ Rank and filter (seen, blocked, deleted). ⑤ Return 20 items and a cursor.

Cold and inactive users

Skip fan-out for users inactive for 30 days: that saves most of the writes. When one returns, rebuild their feed on read (pull from followees), store it, then resume pushing. The first load is slower; every later load is fast.
