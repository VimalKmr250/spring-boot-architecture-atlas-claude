What one well-tuned node can take, to an order of magnitude

An estimate means nothing until it meets a capacity. These ranges are for a commodity cloud node (8–32 cores, SSD, 10 Gbps) doing simple operations. Real numbers depend heavily on payload size, query shape and tuning, so treat them as "which order of magnitude" guides and say so in the interview.

Other limits per nodeRough practical ceiling
Relational DB size1–10 TB before backups, vacuum and migrations get painful
Redis memory25–100 GB per instance; cluster beyond
Concurrent WebSockets per server100 k – 1 M, bounded by memory (~10–50 KB each)
Kafka partition write rate~10 MB/s per partition is a safe planning figure
DB connections (PostgreSQL)a few hundred active; put a pooler in front
Network per instance10–25 Gbps; egress cost often binds first
How to use themSay "roughly" and the order of magnitude: "About 3,000 writes a second at peak. A single PostgreSQL primary handles that with headroom, so I won't shard on day one, but I'll pick a partition key now so sharding later is a migration, not a redesign." Then move on. Nobody will argue about 5k versus 15k.
