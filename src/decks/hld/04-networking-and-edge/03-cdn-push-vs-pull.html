A CDN moves bytes close to users so your origin never sees most requests

A content delivery network is a fleet of caching proxies in hundreds of locations. It cuts latency (the edge might be 10 ms away when the origin is 150 ms away) and it absorbs load and DDoS traffic. The main decision is how content reaches the edge: fetched on first request (pull) or uploaded ahead of time (push).

Cache keys and headers

Cache-Control: public, max-age=86400 lets the edge cache a response, and private or no-store stops it. The cache key is usually URL plus selected headers, so keep the key small: an unneeded Vary header or a tracking query parameter destroys the hit ratio.

Invalidation

Prefer versioned URLs (app.3f9a.js, /img/v2/…): a new version is a new object, so nothing needs purging. Keep purge APIs for mistakes. For HTML, use short TTLs with stale-while-revalidate.

More than static files

Modern CDNs terminate TLS, run a WAF and absorb DDoS, cache public API responses for seconds, sign URLs for private media, and run small functions at the edge. An origin shield (a mid-tier cache) stops 300 PoPs from all missing to the origin at once.
