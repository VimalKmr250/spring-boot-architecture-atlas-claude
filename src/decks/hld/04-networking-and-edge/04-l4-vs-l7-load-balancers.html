An L4 balancer routes connections; an L7 balancer routes requests

The layer tells you how much of the packet the balancer can read. A layer-4 balancer sees addresses and ports, so it forwards whole TCP or UDP connections, blindly and very fast. A layer-7 balancer terminates TLS and reads the HTTP request, so it can route on path, header or cookie, at the cost of more CPU per request.

Layer 4Layer 7
Routes onIP, port, protocolHost, path, method, headers, cookies, JWT claims
Unit of balancingConnection: a long-lived HTTP/2 or gRPC connection sticks to one serverRequest: can spread requests from one connection across servers
TLSPass-through (or terminate)Terminates, and can re-encrypt to the backend
ExtrasVery high throughput, low latency, any TCP/UDP protocolRetries, header rewrites, compression, auth hooks, canary splits, WebSocket upgrade
ExamplesAWS NLB, GCP Network LB, IPVS, HAProxy (TCP mode)AWS ALB, Envoy, Nginx, HAProxy (HTTP mode), Traefik
The gRPC gotchagRPC multiplexes many calls over one long-lived HTTP/2 connection. Behind an L4 balancer, each client's connection is pinned to one server, so load ends up badly skewed. Use an L7 proxy that balances per request, or client-side load balancing.
