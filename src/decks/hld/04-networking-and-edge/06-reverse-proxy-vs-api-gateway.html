A gateway is a reverse proxy that knows about your API

A reverse proxy sits in front of servers and hides them: it terminates TLS, compresses, caches and buffers. An API gateway adds API-aware policy: who is calling, how often they may call, and which of many services should answer. A service mesh applies the same ideas to traffic between services.

Put in the gateway

Cross-cutting, request-level policy that should be identical for every service: token validation, coarse authorisation (scopes), rate limits, request size limits, CORS, request IDs, access logs.

Keep out of the gateway

Business logic, orchestration across services, and anything that needs a database transaction. A gateway full of logic becomes a distributed monolith that every team queues to change.

BFF: one gateway per client

A backend for frontend is a thin gateway per client type (web, iOS, partner). It aggregates and shapes responses for that client, so the mobile app gets one call instead of six, and web and mobile evolve separately.
