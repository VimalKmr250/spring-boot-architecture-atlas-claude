Uploads flow through an event-driven transcoding pipeline; playback never touches it

Upload and playback share only two things: object storage and the metadata store. The upload side is asynchronous. A stored original emits an event, an orchestrator runs a transcoding DAG on a worker fleet, and the video flips to READY when renditions exist. The playback side is a thin API that hands out a signed manifest URL, and the CDN does the rest.

An event starts the pipeline

The storage "object created" event, or the complete call, publishes video.uploaded. The orchestrator builds a DAG for that video, fans tasks out to a queue and tracks them. Every task is idempotent, keyed by (video, chunk, profile), so a retry overwrites instead of duplicating.

Signed, short-lived URLs

The playback API authorises the viewer (region rights, age, subscription) and returns a manifest URL with a token valid for a few hours. The CDN checks the token at the edge, so authorisation stays centralised while bytes stay local. Studio content adds DRM on top.

An origin shield protects storage

Hundreds of edge locations missing on the same new segment would each hit origin. A regional shield layer collapses those into one fetch and caches it. Origin load becomes the number of regions, not the number of edges.
