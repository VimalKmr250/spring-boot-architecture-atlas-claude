Wall clocks disagree, so don't use them to decide which write came last

Every machine's clock drifts, and NTP corrects it only to within a few milliseconds, sometimes by jumping backwards. If two nodes timestamp writes and "last write wins", a node whose clock runs fast wins even when it wrote first. Distributed systems order events with logical clocks, and fall back on physical time only with explicit uncertainty bounds.

Lamport clocks

One counter per node, carried on every message. They give a total order consistent with causality (ties broken by node id). They cannot tell you whether two events were concurrent.

Vector clocks / version vectors

One counter per node, kept as a vector. Comparing two vectors tells you "happened before", "happened after", or "concurrent, so this is a conflict". Dynamo-style stores use them to detect siblings that need merging.

Hybrid logical clocks (HLC)

Physical time plus a logical counter. The timestamps stay close to wall time (readable, useful for TTLs) but never go backwards and respect causality. CockroachDB and YugabyteDB use them.

TrueTime (Spanner)

GPS and atomic clocks expose time as an interval [earliest, latest], and a commit waits out the uncertainty (a few ms) before it becomes visible. Real-time ordering across the globe, paid for in hardware and latency.
