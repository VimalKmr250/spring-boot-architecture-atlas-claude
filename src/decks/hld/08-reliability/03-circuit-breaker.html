Stop calling a dependency that is failing, and check back later

A circuit breaker wraps calls to one dependency and watches their outcomes. When failures or slow calls cross a threshold, it opens and fails subsequent calls immediately, without making them. That protects the caller's threads and gives the dependency room to recover. After a cool-down it lets a few trial calls through to see whether the dependency is healthy again.

Choose the fallback first

An open breaker is only as good as what you return instead: a cached or default value ("recommended for you" becomes "bestsellers"), a degraded response ("shipping estimate unavailable"), a queued write ("we'll confirm by email"), or, for critical paths, a clear, fast error.

Tune per dependency

Base the window and threshold on each dependency's normal error rate. Count slow calls as failures, not just errors. Use one breaker per dependency (or per endpoint), never one for the whole application. Emit state changes as metrics and alert when a breaker opens.

Where it lives

In-process libraries (Resilience4j, Polly) or in the mesh (Envoy's outlier detection ejects bad hosts from the pool). Combine it with timeouts, which bound each call; retries, which go inside the breaker; and bulkheads, which bound concurrency.
