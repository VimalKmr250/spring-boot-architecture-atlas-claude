Generate IDs without a central counter by putting time and machine in the bits

An auto-increment column works until you have several databases, several regions, or a client that needs an ID before the insert. Distributed ID schemes let every node mint unique IDs with no coordination. The better ones are also roughly time-sortable, which keeps B-tree inserts sequential and makes "latest first" queries cheap.

A good defaultUse UUIDv7 (or ULID) for entity ids: no coordination, and time-ordered, so it's index-friendly. Use a Snowflake-style 64-bit id when size matters at huge volume (tweets, messages). For short public codes (a URL shortener, an order reference), encode a number in base62 and don't make them guessable where that matters (§12).
