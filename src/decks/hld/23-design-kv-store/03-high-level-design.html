A ring of identical nodes: any one coordinates, N replicate, W or R must answer

There is no master. A client, or a partition-aware driver, sends a request to any node, and that node coordinates. It computes the key's replicas from the ring, forwards the request to all N, and replies as soon as W acknowledge a write or R answer a read. Every node runs the same stack, so the cluster grows by adding identical machines.

Membership by gossip

Every second, each node exchanges its view of the cluster (who's up, which tokens they own, their heartbeat counters) with a few random peers. Changes reach all nodes in O(log n) rounds, with no central registry to fail. Seed nodes only help new nodes join.

Failure detection is a suspicion level

Instead of a fixed timeout, a phi-accrual detector turns the heartbeat inter-arrival history into a suspicion level. That adapts to slow networks. A suspected node is routed around, and no data moves until an operator or a policy decides it is permanently gone.

Adding a node

A new node takes vnode ranges from existing owners and streams those ranges in the background while the old owners keep serving. Only about 1/n of the data moves (n nodes), which is the whole point of consistent hashing compared with hash mod N.
