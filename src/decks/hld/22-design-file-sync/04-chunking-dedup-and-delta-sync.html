Deep dive 1: pick block boundaries so that an edit changes as few blocks as possible

Delta sync works only if an edit leaves most block hashes untouched. Fixed 4 MB blocks manage that for in-place edits but fail badly on insertions, because every later boundary shifts. Content-defined chunking puts boundaries where the content itself has a certain pattern, so they move with the content and an insertion disturbs only the chunk it lands in.

Dedup, and its privacy catch

Identical blocks are stored once, with a reference count, across files and versions. Deduplicating across users saves more but leaks information: if an upload is skipped, the file already exists somewhere. Many services therefore deduplicate only within an account or namespace.

Pipeline the upload

Hash, compress and upload blocks concurrently as a stream, rather than one file at a time. Progress is recorded in the local database, so a crash or reboot resumes where it stopped. A 20 GB file commits once, after its last block is stored.

Delta on the way down, too

A downloading device first checks which of the new version's hashes it already has, from the previous version or another file, and fetches only the rest. It assembles the new file in a temporary path and renames it atomically, so a half-written file never appears.
