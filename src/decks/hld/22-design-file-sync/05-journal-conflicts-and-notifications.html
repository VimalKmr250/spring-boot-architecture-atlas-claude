Deep dive 2: an ordered journal and cursors for sync, parent revisions for conflicts

Metadata consistency rests on one structure: an append-only, gap-free journal per namespace. A device is always "caught up to seq N". Being told something changed only prompts it to pull from its cursor. Concurrent edits are caught with optimistic concurrency. A commit names the revision it started from, and if that's no longer the latest, the server refuses and the client keeps both copies.

Why not last-writer-wins?

LWW by timestamp silently discards someone's work, and device clocks disagree anyway. Revision numbers assigned by the server give a total order per file. parentRev detects the conflict exactly, and "keep both" guarantees nothing is lost. Text formats could be merged, but only by apps that understand them.

Moves and deletes are edits too

A rename is recorded as one journal entry (old path to new path), not a delete plus an add, so clients move the local file instead of re-downloading it. A delete keeps the old blocks for the retention window, which is what makes restore possible.

Garbage-collect carefully

When no version references a block any more, its refcount reaches zero, but don't delete it immediately: an in-flight commit may be about to reference it. Mark-and-sweep with a grace period (days) is the safe pattern. An accidental block deletion means permanent data loss.
