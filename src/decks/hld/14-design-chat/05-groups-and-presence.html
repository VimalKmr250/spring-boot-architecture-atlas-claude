Deep dive 2: fan-out to groups, and presence without a broadcast storm

Groups multiply delivery work by the member count. Presence multiplies it by the number of contacts, on every status change. Both are managed the same way: store once, fan out only to the live connections that need it, batch per gateway, and compute everything else lazily when someone looks.

Storage layout

Messages: partition (conv_id, month), clustered by seq DESC, so "latest 50" and "before seq X" are single-partition slices. Media lives in object storage, and the message holds a URL, size and thumbnail hash. Old months move to cheaper storage tiers.

Typing indicators and receipts

These are ephemeral and high-volume. Deliver them best-effort over the socket and never persist them. Coalesce read receipts to the latest seq, and in big groups show aggregated counts ("read by 12"), not per-member events.

Unread counts

Store last_seq and last_read_seq per member and conversation. The badge is the difference, summed across conversations. Never count by scanning messages. Cache the total per user and adjust it on each message and read event.
