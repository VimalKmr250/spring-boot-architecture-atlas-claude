Reconnect storms, regions and encryption are where chat designs get tested

The steady state is easy to draw. Interviewers probe the transitions. What happens when a gateway holding 500k sockets dies, or a region fails? How do two users in different regions keep one order? And what changes when the server can't read the messages?

Follow-upAnswer sketch
End-to-end encryptionClients encrypt per recipient device (Signal protocol). The server stores and routes ciphertext and holds public prekeys. Search and moderation move to the client.
Edit / deleteA new event referencing the original seq; clients apply it. Deletes are tombstones, purged later.
Spam and abuseRate limits per sender, reputation scores, reports, and metadata-based detection, since content is encrypted.
Message searchServer-side index if not E2E; otherwise a local index on the device.
Summarise the trade-offs"We chose at-least-once delivery with seq-based dedup over exactly-once. Wide-column storage partitioned by conversation over a relational database. Stateful gateways kept thin, with state in a TTL'd registry. And a home region per conversation for ordering, accepting one cross-region hop for remote members."
