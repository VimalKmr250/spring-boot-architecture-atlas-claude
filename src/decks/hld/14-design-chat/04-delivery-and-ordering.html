Deep dive 1: one message from Alice's phone to Bob's, with receipts

Follow a single message through the system. The two properties to protect are durability before acknowledgement (the tick means it's safe) and a single order per conversation (every device shows the same sequence). Both come from one decision: the server assigns each message a per-conversation sequence number as it persists it.

Assigning the sequence

There must be exactly one writer of a conversation's counter. Options: a per-conversation Redis INCR, persisted with the message; a conditional update on the conversation row; or routing every send for a conversation through one Kafka partition, whose single consumer numbers the messages. Never use client clocks.

Acks at every hop

Client → server: "sent" only after the write is durable, and the client retries with the same client_msg_id until it arrives. Server → client: the device acknowledges the highest seq it has, and anything unacknowledged is redelivered or picked up by sync. So delivery is at-least-once, and display is deduped by seq.

Multi-device

Each device is a separate connection with its own "acknowledged up to" position. Alice's own messages are also delivered to her other devices. Read state is per user: reading on the phone clears the badge on the laptop via a receipt to self.
