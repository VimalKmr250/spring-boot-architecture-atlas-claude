Blobs go to object storage; the database keeps only their metadata

Photos, videos, documents, backups and logs belong in an object store (S3, GCS, Azure Blob). It is effectively unlimited, cheap per GB, and designed for eleven nines of durability. Databases are for the small, queryable facts about those objects. The best pattern keeps the bytes off your application servers entirely.

What object stores are

A flat namespace of immutable objects addressed by key, served over HTTP. There is no in-place edit (rewrite the object instead), no rename, and listing is slow. Large objects use multipart upload (parallel, resumable parts). Strong read-after-write consistency is now standard on S3, GCS and Azure.

Cost levers

Lifecycle rules move cold objects to cheaper tiers (infrequent access, then archive) and expire temporary files. Egress is often the biggest bill: serve through a CDN and keep processing in the same region as the bucket.

Security

Buckets are private by default and stay that way. Presigned URLs grant one operation on one key for minutes. Content types are validated and sizes capped at signing time. Scan uploads before anyone else can download them. Keys include an unguessable id, never a user-controlled filename.
