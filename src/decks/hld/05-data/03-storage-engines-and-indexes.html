B-trees update in place; LSM-trees append and merge later

Under every database is a storage engine, and there are two main families. B-trees (PostgreSQL, MySQL/InnoDB) keep sorted pages on disk and modify them in place, which makes them good at reads and range scans. LSM-trees (Cassandra, RocksDB, ScyllaDB, Bigtable) buffer writes in memory and flush them as immutable sorted files, which makes them good at heavy write loads.

Indexes: speed reads, tax writes

  • Primary index: the table is ordered by it (clustered) or points into it.
  • Secondary index: another sorted structure. Every insert updates each one, so five indexes means roughly six writes.
  • Composite (user_id, created_at) serves "user X's latest", but not "all rows since T". Column order matters.
  • Covering index: holds every column the query needs, so the table is never read.
  • Index for your queries, check with EXPLAIN, and drop unused indexes.
