Writing to the database and the broker separately will eventually lose an event

"Save the order, then publish OrderPlaced" is two writes to two systems, with no transaction spanning them. A crash, timeout or deploy between them leaves the order saved and the event never sent, or the event sent for an order that rolled back. The transactional outbox makes it one write.

Poller vs CDC relay

A poller runs SELECT … FROM outbox WHERE published = false ORDER BY id every few hundred ms. It's simple, and it adds DB load and latency. CDC tails the database log (Debezium on the WAL or binlog): lower latency, no polling load, one more component to run.

Still at-least-once

The relay can publish a row and crash before marking it sent, so the row is published again. The outbox guarantees no loss, not no duplicates. Put a unique event id on every message and dedupe on the consumer side.

The inbox is its mirror

On the consuming side, record each processed event id in the same transaction as its effects (previous slide). Outbox plus inbox gives effectively-once processing across services without distributed transactions.
