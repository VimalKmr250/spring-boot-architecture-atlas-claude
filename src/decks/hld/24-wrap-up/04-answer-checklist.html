The same eight steps every time, run as a loop rather than a line

The framework from the start of the deck, now as a checklist you can run in any round. It's a loop because good interviews are. When the interviewer adds a constraint ("now make it multi-region", "what if a celebrity posts?"), go back to requirements and numbers, re-derive, and say what changes.

Before you draw a box

  • Written: 3–5 functional requirements and explicit non-goals.
  • Written: latency, availability, consistency and durability targets.
  • Numbers: peak QPS (reads and writes), storage over years, bandwidth.
  • The one ratio or number that shapes the design, circled.
  • API sketched: the write path carries an idempotency key.

Before you say "done"

  • Every store: what it is the source of truth for, and how it scales.
  • Every hop: timeout, retry, and what the user sees on failure.
  • No single point of failure left unnamed; a plan for the hot key.
  • Observability: the SLIs you'd alert on.
  • Three trade-offs stated, and what you'd do at 10× or with more time.
