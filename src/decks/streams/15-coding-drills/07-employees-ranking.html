Employees: highest, second highest, top N

The ranking questions are where interviewers probe ties and the difference between "second highest salary" and "the second person in a sorted list". Remember that Emeka and Farah tie at 81,000.

Drills 59–64
// 59 · Highest paid employee
employees.stream().max(Comparator.comparingDouble(Employee::salary))
         .map(Employee::name);                               // Optional[Asha]

// 60 · Highest paid in each department
employees.stream().collect(groupingBy(Employee::dept, TreeMap::new,
        collectingAndThen(maxBy(Comparator.comparingDouble(Employee::salary)),
                          o -> o.get().name())));
// {Engineering=Asha, Finance=Goran, Sales=Emeka, Support=Jia}

// 61 · Second highest salary, and who earns it
Optional<Double> second = employees.stream().map(Employee::salary).distinct()
        .sorted(Comparator.reverseOrder()).skip(1).findFirst();   // Optional[118000.0]
employees.stream().filter(e -> second.isPresent() && e.salary() == second.get())
         .map(Employee::name).toList();                      // [Bruno]

// 62 · Nth highest salary, n = 3
employees.stream().map(Employee::salary).distinct()
         .sorted(Comparator.reverseOrder()).skip(n - 1).findFirst();   // Optional[98000.0]

// 63 · Second highest salary in each department
employees.stream().collect(groupingBy(Employee::dept, TreeMap::new,
        collectingAndThen(toList(), list -> list.stream().map(Employee::salary).distinct()
                .sorted(Comparator.reverseOrder()).skip(1).findFirst())));
// {Engineering=Optional[118000.0], Finance=Optional[88000.0],
//  Sales=Optional[72000.0], Support=Optional[54000.0]}

// 64 · Top two earners in each department
employees.stream().collect(groupingBy(Employee::dept, TreeMap::new,
        collectingAndThen(toList(), list -> list.stream()
                .sorted(Comparator.comparingDouble(Employee::salary).reversed())
                .limit(2).map(Employee::name).toList())));
// {Engineering=[Asha, Bruno], Finance=[Goran, Hana], Sales=[Emeka, Farah], Support=[Jia, Ivo]}
Drills 65–69
// 65 · Earning more than their department's average (two passes)
Map<String, Double> avg = employees.stream()
        .collect(groupingBy(Employee::dept, averagingDouble(Employee::salary)));
employees.stream().filter(e -> e.salary() > avg.get(e.dept()))
         .map(Employee::name).toList();
// [Asha, Bruno, Emeka, Farah, Goran, Jia]

// 66 · Youngest in each department
employees.stream().collect(groupingBy(Employee::dept, TreeMap::new,
        collectingAndThen(minBy(Comparator.comparingInt(Employee::age)),
                          o -> o.get().name())));
// {Engineering=Chen, Finance=Hana, Sales=Dara, Support=Ivo}

// 67 · Sort by salary, highest first, then by name
employees.stream()
         .sorted(Comparator.comparingDouble(Employee::salary).reversed()
                           .thenComparing(Employee::name))
         .map(Employee::name).toList();
// [Asha, Bruno, Chen, Goran, Hana, Emeka, Farah, Dara, Kofi, Jia, Ivo]

// 68 · Oldest employee
employees.stream().max(Comparator.comparingInt(Employee::age))
         .map(Employee::name);                               // Optional[Goran]

// 69 · Give Support a 10% raise; records are immutable, so map to new ones
employees.stream()
         .map(e -> e.dept().equals("Support")
                 ? new Employee(e.id(), e.name(), e.dept(), e.salary() * 1.10,
                                e.age(), e.gender(), e.city())
                 : e)
         .toList();
// Ivo's new salary prints as 59400.00000000001
#The follow-up they askWhat to say
60Emeka and Farah both earn 81,000. Why Emeka?maxBy keeps the first of equal elements, in encounter order. If the answer should be "both", find each department's maximum, then filter everyone equal to it.
60Can you avoid the Optional?toMap(Employee::dept, e -> e, BinaryOperator.maxBy(cmp)) gives Map<String, Employee> directly. The o.get() above is safe because a group is never empty.
61Why distinct() before skip(1)?Two people on the top salary would otherwise make the "second highest" equal to the highest. This is exactly what the SQL version, with DENSE_RANK, does.
69Why does Ivo get 59400.00000000001?Because 1.10 cannot be represented exactly as a double. Money belongs in BigDecimal or long cents, and this output is the argument for it.
