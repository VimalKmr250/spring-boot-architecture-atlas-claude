Method references, and comparators built from parts

A method reference is a lambda that only calls one existing method. There are four kinds, and knowing which one you are writing explains the compile errors. Comparators are built by composing small pieces, and the one type-inference trap in the whole API lives here.

KindExampleThe lambda it stands for
Static methodInteger::parseInts -> Integer.parseInt(s)
Instance method of a particular objectmailer::sendReceipt · System.out::printlno -> mailer.sendReceipt(o)
Instance method of an arbitrary object of a typeString::toUpperCase · Order::customers -> s.toUpperCase(): the first argument is the receiver
ConstructorArrayList::new · String[]::new() -> new ArrayList<>() · n -> new String[n]
Comparator combinators, and the trap
orders.stream()
      .sorted(Comparator.comparing(Order::customer)                   // A to Z
                        .thenComparing(Order::total, Comparator.reverseOrder()))
      .toList();                                                      // then biggest first

orders.stream().sorted(Comparator.comparingDouble(Order::total).reversed());  // fine

orders.stream().sorted(Comparator.comparing(o -> o.total()).reversed());
// error: cannot find symbol
//   symbol:   method total()
//   location: variable o of type Object

orders.stream().sorted(Comparator.comparing((Order o) -> o.total()).reversed());  // fine

// Null customers last instead of a NullPointerException
orders.stream().sorted(Comparator.comparing(Order::customer,
                       Comparator.nullsLast(Comparator.naturalOrder())));

// Map entries by value, highest first: type arguments required
stockBySku.entrySet().stream()
          .sorted(Map.Entry.<String, Integer>comparingByValue().reversed())
          .map(Map.Entry::getKey)
          .toList();

Why reversed() breaks inferenceJava infers a lambda's parameter type from where the lambda is used. In comparing(o -> o.total()).reversed(), the call to comparing is the receiver of .reversed(), so it has no target type, and T falls back to Object. A method reference such as Order::total, or a typed parameter such as (Order o), carries the type with it.
