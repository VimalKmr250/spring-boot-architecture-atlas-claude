Nine shapes of lambda, and how to read a stream signature

Every stream method takes an interface from java.util.function, or a Comparator. Know the shape — what goes in, what comes out — and every signature on these slides reads at a glance. It also answers "what is a Predicate?" in five seconds.

The primitive variants

They exist so primitive streams never box. IntPredicate, IntFunction<R>, ToIntFunction<T>, IntUnaryOperator, IntBinaryOperator, IntConsumer, IntSupplier, ObjIntConsumer<T>, IntToLongFunction, IntToDoubleFunction, and the same again for Long and Double. The naming rule: ToInt… means it returns an int, Int… means it takes one.

Composition, and the effectively-final rule
Predicate<Order> paid  = o -> "PAID".equals(o.status());
Predicate<Order> large = o -> o.total() > 500;
orders.stream().filter(paid.and(large.negate()));         // paid and small

Stream.of("a", "", "b").filter(Predicate.not(String::isEmpty)).toList();   // [a, b]

Function<Order, Integer> nameLength =
        ((Function<Order, String>) Order::customer).andThen(String::length);

int threshold = 500;
orders.stream().filter(o -> o.total() > threshold);      // reads a local: fine
// threshold++;  would make the lambda above a compile error
"local variables referenced from a lambda expression must be final or effectively final"So int count = 0; orders.forEach(o -> count++); does not compile. The usual workaround, an int[] count = {0} or an AtomicInteger, compiles and brings back the shared mutable state that the side-effects slide warns about. The idiomatic answer is almost always count() or a collector. A @FunctionalInterface is any interface with exactly one abstract method; default methods and methods inherited from Object do not count.
