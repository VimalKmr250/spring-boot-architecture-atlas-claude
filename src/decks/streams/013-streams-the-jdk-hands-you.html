JDK methods that already return a stream

Since Java 8, and especially since 9, a lot of the JDK returns streams directly. The ones backed by a file or another resource hold it open until the stream is closed. That is the one rule people miss, because a terminal operation does not close the stream.

// Files.lines holds an open file handle until close()
try (Stream<String> lines = Files.lines(Path.of("orders.csv"))) {
    long paid = lines.skip(1)                        // the header row
                     .filter(l -> l.endsWith(",PAID"))
                     .count();
}

// An Iterable with no stream() method of its own

       .map(MatchResult::group).toList();                       // [1, 22, 333]

The leak no test catchesFiles.lines(path).filter(…).count() without try-with-resources leaves the file open. Stream is AutoCloseable, but nothing closes it for you: not the terminal operation, and not garbage collection in any timely way. In a long-running service each call leaks a file descriptor until the process fails with "Too many open files". Streams over collections, arrays and generators hold no resource and need no closing. The difference is invisible at the call site, which is the whole problem. Close handlers registered with onClose are how Files.lines releases its handle.
