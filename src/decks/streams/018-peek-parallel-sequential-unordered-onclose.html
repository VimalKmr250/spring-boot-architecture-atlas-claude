Operations that change how a pipeline runs, not what it computes

peek looks at elements in passing, and exists for debugging. The other four set flags on the whole pipeline: run in parallel or sequentially, ignore encounter order, and register cleanup for when the stream is closed.

Each one, with its effect
// peek: watch elements while debugging, then delete it
List<String> ids = orders.stream()
        .filter(o -> o.total() > 500)
        .peek(o -> log.debug("large order {}", o.id()))
        .map(Order::id)
        .toList();

// The last parallel()/sequential() call wins, for every stage
orders.stream().parallel().map(Order::id).sequential().isParallel();  // false

// unordered(): allow the order to be lost, for cheaper parallel work
Set<String> someIds = ids.parallelStream().unordered().limit(100)
                         .collect(Collectors.toSet());

// onClose: cleanup that close() runs, in registration order
try (Stream<String> s = Stream.of("a").onClose(() -> System.out.println("closed"))) {
    s.count();
}                                                     // prints "closed"
MethodWhat it really does
peek(action)Runs the action on each element that flows past. Elements that never flow are never peeked: short-circuits, and count() on a sized stream. The Javadoc says it "exists mainly to support debugging".
parallel() · sequential()Sets one mode for the entire pipeline, whatever its position. There is no way to run one stage in parallel.
unordered()Drops the ordering constraint. It does not shuffle anything; it only permits operations to stop preserving order.
onClose(handler)All handlers run on close(), even if one throws. The first exception propagates, with the rest attached as suppressed.
isParallel() · close()Query the mode; close the stream. After close(), using the stream throws IllegalStateException.
peek that changes thingsorders.stream().peek(o -> o.markExported()).count() marks nothing. The list's size is known, so since Java 9 count() returns it without running the pipeline, and peek never fires. Any logic that must run belongs in forEach, or better, in a plain loop that says what it does.
