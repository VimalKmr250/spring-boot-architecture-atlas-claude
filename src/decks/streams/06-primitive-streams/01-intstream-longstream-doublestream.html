Primitive streams exist to avoid boxing

A Stream<Integer> holds an object per element. IntStream, LongStream and DoubleStream hold primitives, and add the numeric operations a Stream<T> cannot: sum, average, statistics, ranges. What they lack matters just as much: no toList(), no collect(Collector), no sorted(Comparator) and no gather.

Crossing between object and primitive streams
int units = orders.stream()
        .flatMap(o -> o.lines().stream())
        .mapToInt(Line::qty)                             // Stream<Line> → IntStream
        .sum();

OptionalDouble avgTotal = orders.stream().mapToDouble(Order::total).average();

int[] squares = IntStream.rangeClosed(1, 5).map(i -> i * i).toArray();
// [1, 4, 9, 16, 25]

List<Integer> asList = IntStream.of(3, 1, 2).boxed().toList();   // box to collect

// IntStream.sorted() is ascending only; box to sort another way
List<Integer> desc = IntStream.of(3, 1, 2).boxed()
        .sorted(Comparator.reverseOrder())
        .toList();                                                   // [3, 2, 1]

Collect without boxingcollect(supplier, ObjIntConsumer, combiner), the only collect they have
chars() gives you numbers"abc".chars().forEach(System.out::println) prints 97, 98, 99. The stream is an IntStream of UTF-16 code units. Turn them back with mapToObj(c -> (char) c) or Character.toString(c), and use codePoints() when the text can contain emoji or other characters outside the Basic Multilingual Plane.
When boxing actually mattersA Stream<Integer> allocates an Integer per element outside the small cache of −128 to 127, and every arithmetic step unboxes it again. In a request handler over fifty items this is noise. In a numeric loop over millions it dominates, which is the case the primitive streams are for.
