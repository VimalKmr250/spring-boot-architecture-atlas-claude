Four numeric answers that surprise people

The primitive streams and numeric collectors are convenient and nearly always right. These four edge cases are the exceptions that turn into production bugs: overflow, the average of nothing, the statistics of nothing, and floating-point totals. Every output below is from JDK 25.

1 · sum() overflows silently

IntStream.of(Integer.MAX_VALUE, 1).sum();                   // -2147483648
Stream.of(Integer.MAX_VALUE, 1)
      .collect(Collectors.summingInt(x -> x));              // -2147483648
IntStream.of(Integer.MAX_VALUE, 1).asLongStream().sum();    // 2147483648

A revenue total held in cents as an int overflows at about $21.4 million, with no exception. Sum into a long with asLongStream() or mapToLong, or use Math.addExact in a reduce if overflow must fail loudly.

2 · The average of nothing: empty, or zero

IntStream.empty().average();                                // OptionalDouble.empty
Stream.<Integer>empty()
      .collect(Collectors.averagingInt(x -> x));            // 0.0

The stream says there is no average; the collector says it is zero. A dashboard showing an average order value of $0.00 on a day with no orders is this bug. Prefer the OptionalDouble, and decide what "no data" should display.

3 · The statistics of nothing

IntStream.of(4, 8, 15).summaryStatistics();
// IntSummaryStatistics{count=3, sum=27, min=4, average=9.000000, max=15}

IntStream.empty().summaryStatistics();
// IntSummaryStatistics{count=0, sum=0, min=2147483647,
//                      average=0.000000, max=-2147483648}

On an empty stream, getMin() is Integer.MAX_VALUE and getMax() is Integer.MIN_VALUE. Check getCount() before reading either, or a report shows a minimum price of 2,147,483,647.

4 · Floating-point totals depend on how you add

DoubleStream.of(0.1, 0.2, 0.3).sum();      // 0.6
double s = 0;
for (double d : new double[]{0.1, 0.2, 0.3}) s += d;
// s is 0.6000000000000001

DoubleStream.sum() uses compensated summation, so it is more accurate than a naive loop, and refactoring between the two changes the last digits. For money, neither is right: use long cents, or BigDecimal with reduce(BigDecimal.ZERO, BigDecimal::add).

The statistics classesIntSummaryStatistics, LongSummaryStatistics and DoubleSummaryStatistics compute count, sum, min, average and max in one pass. Get them from summaryStatistics() on a primitive stream, or from Collectors.summarizingInt and friends, which also work downstream of a groupingBy: one pass gives the statistics of every group.
