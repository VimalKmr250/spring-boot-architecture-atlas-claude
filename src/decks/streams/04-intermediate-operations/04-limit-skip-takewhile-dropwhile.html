Slicing by count, and slicing by condition

limit and skip slice by position. takeWhile and dropWhile (Java 9) slice at the first element that fails a condition. Only limit and takeWhile can end an infinite stream.

Five ways to cut the same list
List<Integer> xs = List.of(1, 2, 5, 1, 2);

xs.stream().limit(2).toList();                  // [1, 2]
xs.stream().skip(2).toList();                   // [5, 1, 2]
xs.stream().takeWhile(x -> x < 3).toList();     // [1, 2]        stops at 5
xs.stream().dropWhile(x -> x < 3).toList();     // [5, 1, 2]     keeps all from 5
xs.stream().filter(x -> x < 3).toList();        // [1, 2, 1, 2]  looks at everything

// Page 3, twenty per page

// Log lines up to the first error, in timestamp order
List<String> log = List.of("09:00 start", "09:01 ok", "09:02 ERROR disk full", "09:03 ok");
log.stream().takeWhile(l -> !l.contains("ERROR")).toList();   // [09:00 start, 09:01 ok]
MethodWatch for
limit(n)Short-circuits. A negative n throws IllegalArgumentException. On an ordered parallel stream it must find the first n by position, which costs; unordered() removes that cost if any n will do.
skip(n)Still reads the skipped elements. Paging a database stream with skip fetches every earlier row: page in SQL instead.
takeWhile(p) 9Not a filter: it stops at the first failure. On sorted data the two agree; on unsorted data they do not.
dropWhile(p) 9Drops the leading run only. Everything after the first failure is kept, even if it matches p.
takeWhile on an unordered streamOver a HashSet there is no "first" element, so the Javadoc allows takeWhile to return any subset of the matching elements, including none. The behaviour is nondeterministic. Slice by condition only on ordered sources, where "until the first failure" means something.
