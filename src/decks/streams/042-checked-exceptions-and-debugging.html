Checked exceptions, and seeing inside a pipeline

No interface in java.util.function declares a checked exception, so a lambda that calls a throwing method does not compile. There are four ways out, each with a cost. And a pipeline has no loop variable to watch, so debugging it needs different habits.

Four ways to handle IOException in a stream
// 1 · Wrap in an unchecked exception, and unwrap at the edge
List<String> contents = paths.stream()
        .map(p -> {
            try { return Files.readString(p); }
            catch (IOException e) { throw new UncheckedIOException(e); }
        })
        .toList();

// 2 · The same, moved into a named helper so the pipeline stays readable
List<String> contents2 = paths.stream().map(this::readOrThrow).toList();

// 3 · Keep failures as data, and decide afterwards
record Attempt(Path path, String content, IOException error) {}
Map<Boolean, List<Attempt>> outcome = paths.stream()
        .map(this::tryRead)                                   // never throws
        .collect(Collectors.partitioningBy(a -> a.error() == null));

// 4 · A plain loop, where "throws IOException" just works
for (Path p : paths) contents3.add(Files.readString(p));
OptionCost
1 · WrapCallers must know to catch UncheckedIOException; the first failure aborts the rest
2 · HelperSame behaviour, far more readable
3 · Failures as dataMore code, but one bad file no longer hides the other results
4 · LoopNone, when the exception should simply propagate
"Sneaky throw" tricksHide a checked exception from the compiler, so nobody is forced to handle it. Avoid

Debugging a pipeline

  • Insert .peek(x -> log.debug("after filter: {}", x)) between stages, then remove it.
  • IntelliJ IDEA's Trace Current Stream Chain shows every element at every stage, in the debugger.
  • Split a long pipeline into named Predicates and methods. A stack trace full of lambda$process$3 tells you nothing; isOverdue does.
  • Exceptions thrown inside a stage surface from the terminal operation, even in parallel, where they are rethrown on the calling thread.
