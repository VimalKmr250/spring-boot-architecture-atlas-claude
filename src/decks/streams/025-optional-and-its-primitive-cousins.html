Optional is a return type that means "maybe nothing"

findFirst, findAny, min, max and one-argument reduce return an Optional, because an empty stream has no answer. Used as intended, as a return type that makes the caller decide what "empty" means, it removes a class of NullPointerExceptions. Used as a field type, a parameter or a roundabout null check, it adds noise and new bugs.

The methods worth knowing, in use
String email = customers.stream()
        .filter(c -> c.id().equals(id))
        .findFirst()                                  // Optional<Customer>
        .map(Customer::email)                         // Optional<String>
        .orElseThrow(() -> new CustomerNotFound(id));

Optional<Order> big = orders.stream().filter(o -> o.total() > 1_000).findFirst();
big.ifPresentOrElse(this::flag, () -> log.info("no large orders"));   // 9

// orElse always evaluates its argument; orElseGet only when empty
Order a = big.orElse(repository.loadFallback());      // queries even when present
Order b = big.orElseGet(repository::loadFallback);    // queries only when empty

Optional<String> code = primary.or(() -> secondary);  // an alternative Optional (9)
List<Order> found = ids.stream().map(this::find)      // Stream<Optional<Order>>
        .flatMap(Optional::stream).toList();           // keep the present ones (9)
