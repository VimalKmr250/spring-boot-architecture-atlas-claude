Five collectors for plain collections

toList, toSet and toCollection build a collection you can change, although only toCollection promises it. toUnmodifiableList and toUnmodifiableSet (Java 10) build one you cannot. The only real decisions are mutability, nulls and order.

One of each
List<String> customers = orders.stream().map(Order::customer)
        .collect(Collectors.toList());

Set<String> statuses = orders.stream().map(Order::status)
        .collect(Collectors.toSet());                         // no order

TreeSet<String> sortedCustomers = orders.stream().map(Order::customer)
        .collect(Collectors.toCollection(TreeSet::new));      // sorted, deduplicated

Set<String> firstSeen = orders.stream().map(Order::customer)
        .collect(Collectors.toCollection(LinkedHashSet::new)); // deduplicated, in order

List<String> frozen = orders.stream().map(Order::id)
        .collect(Collectors.toUnmodifiableList());            // 10

Stream.of("a", "a").collect(Collectors.toUnmodifiableSet());  // [a]: no error
CollectorGives youNullsOrder
toList()An ArrayList today; the type, mutability and thread-safety are unspecifiedAllowedKept
toSet()A HashSet today; likewise unspecifiedOne allowedNone
toCollection(supplier)Exactly what the supplier createsAs that class allowsAs that class keeps
toUnmodifiableList() 10An unmodifiable listNullPointerExceptionKept
toUnmodifiableSet() 10An unmodifiable set; one of each group of duplicates is keptNullPointerExceptionNone
"Unspecified" is a real word hereThe Javadoc for toList() and toSet() says there are no guarantees on the type, mutability, serializability or thread-safety of the result. Today's JDK returns an ArrayList and a HashSet, and plenty of code relies on that. If your code mutates the result, toCollection(ArrayList::new) turns an accident into a contract.
Which list ending to pickFor a result nobody should change, use Stream.toList(), which also accepts nulls. For an unmodifiable list with nulls rejected, use toUnmodifiableList(). For a list the caller will change, use toCollection(ArrayList::new). Inside a grouping you still need Collectors.toList(): Stream.toList() is a terminal operation, not a collector, so it cannot go downstream.
