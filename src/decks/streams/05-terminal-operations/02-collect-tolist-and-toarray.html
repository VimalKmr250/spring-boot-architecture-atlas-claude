Getting a collection or an array out

Four ways to end in a container. toList() (Java 16) is the short one, and it returns an unmodifiable list. collect(Collector) takes any of the 44 Collectors. collect(supplier, accumulator, combiner) builds a mutable container by hand. toArray gives an array.

Each form, and what it returns
List<String> ids = orders.stream().map(Order::id).toList();       // unmodifiable (16)

List<String> editable = orders.stream().map(Order::id)
        .collect(Collectors.toCollection(ArrayList::new));        // mutable, guaranteed

String[] idArray = orders.stream().map(Order::id).toArray(String[]::new);
Object[] raw     = orders.stream().map(Order::id).toArray();      // Object[], not String[]

// Three-argument collect: create, add one, merge two (the merge is for parallel)
StringBuilder abc = Stream.of("a", "b", "c")
        .collect(StringBuilder::new, StringBuilder::append, StringBuilder::append);
// abc

ArrayList<String> copy = orders.stream().map(Order::id)
        .collect(ArrayList::new, ArrayList::add, ArrayList::addAll);

The refactor that breaks callersAn IDE offers to replace .collect(Collectors.toList()) with .toList(). It compiles, the tests pass, and a caller three layers away that does result.add(…) or result.sort(…) now throws UnsupportedOperationException in production. Before accepting it, check whether anyone mutates the result. If they must, say so with toCollection(ArrayList::new).
toArray() and the cast(String[]) stream.toArray() compiles and throws ClassCastException: the no-argument form always creates an Object[]. Pass the array constructor, toArray(String[]::new), and the stream allocates the right type, sized once when the size is known.
