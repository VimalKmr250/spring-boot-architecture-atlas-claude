reduce folds a stream into one value, if you respect its rules

reduce combines elements pairwise until one value remains. It has three forms. All of them need an associative operation, and the two with an identity need a real identity. Break either rule and a sequential test passes while the parallel result is wrong.

The three forms, then a broken identity
// 1 · identity + operator: never empty, returns the identity for no elements
int sum = Stream.of(1, 2, 3, 4).reduce(0, Integer::sum);               // 10

// 2 · operator only: empty stream, empty Optional
Optional<Integer> max = Stream.of(3, 1, 4).reduce(Integer::max);       // Optional[4]

// 3 · identity + accumulator + combiner: the result type differs from T
int letters = Stream.of("a", "bb", "ccc")
        .reduce(0, (acc, s) -> acc + s.length(), Integer::sum);         // 6

// 1 is not the identity of +, and parallel adds it once per chunk
IntStream.rangeClosed(1, 4).boxed().reduce(1, Integer::sum);              // 11
IntStream.rangeClosed(1, 4).boxed().parallel().reduce(1, Integer::sum);   // 14 on 20 cores
RuleMeansBroken by
Identityop(identity, x) == x for every xreduce(1, Integer::sum); reduce(" ", String::concat)
Associative(a op b) op c == a op (b op c)Subtraction, division, averaging pairs
Stateless, no side effectsDepends only on its argumentsReading or writing a field inside the lambda
Combiner agrees (form 3)combiner(u, accumulator(identity, t)) equals accumulator(u, t)A combiner that ignores one side
Reaching for reduce to…Use insteadWhy
Sum, count, min, maxmapToInt(…).sum(), count(), max(cmp)Clearer, and the primitive versions do not box
Build a list or a mapcollectreduce with immutable collections copies on every step: O(n²). Mutating the identity instead is a parallel data race
Join stringsCollectors.joining()reduce("", String::concat) copies the growing string every time: O(n²)
Say this in the interview"reduce is for combining immutable values with an associative operation that has an identity. For accumulating into a container I use collect, which is the mutable reduction: each thread fills its own container and the combiner merges them." That one distinction is most of what the reduce-versus-collect question is checking.
