Split into two, or compute two things in one pass

partitioningBy is a groupingBy with a boolean key, and it always returns both keys. teeing (Java 12) sends every element to two collectors and merges their results: two aggregates, one pass over the data.

partitioningBy, in both forms
Map<Boolean, List<Order>> bySize = orders.stream()
        .collect(Collectors.partitioningBy(o -> o.total() > 500));
List<Order> large = bySize.get(true);
List<Order> small = bySize.get(false);

Map<Boolean, Long> paidVsNot = orders.stream()
        .collect(Collectors.partitioningBy(o -> "PAID".equals(o.status()),
                 Collectors.counting()));

Stream.<Integer>empty().collect(Collectors.partitioningBy(x -> x > 0));
// {false=[], true=[]}: both keys, even for no input

// The same split with groupingBy: only keys that occur
orders.stream()
      .collect(Collectors.groupingBy(o -> o.total() > 500))
      .get(true).size();     // NullPointerException when no order is large
teeing: two collectors, one merge (12)
// The cheapest and the dearest order, in one pass
record Range(double min, double max) {}
Range range = orders.stream().collect(Collectors.teeing(
        Collectors.minBy(Comparator.comparingDouble(Order::total)),
        Collectors.maxBy(Comparator.comparingDouble(Order::total)),
        (lo, hi) -> new Range(lo.map(Order::total).orElse(0.0),
                              hi.map(Order::total).orElse(0.0))));

// Average as sum / count, one pass
double avg = orders.stream().collect(Collectors.teeing(
        Collectors.summingDouble(Order::total),
        Collectors.counting(),
        (sum, n) -> n == 0 ? 0 : sum / n));

Stream.of(3, 1, 4, 1, 5).collect(Collectors.teeing(
        Collectors.counting(),
        Collectors.summingInt(x -> x),
        (count, sum) -> sum + "/" + count));   // 14/5

partitioningBy or groupingBy?

Two outcomes of a yes-or-no question: partitioningBy, and you can call get(true) and get(false) without null checks. Three or more outcomes, or keys that are not boolean: groupingBy. The returned map is a small special-purpose class, so do not try to put other keys into it.

Why not just two pipelines?

Over a list, two pipelines cost two passes, which is usually fine. Over a stream you can read only once, such as lines from a file or rows from a cursor, a second pipeline is not possible. teeing is the one-pass answer, and its merger runs once, at the end.
