Stream or loop: readability first, then measure

A stream is not faster than a loop. For small collections it is usually a little slower, because it builds a pipeline and calls lambdas. It is often much clearer. Choose on clarity, and argue about speed only where a profiler shows the code is hot.

The same revenue report, twice
// Loop: the mechanics are on the page
Map<String, Double> byLoop = new HashMap<>();
for (Order o : orders) {
    if ("PAID".equals(o.status())) {
        byLoop.merge(o.customer(), o.total(), Double::sum);
    }
}

// Stream: the intent is on the page
Map<String, Double> byStream = orders.stream()
        .filter(o -> "PAID".equals(o.status()))
        .collect(Collectors.groupingBy(Order::customer,
                 Collectors.summingDouble(Order::total)));
Prefer a stream whenPrefer a loop when
The shape is filter, transform, collectYou must stop early on complex state
You are grouping, partitioning or aggregatingThe body calls methods that throw checked exceptions
Each step can be named and reusedSeveral variables change together on each iteration
The source may be large or lazy, or read only onceIt is a tight numeric loop over an array, on a hot path
Parallelism might be wanted laterYou need to step through it in a debugger, line by line

Where the cost really is

A pipeline allocates a few small objects up front. Per element, lambdas are called through interfaces, and the JIT usually inlines those once the code is hot. The two costs that actually show up are boxing in numeric pipelines, and unnecessary parallelism.

Where streams are genuinely cheaper

Laziness and short-circuiting: anyMatch over a lazily loaded source stops at the first hit, and no intermediate collections are built between steps. A loop gets the same only if you write the break and fuse the steps by hand.

Readability cuts both ways

A six-stage pipeline with nested collectors can be harder to read than the loop it replaced. When a pipeline needs a comment to explain it, extract the steps into named methods or predicates, or write the loop.
