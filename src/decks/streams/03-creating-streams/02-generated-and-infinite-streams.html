Streams that make their own elements

Some factories compute their elements instead of reading them. iterate and generate are infinite, so something downstream must short-circuit. The three-argument iterate and range are finite, and they replace the classic counting for loop.

The filter that never endsStream.iterate(1, n -> n * 3).filter(n -> n <= 100).toList() never returns. You know the values only grow; filter does not, and it is not short-circuiting, so it keeps reading the infinite source. Use the three-argument iterate, or takeWhile(n -> n <= 100), which stops at the first failure.
iterate or generate?If each value depends on the one before, it is iterate. If each is independent, it is generate. generate is unordered, so a parallel generate(…).limit(n) may call the supplier from several threads at once. Give it a supplier that is safe to share.
