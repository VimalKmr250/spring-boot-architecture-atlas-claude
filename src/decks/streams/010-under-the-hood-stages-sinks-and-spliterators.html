How a pipeline is built, and how it runs

Each intermediate call wraps the previous stage in a new pipeline object and records its flags. The terminal call walks back to the source, builds a chain of Sinks ending in the terminal's own sink, and pushes every element into that chain from a Spliterator. There is no queue between stages and no intermediate collection. This is the machinery the stepper on slide 5 animates.

The loop that runs a sequential pipeline (simplified from AbstractPipeline)
wrappedSink.begin(spliterator.getExactSizeIfKnown());
if (!canShortCircuit) {
    spliterator.forEachRemaining(wrappedSink);     // push everything
} else {
    do { } while (!wrappedSink.cancellationRequested()
                  && spliterator.tryAdvance(wrappedSink));
}
wrappedSink.end();

Say this in the interview"A stream is a linked list of stages. The terminal operation turns them into a chain of sinks and drives a spliterator into the first one, so each element runs the whole chain before the next is read. Stateful stages buffer, and short-circuiting ones stop the source by answering cancellationRequested." Four sentences that answer most of the "how do streams work internally" follow-ups.
