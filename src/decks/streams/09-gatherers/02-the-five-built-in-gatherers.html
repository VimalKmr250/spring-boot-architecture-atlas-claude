Five gatherers ship in java.util.stream.Gatherers

Two windows, two accumulations, and one concurrency tool. Each replaces a pattern that used to need a loop or an external library. All outputs below are from JDK 25.

All five
IntStream.rangeClosed(1, 7).boxed().gather(Gatherers.windowFixed(3)).toList();
// [[1, 2, 3], [4, 5, 6], [7]]           the last window may be short

IntStream.rangeClosed(1, 5).boxed().gather(Gatherers.windowSliding(3)).toList();
// [[1, 2, 3], [2, 3, 4], [3, 4, 5]]     each window drops one, adds one

IntStream.rangeClosed(1, 4).boxed()
         .gather(Gatherers.scan(() -> 0, Integer::sum)).toList();
// [1, 3, 6, 10]                         a running total: one output per input

IntStream.rangeClosed(1, 4).boxed()
         .gather(Gatherers.fold(() -> 0, Integer::sum)).toList();
// [10]                                  one output, but the stream carries on

List<Invoice> invoices = orderIds.stream()
        .gather(Gatherers.mapConcurrent(16, billing::fetchInvoice))
        .toList();                       // 16 calls in flight, results in input order
GathererWatch for
windowFixed(n)The last window can be shorter than n. An empty stream produces no window.
windowSliding(n)Fewer than n elements still produce one short window: [1, 2] with n = 3.
scan(initial, f)Sequential and order-dependent. The seed itself is not emitted.
fold(initial, f)Sequential, for reductions no combiner can express. On an empty stream it emits the seed, [0], where reduce(op) would give an empty Optional.
mapConcurrent(max, f)Runs f on virtual threads, at most max at once, and keeps encounter order. If a call fails, the exception is rethrown as a RuntimeException and the remaining tasks are cancelled. max < 1 throws IllegalArgumentException.

A moving average in one pipeline

prices.stream().gather(Gatherers.windowSliding(7)).map(w -> w.stream().mapToDouble(d -> d).average().orElseThrow()).toList() is a seven-day moving average. Before Java 24 this took an index loop over a list, and could not work on a stream you can only read once.

mapConcurrent is not a parallel stream

A parallel stream splits CPU work across the common pool's platform threads. mapConcurrent overlaps waiting, such as remote calls, on virtual threads, with a hard cap that protects the service being called. For I/O-bound fan-out it is the right tool; parallelStream() with blocking calls is the wrong one.
